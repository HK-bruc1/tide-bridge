# 10. RDX 测试 AppKey 与设备 MAC 白名单

## 配置入口

在 `SDK/apps/earphone/include/t2620_project_config.h` 修改
`TCFG_RDX_TEST_APPKEY_MAC_LIST`，例如：

```c
#ifndef TCFG_RDX_TEST_APPKEY_MAC_LIST
#define TCFG_RDX_TEST_APPKEY_MAC_LIST \
    "AABBCCDDEEFF", \
    "112233445566",
#endif
```

上述地址仅为格式示例，必须替换成实际获准设备的本机 BLE MAC。
每项为 12 位十六进制字符串，不带冒号、横线或空格，大小写均可。
最后一项保留逗号；应用代码自动追加 NULL 终止项。
默认宏为空，表示没有任何设备获准使用测试 AppKey。
修改后需要重新编译并烧录，当前不提供运行时或 VM 白名单写入接口。

MAC 来自库内 `le_controller_get_mac()`，按数组下标 5 到 0 格式化。
可使用 BLE 初始化日志中 `le_controller_get_mac success, ble mac:` 的
显示地址，去掉冒号后填写。不要填写手机/PC 的地址、经典蓝牙地址或认证码。

## 初始化与鉴权

`rdx_app.c` 使用静态只读数组保存名单，在 `rdx_app_tasks_init()` 中，
先调用 `rdx_protocol_register_test_appkey_mac_list()`，再启动 BLE 服务和协议任务。
库保留数组指针，名单在整个固件运行期间有效，无需逐连接注册。

`APP_CUSTOM_TEST_EN`（`1 << 27`）选择库内测试 AppKey。
收到 `*APP#appkey#` 后，库先解密；若匹配这个特殊测试 Key，优先检查本机
BLE MAC 是否在名单中。即使该 Key 同时等于当前项目 Key，也不会跳过名单检查。
其他项目收到相同测试 Key 时同样受该名单限制，因此注册不按项目宏裁剪。
普通项目 Key 的既有校验分支保持不变。

匹配成功返回 `*DEV#appkey#0`；空名单、未命中或读取 MAC 失败返回
`*DEV#appkey#1`，并调用现有 `rdx_ble_server_app_disconnect()`。
这条库内失败路径没有改成 `rdxclose` 逻辑释放，不保证保留同链路 HID。
名单仅限制特殊测试 Key 的使用设备，不代表所有 RDX 命令已有会话鉴权门禁。

## 验证

主机契约检查注册时序、静态生命周期及 NULL 终止；固件构建检查库接口链接。
实机还需分别验证：空名单拒绝、命中成功、未命中拒绝、大小写兼容、重新连接后
策略仍有效，以及普通项目 AppKey 行为不变。失败时观察应答及实际断连，
同时检查同链路 HID 的影响。示例地址不作为实机验收数据。
