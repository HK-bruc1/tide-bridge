# 10-9. 会议录音落盘 APP 对接说明

> 更新：2026-10-30。设备端已实现并通过构建/主机测试；当时 APP 联调及实板验收待完成。设备端设计见 [10-8](10-8.会议录音落盘APP控制方案.md)。
>
> 2026-11-05：在线 F18 改为设备直接启动并主动上报 `record`。用户反馈这一流程测试可用，所测手机 APP 可以兼容；其他版本及未明确覆盖的场景仍需验证。

## 1. 功能

APP 新增「会议录音落盘」设置：

- **开启 `1`（默认）**：保持原逻辑，会议在设备保存；在线时同时推流，断开后继续本地录音。
- **关闭 `0`**：会议仅向已就绪的 RDX APP 推实时流，不在设备保存；未连接、未订阅通知或流未就绪时不能开始，正在录音/暂停时失去 RDX 则结束，不转离线。

适用于 APP 普通 CHAT 会议及 F18 会议；不改变 F19 灵感、CALL 或工厂/DUT。设备持久保存，重连、换 APP、重启不变，整机恢复出厂后开启。录音提示音 `rectone` 是另一独立设置；无资格开始的会议不播放录音提示音。

APP 主动闪记和 F19 灵感不属于本设置范围：它们使用 `flashnote`，不受 `recsave` 控制；会议使用 `record`。闪记的推流、本地保存及会话控制见 [10-10](10-10.灵感录音复用闪记协议融合方案.md)。

## 2. 设置指令

```text
查询：*APP#custom#recsave#get,<id>#
设置：*APP#custom#recsave#set,<id>,<enable>#
应答：*DEV#custom#recsave#<id>,<result>,<current>#
```

| 字段 | 约定 |
| --- | --- |
| `id` | 1～65535，最多 5 位十进制数字，原样带回，包括前导零 |
| `enable/current` | `1` 开启落盘，`0` 关闭；按设备返回的 `current` 显示 |
| `ok` | 查询成功，或设置已保存并生效 |
| `busy` | 本次未修改，录音待开始、录音、暂停、提示音、停止收尾或其他系统忙状态；不要自动重试 |
| `arg` | 本次未修改，格式错误，开发阶段排查 |
| `vmerr` | 本次保存失败，保持当前生效值；提示失败，不显示已保存 |

全部小写、不带空格、多余字段、换行或额外终止符。非法/缺失 `id` 不回复。合法请求最长 32 字节，应答最长 34 字节。

```text
APP -> *APP#custom#recsave#get,1#
DEV -> *DEV#custom#recsave#1,ok,1#

APP -> *APP#custom#recsave#set,2,0#
DEV -> *DEV#custom#recsave#2,ok,0#

录音中尝试开启，未修改：
APP -> *APP#custom#recsave#set,3,1#
DEV -> *DEV#custom#recsave#3,busy,0#
```

## 3. APP 状态处理

1. RDX 建立并订阅通知后查询一次，重连重新查询；不轮询，不在每次录音前重复设置。
2. 用户设置期间禁止重复操作；仅将匹配本次 `id` 的应答用于结束请求，始终按 `current` 刷新显示。
3. 同一时间仅一个配置请求；连接内 ID 递增。建议超时 2 秒，SET 超时视为“未确认”，使用新 ID 发 GET 核实，不盲目重复 SET。
4. 独立探测 `recsave`，不能因支持 `rectone` 就认为也支持此功能。旧固件 GET 超时隐藏该设置，不显示为关闭。
5. 默认 MTU 下应答会拆成多条通知。拼帧从 `*DEV#custom#recsave#` 起，收到之后第一个 `#` 结束；未完成又出现新 `*DEV#` 则丢弃旧半帧。规则同 [10-7](10-7.录音提示音APP对接说明.md)，注意前缀不同。

录音控制协议不变，**设置返回值不是录音 START 返回值**。不落盘会议仍使用原 START/PAUSE/RESUME/STOP 和标记协议；RDX 不可用时不能延迟补发开始，重连不自动续录。

在线 F18 双击开始时，设备自行受理并开启会议，不发送旧的 `*DEV#devrec#...#` 握手，也不需要 APP 回发 `*APP#record#1#...#`。录音初始化成功后，设备主动发送 `*DEV#record#...#` 开始状态；双击结束后上报停止状态。APP 须处理没有对应本端请求的状态并更新会议 UI，不要因为收到主动状态而重新发送 START。APP 主动开始/暂停/恢复/停止仍使用原 `record` 指令；F19 仍使用独立的 `flashnote` 状态。

不落盘时 START 被拒的表现：协议没有新增错误码。若当前链路仍可通知，设备回推当前录音状态（仍为 STOP）；没有提示音、灯效变化或回放中断。APP 发出 START 后如收到仍为 STOP 的状态，应视为“未开始”，提示用户检查连接，不要自动重发。

录音中失去 RDX（物理断开、`rdxclose`、关闭通知订阅）时，设备自行结束本次会议；若录音已真正开始且 `rectone=1`，设备会播放一次结束提示音（与 F19 一致）。开始提示音未放完即断开时只取消开始，不播结束音。物理断开后无法向 APP 回推 STOP，重连后请以查询到的录音状态为准，并按“已结束”处理本地 UI。

设备没有本次录音文件。APP 必须按当前在线会议关联状态和标记，允许无文件身份，停止后不等待设备文件保存/下载，也不能关联到上次文件。无文件会议的 `record` 状态报文可省略尾部 SN 和文件名，不能强制按显式 `0##` 解析；在线 `flashnote` 状态则按闪记协议显式发送 `0##`。用户确认免握手兼容并不代表上述无文件相关细节均已验证，仍需逐项核实。

## 4. 联调前置与检查

- 使用包含本功能的固件，设备已完成产品绑定；关闭工厂/DUT/OTA 等占用，RDX 通知及音频通道正常就绪后测试合法开始。
- 先 GET，再在完全空闲时 SET 关闭并确认 `ok,0`；保持 `rectone=1`，检验未连接/仅 HID/未订阅/流未就绪时 F18 无声拒绝。
- 分别用 APP 和 F18 开始，检查实时流持续、会议灯效/手势不变、暂停/恢复/标记有效；确认没有新文件/索引及旧文件串入。
- 使用新固件分别在 `recsave=0/1` 下验证：F18 开始不依赖 APP 回复 `devrec`，APP 能接收主动 `record` 状态、显示会议并接收 `stream`；结束及快速再次双击、提示音期间取消均正确。用户已确认所测手机 APP 基本兼容，其他版本及未明确覆盖的边界场景仍需验证。
- 录音及暂停时分别测试物理断开、`rdxclose`、CCC 关闭：设备结束且不落盘，重连不续录，可重新开始。
- 检查录音各忙阶段 SET 返回 `busy`、GET 正常；默认 MTU 能拼帧；重启保持关闭，整机恢复出厂为开启。
- 重新开启落盘，回归离线会议、在线推流落盘及断连续录；`rectone` 开/关与 `recsave` 开/关交叉验证。
