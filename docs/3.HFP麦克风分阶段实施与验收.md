## 11. 分阶段实施与门禁

Phase 0～4 构成一期 Windows 原生语音输入路径；一期可跳过可选 Phase 5，直接进入 Phase 6 量产冻结。除关闭重复枚举的 Classic HID 外，Phase 1～6 保持既有 A2DP、AVCTP、SPP、MAP、产测/DUT 和 Classic 无线升级能力，不在本方案中做 Profile 裁剪。Phase 5 是后期 F24 + Agent 增强，启用时必须继承一期全部门禁并在完成后重新执行 Phase 6。每个执行阶段都必须满足代码评审、host 测试、正式工具链构建、设备验收和前序能力回归。

### Phase 0：冻结基线与确认 SDK 复用

**目标**

证明 SDK 已有能力和当前阻断点，不改变产品行为。

**实施内容**

1. 记录当前宏、名称、地址、SDP Profile 和 HOGP 契约。
2. 记录当前 Classic 被 RDX 延迟关闭的启动日志。
3. 在实验配置中只阻止 RDX shutdown，验证 SDK 原生配对、回连、SLC 和 SCO。
4. 记录 Windows 的 HFP、Classic HID、A2DP 和 BLE HOGP 枚举。
5. 记录 SCO active 时 DAC、下行波形、底噪和功耗。
6. 记录 T2620 实际出现的 SLC 事件类型和顺序，确认 `BT_STATUS_HFP_SERVICE_LEVEL_CONNECTION_OK`、`BT_STATUS_CONN_HFP_CH` 是单独出现还是重复出现。
7. 在 `TCFG_BT_DUAL_CONN_ENABLE=0` 下实测 `write_scan_conn_enable()`、`dual_conn_state_handler()`、`dual_conn_close()` 的扫描和关闭行为。
8. HFP audio active 时连续发送 HOGP report，验证基础并发假设。
9. 使用现有 LONG 事件或等效交互样机进行约 750 ms 长按体验预演，由产品负责人冻结“长按触发 Windows 语音输入”是否可接受。
10. 记录 adapter 输出的 KEY5 `CLICK/LONG/HOLD/HOLD_nSEC/UP` 最终事件流，确认短按不产生 UP、长按松手保留 UP，不能只依据底层 key driver 推断。
11. 记录 `BT_STATUS_SCO_STATUS_CHANGE` 的原始 `event/value/args`，验证 `0xff` close、包长、raw eSCO type 与 CVSD/mSBC 派生关系。
12. 在目标 Windows 版本上手动将本设备 HFP Mic 设为默认输入，验证 `Win+H` 在目标文本应用中的启动/停止、焦点、语言、隐私权限、网络依赖和 SCO 打开行为。
13. 记录 A2DP/HFP 是否改变 Windows 默认播放或录音端点；在多个麦克风及两台同型号设备场景中确认一期只能依赖用户手动选择默认输入。
14. 临时启用 `RDX_HOGP_KEY_ACTION_TEST_ENABLE`，将 `s_rdx_hogp_test_keymap` 的 KEY5 槽位设为 LGUI + H，通过 KEY5 CLICK 验证 HOGP → `Win+H` → Windows 语音输入 → HFP/SCO → STT 闭环。注意现有 HID ready 路由仅在 `KEY_ACTION_CLICK` 时调用 `rdx_hogp_key_action_click()`（`rdx_app.c` key remap），LONG/HOLD/UP 被直接消费，因此该 PoC 不验证 LONG/HOLD/UP、`gesture_owner` 或一期正式路由；完成后恢复测试宏和 keymap。LONG 事件流由第 9、10 条独立验证，正式长按触发在 Phase 4 实现。

**自动验收**

- 现有统一 host 测试全部通过；
- 新增 `test_hfp_mic_foundation.ps1`，冻结现有 HFP/mSBC/HOGP 和 SDK owner；
- 新增 `test_hfp_mic_reuse_contract.ps1`，禁止新增 pairing/bond/SCO owner。

**设备验收**

- 日志可观察 ACL -> SLC -> SCO open/close；
- 基线日志明确实际 SLC 事件来源；两个 SLC 事件都出现时只形成一次状态迁移和一次业务计数；
- SDK 原生 60 秒开机回连、120 秒超距回连和 120 秒 Inquiry 行为得到实测；
- `TCFG_BT_DUAL_CONN_ENABLE=0` 时现有 scan/state/close 入口行为符合单连接产品预期；
- HFP audio active 时 HOGP report 可持续发送，无立即掉线或明显阻塞；
- 约 750 ms 长按阈值取得产品确认；若不接受，停止后续语音触发实施并单独评审按键语义；
- adapter 后最终按键日志证明 CLICK 与 LONG/HOLD/UP 语义符合单次触发假设；
- SCO raw value 与规范化 codec 的映射得到实测；
- `Win+H` PoC 能在目标 Windows/应用/语言组合中使用本设备默认 HFP Mic 完成听写，并记录系统定义的启停行为；
- 默认输入不是本设备、无文本焦点、语音权限关闭、断网及多设备场景的实际表现和用户恢复步骤已记录；
- 能明确区分“Profile 已编译”和“Classic 被 RDX 主动关闭”。

**回归范围**

HOGP、RDX Config、DUT、OTA、离线录音、本地播放、SD/DAC 电源。

**退出条件**

基线报告证明无需新建 Classic/HFP 控制状态机，所有未知事件有原始日志；一期目标 Windows 矩阵、`Win+H` 行为、默认麦克风前提、长按触发语义、下行音频处理需求和 SDK 单连接行为已经冻结。

### Phase 1：保留 SDK Classic 生命周期并拆分 RDX 电源动作

**目标**

让 T2620 使用 SDK 已有 Classic/HFP 能力，不引入新的连接管理，并保留现有产测、DUT 与 Classic 无线升级链路。

**实施内容**

1. 增加 `TCFG_RDX_HFP_MIC_ENABLE`，T2620 开启，其他产品默认关闭。
2. 拆分 Classic disable 与 board idle power。
3. HFP 产品启动时不再调度 RDX Classic shutdown。
4. DUT 退出按产品开关调用 `dual_conn` 公开状态重算入口恢复 SDK 正常连接管理，不能只跳过 shutdown。
5. T2620 overlay 冻结 HFP、mSBC，并关闭 Classic HID。
6. 保持 A2DP、AVCTP、SPP、MAP、PNP、`TCFG_AUDIO_DUT_ENABLE`、`TCFG_UPDATE_BT_LMP_EN` 与 BLE priority 当前值；Profile 配置不随 HFP Mic 开关派生。
7. 产品覆盖放在 `t2620_project_config.h`，禁止修改工具生成的 `sdk_config.h/c`；只覆盖本方案明确需要改变的 HFP/mSBC/Classic HID 和新增模块开关。
8. board idle power 在关闭 SD/DAC 前确认资源 idle，并验证启动后 1 秒内快速回连/SCO 竞态。

**自动验收**

- HFP 产品不调用延迟 Classic shutdown；
- 非 HFP 产品保留原行为；
- board power action 不受 HFP 开关跳过；
- DUT HFP 恢复路径使用 `dual_conn` owner 的公开入口，不直接写 LMP scan；
- 新代码不出现第二套 timer/page list/link key；
- `test_hfp_mic_config.ps1` 冻结 T2620 HFP/mSBC/Classic HID 有效宏，并确认 A2DP、AVCTP、SPP、MAP、音频 DUT 和 BT LMP update 保持开启；
- 配置矩阵冻结 `HFP Mic=1/HFP=0` 编译失败，同时允许 `HFP Mic=1/HOGP=0` 的独立普通麦克风组合；
- 全量 host 测试和固件构建通过。

**设备验收**

- Windows 只枚举 BLE Keyboard，不枚举 Classic Keyboard；
- HFP 首次配对、开机回连、超距回连由 SDK 正常完成；
- 删除 Windows 旧 bond 后重新配对，确认 Classic HID 不再枚举；A2DP/AVCTP 等既有端点及 HFP Mic/Hands-Free 下行符合基线记录；
- 进入/退出 DUT 后 SPP 产测通道正常，Classic BT LMP 无线升级完成并可正常重启回连；
- DUT 进入/退出后扫描、回连 timer、SLC 和 SCO 均恢复到 SDK 正常状态；
- SD/DAC 功耗行为与基线一致，快速回连/SCO 不会被延迟 board idle power 关断。

**回归范围**

Phase 0 全部项目，重点覆盖 DUT、软关机、OTA 和非 T2620 RDX 产品。

**退出条件**

Classic 生命周期只有 SDK owner，RDX 不再用一个 shutdown 同时控制协议栈和板级电源；产测、DUT、SPP 和 Classic 无线升级能力无回归。

### Phase 2：只读状态监视与 RDX binding

**目标**

补齐模块化状态、日志和诊断，不改变连接或音频行为。

**实施内容**

1. 新增 `bt_hfp_mic_status.*`。
2. 新增薄 `rdx_hfp_mic.*`，从现有 RDX BT handler 转发事件。
3. 实现 single-link 地址绑定、快照、规范化 codec、raw eSCO 字段、统计、幂等和 dump。
4. `rdx_hfp_mic` 和公共 status 不 include/call HOGP；跨链路诊断由 `rdx_app` 分别读取 HFP snapshot 与 HOGP ready 后输出。

**自动验收**

- `test_hfp_mic_module_contract.ps1` 检查依赖和禁止控制符号；
- `test_hfp_mic_status_contract.ps1` 检查 ACL/SLC/audio 派生规则；
- status contract 检查 SLC 补齐 ACL、audio 补齐 ACL/SLC、下层断开清理上层事实、所有 `1 -> 0` 计数，以及迟到的异地址事件不能清理当前 peer；
- status contract 冻结 `value == 0xff` close、raw eSCO type/包长提取和 CVSD/mSBC 规范化规则；
- API contract 明确默认 app_core task affinity；跨任务读取必须整体复制快照；
- status/binding 不出现 scan、bond、reconnect、`esco_*`、`bt_cmd_prepare`；
- 模块依赖检查禁止 `rdx_hfp_mic` include/call HOGP，并禁止 HOGP transport include/call HFP binding；
- 全量 host 测试和固件构建通过。

**设备验收**

- 快照与 SDK 日志一致；
- 重复 SLC/SCO close 幂等；
- 两个 SLC ready 事件连续到达时，`slc_connect_count` 只增加一次，`duplicate_event_count` 正确增加；
- 快速断开/重连时，旧 peer 的迟到 SLC/SCO close 不会清除新 peer；
- 未知事件只计数，不改变事实位；
- 观察模块开关不影响连接、音频、功耗。

**回归范围**

HFP 单链路、HOGP 单链路、HFP+HOGP、睡眠唤醒、异常断电。

**退出条件**

状态监视连续 60 分钟无漂移，关闭模块时行为与 Phase 1 一致。

### Phase 3：名称与 HOGP/HFP 共存冻结

**目标**

形成可量产的双端点名称、Windows 默认输入流程和射频配置。

**实施内容**

1. 落实 BLE RDX+HOGP / Classic Mic 名称与 VM 迁移策略。
2. 保证 BLE 统一广播名与 GAP `0x2A00` 一致。
3. 验证 Classic 编译期名称、EIR、Windows 缓存和重新配对行为；动态改名不可靠时明确关闭该产品能力。
4. 对 BLE high priority 做 `0/1` A/B 测试并冻结结果。
5. 保持 RDX/HOGP 单 BLE link 和 capability 模型，不增加 BLE 连接数或 owner。
6. 冻结一期 Windows 默认输入设备设置/恢复流程，以及多麦克风、多同型号设备的已知限制。
7. 冻结目标 Windows 版本、显示/语音语言、权限、网络条件和文本应用矩阵。
8. 冻结最终 SDP/Windows 枚举：Classic HID 必须关闭；A2DP、AVCTP、SPP、MAP、PNP 及 HFP 固有的 Hands-Free 下行端点按当前产品配置保留并记录。

**自动验收**

- `test_hfp_hogp_coexistence_contract.ps1` 禁止双向控制；
- `test_hfp_mic_config.ps1` 冻结 overlay/Profile 配置；
- 名称测试冻结统一广播名和 GAP 名；
- Windows 验收 contract 冻结默认输入、焦点、语言/权限/网络条件和不支持场景；
- 全量 host 测试和固件构建通过。

**设备验收**

- HOGP first、HFP first 两种配对顺序均通过；
- HFP active 时普通 HOGP 按键正常；
- 任一链路断开、回连不关闭另一条链路；
- Windows 显示 Keyboard 和 Mic 两个清晰端点。
- 默认输入为本设备时，`Win+H` 使用其 HFP Mic；默认输入变化时按冻结的用户流程恢复；
- 两台同型号设备同时连接时如实验证一期依赖用户选择默认 Mic，不承诺自动关联；
- Windows 不显示 Classic Keyboard；A2DP/AVCTP 与 HFP 固有音频端点符合 Phase 0/1 对照记录，不能误判为本次 HFP 改造缺陷。

**回归范围**

HOGP Report Map/handle/payload、BLE Config、RDX App、HFP/A2DP 音频、SPP 产测、DUT 和 Classic 无线升级。

**退出条件**

BLE priority 有双向数据支撑，名称、Windows 枚举、默认输入流程和一期系统依赖入库。

### Phase 4：一期 KEY5 触发 Windows 语音输入

**目标**

复用现有 `LONG/HOLD/UP` 和 HOGP click executor，让 KEY5 每次长按可靠发送一次 `Win+H`，完成无需 PC Agent 的 Windows 语音输入闭环。

**实施内容**

1. 新增轻量 `rdx_voice_trigger.*`，不扩展 HOGP press/release API。
2. 增加独立 `TCFG_RDX_VOICE_TRIGGER_ENABLE`，T2620 开启，非目标产品默认关闭；编译期要求 trigger 同时具备 `TCFG_RDX_HFP_MIC_ENABLE=1` 与 `TCFG_RDX_HOGP_ENABLE=1`，但 trigger 源码不 include/call HFP。
3. 在现有 executor 中提取 `rdx_hogp_key_action_click_action()`，让原 key-id click 和语音 trigger 共用发送/release 实现；补充标准 `HID_KEYBOARD_USAGE_H=0x0B` 常量。
4. 使用标准 Keyboard action 表达 GUI modifier + `H`，保持现有 8-byte Report。
5. KEY5 LONG 按当时 HOGP ready 建立 `ONLINE/OFFLINE` owner；ONLINE 只尝试一次 click 并消费后续 HOLD/UP，OFFLINE 强制把完整 LONG/HOLD/UP 序列送到既有离线 key table。
6. KEY5 三击不再切换 BLE 模式；CLICK 保持既有短按策略；owner 建立后不因 ready-loss/ready-gain 改变，UP 完成原路由后清理 owner。
7. 固件不维护 Windows 听写开关状态，不根据 SCO active 补发或反向发送 `Win+H`。
8. 提供一期用户设置说明：配对两个端点、将本设备 HFP Mic 设为默认输入、启用语音权限并把焦点置于支持的文本框。

**自动验收**

- 新增 `test_rdx_voice_trigger_contract.ps1`，覆盖 LONG/HOLD/UP、单次 click、ONLINE/OFFLINE owner 建立和清理；
- 冻结 `HID_KEYBOARD_USAGE_H=0x0B`，以及 key-id click/voice trigger 对同一 `click_action()` executor 的复用；
- 冻结 voice trigger 源码独立于 HFP 状态、默认关闭且不改变非目标产品；配置 contract 检查 HFP Mic/HOGP 产品组合门禁及 trigger/PTT 互斥；
- 配置矩阵覆盖 trigger 开启但 HFP Mic 或 HOGP 任一关闭时编译失败，以及 trigger/PTT 同时开启时编译失败；
- 覆盖 `HOLD_1SEC/3SEC/5SEC` 等转换事件，保证一次物理长按最多尝试一次 `Win+H`；
- 覆盖 ONLINE LONG 后 ready 丢失再 UP：UP 必须被 ONLINE owner 消费，不能落入 KEY5 离线录音动作；
- 覆盖 OFFLINE LONG 后 ready 恢复再 UP：LONG 必须产生 `APP_MSG_RECORD_SWITCH`，UP 必须继续产生 `APP_MSG_LONG_PRESS_HOLDUP`，不能被在线路由吞掉；
- HID not ready 的新 KEY5 手势完整走离线默认分发，不只检查 LONG；
- 不新增 F24、held report、PTT active、press/release、ready-loss observer 或第二个 HID sender；
- Report Map、handle 和 8-byte payload 字节不变；
- 语音触发源码不 include/call HFP/Classic/SCO；
- 全量 host 测试和固件构建通过。

**设备验收**

- 小于 long 阈值的短按不触发 Windows 语音输入；
- 达到 long 后只产生一次 `Win+H`，HOLD 10 秒不重复触发，松开不发送第二次快捷键；
- 目标 Windows/语言/文本应用矩阵中，默认输入为本设备时能打开 SCO 并完成听写；
- 默认输入错误、无文本焦点、权限关闭和网络不可用时的行为与用户恢复说明一致；
- 按住期间断开 HOGP、关闭 CCC、suspend 或加密失效，随后松手均不触发本地录音或其他离线动作；
- HID not ready 时 LONG 进入本地录音路径，即使按住期间 HOGP ready，后续 HOLD/UP 仍完成同一次离线手势且不发送 `Win+H`；
- HFP idle/active 各完成 1,000 次触发，无重复快捷键、卡键或 KEY1～KEY4 回归；
- Windows 听写处于已打开、已停止或自动停止等不同状态时，KEY5 行为均与冻结的系统语义一致。

**回归范围**

KEY1～KEY4、KEY5 短按/三击、自定义 keymap、HID ready/not ready、离线按键、HFP 音频、Windows 默认输入变化。

**退出条件**

一期不依赖 PC Agent；KEY5 只产生可靠的 `Win+H` 系统快捷键，Windows 前置条件、系统行为和产品限制均已冻结并可复现。

### Phase 5：二期可选增强，F24 真 PTT 与指定麦克风

**目标**

在一期量产能力稳定后，通过 F24 + PC Agent 实现按住采集、松开停止，并精确选择同一物理设备的 HFP Mic。本阶段不是一期发布门禁。

**实施内容**

1. 启用默认关闭的 `TCFG_RDX_VOICE_PTT_ENABLE`；沿用其对 HFP Mic/HOGP 的组合门禁，并与 `TCFG_RDX_VOICE_TRIGGER_ENABLE` 保持编译期互斥。
2. 在 Windows 上调查并冻结 Keyboard/Mic 稳定关联字段；自动关联不可用时设计用户绑定、持久化和解绑流程，禁止只按名称匹配。
3. 扩展 HOGP key action press/release、held/transient 合成、desired/last-sent/dirty 重试和必要的全零 baseline 屏障。
4. 新增 `rdx_voice_ptt.*`；沿用 `ONLINE/OFFLINE` gesture owner，ONLINE LONG 发送 F24 down、UP 释放 F24并消费 HOLD，OFFLINE 长按仍完整走既有 key table。
5. 通过通用 HOGP lifecycle observer 收敛 ready-loss；transport 不得反向依赖 PTT。

## 14. 分期量产形态

```text
SDK owner：
  earphone / dual_conn / bt_event_func = Classic 生命周期、配对、回连、bond
  phone_call / esco                  = HFP 音频

新增公共模块：
  bt_hfp_mic_status = 带 peer 校验的单链路只读状态和统计

RDX 产品模块：
  rdx_hfp_mic       = 产品开关、事件转发、诊断
  rdx_voice_trigger = 一期 KEY5 LONG/HOLD/UP、ONLINE/OFFLINE owner、单次 Win+H click

RDX 组合入口：
  rdx_app            = 组合 HFP Mic + HOGP + voice trigger，输出跨链路诊断

一期 BLE：
  rdx_hogp_key_action = 复用既有 click executor，不引入持久 held 状态
  rdx_hogp_keyboard   = 既有 ATT notify transport

一期 PC：
  Windows 语音输入接收 Win+H，使用用户选定的默认 HFP Mic 完成 STT/文本输入
  无自研 Agent；不承诺真 PTT 或多设备自动关联

二期可选增强：
  rdx_voice_ptt      = F24 down/up、gesture owner/active 与 ready-loss/ready-gain 语义
  rdx_hogp_key_action = press/release、held/transient、desired report 与失败收敛
  rdx_hogp_keyboard   = ready baseline 屏障与通用 lifecycle observer
  PC Agent            = 稳定关联 Keyboard/Mic，指定本设备 HFP Mic，实现真 PTT、STT 和文本注入
```

该方案的模块化目标不是把 JL SDK 再包装一遍，而是明确唯一 owner，并在其上增加最小、可关闭、可诊断的产品能力。
