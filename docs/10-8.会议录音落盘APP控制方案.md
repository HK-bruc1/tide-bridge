> 更新：2026-10-30。设备端已实现，Windows 构建与 23 项主机测试通过；APP 联调及实板验收待完成。
> 参考提交：`bb01e77d91b30c90cebdb838457c817ce7013ad4`（录音提示音开关）。
> APP 指令与联调说明见 [10-9](10-9.会议录音落盘APP对接说明.md)；原有录音转换及提示音规则见 [10-2](10-2.离线在线模式转换时的体验优化.md)、[10-6](10-6.录音提示音APP控制方案.md)、[10-7](10-7.录音提示音APP对接说明.md)。

## 1. 范围与行为

新增设备级持久化开关 `recsave`，默认开启。只决定会议是否在设备保存，不改变会议业务类型、按键手势、编码参数和灯效。

| 设置 | 开始时 RDX 未就绪 | 开始时 RDX 就绪 | 录音期间 RDX 失效 |
| --- | --- | --- | --- |
| `1` 开启落盘 | 原有本地会议 | 原有推流并落盘 | 按原规则转离线继续保存 |
| `0` 关闭落盘 | 立即拒绝，不保留待开始请求 | 只推实时流，不建录音文件 | 待开始则取消，已开始则停止；不转本地、不补建文件 |

RDX 就绪指当前 owner/token 有效、通知 CCC 已订阅、音频发送通道就绪；仅有 ACL、仅 HID 连接或 RDX 接入尚未完成都不满足。仅 HID 断开不影响另一路有效 RDX。

本轮覆盖 APP 主动发起的普通 CHAT 会议，以及任一实体键绑定 F18 后的会议入口。F18 仍为双击开始/结束、单击标记、松开不结束。F19 灵感、CALL、DUT/工厂录音及已有文件的回放/下载/删除不变。

**待产品确认的口径（目前按兼容性实现）：**

- “不允许开启录音”仅限定于 APP/F18 会议，不扩展到 F19 离线灵感。
- VM 不存在、值非法或读取失败时默认开启落盘；若客户要求禁止留存的强隐私保证，需要另定 VM 故障时的拒绝策略，当前不提供此保证。

## 2. 准入与提示音

处理顺序为：识别会议及原请求归属 → 校验本次策略所需的 RDX/系统资格 → 登记请求 → 原有 APP 握手、提示音和录音启动。

- **先拒绝，再谈提示音。** 不落盘会议无法推流时，在状态改变、开始通知、播放中断、录音提示音、录音灯效和存储动作之前返回；不通过 START 后再 STOP 的方式补救。
- **拒绝不延迟补开。** 本次被拒绝后，即使稍后连接/订阅完成，也必须重新发起开始。
- **异步继续复核。** 复用原请求代次、RDX token、提示音 epoch 和 worker 门禁；排队、提示音及音频打开前失效均不能改走落盘。
- **停止不被开始门禁拦截。** APP STOP、F18 结束、传输丢失及系统屏障继续收尾；PAUSE 仍占有会话，不允许改设置。
- **暂停丢失接收端也结束。** 不落盘会议不启用离线录音的 30 分钟暂停保留定时器。

`rectone` 与 `recsave` 独立：合法会议按原提示音开关播放或静音；不允许开始的会议，无论 `rectone` 是什么值，都不能产生开始/结束录音提示音。合法开始提示音已经发出后才断连，无法撤回已发出的声音，但必须使后续启动失效；未实际开始的请求不补播结束音。

## 3. 配置生命周期

- 开机读取独立 `VM_RDX_RECORD_SAVE = 168`；默认开启，不因读失败主动补写。
- 设备是唯一配置来源；断连、逻辑释放、换 APP、重启不主动改变设置。
- GET 返回当前 RAM 值。SET 仅在录音业务完全空闲时提交，包括待 APP 回复、提示音、初始化、暂停和停止收尾均返回 `busy`，不等空闲后补执行。
- 复用 `rdx_record_config_busy()`，保留 DUT/工厂、OTA、格式化、存储切换、关机和恢复出厂等既有保护。
- SET 写入并回读一致才更新 RAM、返回 `ok`；失败返回 `vmerr`、保持当前 RAM 值，下次同值 SET 仍需重新验证。回读失败不保证 Flash 仍为旧值，重启后以实际读取为准。
- 整机恢复出厂写回开启并校验；失败则整体失败、不重启。单独重置配键不影响设置。
- 请求在 `app_core` 执行，执行及回复均验证原 token；写 VM 期间断连不回滚已完成提交，也不将应答转发给新连接。

配置忙保护覆盖请求至收尾，所以本次请求/会话的落盘策略不会被中途修改；不在每帧回调中重新选择录音路线。

## 4. 实现落点

不是新增录音引擎，主体复用现有在线 F19 的纯推流、提示音、暂停/恢复和 FIFO/worker 关闭路径；会议仍保留 MEETING 类型。

| 文件/入口 | 实际改动 |
| --- | --- |
| `rdx_record_save.c/.h` | 独立 `recsave` GET/SET、VM 保存、默认值和恢复出厂 |
| `rdx_app.c` | custom 分发；F18/普通会议开关路由；APP 发起的不落盘会议也可被 F18 停止 |
| `rdx_record.c` | `rdx_record_cmd_handle_admit()` 在 APP START 副作用前准入；纯推流判定覆盖不落盘会议 |
| `rdx_record.c` | 复用无文件初始化、逐帧推流、PAUSE/RESUME、标记与停止路径；关闭前快照防止 sink 清理后误调用文件保存 |
| `rdx_ble_server.c` / `rdx_app.c` | 复用物理断开/逻辑释放收尾；新增 RDX CCC 关闭时的不落盘会议接收端丢失通知 |
| `rdx_record_tone.c/.h` | 导出共用配置忙判断，原 `rectone` 行为不变 |
| `rdx_vm.c` / `syscfg_id.h` / `SDK/Makefile` | 初始化、整机恢复出厂、VM ID 和编译接入 |

不修改 `RecordStatus` ABI、预编译库、生成配置或音频流程。健康存储仅容量不足时，不落盘会议跳过文件空间准入；格式化、存储故障/隔离、PC 切换等系统保护仍生效。

**CDC 范围不扩大。** 会议即使不落盘，仍与 CDC LIST/GET 双向互斥；只有原有在线 F19 保留已审阅的 CDC 并发例外。

## 5. APP 接口与状态

```text
查询：*APP#custom#recsave#get,<id>#
设置：*APP#custom#recsave#set,<id>,<enable>#
应答：*DEV#custom#recsave#<id>,<result>,<current>#
```

`id` 为 1～65535，最多 5 位，原样回带；`enable/current` 为 `0/1`；结果为 `ok/busy/arg/vmerr`。严格语法、原连接应答、默认 MTU 分包和超时后新 ID 查询规则沿用 `rectone`，详见 10-9。

录音控制仍走原 `record`/`recmark` 协议，不新增 START 错误码。能通知时返回 STOP/当前状态；物理断开无应答目标时只做本地拒绝/收尾。

不落盘会话初始化时清空旧文件身份；标记仅保留本次 RAM 偏移并上报 APP，不生成本地 DAT。**APP 对无文件会议状态、`sn=0`/空文件名标记及停止后不等待下载的兼容性待核实**，不能仅凭主机模拟宣称联调完成。
