# RDX 框架优化方案 — P3a-P4：业务层 timer/Q_CALLBACK 直连清理（5 文件收口）

> 依据：`docs/11.RDX框架优化方案-P2-service层JL直连清理.md` 附录 C — P2 已完成，P3a 可独立推进。
> 定位：面向开发者的技术执行方案，包含差距清单 + 具体改造步骤 + 验证方式。
> 范围：`rdx_app.c`、`rdx_charge.c`、`rdx_ble_server.c`、`rdx_battery.c`、`rdx_dut.c` 中直接调用 `sys_timeout_add` / `sys_timeout_del` / `sys_timer_re_run` / `Q_CALLBACK` 的清理。OSAL wrapper 已在 P2 补齐，**不新增任何 OSAL API**。
>
> **定位**：本文档是 Doc 9 提出的"旧业务 `.c` 大量迁移"债务的一部分。全业务层直连总量 **55 处**（timer 46 + Q_CALLBACK 9）。P3a（含 P4）已收口 **32 处**（5 文件：20 timer + 3 timer + 9 Q_CALLBACK）。剩余 **23 处**（record 16 + ota 7）留到后续阶段。

# Part 1 — 差距分析

## 1.1 总体概览

P2 完成后，`service/*.c` 中的 `sys_timeout_*` 直连已全部清理。业务层 `.c` 文件中 timer 直连总量为 **46 处**（`sys_timeout_add/del` 41 处 + `sys_timer_re_run` 4 处 + `sys_timeout_add_2_task` 1 处）。P3a 的范围限定为 4 个业务入口文件，收口其中 20 处：

| `rdx_charge.c` | 2 | 2 | 0 | **4** | |

| `rdx_battery.c` | 1 | 1 | 0 | **2** | |

# Part 2 — 改造方案

## 2.1 总体思路

1. P3a **不需新增任何 OSAL API** — `rdx_os_timer_add` / `rdx_os_timer_del` / `rdx_os_timer_re_run` 已在 P2 阶段补齐
2. 逐文件替换 20 处直连调用
3. 补齐缺失的 `#include "rdx_jl_osal.h"`
4. 同步完成 **P4**（`rdx_dut.c`）的 timer 直连与 Q_CALLBACK 手动数组清理（3 timer + 9 callback2，复用 P2/P3a 模式，无新增 API）
5. 扩展 boundary check 规则（按文件名白名单覆盖 P3a 四个文件，并新增 P4 对 `rdx_dut.c` 的三条规则）

**替换规则**：

```c
// sys_timeout_del → rdx_os_timer_del（签名一致）
sys_timeout_del(timer_id);
→
rdx_os_timer_del(timer_id);

// sys_timer_re_run → rdx_os_timer_re_run（签名一致）
sys_timer_re_run(timer_id);
→
rdx_os_timer_re_run(timer_id);

// sys_timeout_add → rdx_os_timer_add（priv 和 cb 参数顺序对调！）
id = sys_timeout_add(priv, cb, timeout_ms);
→
id = rdx_os_timer_add(cb, priv, timeout_ms);
```

> `sys_timeout_add` 和 `rdx_os_timer_add` 的参数顺序差异是 JL SDK 和 OSAL 的设计决策（OSAL 遵循 "callback first" 惯用风格）。替换时逐处核对。

## 2.3 边界检查脚本扩展

### P3a 规则

在 `tools/check_rdx_boundaries.ps1` 中 P3a 规则追加在现有规则之后：

```powershell
# P3a: 4 specified business .c files must not call sys_timeout_* / sys_timer_re_run directly
$p3aTargetNames = @("rdx_app.c", "rdx_charge.c", "rdx_ble_server.c", "rdx_battery.c")
$p3aTargetFiles = $allRdxFiles | Where-Object {
    $_.Name -in $p3aTargetNames -and
    $_.FullName -match "[/\\]rdx_protocol[/\\]"
}

$p3aSysTimeoutHits = Find-Pattern -Files $p3aTargetFiles `
    -Pattern "\bsys_timeout_(add|del)\b"
Assert-NoHits "P3a files have no direct sys_timeout_add/del calls" $p3aSysTimeoutHits

$p3aSysTimerHits = Find-Pattern -Files $p3aTargetFiles `
    -Pattern "\bsys_timer_re_run\b"
Assert-NoHits "P3a files have no direct sys_timer_re_run calls" $p3aSysTimerHits
```

> 使用**文件名白名单**而非全业务层扫描，避免 `rdx_record.c`、`rdx_ota.c`、`rdx_dut.c` 触发误报。P4 完成后 `rdx_dut.c` 从白名单误报项中移除。

### P4 规则（同次提交完成）

```powershell
# P4: rdx_dut.c must have no direct sys_timeout_add/del and no Q_CALLBACK
$dutFile = $rdxBusinessCFiles | Where-Object { $_.Name -eq "rdx_dut.c" }
if ($dutFile) {
    $dutSysTimeoutHits = Find-Pattern -Files @($dutFile) `
        -Pattern "\bsys_timeout_(add|del)\b"
    Assert-NoHits "rdx_dut.c has no direct sys_timeout_add/del calls" $dutSysTimeoutHits

    $dutSysTimerHits = Find-Pattern -Files @($dutFile) `
        -Pattern "\bsys_timer_re_run\b"
    Assert-NoHits "rdx_dut.c has no direct sys_timer_re_run calls" $dutSysTimerHits

    $dutQCallbackHits = Find-Pattern -Files @($dutFile) `
        -Pattern "\bQ_CALLBACK\b"
    Assert-NoHits "rdx_dut.c has no hand-rolled Q_CALLBACK arrays" $dutQCallbackHits
}
```

> P4 同步移除 P3 规则中对 `rdx_dut.c` 的 `Q_CALLBACK` 豁免。
