# 工厂 APP 按键与喇叭测试对接说明

> 更新日期：2026-09-18
>
> 状态：待评估接口，新增命令尚未实现。用于 APP 开发评审，实际联调以双方确认后的固件为准。
>

## 1. 接入约定

- 沿用现有 BLE RDX 连接、通知订阅和 DUT 进入流程，消息为 ASCII 文本。
- **进入按键测试页面才查询完整布局**，进入 DUT 时不增加公共查询。喇叭测试可以独立启动。
- 按键位置和字母标识由设备直接提供，数量由布局统计，APP 不写死五个键。
- 按键、喇叭及其他 DUT 测试互斥；切换测试前先发送上一项的停止命令，固件按接收顺序处理，停止上一项后再启动下一项。
- 布局查询需要等待响应；按键停止、喇叭开始和停止命令不回包，APP 不等待确认。主动按键事件不作为请求响应。

```text
APP 请求：*APP#custom#<命令>#<值>#
设备回报：*DEV#custom#<名称>#<值>#
```

## 2. 按键测试

### 2.1 一次查询布局，直接渲染

进入按键测试页面后，APP 一次查询完整布局，响应直接携带按键字母标识：

```text
APP → *APP#custom#ft_key_layout#1#
设备 → *DEV#custom#ft_key_layout#A,B,C&D,E#
```

请求值固定为 `1`。响应中 `&` 分隔行，`,` 分隔同一行的按键；每行只列实际按键，各行数量可以不同。APP 直接使用收到的字母标识显示按钮，后续以同一标识匹配事件，不需要计算字母编号。

固件按实物位置从上到下、每行从左到右依次分配 A、B、C……。

| 布局响应值 | APP 渲染 |
|---|---|
| `A,B,C,D,E` | 一行：A B C D E |
| `A,B,C&D,E` | 第一行 A B C；第二行 D E |
| `A,B&C,D&E` | 第一行 A B；第二行 C D；第三行 E |
| `NONE` | 无待测按键，显示“不适用”，不判为通过 |

示例 `A,B,C&D,E` 渲染为：

```text
[A] [B] [C]
[D] [E]
```

APP 的解析逻辑：

```text
按 "&" 拆分行，再按 "," 拆分每行的按键标识
校验完整布局
逐行遍历标识，以标识原文作为 id 和显示文字，创建待测按钮
按键总数 = 各行按键数量之和
```

按下 E 时，固件上报 `*DEV#custom#ft_key_event#E#`，APP 直接找到 E（第 2 行第 2 个键）并标绿。

### 2.2 完整操作示例：进入页面到测试完成

前提：设备已连接、APP 已订阅 RDX 通知并按现有流程进入 DUT，上一项测试已停止。以下为同一轮五键测试的完整时序，包含 2.1 的布局查询。

**查询布局同时开启检测，无需单独发送开启指令。** 非空布局响应表示检测已成功开启；固件保证先回复完整布局，再上报按键事件。返回 `NONE` 或错误时不启动检测。APP 校验布局后立即建立计分集合并渲染；即使 UI 尚未绘制完成，也要保留随后到达的有效事件。

```text
① 工人进入按键测试页面，APP 显示“正在加载按键布局”
APP → *APP#custom#ft_key_layout#1#
设备 → *DEV#custom#ft_key_layout#A,B,C&D,E#

② APP 校验布局，直接读取布局中的 A～E 并生成按钮，全部显示“未检测”
    [A] [B] [C]
    [D] [E]
检测已开启，APP 显示“请按下设备上的每一个按键”，进度 0/5。

③ 工人按键，设备主动上报；APP 不需要轮询
工人按下 C：
设备 → *DEV#custom#ft_key_event#C#
APP：C 标绿，进度 1/5。

工人按下 A：
设备 → *DEV#custom#ft_key_event#A#
APP：A 标绿，进度 2/5。

工人再次按下 C：
设备 → *DEV#custom#ft_key_event#C#
APP：C 保持绿色，进度仍为 2/5。

工人依次按下 B、D、E：
设备 → *DEV#custom#ft_key_event#B#
设备 → *DEV#custom#ft_key_event#D#
设备 → *DEV#custom#ft_key_event#E#
APP：依次标绿，进度达到 5/5。

④ 全部按键检测到后，APP 通知固件结束按键测试
APP → *APP#custom#ft_key#0#
固件停止按键检测，不回包。

⑤ APP 发出停止命令后，保存本轮通过结果，允许进入下一项测试，无需等待响应。
```

工人可以按任意顺序操作；A～E 由布局位置决定，与按下的先后顺序无关。APP 根据标识找到格子并标绿，用标识集合去重。中途退出页面也发送上述停止指令，无需等待响应，但不判为通过。APP 结束本轮后忽略后续到达的按键事件。

## 3. 喇叭测试

### 3.1 开始播放

```text
APP → *APP#custom#ft_speaker#1#
设备 → *DEV#custom#ft_speaker#1#
```

固件播放固定音频

### 3.2 工人确认通过后停止

工人听音并点击“喇叭测试通过”后，APP 保存人工结论并发送：

```text
APP → *APP#custom#ft_speaker#0#
设备 → *DEV#custom#ft_speaker#0#
```

固件停止播放
