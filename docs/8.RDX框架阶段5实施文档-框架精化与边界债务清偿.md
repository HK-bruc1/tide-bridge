# RDX 框架阶段 5 实施文档：框架精化与边界债务清偿

> 版本：v1.0（阶段 5 入口文档初稿）
> 日期：2026-06-29
> 对应大纲：`docs/3.RDX框架JL平台复用性优化大纲.md` 阶段 5
> 前置条件：阶段 4 已完成迁移收口、host mock 骨架、静态边界检查、三组合 clean build；详见 `docs/7.RDX框架阶段4实施文档-迁移收尾与可验证性建设.md`。

## 1. 阶段定位

阶段 5 不是继续扩大重构面，而是对阶段 4 已归档的剩余项做 **高风险边界债务清偿**：

1. 清理仍跨层直连的高风险路径，尤其是 BLE stop/cleanup 与 record/uxfile/protocol 的耦合。
2. 补齐阶段 4 未作为硬阻塞处理的验证缺口，包括 host mock 扩展、目标板冒烟、错误码统一和 `.map` 对比策略。
3. 对 `rdx_app.c` 剩余函数按阶段 4 附录 C 的分类做低风险迁移，不以强行达成行数指标为唯一目标。

阶段 5 的核心原则是：**只清偿边界明确、验证路径明确、回滚方式明确的债务**。对 ABI wrapper、产品入口、跨 service 编排函数，允许长期保留在 `rdx_app.c`，但必须有清单和理由。

## 3. 非目标

- 不重写 `rdx_record.c`、`rdx_ble_server.c`、`rdx_spi.c` 的核心状态机。
- 不删除 `rdx_app_*` 旧 ABI wrapper。
- 不把 `rdx_app.c` 行数/函数数作为唯一硬门禁；行数下降必须服从 ABI 稳定和时序稳定。
- 不引入动态内存、不引入线程模型变化。
- 不在没有目标板验证条件时合入 BLE 时序语义变化。

## 4. 任务 A：BLE 剩余边界 cutover

### A.1 现状

阶段 4 已完成：

- `rdx_ble_service_on_connected()` 只发布 `RDX_EVENT_BLE_CONNECTED`。
- `rdx_ble_service_on_disconnected()` 只发布 `RDX_EVENT_BLE_DISCONNECTED`。
- `rdx_record_service` 订阅 BLE connect/disconnect 并执行录音中断/恢复逻辑。

仍未完成：

- `rdx_ble_service_stop_recording()` 仍直接读取 `RecordStatus` 并调用 `rdx_record_process()`。
- `rdx_ble_service_cleanup_protocol_state()` 仍直接调用 `rdx_uxfile_recordFileData_sendBuf_free()` / `rdx_uxfile_datFileInfo_sendBuf_free()`。

### A.2 目标

BLE service 不再直接操作 record/uxfile/protocol 状态。BLE 层只表达事件或调用明确 service API：

| 当前调用 | 阶段 5 目标 |
|---|---|
| `rdx_ble_service_stop_recording()` 直接操作 `RecordStatus` | 改为 `rdx_record_service_stop_from_ble()` 或 `RDX_EVENT_BLE_STOP_RECORDING` |
| `rdx_ble_service_cleanup_protocol_state()` 直接 free uxfile buffer | 改为 `rdx_storage_service_cleanup_ble_buffers()` 或 `RDX_EVENT_BLE_CLEANUP_PROTOCOL_STATE` |

### A.3 建议实现路径

1. 先扫描调用者，确认 stop/cleanup 只来自 BLE 业务路径。
2. 新增 record/storage 明确 API，优先 API 而非事件：
   - `rdx_record_service_stop_from_ble(void)`
   - `rdx_storage_service_cleanup_ble_buffers(void)`
3. `rdx_ble_service.c` 只调用 service API，不再 extern `rdx_record_*` / `rdx_uxfile_*`。
4. 若后续确认需要完全异步，再把 service API 内部改为 event，不改变 BLE service 外观。

### A.4 验收

- [ ] `rg "rdx_record_|RecordStatus|rdx_uxfile_" service/rdx_ble_service.c` 仅允许注释或 service API 名称命中。
- [ ] BLE connect/disconnect/forced stop 路径无双执行。
- [ ] BLE 录音 30 秒、断开、重连、强制停止冒烟通过。
- [ ] `tools/check_rdx_boundaries.bat` 通过。
- [ ] 主力组合 clean build 通过。

## 5. 任务 B：`rdx_app.c` 剩余候选迁移

### B.1 迁移范围

只处理阶段 4 附录 C 中 D 类的 7 个候选：

| 候选 | 目标归属 |
|---|---|
| `rdx_app_clk_is_locked()` | 新增 `rdx_clock_service.c` |
| `rdx_app_clk_lock()` | 新增 `rdx_clock_service.c` |
| `rdx_app_clk_unlock()` | 新增 `rdx_clock_service.c` |
| `rdx_app_clk_lock_with_timer()` | 新增 `rdx_clock_service.c` |
| `rdx_app_clk_unlock_with_timer()` | 新增 `rdx_clock_service.c` |
| `sdmmc_set_power()` | `rdx_storage_service.c` 或 board power helper |
| `rdx_led_hardware_init()` | board/port 初始化或保留为 product hook wrapper |

### B.2 保留策略

以下函数不作为阶段 5 必迁目标：

- A 类 ABI wrapper：保留旧符号和旧签名。
- B 类协调器 / 生命周期 / 产品入口：继续留在 `rdx_app.c`。
- C 类产品特定函数：除非有明确复用需求，否则不迁移。

### B.3 验收

- [ ] D 类 7 个候选逐项给出处理结果：已迁移 / 保留 / 延期，并说明原因。
- [ ] 已迁移函数在 `rdx_app.c` 仅保留 thin wrapper 或删除内部实现。

## 7. 任务 D：统一错误码收口

### D.1 目标

在不破坏旧调用方的前提下，让新增 service API 返回 `rdx_err_t`，避免继续扩散 `-1`。

### D.2 优先范围

| 模块 | 目标 |
|---|---|
| storage service | `format/sync/status` 接口返回 `RDX_OK` / `RDX_ERR_*` |
| BLE service | stop/cleanup API 返回 `rdx_err_t` |
| WiFi service | power/control/transport wrapper 返回 `rdx_err_t` |

旧 ABI wrapper 如必须返回 `int`，可在 wrapper 内将 `rdx_err_t` 映射为旧返回值。

### D.3 验收

- [ ] 新增或改造的 service public API 返回 `rdx_err_t`。
- [ ] `service/*.c` 中裸 `return -1;` 清单已列出，所有仍保留项说明原因。阶段 4 基线清单：

  ```text
  rdx_device_service.c:119: return -1;  /* pair: au_code/mac_str NULL */
  rdx_device_service.c:121: return -1;  /* pair: au_code 全 0 */
  rdx_device_service.c:123: return -1;  /* pair: mac_str 全 0 */
  rdx_device_service.c:125: return -1;  /* pair: label_sn 全 0 */
  rdx_device_service.c:142: return -1;  /* pair: VM write 失败 */
  ```

- [ ] 旧 ABI 行为不变。

## 10. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| BLE stop/cleanup cutover 改变时序 | 高 | 先保持同步 API；只移动所有权，不改变调用时机；必须目标板冒烟 |
| host mock 过度模拟 SDK | 中 | mock 只覆盖边界行为，不模拟复杂硬件时序 |
| 错误码改造破坏旧调用方 | 中 | 旧 ABI wrapper 保留 `int` 兼容返回；内部使用 `rdx_err_t` |
| `rdx_app.c` 行数目标诱导过度迁移 | 中 | 只迁 D 类候选；A/B/C 类默认保留 |
| `.map` 基线不可重建 | 低 | 阶段 4 收尾提交建立新基线，后续只做增量对比 |
