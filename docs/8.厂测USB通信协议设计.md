## 1. 范围与现有代码边界

CDC 仅提供字节传输，不直接访问 SD；但通过 CDC 发起的录音、格式化和整包结束会访问 SD，仍须经过已有业务与存储准入检查。

当前仓库已有 CDC 类驱动、后台枚举入口、DUT 动作和拨码/MSC 切换逻辑；阶段 1A 已新增厂测 CDC 开关和 `usb_factory_*` 枚举协调接口，实现在 `device/usb/device/task_pc.c`，由拨码的 app_core 定时服务发布准入，USB 任务执行类切换。此阶段复用 `USBSTACK_CDC_BACKGROUND` 做最新目标协调，不分配应用 RX 消息。本文的字节传输层、厂测消息、身份查询和 DUT 公共接口仍为后续实施要求。

| 已有代码 | 源码事实 | 对设计的约束 |
|---|---|---|
| `device/usb/device/task_pc.c` | OTG 插入时可经 standby 启动 CDC，返回 0 可抑制应用 IN 事件 | 能避免插线进入 PC，但不能独自覆盖带线拨码切换 |
| `device/usb/usb_task.c` | START 先 stop；PAUSE 后可直接启动 CDC；CDC_BACKGROUND 直接启动 CDC | 所有启动入口须统一门控，不能只改 standby |
| `device/usb/device/cdc.c` | 收发共用 mutex；write 按包循环并返回累计 offset；release 释放全局句柄 | 须核实发送计数、短写、等待时间和收发/释放并发 |
| `rdx_protocol/rdx_dip_switch.c` | ON→OFF 等待 OTA/格式化/DUT，再排空业务并受控复位；OFF→ON 请求退出 PC | 保留当前保护，CDC 不绕过排空、复位和 SD 恢复 |
| `rdx_protocol/rdx_dut.c` | BLE 入口返回 void，异步投递；进入 DUT 会断开 BLE、关闭广播 | 不能仅更名入口就获得可靠 USB 命令接口 |
| `rdx_protocol/rdx_vm.c` | 初始化已有 AuthKey 打印 | “AUTH 不记日志”需要同时整改已有日志 |

表中 `device/usb/` 与 `rdx_protocol/` 分别位于 `SDK/apps/common/` 和 `SDK/apps/common/third_party_profile/`。

阶段 1A 的 factory 分支不注册应用收发消费者，bulk OUT 配置为不触发接收中断、不读取端点数据，等待硬件缓冲耗尽后背压；实际 NAK、主机写超时及总线复位后行为须板测。停止时先屏蔽设备中断源再释放资源，并回收 CDC mutex；该阶段约束不能替代阶段 2 的在途 I/O 与会话同步。

## 2. 运行时分流与业务边界

### 2.1 稳态分流

| 拨码/OTG 条件 | USB 数据功能 | BLE/正常业务 | 充电 |
|---|---|---|---|
| OFF + 电脑，从机角色确认且安全切换完成 | 仅 MSC，APP_MODE_PC | 关闭，SD0 由电脑独占 | 保持 |
| ON + 电脑，未进入 DUT | 不枚举 USB 数据类，不进入 APP_MODE_PC | 正常开机业务保持 | 保持 |
| ON + 电脑，按键进入 DUT 且准入通过 | 仅 CDC ACM，不进入 APP_MODE_PC | BLE/SPP 厂测通道，见 2.2 | 保持 |
| 充电器，仅 VBUS、无从机角色 | 不枚举数据类 | 按现有拨码和充电策略 | 保持 |
| OFF + 无 USB | 无 | 正常关机 | — |
| ON + 无 USB | 无 | 正常 BLE 业务 | — |

这是稳态目标；切换期间允许暂时无 USB 数据功能，不允许 MSC/CDC 复合枚举或 SD 双重所有权。

正常 CDC 启动必要条件为 `ON && factory_dut_active && get_charge_online_flag() && usb_otg_online(0)==SLAVE_MODE`（`factory_dut_active` 表示按键流程已完成进入厂测模式的逻辑状态，具体接口实施时确定）。该组合表示本工程已确认 USB 主机角色，不是主机操作系统或厂测站身份认证。还必须满足：PC 已完成退出、SD 已归还固件并恢复就绪、不在关机/切换失败/排空状态。角色未确认时保持安全充电状态，通过后续协调重试，不因一次判断失败永久漏启动。阶段 3 的受限 CDC 按第 4.2 节处理：DUT 等待退出是唯一的 OFF 重连例外，厂测失败恢复另允许 ON 下不依赖 SD 就绪的受限重连。

### 2.2 CDC 与厂测模式的边界

CDC 仅用于产测，对正常用户模式不可见：开机但未进入 DUT 时，插入电脑仅供电/充电并保持正常业务，不枚举 CDC，也不提供 USB 查询入口。按键完成进入 DUT 后，满足第 2.1 节条件才枚举 CDC；支持先进入 DUT 再插线，也支持先插线再按键进入，无需重新插拔。插线或主机请求不能触发 DUT。OFF 稳态仍仅 MSC。第 4.2 节受限恢复仅属于本次已进入过厂测的故障/退出过程，不是正常用户模式入口。

进入 DUT 产测模式沿用原有按键事件流程；CDC 不另建自动进入流程，不以收到测试命令替代按键进入。正常模式无 CDC，主机不能发送测试请求或期待 ERR STATE；仅在受限恢复会话仍存在、或退出前请求已进入处理层时执行状态拒绝。退出已使会话失效的旧请求直接清理，不跨会话补发响应。厂测 DUT 与经典蓝牙射频 DUT 必须区分，不能为启用 CDC 测试而无条件切入会断开 BLE/SPP 的射频测试状态。

| 厂测通道 | 目标用途与边界 |
|---|---|
| BLE | 保留工厂产测 APP 的现有测试入口及外部协议 |
| 经典蓝牙 SPP | 保留 MIC 频响测试通道，不将音频测试数据改走 CDC |
| USB CDC | 在按键进入 DUT 后收发测试指令，复用 BLE 对应测试命令的业务语义与公共处理逻辑 |

厂测模式目标为 BLE、经典蓝牙 SPP 与 CDC 通道可用；通道可用不代表允许同时操作 MIC、录音或存储，同一资源仍经过公共仲裁。正常模式不启动 CDC，原有 HOGP 行为保持不变，DUT 内 HOGP 行为需随原有厂测流程核实，本文不新增 DUT 内 HOGP 保持在线的承诺。

现有 DUT 代码中断开 BLE、关闭广播及进入经典蓝牙 DUT 的分支是阶段 3 必须核对、适配的实现差异，不能当作三通道共存已实现。CDC 与 BLE 共享测试能力不等于两者传输帧逐字节相同：第 6 节仍保留 CDC 文本封装设计，阶段 3 核对现有 BLE 命令映射、参数与结果后接入同一公共接口，响应回到请求来源，避免向其他通道误发。

上述边界不改变阶段顺序：阶段 1 接入按键 DUT 状态观察、枚举门控与生命周期；阶段 2 验证该门控下的双向字节收发及任务回调；阶段 3 接入测试命令准入、共享测试逻辑及 BLE/SPP/CDC 厂测共存。阶段 1/2 不提前开放厂测命令，也不以 DUT 三通道共存作为已完成能力。

## 4. USB 生命周期与热切换

### 4.1 统一协调入口

新增幂等的厂测 USB 协调逻辑，区分 `NONE / MSC / CDC / STOPPING` 实际状态。拨码、OTG、按键进入 DUT 完成、DUT 退出、模式退出完成、存储恢复完成和关机事件驱动协调；app_core 决定目标，USB 任务串行执行硬件启动/停止并回报结果。请求入队不能当成启动成功。

`usb_cdc_background_standby()` 在 ON 时抑制应用 IN 事件，即使业务尚未就绪也不能转入 PC；允许 CDC 时请求启动，否则由后续协调重试。OFF 稳态继续现有 MSC 路径；第 4.2 节受限重连状态同样抑制 PC IN。所有 `USBSTACK_START`、`USBSTACK_PAUSE`、`USBSTACK_CDC_BACKGROUND` 和直接后台启动入口均执行相同策略检查。

`usb_cdc_background_run()` 只注册 CDC 并配置设备，不负责停止旧类。实际类变化必须先停止旧 USB、调用 `usb_device_mode(..., 0)` 释放，再注册目标类；同类重复协调不得反复重枚举。过期启动请求须在 USB 任务执行前重新核对生命周期与最新目标。

### 4.2 转移规则

| 场景 | 必须执行的顺序 |
|---|---|
| ON 插电脑 | 未进入 DUT 时仅充电及正常业务；已按键进入 DUT 时，从机确认 → 业务/SD 准入 → CDC；不进入 PC |
| ON 带线按键进入 DUT | 厂测进入完成 → 重查角色及存储准入 → CDC，不等待新 OTG IN |
| 正常退出 DUT | 关闭新测试准入 → 完成业务清理；阶段 3 尽力有界发送退出响应 → 停止 CDC 并清理会话 → 恢复允许的正常业务。不得无限等待主机读取，响应丢失按结果未知处理；失败恢复例外见下文 |
| OFF 插电脑 | 沿用冷启动导出准入 → PC/MSC；不初始化 CDC 厂测会话 |
| 带线 OFF→ON | PC 停止 MSC → SD 归还并完成恢复 → 正常业务就绪；未进入 DUT 不启动 CDC，后续按键进入再枚举，不能等待新的 OTG IN |
| 带线 ON→OFF | 关闭新增业务准入 → 等待已有 OTA/格式化/DUT → 按现有录音/BLE/file fence 排空并复位 → 冷启动重新采样 → MSC 或最新目标 |
| 拔线/角色失效 | 关闭新请求准入 → 停止并清理 CDC 会话 → 不启动其他数据类；BLE 按现有策略运行 |
| 切换失败或关机 | 停止接受厂测动作；保留现有失败保护，不强行导出或启动 CDC |

等待 DUT 退出时，已有 CDC 会话可保留用于 GET_STATUS、`ft_dut 0` 或停止当前测试；拒绝新测试、格式化和整包结束。该状态是 ON→OFF 的排空例外，不是 OFF 稳态 CDC。DUT 已退出并开始排空后停止 CDC。不得先切断退出 DUT 的唯一通道，再无限等待 DUT 结束。

阶段 3 增加独立的 DUT 等待退出状态：仅当本次启动已进入 DUT、收到拨 OFF 请求且尚未开始业务排空时建立。此状态不随 USB 拔线或总线复位清除。恢复 VBUS 且重新确认从机角色后，允许重新枚举受限 CDC；不得启动 MSC，也不要求正常业务/SD 恢复就绪才能查询或请求安全退出。仍禁止在关机、切换失败或排空已开始时启动，动作本身继续执行存储安全检查。

受限会话仅允许 PING、GET_STATUS、`DUT ft_dut 0` 和当前可停止测试的停止命令；其他命令返回 ERR STATE。RUNNING 时仍按第 6.2 节返回 BUSY，不中断格式化或正在保存的录音。拔线不自动退出 DUT或强制取消动作；重新插线后可查询和退出。拨回 ON 且尚未排空时取消该等待限制；DUT 完成退出或整机复位后清除此状态，冷启动 OFF 不得据此恢复 CDC。阶段 1/2 不提供这条厂测恢复通道，也不得以 CDC 可退出 DUT 作为阶段验收前提。

OUT 仍需走到 USB stop。当前 `usb_task.c` 会转发 OUT，`pc_device_event_handler()` 在非 PC 模式下可请求 STOP；实施时须核对所有活动模式下的派发可达性。连续插拔和拨码反转依靠最新目标协调，不能靠旧消息继续枚举。

**厂测失败后的 ON 受限恢复（阶段 3）**

厂测故障恢复是独立于 DUT 动作开关的受限状态，不属于正常用户模式。正常退出且无失败标志时关闭 CDC；存在失败标志时，退出 DUT 仅结束测试动作，设备仍处于厂测故障恢复状态，可按本节重连查询。整机复位清除此运行时状态，不能据此自动枚举 CDC；重新进入须遵守按键及存储准入。故障状态下不得向工站宣称已恢复正常用户模式。

本次启动内，已接纳的格式化或整包结束动作进入 FAILED 时，设置独立的厂测失败恢复标志。该标志不随拔线、总线复位、拨码反转或退出 DUT 清除，仅在整机复位时清除；不得由冷启动的 SD 异常自行建立。它与 DUT 等待退出状态分别维护，不能随 LAST 记录被下一动作覆盖而消失。

该标志存在且拨码为 ON 时，已有 CDC 转为受限准入；重新确认 VBUS 和从机角色后允许受限重连，不以 SD 就绪或正常业务恢复为前提。仍须确认 PC/MSC 已退出、USB 旧类已释放，且未进入关机、切换失败或业务排空；不能绕过 SD 所有权保护。此处的厂测动作失败不等于 USB 切换失败，后者仍禁止启动 CDC。

ON 失败恢复仅允许 PING、GET_STATUS、`DUT ft_dut 0`、当前可停止测试的停止命令，以及 DUT 内的 `DUT ft_key_dut_enable 1`；其余命令返回 ERR STATE。重新使能按键须确认 VM 持久化成功。停止/退出仍须等待必要的保存与资源释放，不得将存储未就绪一概作为拒绝退出的理由，也不得丢弃未保存数据后回复 DONE；无法安全完成时保留故障保护并反馈失败。退出 DUT 不代表存储已恢复，不得恢复依赖故障存储的业务。

失败恢复与 OFF 等待退出同时存在时，使用 OFF 等待退出的较窄白名单，禁止重新使能按键；拨回 ON 只取消 OFF 等待限制，失败恢复限制仍保留。OFF 且 DUT 已退出时不再据此启动 CDC，后续排空/导出仍须通过原有存储保护。工站应在提交停止、退出或使能按键前读取并保存不含 AUTH 的失败状态；这些成功接纳的新动作会按第 6.2 节覆盖 LAST 记录。后续修复遵循第 7 节人工/工站恢复流程，不在该受限状态中自动重试格式化或整包结束。

### 4.3 会话与资源释放

每次 CDC 启动分配递增 session generation。RX 通知、命令和 TX 队列均携带 generation；重新枚举后丢弃旧消息。消息传稳定的 USB ID 与 generation，避免把可过期资源指针当作会话身份。

阶段 2 起，会话失效同时覆盖正常 DUT 退出、物理拔线、角色失效、USB 总线复位、取消配置及发送超时重建；不依赖这些事件一定经过完整 stop/start。先关闭准入并使旧 generation 失效，清理旧数据，完成传输准备后才开放新会话。USB 总线复位不等于整机复位，不清除已接受动作的状态记录。

串口关闭/重开不必触发 USB 复位，不能自动视为新会话。阶段 2 实施前须确定控制线变化的检测与清理方式，并实测目标驱动；若无法可靠检测，异常恢复必须显式重新枚举或拔插，不能仅依靠 PC 清空输入缓冲或发送 PING 判定会话已清理。工站遵守同一恢复步骤。

USB 任务停止前关闭准入并等待在途 I/O 安全退出，之后才能 `cdc_release()`；app_core 不能在释放过程中使用句柄。需实现生命周期锁或等效串行 I/O 所有权，且定义锁顺序，禁止 app_core 同步等待 USB stop、USB 任务又等待 app_core 的死锁。

断线清除半行、超长丢弃状态、待解析数据和未发送响应。已接受的格式化等动作不因拔线强制中止；安全完成并保留本次启动内的状态，供重连查询。旧回调不得向新会话发送旧响应。

## 5. CDC 收发与背压

### 5.1 接收

`usb_cdc_wakeup()` 位于中断上下文，只投递或合并 RX 通知，不解析、不执行 DUT、不收发协议响应。厂测消息处理在任务上下文调用 `cdc_read_data()`，每次读缓冲至少覆盖当前最大包长（当前 64 字节），跨包组帧。

现有驱动会按最大包读取后裁剪到调用者长度，小缓冲可能丢尾部。通知队列满不能只打一条日志后遗失数据：采用 pending 标志与有界补偿调度，并确认端点 NAK/重通知行为；不能假定丢一次消息必有下一次中断。每轮处理包数设上限，主动让出 app_core。

### 5.2 发送

协议层只生成完整响应，进入有界 TX FIFO。初始容量为 4 条、每条最多 258 字节（256 字节正文加 CRLF），实施时计入 RAM 预算。动作执行前必须预留应答容量，不能执行完才发现无处回复。

发送保留 `offset`，按 `cdc_write_data()` 返回长度推进，只有完整行写完才移除。返回 0 表示本次无进展，可能是未就绪或底层发送失败；不能立即通过同一不可用通道发送 `ERR BUSY`。正数短写必须继续发送剩余部分，不得插入另一条响应造成串行混帧。

采用有界重试与发送超时。超时后停止该会话的后续响应并清理/重建传输，客户端按超时处理；禁止将半条响应与后续响应拼接。`ERR BUSY` 仅用于通道可回复且命令尚未执行的业务占用或容量拒绝。队列完全耗尽时通过接收背压或关闭会话处理，禁止无限分配内存。

`cdc_write_data()` 当前含无限等待语义的 mutex 获取和循环 bulk 写，尚不能证明 app_core 最坏耗时有界。阶段 2 必须验证底层等待行为：若不能保证有界，需改成有界非阻塞发送或由可安全停止的专用 I/O 任务承担，协议与 DUT 仍留在 app_core。仅规定“单写者”不能替代此项。读写共享 mutex，迁移发送任务时也要验证接收不会被长时间阻塞。当前发送循环在累计 offset 前检查传输状态，须核实底层返回正数但状态改变时的计数路径，禁止把已发送数据当作未发送重新续传。

字节传输的保证限定于正常连接且成功接纳的数据：完整、有序、不重复。队列满时明确拒绝或背压，不允许静默丢弃后继续报成功。超时、复位或拔线允许未完成数据丢失，但必须报告传输失效并清理会话；不提供跨会话自动重传或业务“恰好执行一次”的保证。协议动作是否已执行仍按第 6 节查询与结果未知规则处理。

当前控制线处理收到 SET_CONTROL_LINE_STATE 后直接置就绪位，未按 DTR/RTS 清零。因此不能以 DTR 作为厂测身份或可靠断线判据。客户端打开串口完成控制请求后先 PING；波特率只是 CDC line coding 参数，不决定 USB bulk 速率。

## 6. 文本协议 v1

本节定义 CDC 的传输封装，不另建一套 BLE 测试业务实现；命令适配与模式准入遵循第 2.2 节。

### 6.1 帧与请求顺序

- ASCII，CRLF（`\r\n`）结尾；请求正文 ≤128 字节，响应正文 ≤256 字节。
- 命令关键字与 DUT 名称不区分大小写，参数严格匹配；输出大小写固定。
- DUT 请求使用单个 ASCII 空格分隔，不接受额外字段、前后空白、符号整数或 `atoi()` 式前缀解析。
- `;` 与 `=` 仅用于响应字段；字段值不得包含 `;`、`=`、CR、LF 或其他控制字符。
- 空行、非 ASCII、非法控制字符、裸 LF、孤立 CR 和非法语法返回 `ERR CMD`；超长行返回 `ERR ARG`。非法帧整体拒绝，具体丢弃与恢复规则如下，不能从错误位置之后重新尝试匹配命令。
- 客户端采用一问一答，不流水发送。设备仍须按到达顺序处理同包多行，并在每条 DUT 的准入结果确定后再处理下一条，不能二次异步入队导致后继检查旧状态。
- 每个有效请求最多一条响应；断线或传输故障允许响应不可达，不能据此推断命令未执行。

分帧器仅在完整 CRLF 到达后校验并提交正常帧。CR 暂存为结束符候选，不计入正文；其后不是 LF 即判为孤立 CR。正文只接受 `0x20–0x7E`；出现其他字节、裸 LF、孤立 CR，或正文出现第 129 字节时，锁定该帧的首个错误并进入丢弃状态。丢弃状态不保存正文、不解析任何命令，一直消费到下一完整 CRLF（可跨 USB 包）；裸 LF 本身不作为恢复边界。若同一字节同时触发非法字符和超长，优先 ERR CMD；进入丢弃后不改变错误码。

错误响应在消费到完整 CRLF 后仅发送一次，然后开始接收下一帧；空行及完整但语法非法的帧也只响应一次。丢弃期间没有 CRLF 时保持有界内存且不产生重复错误响应，会话失效则清除该状态。客户端遇到无响应按超时恢复会话，不自动补发原动作。错误响应仍受第 5.2 节队列与背压规则约束。

| 输入字节流（转义表示实际字节） | 结果 |
|---|---|
| `\x80DUT ft_format 1\r\nPING\r\n` | 一条 ERR CMD，再一条 OK PONG；格式化不执行 |
| `PING\nDUT ft_format 1\r\nPING\r\n` | 裸 LF 后持续丢弃到首个 CRLF；仅 ERR CMD、OK PONG |
| `PING\rDUT ft_format 1\r\n` | 孤立 CR 使整帧非法；仅 ERR CMD，格式化不执行 |
| 129 个 `A` 后接 `DUT ft_format 1\r\nPING\r\n` | 仅 ERR ARG、OK PONG；丢弃期间不解析 DUT |

### 6.2 命令与响应

```text
PING\r\n
-> OK PONG\r\n

GET_INFO\r\n
-> OK PROTO=1;NAME=<名称>;AUTH=<24字符>;ADDR=<12位HEX>;FW=<产品版本>\r\n

GET_STATUS\r\n
-> OK DUT=<0|1>;ACTIVE=<动作>;LAST_ID=<编号>;LAST_CMD=<命令>;LAST_STATE=<状态>;LAST_ERR=<原因>\r\n

DUT <name> <value>\r\n
-> OK ID=<编号>;STATE=<DONE|RUNNING>\r\n
-> ERR <code>\r\n
```

GET_STATUS 仅在有效厂测 CDC 会话中可用，不改变业务；DUT 已退出时，仅第 4.2 节的厂测故障恢复状态仍允许该查询，正常用户模式无 USB 查询入口。`ACTIVE` 为 `NONE/OLED/MOTOR/REC/WIFI/FORMAT/FINALPACK`；`LAST_CMD` 为规范小写 DUT 名称或 `NONE`；`LAST_STATE` 为 `NONE/RUNNING/DONE/FAILED`；`LAST_ERR` 为 `NONE/STATE/BUSY/IO/UNSUPPORTED`。无历史时 ID 为 0，其余历史字段为 NONE。

成功接纳的 DUT 请求分配本次启动内单调递增的非零 u32 ID，重连保留、复位清零；耗尽时拒绝新动作。它用于状态关联，不是跨重启幂等令牌。`DONE` 表示软件动作或设置完成，不代表马达、LED、录音等物理测试通过。

USB、BLE 与物理按键共用同一 ID 序列和 LAST 记录：每条经公共接口成功接纳的动作（包括幂等设置）都更新记录，拒绝及只读查询不更新。非 USB 入口须先归一化为本文的 DUT 命令名称；异步完成只能更新仍匹配自身 ID 的记录。所有入口在 app_core 串行仲裁，RUNNING 期间均禁止接纳新的修改动作；终态后其他入口可以提交新动作并覆盖 LAST。v1 不提供 USB 独占控制权，也不保留可按 ID 检索的历史。

工站仅在收到接受响应、持续保持同一有效会话，且 GET_STATUS 的 LAST_ID 与已收到的 ID 相同时，将该状态认定为自身请求的结果。ID 不同表示记录已被覆盖，不能用 LAST_CMD 相同推断成功。接受响应丢失、会话失效、串口关闭重开或工站进程重启后，未确认结果一律标记为“结果未知”；重连 GET_STATUS 仅用于判断设备当前状态及安排恢复，不自动将其归属到旧请求。v1 不提供启动标识，不能凭重连后的同 ID、同命令或 ID 为 0 证明启动连续性或原动作未执行。此前已经确认的终态记录可保留，但不得据此推断掉电后的物理状态。

长动作返回 RUNNING，客户端轮询 GET_STATUS 至 DONE/FAILED。RUNNING 期间只允许只读查询，新的 DUT 请求返回 ERR BUSY，不能覆盖该记录。持续亮灯、马达循环和已启动录音通过 ACTIVE 表示，其启动设置完成后请求可为 DONE，因此随后仍可提交停止/退出命令。终态保留到下一条 DUT 请求成功接纳。v1 不发送自发 EVT，避免请求响应与事件交错。

### 6.3 错误码

| 错误码 | 含义 |
|---|---|
| CMD | 未知命令或语法非法 |
| ARG | 参数不在允许集合、请求超长 |
| BUSY | 当前动作/业务占用，或能够回复时的容量不足；请求未执行 |
| STATE | 未进入 DUT、存储/USB 切换状态不允许、身份未就绪 |
| DATA | 身份字段非法或超出协议范围 |
| UNSUPPORTED | 当前产品未编译对应测试功能 |
| IO | 操作提交、持久化或即时执行失败 |

异步完成失败通过 LAST_STATE/LAST_ERR 返回，不补发第二条请求响应。接受响应丢失时不得自动重发格式化、整包结束或关机；按第 6.2 节标记结果未知，并在传输恢复后查询当前状态。复位后历史不可恢复时同样报告结果未知，重新进行人工或工站流程判定；轮询超时不表示动作已取消，不解除设备的 RUNNING 保护。

### 6.4 GET_INFO 字段

| 字段 | 来源与约束 | 异常处理 |
|---|---|---|
| PROTO | 固定 `1` | 协议不兼容时客户端拒绝继续 |
| NAME | `rdx_ble_server_get_local_name()`，1–24 字节安全可打印 ASCII | VM 无名可使用现有默认名；非法字符/超长 ERR DATA，不静默截断 |
| AUTH | `rdx_vm_get_auth_info()->AuthKey`，恰好 24 字符，`[0-9A-Za-z]` | 初始化完成且全零返回 24 个字符 `0`，测试站判未烧录；部分无效 ERR DATA |
| ADDR | `le_controller_get_mac()`，12 大写 HEX，顺序 `[5][4][3][2][1][0]` | 控制器未初始化 ERR STATE；无效值 ERR DATA |
| FW | 当前产品分支的 `FIRMWARE_VERSION`，1–32 字节安全可打印 ASCII | 与产品上报版本保持同源，非法/超长 ERR DATA |

初始化未完成与“初始化完成但未烧录”必须区分。不得对定长 AuthKey 无界 `strlen/%s`；字段输出前检查长度和字符。FW 不使用 `sdk_version_info_get()`：该函数返回 SDK 链接段版本串，无产品版本或 32 字节保证。当前 GET_INFO 最大正文为 123 字节，含 CRLF 为 125 字节。

ADDR 与 `rdx_app_earphone_get_dev_base_info()` 的 `ble_mac_str` 保持同序；VM 烧录地址初始化会调用 `le_controller_set_mac()`。测试站将运行时地址与烧录记录比较，不一致判失败；设备仅返回一个地址并不能自行证明烧录一致。

USB 为物理厂测通道，v1 无额外鉴权。AUTH 仅供工站内存校验，固件和测试站不得打印或持久化。实施时同时清除 `rdx_vm.c` 已有 AuthKey 的 `put_buf` 与字符串日志，并检查 GET_INFO 收发调试日志不会泄露该字段。

## 7. DUT 公共接口与动作语义

新增传输无关的有返回值命令接口，执行状态检查、资源预留、目标状态设置和结果记录。USB 在 app_core 调用；BLE 适配层投递后调用同一接口，BLE 原有外部协议兼容处理留在适配层，公共动作不主动发送 BLE 指示。

物理按键入口也必须经过同一仲裁，不得直接绕过 RUNNING、存储互斥和切换准入。异步完成回到 app_core 更新动作状态，并按动作 ID 关联，不能只依赖 USB generation。所有入口采用第 6.2 节的全局 ID、LAST 覆盖及结果未知规则；受限恢复白名单也对所有入口生效，不能通过 BLE 或按键绕过 USB 禁止的新测试。

禁止原样复用现有 void BLE 入口后无条件回复 OK。它使用 `strstr/atoi`、入队失败只记日志，并在异步执行前发送指示，无法证明动作成功。进入 DUT 的执行端须从“翻转状态”改为“设置目标状态”，重复 `ft_dut 1/0` 不得反向切换。

| USB 请求 | 实施语义与结果 |
|---|---|
| `DUT ft_dut <0|1>` | CDC 不负责从正常模式进入 DUT：参数 1 仅在已由按键进入 DUT 时幂等返回 DONE，否则返回 ERR STATE。参数 0 请求安全退出；退出完成清理当前可停止测试，按当前拨码、存储及故障状态恢复允许的业务策略 |
| `DUT ft_oled <0|1>` | LED 测试开关，保留兼容命名；设置完成 DONE，物理灯效由仪器判定 |
| `DUT ft_motor <0|1>` | 马达测试开关；未编译支持返回 UNSUPPORTED，不能空执行回成功 |
| `DUT ft_rec <0|1>` | 启停录音测试；复用录音准入及停止保存流程，异步保存未完成时 RUNNING |
| `DUT ft_wifi <0|1>` | WiFi 测试开关；未编译支持返回 UNSUPPORTED，状态以实际接口结果为准 |
| `DUT ft_format <1>` | 格式化，RUNNING 后由完成回调记 DONE/FAILED；与录音/传输/MSC/其他测试互斥 |
| `DUT ft_poweroff <1>` | 接受并尽力发送响应后走正常关机清理；断线不代表关机测试通过，工站检测电源/重连状态 |
| `DUT ft_finalpack_end <0>` | 停止并保存业务 → 重置参数（保留按键进入能力）→ 格式化成功 → 最后写入并回读验证按键禁用标记 → 断开并关机；任一步失败记录 FAILED，不按成功路径关机 |
| `DUT ft_key_dut_enable <1>` | 仅重新使能按键 DUT 并持久化；当前接口只有使能动作，v1 的参数 0 返回 ARG |

除 ft_dut 外均须处于 DUT。不同测试同时启动返回 BUSY；已达到相同开关目标可幂等成功。录音停止等异步动作完成前保持占用，非可取消的格式化/整包结束期间拒绝退出与其他修改命令，允许 GET_STATUS。

当前 `rdx_dut_finalpack_end_format_cb()` 未按 result 区分成功失败即继续关机，需要修正。最终打包是破坏性流程，仅在工站显式请求后执行；其软件结果与外部供电下真正关机的验收分别处理。关机相关响应不可达时结果为未知，禁止自动循环重试。

整包结束不承诺原子回滚，各步骤必须检查结果，失败即停止后续成功流程并记 FAILED。按键禁用是最后的持久化提交步骤：参数重置及格式化成功前不得禁用按键，参数重置接口也不得隐式提前写入禁用标记。这样前序失败或掉电后仍保留按键进入能力；存储未就绪仍须维修，不能绕过枚举与存储准入。

按键禁用写入失败或回读不符时，持久化状态可能不确定；本次启动保留受限恢复，工站显式重新使能按键并回读验证后才能安排重启。若此时掉电，或最后提交成功但响应/关机确认丢失，不能保证重启后仍可按键进入。该设备转入维修流程，不自动重试整包结束，也不以禁用标记推断包装成功。

阶段 3 开放整包结束前，必须实测并记录通过 JL Studio / ISD 维修工具恢复按键使能配置的具体操作、VM 保留/清除范围及身份数据保留结果；普通重刷是否保留禁用 VM 必须核实，不能把“重新刷机”视为已验证恢复步骤。验证前保持此命令返回 UNSUPPORTED。维修恢复不新增正常模式下的 CDC 后门，不允许普通 USB 请求开启产测。

失败后保留查询及安全退出能力；重新使能按键须确认持久化成功。复位后结果按未知处理，不自动继续整包结束。工站需检查参数、按键标记及存储状态；若需要自动跨复位恢复，另行设计持久化阶段记录。

## 8. 实施阶段与交付要求

### 8.1 三阶段总览

第 2–7 节描述最终能力，不要求第一阶段一次实现。每阶段完成代码检查与对应板测后再进入下一阶段；构建成功不等于电脑已识别串口，串口识别成功也不等于收发或厂测协议已完成。

| 阶段 | 目标 | 交付物 | 当前状态 |
|---|---|---|---|
| 1：串口识别 | ON 未进入 DUT 隐藏 CDC，按键进入后识别 COM，OFF 保留 MSC | 枚举固件、描述符记录、插拔及切换板测记录 | 新门控基础板测通过；本轮收束基础回归通过，背压、多轮稳定性与新增异常未闭环；1A/1B 未完整验收 |
| 2：双向收发与接收回调 | PC 数据到达任务回调，设备数据完整返回 PC | 传输接口、独立收发测试程序、异常收发记录 | 待实施 |
| 3：厂测协议接入 | 在可靠传输上实现本文身份查询及 DUT 流程 | 厂测固件、工站客户端、完整验收记录 | 待实施 |

### 8.2 阶段 1：先让电脑识别虚拟串口

**目标与范围**

本阶段必须先观察真实按键进入完成与退出状态，接入所有枚举入口；不得用按键按下、异步请求入队或通用射频 DUT 标志代替进入完成。初始化和复位默认关闭准入，进入失败不枚举，退出开始即禁止新启动；USB 任务执行前重查最新状态。原按键进入/退出若不能可靠完成，须在本阶段补齐最小生命周期适配，不能伪造 DUT 状态绕过验收。完整 BLE/SPP 厂测适配仍留到阶段 3。

只开放 CDC 枚举及串口打开、关闭所需的标准控制请求。此阶段不实现应用数据回显、PING、身份读取或 DUT 命令；串口工具发送数据不应触发业务动作，也不要求收到回复。

**检查点 1A：基础识别**

先完成配置、单独枚举和电脑驱动识别，以固定拨码状态验证。1A 是中间检查点，不代表热切换已通过；其固件仅用于受控板测，任何未完成的切换路径也不得允许 MSC/CDC 同时注册或 SD 双重所有权。

1. 增加第 3 节的项目级开关及最终配置检查。开发默认关闭，板测固件明确启用；保持 MSC、PC 模式和调音互斥约束。
2. 隔离现有调音工具接收入口，避免单独启用 CDC 后仍引用或调用调音消费者。
3. 实现第 4 节中枚举所需的启动/停止协调：ON 未进入 DUT 不枚举数据类、ON 按键进入 DUT 后仅 CDC、OFF 仅 MSC；所有启动入口统一门控，禁止同次注册两个数据功能。
4. 对主机误发数据，优先使用 bulk OUT 端点背压，允许主机写超时，不解析、不回复。必须确认中断不会持续触发或重复投递；若现有驱动无法安全背压，才采用任务上下文每轮有界读取并丢弃，不注册业务接收回调、不打印原始内容。该最小丢弃路径的 I/O 与释放同步必须在本阶段完成，不能延期到阶段 2。
5. 拔线、角色失效和关机时可靠停止 CDC；保护标准控制请求、中断及可能的丢弃读取与资源释放的并发。应用收发队列及完整会话机制留到阶段 2。
6. 检查 CDC 设备、接口、端点及字符串描述符，记录实验 VID/PID、序列号来源、Windows 版本、驱动名称和 COM 号。确认目标 Windows 环境是否自动绑定串口驱动；如需要 INF，明确交付和安装方式。

**1A 通过标准**

- ON 插入电脑、ON 带线冷启动但未进入 DUT：不出现 CDC 或 MSC，充电及正常业务保持。分别验证先按键进入 DUT 再插线、先插线再按键进入：出现可正常打开/关闭的 COM，无设备错误；退出 DUT 后 CDC 消失。冷启动不得因上次曾进入 DUT 自动开放 CDC。
- OFF 插入电脑、OFF 带线冷启动：保持现有 MSC 行为，不出现 CDC COM 口；纯充电器不枚举数据类。
- 串口工具误发单包及连续数据时，无业务动作或回复、无中断/消息洪泛，拔线后仍可重新枚举。允许主机因背压写超时，不以此判定阶段 2 收发能力。
- 完成首次枚举和端口打开/关闭记录，再推进 1B；不得以固件启动日志代替设备管理器及驱动记录。

**检查点 1B：生命周期与业务共存**

1. 覆盖带线 OFF→ON：PC 停止 MSC、归还并恢复 SD、业务就绪后保持正常模式且不启动 CDC；按键进入 DUT 后启动 CDC，不等待新的 OTG IN。ON→OFF 沿用现有等待、排空和复位规则。异步请求必须核对最新目标，同类重复请求不反复枚举。

### 8.3 阶段 2：打通发送、接收与任务回调

**目标与接口边界**

建立与厂测命令无关的字节传输层：PC → USB RX 通知 → 任务上下文接收回调；设备 → 有界 TX 队列 → PC。USB 包边界不是应用消息边界，回调只交付字节与长度，不假定一次回调对应一次 PC 写入。

具体函数名在实施时确定，但接口必须明确：回调运行任务、数据缓冲的有效期、发送时是否复制数据、返回值表示入队还是完成、未就绪/队列满/会话失效如何报告。建议接收数据仅在回调期间有效，消费者需保留时自行复制；发送入队成功不能表示主机已经收到。

**计划工作**

1. 中断只通知或合并 pending；任务按最大包长读取，有界处理并让出 CPU。处理通知投递失败后的补偿，避免一次丢通知导致永久不再接收。
2. 实现有界发送、短写续传和超时处理。验证底层 bulk 写的最坏耗时及返回长度计数，主机停止读取不得阻塞正常业务；若现有驱动无法保证，改造有界 I/O 或引入可安全停止的专用 I/O 任务。
3. 实现 generation、I/O 与 release 同步及旧队列清理。会话失效须覆盖物理拔线、总线复位、取消配置及超时重建；另行定义串口关闭重开后的清理策略，不依赖现有 DTR 位作为可靠断线判据。
4. 提供仅用于阶段 2 板测的原始字节回显入口，以及设备主动发送固定测试字节的入口，验证两个方向。测试入口有独立开关，阶段 3 接入协议时关闭，不能与协议消费者同时读取 CDC 数据。
5. 提供最小 PC 测试脚本，按预期长度累计接收并逐字节比较；测试数据由 PC 生成，不使用 AUTH 或真实业务数据。

**通过标准**

- PC 发送的数据进入任务回调，设备回显完整一致；设备主动发送的数据也能被 PC 正确接收。
- 正常连接且数据被成功接纳时，覆盖 1、63、64、65、128、256 字节及跨多包数据、连续发送和含 `0x00` 的二进制数据，不丢字节、不乱序、不重复。至少完成 1000 轮完整字节比较。
- 覆盖 RX 通知失败、TX 队列满、0 写、正数短写、主机停止读取及超时，无无限等待、内存持续增长或正常业务卡死。
- 故障时允许未完成数据丢失，不要求跨会话补发；必须报告失效并按第 4.3 节完成清理与恢复，新会话不收到旧数据。分别记录拔线、总线复位、取消配置、发送超时和串口关闭重开的恢复步骤，不能仅用重新打开 COM 口代替会话失效处理。
- 测试回显仅在真实按键进入 DUT 后开放，退出时关闭并清理在途 I/O。与该 DUT 模式已允许的业务并行验证，对尚未实现的 BLE/SPP 共存记录为阶段 3 待验；另测退出后的正常 BLE、双 ACL、HOGP 和录音回归。TX 满时明确拒绝或背压，不得报成功后静默丢弃。

阶段 2 通过后，可描述为“USB 双向字节传输与接收回调已打通”，此时仍没有厂测命令语义。

### 8.4 阶段 3：接入本文厂测方案

复用阶段 2 的传输接口，按以下顺序逐项接入：

1. **只读协议**：实现第 6 节分帧、参数校验、PING、GET_INFO、GET_STATUS，先关闭阶段 2 测试回显。开放 GET_INFO 前清理 AUTH 日志，并确认仅厂测模式可访问、无鉴权读取 AUTH 的产品访问边界。
2. **DUT 公共接口**：实现第 7 节有返回值、幂等目标状态、按序执行及异步结果记录。USB、BLE 和物理按键均经过统一动作仲裁，按第 6.2 节共用 ID 与 LAST 记录；验证终态覆盖和响应丢失时工站不会错误归属结果，异步完成统一回到状态所属任务处理。
3. **动作逐项接入**：先验证按键进入 DUT、CDC 模式准入与安全退出，以及 BLE/SPP 通道可用，再接入灯、马达等可停止测试和录音；最后接入格式化、整包结束及关机。每项明确不支持、提交失败、异步失败和停止完成的反馈。
4. **失败与恢复**：按第 7 节实现整包结束部分失败及复位后结果未知的恢复流程；按第 4.2 节分别实现 OFF 等待 DUT 退出和 ON 厂测失败恢复。验证格式化失败且 SD 未就绪时，ON 下拔插及总线复位后仍能查询、请求安全退出；覆盖两种限制叠加、拨回 ON、退出 DUT 和整机复位后的清理。
5. **工站客户端**：提供 pyserial/Python 或 C# 客户端，支持一问一答、有限超时、状态轮询、身份校验、敏感字段脱敏及结果未知处理。普通请求初始建议超时 2 秒，长动作轮询 500 ms、上限 60 秒，最终按最坏格式化/保存耗时实测冻结。

通过第 9 节完整验收矩阵并关闭阶段 2 测试入口，记录固件版本、开关、描述符、主机环境和工站版本后，才可描述为“厂测 USB 协议已验收”。阶段 1/2 的局部成功不得提前改变整篇文档的待实施/待验收状态。

#### 重建板测固件

2026-09-14 新门控测试包：`output/factory-usb-key-dut-stage1a/`，与旧 `factory-usb-stage1a/` 分开保存，刷写时以新目录的 `manifest.json` 和文件哈希为准。

- 初始化清除准入，退出开始立即撤销；USB 任务执行旧启动消息时再次检查。支持先按键后插线、先插线后按键，正常退出后串口消失。

- 主机检查覆盖正常模式隐藏、两种插线顺序、退出前旧请求失效、失败进入不授予、BLE 进入不授予，以及原有存储交接与关机保护。串口仍无回显和厂测命令。

在 SDK 目录使用原 VS Code wrapper。切换构建配置时先 clean，避免 Make 将另一配置生成的 ELF 误认为最新；此命令仅用于明确启用 CDC 的板测构建。

```powershell
$factoryPreviousMakeflags = $env:MAKEFLAGS
try {
    $env:MAKEFLAGS = 'EXT_CFLAGS=-DTCFG_T2620_FACTORY_USB_CDC_ENABLE=1 BUILD_DIR=objs/factory_cdc'
    .\.vscode\winmk.bat clean
    if ($LASTEXITCODE -ne 0) { throw 'Factory clean failed' }
    .\.vscode\winmk.bat all
    if ($LASTEXITCODE -ne 0) { throw 'Factory build failed' }
} finally {
    $env:MAKEFLAGS = $factoryPreviousMakeflags
}
```

回到默认配置也需先执行 wrapper 的 clean 再 all。刷写使用 JL Studio / ISD 工具，选择本次明确启用的固件；实际验收进度以本节实测记录为准。
