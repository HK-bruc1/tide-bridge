# 通用外置功放低功耗设计

> 更新时间：2026-10-19
> 适用于带独立 EN/SHDN/MUTE 控制的外置功放。本文保留方案、T2620 已取得的收益和平台经验，不保留实施步骤与详细测试用例。

## 1. 采用的方案

**功放跟随实际扬声器输出需求：输出通路稳定且正在输出时开启，输出停止后关闭；不跟随 BLE 连接、快慢广播或整机空闲定时器。**

| 职责 | 原则 |
|---|---|
| 播放业务 | 申请、使用、释放音频输出，不直接写功放 GPIO |
| 音频框架 | 汇总多个播放者，管理输出通路与启动/淡出/停止 |
| 板级功放管理器 | 唯一控制 EN，保证实际输出与开关时序一致 |

- 上电、关机、未知状态和打开失败默认关闭；硬件上下拉覆盖固件接管前的浮空窗口。
- 模拟通路稳定后才允许开启；淡出/停止输出后及时关闭，不等待模拟资源最终释放。
- 回调短小、同步、幂等，不在其中等待或刷日志；器件额外时序遵守规格书。
- 单纯 MIC 录音不需要喇叭功放；监听、侧音或提示音等真实输出由音频框架自然驱动。
- 多输出路由、外置 Codec 或独立 MUTE/EN 的产品，应按实际扬声器路由管理，不能直接照搬片内 DAC 状态。

## 2. T2620 方案与收益

PE5 高有效，开机/关机保持低电平，由 `rdx_peripheral_power_amp_set()` 统一控制：

```text
PE5 开启 = DAC 模拟就绪 && DAC 数字输出运行
```

JL BR28 的 `audio_dac_power_state()` 提供模拟生命周期，`_audio_dac_status_hook()` 提供数字输出状态；组合判断，输出 STOP 后关闭 PE5，不强关 DAC 模拟资源。

**连接待机实测从约 16 mA 降至约 7 mA，录音 MIC、提示音与播放正常，功放优化阶段已通过。** 后续关闭 PA4 后约 6 mA，额外约 1 mA 属于 SD/RGB 共享域收益，不记到 PE5。

三个电源域独立：PA0 是 JL 管理的 MIC 使能；PA4 是 SD NAND/RGB 共享 VDD；PE5 是外置功放使能。整体策略见 [6-0 未连接策略](6-0.T2620外设低功耗与共享VDD电源管理设计.md) 和 [6-2 连接待机策略](6-2.T2620BLE连接后低功耗设计.md)。

2026-10-19 未连接阶段收口：独立 LRC 正常业务版实测慢广播 **0.6–1.6 mA 波动**，用户确认锁定；本轮不改 PE5 策略，不能把整机新基线记为功放单项收益。LRC 默认开启，其余优化暂不执行，详细日志与验收边界见 6-0 第 5 节；本页连接态历史测量不因此重算。

## 3. 踩过的坑

| 问题 | 原因与处理 |
|---|---|
| 已停止播放，PE5 仍常开 | BR28 连接态可能长期保留 DAC 模拟资源，只跟随模拟开关不等于跟随输出；增加数字输出状态门禁 |
| 强关 DAC 后 MIC 无法拾音 | DAC 模拟与 ADC 存在共享资源；不能绕过 JL 准入强关，只关闭不需要的外置功放 |
| 用 BLE 空闲状态直接关功放 | 未连接也可能播放提示音或本地音频；功放与 BLE、PA4 解耦 |
| GPIO 高阻被当作已关闭 | 高阻可能浮空误使能；运行时保持确定关闭电平，复位窗口靠可靠上下拉 |
| 多模块分别操作 EN | 容易产生竞态和软件/硬件状态不一致；保留唯一写脚入口及引脚冲突检查 |
| 电流偏高就认定功放没关 | 软件定时器、共享 VDD 和休眠门禁也会耗电；分开确认负载、唤醒及休眠，不能混算收益 |
| 提示音结束、功放日志打印后出现 MMU 异常 | 异步 `Q_CALLBACK` 漏传参数描述，残留标志导致通过旧指针写回；必须完整投递回调消息，不能依赖任务接收缓冲清零。此问题不应通过取消 PE5 关断或屏蔽异常规避 |

## 4. 维护边界

方案成立不代表所有器件时序都已验证。移植或量产仍需结合规格书、波形和声音确认无首音截断、爆音或复位误开启；调试日志关闭后再做同条件电流对照。

T2620 实现位于 [`rdx_peripheral_power.c`](../SDK/apps/common/third_party_profile/rdx_protocol/rdx_peripheral_power.c)，板级默认电平见 [`src/板级配置.json`](../src/板级配置.json)。`TCFG_T2620_AMP_TRACE_ENABLE` 当前用于联调，量产应关闭。
