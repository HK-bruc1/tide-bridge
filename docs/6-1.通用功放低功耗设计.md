# 通用外置功放低功耗设计

> 更新时间：2026-09-05
> 文档状态：通用设计已形成；T2620 / PE5 功能板测通过，待补示波器时序与功耗量化数据
> 适用范围：由 SoC DAC 或音频 Codec 驱动、带独立 `EN/SHDN/MUTE` 控制脚的外置功放

## 1. 核心结论

外置播放功放不应在整机开机后一直使能，也不应直接跟随 BLE 广播、连接状态、应用页面或固定空闲定时器。正确策略是：

**让功放使能跟随实际音频输出通路的 DAC/Codec 生命周期；输出通路稳定后再开功放，输出通路关闭前先关功放。**

这里应使用 **DAC 生命周期**，不是 ADC 生命周期：

- DAC 是播放输出，决定扬声器功放是否需要工作；
- ADC 是麦克风采集，单纯录音时通常不需要开启扬声器功放；
- 如果录音场景同时存在监听、侧音或提示音，输出部分仍会打开 DAC，功放自然由 DAC 生命周期控制。

## 2. 为什么不使用业务状态直接控制

“未连接”“进入慢广播”“音乐暂停”等业务状态都不能完整代表功放是否空闲。例如 BLE 已进入慢广播时，设备仍可能正在播放经典蓝牙音乐、进行通话或播放本地提示音。如果 BLE 回调直接关闭功放，会切断正常声音。

DAC/Codec 模拟输出生命周期更接近真实硬件需求，并能覆盖开机提示音、按键音、本地播放、经典蓝牙音乐、通话、USB Audio 和 LE Audio 等共用输出路径。

推荐职责划分如下：

| 层次 | 职责 |
|---|---|
| 播放器/业务 | 正常申请、启动、停止和释放音频输出，不直接写功放 GPIO |
| 音频框架 | 汇总多个播放使用者，维护 DAC/Codec 引用和生命周期 |
| 产品/板级功放管理器 | 根据输出生命周期执行功放 EN 时序，独占 GPIO 写权限 |
| 芯片平台 | 提供 DAC/Codec 生命周期 hook 和 GPIO 接口，不包含具体产品业务条件 |

## 3. 通用状态映射

以下以高电平使能的功放为例；低有效器件应反转物理电平，但状态含义不变。

| 系统或输出状态 | 功放 EN | 设计目的 |
|---|---:|---|
| 复位、启动初始化 | 低 | 防止启动浮空、静态功耗和开机冲击声 |
| `OUTPUT_OPEN_PREPARE` | 低 | DAC/Codec 尚未稳定，功放保持关闭 |
| `OUTPUT_OPEN_FINISH` | 高 | 模拟输出稳定后才允许功放工作 |
| 输出正在使用 | 高 | 多个音频使用者共享期间持续工作 |
| `OUTPUT_CLOSE_PREPARE` | 低 | 在模拟输出关闭前先切断功放 |
| `OUTPUT_CLOSE_FINISH` | 低 | 输出关闭后保持低功耗状态 |
| 未知、异常或打开失败 | 低 | 失败安全，优先避免误导通和爆音 |
| 软关机 | 低 | 关机期间保持确定的关闭电平 |

典型时序为：

```text
开启：数字静音/零数据 -> 打开 DAC 模拟部分 -> 输出稳定 -> 功放 EN -> 淡入/正常播放
关闭：淡出 -> 数字静音/停止数据 -> 功放 EN 关闭 -> 关闭 DAC 模拟部分
```

功放 EN hook 只负责硬件边界，不能代替播放器淡出、数字静音和资源释放。如果功放规格书要求额外的 `tON/tOFF`、MUTE 顺序或输入钳位，应把器件时序纳入音频启动/停止流程；不要未经测量就在同步 hook 内加入较长阻塞延时。

## 4. 启动、关机与硬件安全态

MCU 复位后的 GPIO 通常是高阻态。高阻不等于低电平，功放 EN 可能因内部漏电或外部干扰被误触发。因此应同时满足：

1. 原理图为 EN 配置与“关闭态”一致的可靠上下拉；高有效 EN 通常使用下拉；
2. 固件在尽可能早的板级初始化中将 EN 配置为确定的关闭电平；
3. 软关机配置再次将 EN 设置为关闭电平；
4. 固件运行期间关闭态使用输出低/高，不依赖高阻模拟关闭；
5. 复核软关机公共流程是否会短暂把 GPIO 改成高阻，并通过硬件上下拉或 IO 保护消除浮空窗口。

硬件上下拉负责固件接管前的复位窗口，开机 IO 配置负责固件运行后的确定状态，两者不能互相替代。

## 5. 软件实现要求

### 5.1 单一控制入口

功放 EN 必须只有一个物理写入口。BLE、播放器、提示音和关机业务不能各自直接操作同一个 GPIO，否则容易出现一个模块关闭、另一个模块仍认为已开启的竞态。

### 5.2 使用音频框架的汇总生命周期

多个播放者并存时，应由音频框架的引用计数或输出节点生命周期决定何时关闭 DAC。只有最后一个输出使用者释放后，才关闭功放和 DAC。短音效之间允许保留一个经过评估的延迟关闭窗口，以减少频繁开关和爆音；该延时属于音频输出策略，不应由 BLE 空闲定时器重复实现。

### 5.3 生命周期回调约束

功放 GPIO 回调应：

- 同步执行，保证开关边沿与 DAC/Codec 顺序一致；
- 幂等，重复状态不会造成无意义抖动；
- 足够短，不投递异步任务、不等待、不刷日志；
- 未知状态默认关闭；
- 对引脚复用冲突进行编译期检查，不能等到运行时竞争。

如果系统的低功耗唤醒会重新配置 GPIO，软件缓存必须与硬件状态同步，或者在安全关闭路径重新强制写入关闭电平，避免“缓存认为已关闭、硬件实际已浮空”。

## 6. JL/BR28 平台参考实现

JL BR28 DAC 接口提供四阶段通知，应用层可以重定义 `audio_dac_power_state(u8 state)`。通用映射如下：

```c
void audio_dac_power_state(u8 state)
{
    switch (state) {
    case DAC_ANALOG_OPEN_FINISH:
        product_amp_enable(1);
        break;

    case DAC_ANALOG_OPEN_PREPARE:
    case DAC_ANALOG_CLOSE_PREPARE:
    case DAC_ANALOG_CLOSE_FINISH:
    default:
        product_amp_enable(0);
        break;
    }
}
```

这只是平台接入示例。产品策略和 GPIO 归属仍放在产品/板级功放管理模块中，不应把具体引脚或 BLE 条件写进 JL DAC 核心。

## 7. T2620 已实施实例

当前 T2620 工程采用以下配置：

- 外置功放 EN：`PE5`，高有效；
- 开机 IO：`PE5 = PORT_OUTPUT_LOW`；
- 关机 IO：`PE5 = PORT_OUTPUT_LOW`；
- 运行时入口：`rdx_peripheral_power_amp_set()`；
- 控制依据：JL DAC 四阶段生命周期；
- 与 BLE 快/慢广播、两路 ACL 连接数解耦；
- 旧 RDX Wi-Fi 路径若重新占用 PE5，编译期直接报引脚冲突。

## 8. 验收用例

| 用例 | 预期结果 |
|---|---|
| 上电至第一个提示音前 | EN 保持关闭态，无异常高脉冲 |
| 开机/按键提示音 | 正常出声，无首音截断和明显爆音 |
| 连续短提示音 | 不出现不合理的快速抖动 |
| 经典蓝牙音乐暂停/恢复 | 功放正确关闭/恢复，无爆音 |
| 通话接通/挂断 | 语音完整，切换无异常冲击 |
| 本地、USB、LE Audio | 所有实际启用的 DAC 输出路径均能控制功放 |
| 仅麦克风录音 | 无监听输出时功放保持关闭 |
| BLE 慢广播期间播放其他音频 | 功放继续开启，声音不被 BLE 状态切断 |
| 所有音频停止 | DAC 最终关闭后 EN 回到关闭态 |
| 软关机/低电关机 | EN 全程无误开启，最终保持关闭态 |
| 电流测量 | EN 关闭后的整机电流下降符合功耗预算 |

示波器建议同时观察功放 EN、DAC/Codec 输出和扬声器端波形，确认“输出稳定后开功放、输出关闭前关功放”。

## 9. 适用边界

以下情况不能直接照搬“全局 DAC 生命周期 = 功放生命周期”：

- 同一个 DAC 同时连接耳机口、Line-out 和不同功放，但并非所有路由都需要该功放；
- 使用外置 I2S Codec，功放依赖的是 Codec/输出路由状态而不是片内 DAC；
- 功放还承担超声、蜂鸣器或绕过常规音频框架的输出；
- 器件具有独立 MUTE 与 EN，需要两脚时序；
- 硬件 EN 极性、上下拉或上电时序与本例不同。

这些产品应将“DAC 四阶段”升级为“实际扬声器输出路由的生命周期或资源投票”，但仍保持相同原则：业务只申请输出资源，统一功放管理器负责最终 GPIO 和硬件时序。

## 10. 设计结论

通用功放低功耗设计的关键不是“在某个空闲事件中拉低 EN”，而是建立可靠的输出资源生命周期：

- 开机和异常状态默认关闭；
- DAC/Codec 稳定后开启；
- 输出关闭前先关闭功放；
- 多个播放者由音频框架统一汇总；
- 与 BLE、UI 和单一业务状态解耦；
- 用规格书、示波器、听感和电流共同完成量产验收。

在满足这些条件时，功放可以真正做到“使用时开启，不使用时关闭”，同时避免因简单硬编码常开或业务回调直控而产生的额外功耗、截音和爆音。
