# 2-8. HID 键值绑定本地功能设计

本文说明 T2620 当前的按键业务分发架构：**实体键只承载输入，配键决定功能，HID 上报与本地业务独立执行。** 旧文档中按 KEY1～KEY5 硬编码普通功能、按有无 BLE 连接二选一路由的规则不再适用。

## 1. 架构总览

```text
KEY1～KEY5 实体键
        ↓
稳定按下：锁定本次完整配键快照
        ↓
统一输入分发
        ├─ HID 通道：独立检查就绪与输入准入 → 上报 Down / Up
        └─ 本地通道：独立检查业务准入 → 按快照键值识别手势
                                              ↓
                                      app_core 受理业务
                                              ↓
                                回放 / 音量 / 会议录音 / 灵感录音
```

- **功能随键值走，不随物理键走。** 任一实体键配置成相同键值，就执行相同的普通业务。
- **两路并行，不是二选一。** HID 就绪时，本地动作照常执行，并额外上报键值；HID 未就绪或发送受阻，不影响本地业务及其收尾。
- **没有全局“在线模式”。** HID 上报看 HID 就绪，录音选路看 RDX APP 就绪，本地回放与音量不看 BLE 连接状态。
- **HID 报告不是业务结果。** 即使本地动作被拒绝，已准入的 HID Down/Up 仍正常上报，不要求客户端据此反向执行设备端动作。录音与 APP 的既有触发／回复流程不变。

## 2. 键值与业务

本地功能只识别**无修饰键、仅一个有效 Usage** 的配置。组合键、空配置和其他键值不触发这些业务，HID 仍按原配键规则处理。

| 键值 | Usage | 本地业务 |
|---|---|---|
| F13 | `0x68` | 单击播放上一个录音，长按／持续按住快退，松开停止快退 |
| F14 | `0x69` | 单击播放下一个录音，长按／持续按住快进，松开停止快进 |
| F15 | `0x6a` | 单击降低本地播放音量，每次两级 |
| F16 | `0x6b` | 单击提高本地播放音量，每次两级 |
| F17 | `0x6c` | 单击播放／暂停本地录音回放，不承担录音或标记 |
| F18 | `0x6d` | 双击开始／结束会议录音；会议录音中单击标记重点 |
| F19 | `0x6e` | 长按开始灵感录音，松开结束 |
| F20～F24 | `0x6f`～`0x73` | 无本地业务；HID 就绪并准入时上报自定义键 |
| 其他 | — | 无本地业务 |

F13～F17 操作的是设备喇叭回放及本地播放音量，不控制 PC／手机播放、系统音量或录音增益；录音中均不生效。其余存储、提示音、保存等业务保护也继续保留，不因开放在线操作而放宽。

## 3. 三种独立判断

| 判断 | 依据 | 不应混用的条件 |
|---|---|---|
| HID 能否上报 | Input CCC 已启用、链路已加密、未 Suspend，并通过本周期输入准入 | 不能只看是否存在 ACL；就绪或恢复后仍需先稳定全释放 |
| 本地业务能否受理 | 当前手势有效，且系统与对应业务保护允许 | 不因 HID 未就绪或存在 BLE 连接而一概拒绝 |
| 新录音走在线还是本地 | RDX owner 有效、RDX CCC 已配置、音频发送通道就绪，三者同时满足才算 RDX 就绪 | HID 就绪不等于 RDX 就绪；RDX 刚接入但通道未准备好时按本地处理 |

**配键在按下时锁定；录音选路在有效手势被业务受理时判断。** F18 的受理点是双击成立，F19 是长按成立，而不是原始 Down。

因此，只连接 HID 时，既能上报键值，也能本地录音落盘；只连接 RDX 时，本地回放、音量和录音业务同样可用。

## 4. 按压周期与通道隔离

### 4.1 一次按压只使用一份配键

稳定 Down 到释放构成一个按压周期。本周期的 HID 报告、本地手势、按住动作及停止责任，都使用按下时的完整配键快照，不重新读取实时配键。

- 按住期间热配键，HID 按原安全规则释放；本地动作仍按旧快照收尾，新配键从下一次按下生效。
- HID 与本地使用独立队列和失效范围。HID 断链、背压或队列故障不能吞掉本地松开，也不能阻塞 F19 停止或快进／快退收尾。
- 来源失真、本地队列失去可信度或系统取消时，撤销未执行手势，并负责停止本周期已开始的动作。停止未完成前保留重试责任，不能靠清空队列假装结束。
- 实际释放后，不补执行积压的长按／持续按住动作；旧周期的松开、停止和回调也不得影响后来开始的业务。

### 4.2 手势按键值解析，工厂入口按物理键保留

- 普通键值没有双击动作时，松开即结算单击；F18 等待多击窗口，双击不能先执行一次单击。只有同一物理键、同一配键快照的点击才能合并。
- **物理 KEY5 始终保留多击窗口和八击 DUT 入口**，与它配置成什么键值无关；DUT 内保留既有专用控制。这是工厂入口的物理键例外，不是录音专用路径。
- 系统／工厂保护及 KEY5 工厂入口优先于普通业务；识别八击期间不能提前执行普通 F18 双击。
- 当前仅支持单键周期。未经过全释放就从一个有效键切到另一个键时，取消当前动作并等待稳定全释放，不把替换后的键当作新开始。

## 5. 录音分发与生命周期

会议与灵感是两种业务类型，共用现有录音引擎，不能用是否推流、是否按住或物理键号代替业务类型。

| 业务 | 控制方式 | RDX 未就绪时开始 | RDX 就绪时开始 | RDX 断开／逻辑释放 |
|---|---|---|---|---|
| F18 会议 | 双击开始／结束，录音中单击标记 | 本地落盘 | 沿用 APP 会议路径，推流与落盘同步 | 在线会议转离线继续落盘，不结束；重连只同步状态，不恢复该段推流 |
| F19 灵感 | 长按开始，松开结束 | 本地落盘 | 纯推流，不落盘 | 在线灵感结束或取消，不转本地；原本本地录音不因 RDX 断开而结束 |

关键边界：

- **本地开始不被后来连接改写。** F19 和本地 F18 受理后保持既定选路，包括提示音和初始化期间；APP 接入只接管控制／状态，不增开推流。固定路径无法继续时拒绝或取消，不暗中换路。
- **在线 F18 不是 F19 式会话。** 在线会议等待 APP 回复期间，再次双击只会被既有并发开始保护拒绝，不构成取消；本地 F18 尚未开始时，再次双击可以取消。
- **F19 的松开必须覆盖尚未开始的请求。** 即使正在等 APP 回复或播放开始提示音，也要取消本次开始，不能稍后自行开录。开始、松开和停止始终归属同一按压周期及录音会话。
- **录音互斥，暂停不等于空闲。** 会议与灵感不能并行；待开始或停止保存未完成时，不接受新的开始，也不排队自动补开。APP 开启的普通会议可由 F18 标记／结束；CALL、DUT、工厂录音不被 F18／F19 抢占。
- **标记只认真实录音状态。** 会议实际录制且标记成功才显示成功反馈；暂停、待开始、停止中或标记被拒绝都不能显示成功。标记时刻取单击判定完成时刻。
- **连接变化只影响对应通道。** 仅 HID 断开不停止录音。本地会议接入 APP 后，F18 双击只停止当前会议，不在同一次操作里再开始在线录音。

## 6. 反馈原则

- 会议录音白灯呼吸，灵感录音白灯常亮；灯型由业务类型决定，与在线／本地、当前物理键状态无关。开始与结束沿用现有提示音。
- 标记成功使用黄灯；F17 回放开始／恢复／暂停成功保留既有黄灯；F20～F24 在 HID 就绪且本周期准入时，单击使用白灯。
- 上述单次白灯／黄灯沿用 **2 秒**，结束后恢复当时的真实业务灯态，不恢复一份过期场景。
- 单击没有业务反馈时显示电量；双击、长按、持续按住和松开不附加电量提示。高优先级灯态拒绝业务提示时，不改为查电量，也不事后补闪。
- 充电、低电、DUT、工厂、OTA、存储切换、关机等既有保护与优先级不放宽。旧 KEY1 蓝灯／KEY2 白灯的物理键反馈已取消。
- F20～F24 未连接提示音待音源确定，当前未就绪时单击显示电量。HID 报告、白灯和开始提示音都不能作为客户端执行成功或录音已开始的证据。

## 7. 默认配键与兼容

| 实体键 | 默认键值 | 本地功能 |
|---|---|---|
| KEY1 | F13 | 上一个录音／快退 |
| KEY2 | F14 | 下一个录音／快进 |
| KEY3 | F17 | 回放播放／暂停 |
| KEY4 | F18 | 会议录音／标记 |
| KEY5 | F19 | 灵感录音 |

F15／F16 音量键仍可由 APP 下发。配键协议、HID 报告和 VM 格式不变，详见 [A1](2-4.HOGP_APP按键键值下发方案A1.md)／[A2](2-5.HOGP_APP端配键协议对齐文档A2.md)。

**有效旧配键不迁移，包括旧默认和全零配置。** 新默认只用于无有效保存配键、恢复默认配键或恢复出厂的设备。旧默认 F13～F17 的设备，其 KEY5 现在只执行 F17 回放，不再拥有录音特权；体验新默认需主动恢复默认。

本地音量正常调节及重启沿用原生记忆；整机恢复出厂恢复配置最大音量，单独恢复默认配键不重置音量。

## 8. 踩坑与长期约束

| 踩过的坑 | 必须保留的结论 |
|---|---|
| 把“有连接”“HID 就绪”“RDX 就绪”合成一个在线状态，导致本地功能被吞 | 分开判断 HID 上报、本地业务准入和录音选路，不恢复旧的三选一路由 |
| HID 失效或热配键清掉输入周期，F19 只开始不结束 | 本地动作所有权独立保留，沿旧快照收尾；停止责任不能随着 HID 队列一起丢弃 |
| 按实时连接状态启动录音，提示音期间接入 APP 就改变落盘属性 | 在业务受理点确定路线，执行阶段不重新猜测；本地录音接入 APP 不自动推流 |
| 只看“当前未录音”，误把等待 APP、初始化、暂停或停止保存当成空闲 | 区分待开始、活动和停止未完成；业务完成必须以对应流程确认，不能只看一个运行标志 |
| 旧录音协议没有请求 ID，松开后迟到的 START 可能重新开录 | 在线 F19 取消后保留旧请求隔离；匹配的 APP STOP 已确认、worker 也完成收尾后，才允许同一 RDX 会话再次在线开始。不用固定超时或新按键抹掉歧义，也不继续锁死已空闲的本地业务 |
| 旧 Up 或旧回调结束了 APP 后来开启的新录音 | 按压与录音均有自己的归属，旧周期只能结束自己的请求，不能停止后来会话 |
| 在线灵感停止轮询反复置忙，覆盖 worker 已完成的 READY，后续按键业务被拒绝 | 停止已成功提交后只等待完成确认，重复查询不得重新置忙；不能靠删掉忙保护或强行空闲掩盖问题 |
| 把在线会议也当作纯推流按住录音，混淆断连和灯效 | 业务类型与传输路线分开：F18 在线仍落盘且断连续录；只有 F19 在线纯推流、松开或断连结束 |
| 灯效曾实测约 200 ms，但本地源码与产物参数都是 2 秒 | 静态产物不能证明设备映像和实际仲裁时序；核对真实持续时间、到期及抢占证据，不凭参数猜根因。用户后来确认灯效恢复，不反推唯一根因 |

## 9. 范围与维护依据

当前方案限定为**单键输入**，不支持按住 F19 同时按 F18 标记，也不包含 HID 多键聚合。未连接自定义键提示音、多键能力及带请求 ID 的录音协议另行设计，不在本方案中扩展。

截至 2026-10-22，用户已确认功能通过基本验证；这不代表双 ACL、全部异步时序、连续录音收尾、掉电持久化或量产边界全部验收通过。本文不保留阶段实施清单和逐轮测试记录，历史证据查 Git 历史；主机覆盖以 `tests/host/README.md` 为准。

本文是当前按键分发、录音入口及反馈的维护依据；录音接入和断连续录的既有业务规则参见 [10-2.离线在线模式转换时的体验优化](10-2.离线在线模式转换时的体验优化.md)。本架构不改变关机、存储、工厂保护及已锁定的低功耗策略。
