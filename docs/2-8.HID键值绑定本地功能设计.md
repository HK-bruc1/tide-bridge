# 2-8. HID 键值绑定本地功能设计

本文说明 T2620 当前的按键业务分发架构：**实体键只承载输入，配键决定功能，HID 上报与本地业务独立执行。** 旧文档中按 KEY1～KEY5 硬编码普通功能、按有无 BLE 连接二选一路由的规则不再适用。

> 2026-10-30：新增会议落盘开关 `recsave`，默认开启时沿用原规则；关闭时 APP/F18 会议只允许 RDX 就绪后纯推流，未就绪无声拒绝，断开/逻辑释放/CCC 关闭则结束、不转本地。F19 不变。设备端已实现并通过主机测试，新增行为待 APP/实板验收，见 [10-8](10-8.会议录音落盘APP控制方案.md)。
>
> 2026-11-04：F19 灵感录音已从会议状态上报切换为专属 `flashnote` 协议；会议仍使用 `record`。APP 闪记与按键闪记互斥、控制权分离；F19 离线录音中途连接 RDX 只同步状态，不转为在线推流，也不允许 APP 停止按键会话。实现与实板证据见 [10-10](10-10.灵感录音复用闪记协议融合方案.md)。
>
> 2026-11-05：用户确认 F18／F19 组合测试通过，现将产品 F13～F24 全部扩展为左 Ctrl+左 Alt+左 Shift 组合；各 Usage 对应的功能和手势不变。新增其他组合仍需 APP 和实板回归，平台兼容及冲突须分别验证。
>
> 2026-11-05：在线 F18 改为由设备直接启动会议，不再发送 `devrec` 请求并等待 APP 下发 START；初始化成功后主动上报 `record` 状态。用户反馈这一流程测试可用，所测手机 APP 可以兼容；其他版本及未明确覆盖的场景仍需验证。

## 1. 架构总览

```text
KEY1～KEY5 实体键
        ↓
稳定按下：锁定本次完整配键快照
        ↓
统一输入分发
        ├─ HID 通道：独立检查就绪与输入准入 → 上报 Down / Up
        └─ 本地通道：独立检查业务准入 → F19 稳定 Down／其他键值手势
                                              ↓
                                      app_core 受理业务
                                              ↓
                                回放 / 音量 / 会议录音 / 灵感录音
```

- **功能随键值走，不随物理键走。** 任一实体键配置成相同键值，就执行相同的普通业务。
- **两路并行，不是二选一。** HID 就绪时，本地动作照常执行，并额外上报键值；HID 未就绪或发送受阻，不影响本地业务及其收尾。
- **没有全局“在线模式”。** HID 上报看 HID 就绪，录音选路看 RDX APP 就绪，本地回放与音量不看 BLE 连接状态。
- **HID 报告不是业务结果。** 即使本地动作被拒绝，已准入的 HID Down/Up 仍正常上报，不要求客户端据此反向执行设备端动作。F19 按键录音由设备启动并主动上报闪记状态，不依赖 APP 模拟按键。

## 2. 键值与业务

产品 F13～F24 的本地识别要求**恰好一个有效 Usage 且 modifier 恰好为 `0x07`**（左 Ctrl `0x01`、左 Shift `0x02`、左 Alt `0x04`）。裸 F13～F24、其他修饰位、多个普通 Usage 和空配置均不触发这些本地 Usage 业务或 F20～F24 自定义键白灯。KEY5 的物理 DUT 入口及无业务单击的电量反馈不受此限制。

这里限制的是设备本地功能，不是协议白名单。HID 仍按实际配键原样上报；若 APP 下发或设备保存的仍是裸 F13～F24，主机收到的仍是裸键，但设备不会因此执行对应本地功能。要上报组合并执行对应本地功能，必须将配键设置为下述组合。

| 键值 | Usage | 本地业务 |
|---|---|---|
| `0x07`+F13 | `0x68` | 单击播放上一个录音，长按／持续按住快退，松开停止快退 |
| `0x07`+F14 | `0x69` | 单击播放下一个录音，长按／持续按住快进，松开停止快进 |
| `0x07`+F15 | `0x6a` | 单击降低本地播放音量，每次两级 |
| `0x07`+F16 | `0x6b` | 单击提高本地播放音量，每次两级 |
| `0x07`+F17 | `0x6c` | 单击播放／暂停本地录音回放，不承担录音或标记 |
| 左 Ctrl+左 Alt+左 Shift+F18 | `0x6d`，modifier `0x07` | 双击开始／结束会议录音；会议录音中单击标记重点 |
| 左 Ctrl+左 Alt+左 Shift+F19 | `0x6e`，modifier `0x07` | 稳定按下即发起灵感录音，松开结束或取消尚未完成的开始 |
| `0x07`+F20～F24 | `0x6f`～`0x73` | 无本地业务；HID 就绪并准入时上报自定义键，单击可显示自定义键白灯 |
| 其他 | — | 无本地业务 |

F13～F17 操作的是设备喇叭回放及本地播放音量，不控制 PC／手机播放、系统音量或录音增益；录音中均不生效。其余存储、提示音、保存等业务保护也继续保留，不因开放在线操作而放宽。

下文为便于阅读，F13～F24 均指上表的组合，另有注明的裸键除外。F19 的快速入口只改变本地业务触发时机，不修改底层扫描、防抖和 LONG／HOLD 判定时间，也不伪造长按事件。F13／F14 仍等待原长按门槛，HID Down／Up 与按住行为保持独立。任意 KEY1～KEY5 配成 F19 组合都使用同一入口，不增加物理 KEY5 录音特权。

## 3. 三种独立判断

| 判断 | 依据 | 不应混用的条件 |
|---|---|---|
| HID 能否上报 | Input CCC 已启用、链路已加密、未 Suspend，并通过本周期输入准入 | 不能只看是否存在 ACL；就绪或恢复后仍需先稳定全释放 |
| 本地业务能否受理 | 当前手势有效，且系统与对应业务保护允许 | 不因 HID 未就绪或存在 BLE 连接而一概拒绝 |
| 新录音走在线还是本地 | RDX owner 有效、RDX CCC 已配置、音频发送通道就绪，三者同时满足才算 RDX 就绪 | HID 就绪不等于 RDX 就绪；RDX 未就绪时仅允许原有落盘路线，不落盘会议直接拒绝 |

**配键在稳定按下时锁定；录音选路在本地业务受理时判断。** F18 的受理点是双击成立；F19 则由防抖后的稳定 Down 投递到 app_core 受理，不再等待长按。原始电平边沿不直接启动录音，扫描回调不初始化音频或发送 BLE 数据。

因此，只连接 HID 时仍可上报键值，并按产品策略本地录音落盘（会议要求 `recsave=1`，F19 不变）；只连接 RDX 时，本地回放、音量和录音业务同样可用。

## 4. 按压周期与通道隔离

### 4.1 一次按压只使用一份配键

稳定 Down 到释放构成一个按压周期。本周期的 HID 报告、本地手势、按住动作及停止责任，都使用按下时的完整配键快照，不重新读取实时配键。

- 按住期间热配键，HID 按原安全规则释放；本地动作仍按旧快照收尾，新配键从下一次按下生效。
- HID 与本地使用独立队列和失效范围。HID 断链、背压或队列故障不能吞掉本地松开，也不能阻塞 F19 停止或快进／快退收尾。
- 来源失真、本地队列失去可信度或系统取消时，撤销未执行手势，并负责停止本周期已开始的动作。停止未完成前保留重试责任，不能靠清空队列假装结束。
- 实际释放后，不补执行积压的长按／持续按住动作；旧周期的松开、停止和回调也不得影响后来开始的业务。
- F19 每个周期至多尝试开始一次，后续 LONG／HOLD 不重复启动；本次被忙状态拒绝后也不在长按成立时补开。若业务处理前已经松开，丢弃积压的 Down，不事后开录。

### 4.2 手势按键值解析，工厂入口按物理键保留

- 普通键值没有双击动作时，松开即结算单击；F18 等待多击窗口，双击不能先执行一次单击。只有同一物理键、同一配键快照的点击才能合并。
- **物理 KEY5 的点击始终保留多击窗口和八击 DUT 入口**，与它配置成什么键值无关；DUT 内保留既有专用控制。这是工厂入口的物理键例外，不是录音专用路径。KEY5 配成 F19 时，其稳定 Down 与其他实体键一样不等待多击窗口。
- 系统／工厂保护保持不变，识别八击期间不能提前执行普通 F18 双击。KEY5 配成 F19 时，用户已接受八击前各次短按可能发起录音请求或产生短录音；已发出的请求／音频不能靠事后识别八击撤回。
- 八击识别成功后，先取消／停止归属该输入生命周期的 F19，确认清理完成后再按原准入进入 DUT。该请求不能被录音清理时的队列失效吞掉；工厂入口禁用仍阻止进入，不强停其他 APP／会议／通话／工厂录音。系统取消或准入失效后不延迟补进 DUT。
- 当前仅支持单键周期。未经过全释放就从一个有效键切到另一个键时，取消当前动作并等待稳定全释放，不把替换后的键当作新开始。

## 5. 录音分发与生命周期

会议与灵感是两种业务类型，共用现有录音引擎，不能用是否推流、是否按住或物理键号代替业务类型。

| 业务 | 控制方式 | RDX 未就绪时开始 | RDX 就绪时开始 | RDX 断开／逻辑释放 |
|---|---|---|---|---|
| F18 会议，落盘开启（默认） | 双击开始／结束，录音中单击标记 | 本地落盘 | 设备直接启动，推流与落盘同步，主动上报 `record` | 在线会议转离线继续落盘，不结束；重连只同步状态，不恢复该段推流 |
| F18 会议，落盘关闭 | 双击开始／结束，录音中单击标记 | 无声拒绝，不补开 | 设备直接启动，纯推流、不落盘，主动上报 `record` | 取消或结束，不转本地；CCC 关闭同样结束 |
| F19 灵感 | 稳定按下发起，松开结束／取消 | 本地落盘 | 纯推流，不落盘 | 在线灵感结束或取消，不转本地；原本本地录音不因 RDX 断开而结束 |

关键边界：

- **本地开始不被后来连接改写。** F19 和本地 F18 受理后保持既定选路，包括提示音和初始化期间；APP 接入不增开推流。F19 只同步状态，控制权仍属于按键周期；本地会议沿用会议控制规则。固定路径无法继续时拒绝或取消，不暗中换路。
- **F18 不变成按住式业务。** 在线 F18 不再等待 APP 回复；开始提示音或初始化期间再次双击可取消或结束当前请求，F18 松开始终不结束会议。
- **F19 的松开必须覆盖尚未开始的请求。** 即使正在播放开始提示音或初始化，也要取消本次开始，不能稍后自行开录。开始、松开和停止始终归属同一按压周期及录音会话。
- **短按也可能发起 F19。** 不再保证短按无录音请求；后续仍需完成音频初始化和启动帧处理，但不再等待旧会议协议的 APP 回复。提前受理不等于立即有可发送音频，更不等于 APP 已收到。
- **录音互斥，暂停不等于空闲。** 会议与灵感不能并行；待开始或停止保存未完成时，不接受新的开始，也不排队自动补开。APP 开启的普通会议可由 F18 标记／结束；CALL、DUT、工厂录音不被 F18／F19 抢占。
- **标记只认真实录音状态。** 会议实际录制且标记成功才显示成功反馈；暂停、待开始、停止中或标记被拒绝都不能显示成功。标记时刻取单击判定完成时刻。
- **连接变化只影响对应通道。** 仅 HID 断开不停止录音。本地会议接入 APP 后，F18 双击只停止当前会议，不在同一次操作里再开始在线录音。
- **CDC 与在线 F19 纯推流双向共存。** 已受理的 CDC LIST/GET 期间，当前 RDX owner、CCC 和音频流就绪时可由 F19 组合发起灵感纯推流；反向先有在线 F19 时也可由 APP 请求 CDC LIST/GET 下载已有文件，用于自动传输，不要求先松开按键。提示音、启动中及活动会话必须由现有 token/冻结路线证明纯推流且无实际录音写入器，不能只凭 ONLINE 或活动标志放行；不要求 HID 报告就绪。F19 不创建/写入/完成本地录音文件，不抢占 CDC 读占用，也不主动断开 BLE。松开或 RDX 逻辑/物理断开仍取消/结束，不转离线；CDC 完成/取消/拔插也不改写冻结路线。F18、离线 F19、普通 APP 录音及其他存储冲突继续双向拒绝，格式化/故障/隔离、关机和停止屏障等保护不放宽。例外不改变格式化/MSC/RDX 重绑定等其他门禁；详见 [10-4 第 5 节](10-4.CDC通用文件传输业务方案.md)。

## 6. 反馈原则

- 会议录音白灯呼吸，灵感录音白灯常亮；灯型由业务类型决定，与在线／本地、当前物理键状态无关。正常录音开始与结束共用设备 VM 的“录音提示音”开关，默认开启；APP/F18/F19、在线/离线及正常 CHAT/CALL 均适用，同一会话使用固定策略。关闭时跳过播放及等待，其他系统音、异常告警和工厂/DUT 不变，见 [10-6.录音提示音APP控制方案](10-6.录音提示音APP控制方案.md)。
- 标记成功使用黄灯；F17 回放开始／恢复／暂停成功保留既有黄灯；F20～F24 在 HID 就绪且本周期准入时，单击使用白灯。
- 上述单次白灯／黄灯沿用 **2 秒**，结束后恢复当时的真实业务灯态，不恢复一份过期场景。
- 单击没有业务反馈时显示电量；双击、长按、持续按住和松开不附加电量提示。高优先级灯态拒绝业务提示时，不改为查电量，也不事后补闪。
- 充电、低电、DUT、工厂、OTA、存储切换、关机等既有保护与优先级不放宽。旧 KEY1 蓝灯／KEY2 白灯的物理键反馈已取消。
- F20～F24 未连接提示音待音源确定，当前未就绪时单击显示电量。HID 报告、白灯和开始提示音都不能作为客户端执行成功或录音已开始的证据。

## 7. 默认配键与兼容

| 实体键 | 默认键值 | 本地功能 |
|---|---|---|
| KEY1 | 左 Ctrl+左 Alt+左 Shift+F13 | 上一个录音／快退 |
| KEY2 | 左 Ctrl+左 Alt+左 Shift+F14 | 下一个录音／快进 |
| KEY3 | 左 Ctrl+左 Alt+左 Shift+F17 | 回放播放／暂停 |
| KEY4 | 左 Ctrl+左 Alt+左 Shift+F18 | 会议录音／标记 |
| KEY5 | 左 Ctrl+左 Alt+左 Shift+F19 | 灵感录音 |

F15／F16 音量组合仍可由 APP 下发。配键协议、HID 报告和 VM 的**格式**不变；默认内容和产品键本地准入发生变化。各组合的按下报告均为 `07 00 <Usage> 00 00 00 00 00`，松开报告为 8 字节全零，详见 [A1](2-4.HOGP_APP按键键值下发方案A1.md)／[A2](2-5.HOGP_APP端配键协议对齐文档A2.md)。

**有效旧配键不迁移，包括旧默认和全零配置。** 新默认只用于无有效保存配键、恢复默认配键或恢复出厂的设备。原先已保存裸 F13～F24 的设备升级后仍按原配置上报裸键，但对应本地功能不再触发；APP 须先 GET 当前表和 revision，把需要使用的产品键条目改为 `07 <Usage> 00 00 00 00 00` 后整表 SET，保留其他自定义条目；也可由用户选择恢复默认（会重置全部五键）。因此仅升级固件不能保证已有配键自动变为组合。

本地音量正常调节及重启沿用原生记忆；整机恢复出厂恢复配置最大音量，单独恢复默认配键不重置音量。

## 8. 踩坑与长期约束

| 踩过的坑 | 必须保留的结论 |
|---|---|
| 把“有连接”“HID 就绪”“RDX 就绪”合成一个在线状态，导致本地功能被吞 | 分开判断 HID 上报、本地业务准入和录音选路，不恢复旧的三选一路由 |
| HID 失效或热配键清掉输入周期，F19 只开始不结束 | 本地动作所有权独立保留，沿旧快照收尾；停止责任不能随着 HID 队列一起丢弃 |
| 按实时连接状态启动录音，提示音期间接入 APP 就改变落盘属性 | 在业务受理点确定路线，执行阶段不重新猜测；本地录音接入 APP 不自动推流 |
| 只看“当前未录音”，误把待开始、初始化、暂停或停止保存当成空闲 | 区分待开始、活动和停止未完成；业务完成必须以对应流程确认，不能只看一个运行标志 |
| 旧会议录音协议没有请求 ID，松开后迟到的 START 可能重新开录 | F18 和 F19 均由设备直接发起，不再依赖旧会议握手；仍需按周期、会话代次和 token 隔离迟到请求，完成 worker 收尾后才能开始下一会话 |
| 旧 Up 或旧回调结束了 APP 后来开启的新录音 | 按压与录音均有自己的归属，旧周期只能结束自己的请求，不能停止后来会话 |
| 在线灵感停止轮询反复置忙，覆盖 worker 已完成的 READY，后续按键业务被拒绝 | 停止已成功提交后只等待完成确认，重复查询不得重新置忙；不能靠删掉忙保护或强行空闲掩盖问题 |
| 为加速 F19 直接缩短全局长按时间，连带改变快进快退和其他键值行为 | 复用稳定 Down 与配键快照，只给符合当前规则的 F19 组合增加私有本地启动；不改扫描时序，不伪造 SDK LONG |
| F19 松开清理使本地队列失效，八击 DUT 请求一同丢失 | 保留独立有界的工厂入口意图，仅在归属录音已清理且当前工厂门禁仍通过时进入；系统取消不能被当作普通清理继续补执行 |
| 把在线会议当作按住录音，混淆断连和灯效 | 业务类型与路线分开：F18 落盘开启时断连续录，关闭时纯推流且断连结束，但松开不结束；F19 在线仍为按住式纯推流 |
| 灯效曾实测约 200 ms，但本地源码与产物参数都是 2 秒 | 静态产物不能证明设备映像和实际仲裁时序；核对真实持续时间、到期及抢占证据，不凭参数猜根因。用户后来确认灯效恢复，不反推唯一根因 |

## 9. 范围与维护依据

当前方案限定为**单键输入**，不支持按住 F19 同时按 F18 标记，也不包含 HID 多键聚合。未连接自定义键提示音、多键能力及带请求 ID 的录音协议另行设计，不在本方案中扩展。

2026-10-24 曾将 F19 入口从 LONG 提前到稳定 Down，当时仍沿用会议 APP 握手；该历史握手已由 2026-11-04 的闪记协议替代。本轮切换不改变提示音设置和已锁定低功耗策略。

同日先接入“CDC 已在传输时启动在线 F19”，随后按自动传输需求补齐反向 CDC 准入，不扩展多键能力或普通 APP 写盘录音。`COM3_2026-10-24_17-41-14.log` 只支持旧版 CDC-first 启停和反向忙拒绝定位，下载被主动取消，不是完整共存验收。2026-10-26 用户结合 `COM3_2026-10-26_13-49-42.log` 确认基本共存；同次反馈 CDC 传输反复中断，按用户决定另行分析，本轮仅作为共存功能阶段提交。F18（包括在线 F18）与 CDC 的双向互斥不变。两种启动顺序的完整接收、CRC/独立内容、无新增录音文件/索引、音频连续性及断连/拔插交错仍须分别补齐，不由基本共存确认推定全部通过；证据和遗留问题见 [10-4 第 6.3 节](10-4.CDC通用文件传输业务方案.md)。

旧日志 `COM3_2026-10-24_10-21-01.log` 的无提示音两次样本，从已识别的长按受理到首个丢帧后处理点平均约 674 ms；普通 IO 配置还存在约 750 ms 的长按门槛，但旧日志没有实体按下时间点。因此不能把该门槛当作已实测的 APP 端收益。

新增 `[F19_DOWN] key/cycle/down_ms/wait_ms` 记录 app_core 处理本次 Down 的入口：`down_ms` 来自防抖后的稳定按下，`wait_ms` 是调度到该入口的等待，不保证录音已被业务门禁允许；后续 `[RDX_HOLD_RECORD] start request` 才表示现有录音开始请求已受理。`[F19_CANCEL] key/cycle/at_ms` 表示请求取消／停止，不是 worker 已完成清理。扫描回调不打印日志。本轮复用原音频日志，不增加逐帧日志；READY 不是 APP 实收、解码或界面出流的证明，后者需要 APP 侧时间戳。

2026-10-23 新增的正常录音提示音开关单独验收：设备端已实现并有主机行为覆盖，APP 联调及开关 A/B 实板验证尚未完成；此前基本业务的用户确认不包含本功能，不能据此宣称关闭提示音后的延迟、首字或音质已通过。

2026-11-05 用户确认首批 F18／F19 组合测试通过；本轮扩展到其余产品键后仍须回归：APP 读取并下发完整配键、确认应答及重启回读；验证各组合的真实 Down／Up、原有回放／音量／录音手势、F20～F24 反馈以及 HID／RDX 就绪和离线路由，确认裸键不触发相应本地功能。还需在目标 Windows／macOS 版本和会议软件上实测快捷键接收与冲突，增加修饰键不能保证各系统都支持或完全无冲突。
