# 10-4. CDC通用文件传输业务方案

更新日期：2026-10-09

定位：当前 CDC 文件业务的接入、维护和验收依据。

本文统一保存当前方案与历史经验：第 1～8 节用于接入和维护，附录 A 保存调试过程、实测证据及决策。历史采用摘要归档，合并重复实施步骤，不删除关键收益、失败记录或撤回原因；历史阶段的待办不自动代表当前缺口。

## 1. 当前能力与范围

CDC 是通用 USB 通道，产测和文件传输是其不同业务。正常开机时枚举不依赖 DUT、BLE 连接或 SD 健康，但仍受 USB 角色、配置、主机连接及关机状态约束。

| 项目 | 当前状态 |
|---|---|
| 真实录音 | 已支持 LIST 读取现有索引、GET 下载已保存录音、CANCEL 取消 |
| 主机工具 | 菜单选文件、单次下载、同文件重复下载、长度/CRC 校验、报告及可选独立 RAW 对照 |
| 数据通路 | 独立读取 worker、两个 4096 字节缓冲、CDF1 二进制连续流 |
| 性能 | 历史内存源十轮平均约 720 KB/s；首轮真实录音十轮平均 636.36 KB/s，用户确认满足需求 |
| 冲突保护 | 公共存储准入、双向冲突检查、异步清理和隔离已接入；部分实机冲突已获用户反馈 |
| 内存测速 | 开发专用，默认编译关闭；不影响真实文件服务和高速发送路径 |
| 尚未支持 | 断点续传、自动断线恢复、BLE↔CDC 下载进度接力、上传及通用文件删除 |
| 验收边界 | 独立源内容对照、至少 10 MB 真实文件基准及完整异常/冲突矩阵尚未全部关闭 |

连接 CDC 后可直接发送文件命令，无需 BLE 登录、绑定、DUT 或额外解锁。应用登录不等于设备端鉴权：直接串口仍可访问开放命令，这是当前接受的产品边界，不以新增鉴权阻塞接入。

保留文件身份、格式、长度、存储互斥及关机保护；不允许主机任意路径读取。不新增索引系统，不改变既有产测录音的归属及大小限制。

## 2. 架构与 BLE 复用边界

### 2.1 模块职责

| 模块 | 职责 |
|---|---|
| `cdc.c` | USB 端点、DMA 和非阻塞提交；文件流 IN IRQ 每次最多续交一包 |
| `usb_factory_cdc.c/h` | 有界发送队列、背压、代次隔离、超时和低水位补货；沿用原文件名 |
| `rdx_factory_cdc.c` | 通用文本解析、来源日志、任务唤醒；产测命令复用 DUT，file 命令独立准入 |
| `rdx_cdc_file.c/h` | CAPS/LIST/GET/BENCH/CANCEL、CDF1、CRC 和事务收尾 |
| `rdx_cdc_source.c/h` | `cdc_reader` 任务、私有只读句柄、双缓冲、异步打开/读取/关闭及隔离 |
| `rdx_record_format.c` 与 RDX 库补丁 | DAT/MTA/RAW 校验、下载占用、公共在途计数和索引缓存交接 |
| `CDC-test.bat` | 单文件交付：接收器、菜单、校验、RAW/Opus 保存和测试报告 |

USB 层独占端点 I/O；控制任务处理协议和超时；worker 执行阻塞文件 I/O。不在 IRQ 读盘、扫描 CRC 或格式化日志，不绕过统一队列直接发送。

### 2.2 与 BLE 相同和不同的部分

准确定位是：**同一套录音文件体系，两套下载传输实现。**

| 项目 | BLE | CDC |
|---|---|---|
| 列表命令 | `*APP#getlist#`、`*APP#listreq#...` | `*APP#file#list#` |
| 下载命令 | `*APP#opusfile#...`，请求业务包号 | `*APP#file#get#<sn>#<name>#` |
| 调度 | 原有逐块请求/响应 | 一次 GET，连续二进制发送 |
| 封装 | 原 BLE 文件业务报文 | CDF1 DATA/END/ERROR |
| 文件上下文 | 原 BLE 读取状态、游标和缓存 | 私有句柄、读取位置及双缓冲 |
| 生命周期 | BLE 下载与连接清理机制 | CDC 取消、generation 隔离及独立关闭 |

共用的是 DAT 索引、MTA 元数据、RAW 录音、SN/名称/格式规则，以及文件系统和存储生命周期。`rdx_record_format.c` 复用已有校验辅助函数，并新增通用索引身份校验和下载打开入口；不是直接调用 BLE 完整下载状态机。

LIST、真实 GET 和内存 BENCH 共用 CDC 帧发送器；LIST/GET 另共用读取 worker 和存储占用。BENCH 不读盘。

不增加仅为外观一致的 BLE 命令别名，不把 CDC 改为逐块请求。产测命令已统一，不代表通用文件协议也已统一。仅在实际出现重复业务规则时抽取公共能力，不共享传输句柄、游标或会话。

BLE 能按非零业务包号请求，不等于 CDC 已具备断点续传；同一文件体系也不能替代两端有效 RAW 内容的独立对照。

## 3. 命令与线协议

### 3.1 文本命令

请求和文本应答为 ASCII，末尾必须添加实际 CRLF。`APP` 表示上位机，来源由日志及会话单独区分。数字使用无符号十进制，文件名必须通过现有合法性校验，不接受路径、分隔符或超长输入。

| 命令 | 作用 |
|---|---|
| `*APP#file#caps#` | 查询能力，不切换模式 |
| `*APP#file#list#` | 通过 CDF1 发送现有 DAT 的 UTF-8 JSON 数组 |
| `*APP#file#get#<sn>#<name>#` | 下载指定已保存文件，从偏移 0 开始 |
| `*APP#file#cancel#<transfer_id>#` | 取消对应事务 |
| `*APP#file#bench#<size>#<block>#` | 仅 BENCH 编译门控开启时可用 |

| 应答 | 含义 |
|---|---|
| `*DEV#file#caps#1#8192#16777216#<state>#` | 版本、最大 DATA 负载、最大文件长度、状态 |
| `*DEV#file#accepted#<transfer_id>#1#` | 事务受理，文本行 CRLF 后开始按二进制流解析 |
| `*DEV#file#error#<code>#` | 文本阶段拒绝，不进入二进制流 |

状态包括 IDLE、OPENING、STREAMING、CLOSING、QUARANTINED。受理不代表打开或下载成功；受理后的打开错误通过二进制 ERROR 终止。

LIST 结束即释放占用，用户选择期间不持锁；GET 重新校验当前文件身份。无需 OPEN/START 或 FINISH 握手。GET 不接受偏移或块长参数，当前读取块为 4096 字节。

### 3.2 CDF1 二进制格式

多字节整数均小端，不直接发送 C 结构体。每帧为固定 20 字节头、负载、4 字节帧 CRC，最大整帧 8216 字节。

| 字段 | 长度/约定 |
|---|---|
| magic | 4 字节，ASCII `CDF1`，即 `43 44 46 31` |
| version | u8，固定 1 |
| type | u8，DATA=1、END=2、ERROR=3 |
| header_length | u16，固定 20 |
| transfer_id | u32，非零，与当前 generation 绑定 |
| offset | u32，有效数据偏移，从 0 连续累计 |
| payload_length | u32，随后负载字节数 |
| payload | DATA 为 1～8192 字节原始数据；END/ERROR 见下表 |
| frame_crc | u32，覆盖完整帧头及负载，不含自身 |

| 类型 | 负载及偏移 |
|---|---|
| DATA | 原始有效字节，不做十六进制、Base64 或转码 |
| END | `total_size:u32 + file_crc:u32`；offset 等于总有效长度 |
| ERROR | `code:u32`；offset 为此前完整保留 DATA 的累计长度 |

CRC 使用 CRC-32/ISO-HDLC：poly=0x04C11DB7、refin/refout=true、init=0xFFFFFFFF、xorout=0xFFFFFFFF。文件 CRC 覆盖顺序原始字节，不能相加分块 CRC。校验参考：空内容为 0x00000000，ASCII `123456789` 为 0xCBF43926。

文件上限 16,777,216 字节，零长度拒绝。BENCH 的 size 为 1～16,777,216，block 仅 1024/2048/4096/8192；模式字节为 `offset & 0xFF`，尾块可更短。

错误码：1 BAD_REQUEST；2 BUSY；3 NOT_FOUND；4 INVALID_FILE；5 IO_ERROR；6 CANCELLED；7 TIMEOUT；8 UNAVAILABLE；9 BAD_TRANSFER_ID。

transfer_id 在设备运行期间单调分配、跨连接不重用，耗尽后拒绝新事务；重启后上位机必须清空旧会话。当前 offset 用于连续性校验，**不是断点续传入口**。

### 3.3 流边界和取消

- accepted 与二进制帧共用有序发送器，可能在同一次主机 read 中到达；按 CRLF 分界，不按 read 边界分帧。
- 受理前排空旧应答；旧产测实时流或文件业务活动时拒绝新下载，不交错两种输出。
- 直到 END/ERROR 前，设备只输出当前二进制流；下载中仅处理有效 CANCEL，其余命令延后拒绝，不插入文本。控制积压有界，超额导致会话失败。
- 队列满只暂停续交，不重发已提交分片。未提交帧和预读数据可丢弃；部分提交帧必须补齐 CRC，已入队帧按原序发送，然后才发送 ERROR(CANCELLED)。
- 重复有效 CANCEL 幂等；错误 ID 不取消其他事务，按流边界延后回复 BAD_TRANSFER_ID。
- 无法补齐半帧时使会话失效，不在残帧后恢复文本。断线按原生生命周期清理旧队列/DMA，禁止搜索魔数自动重同步。

## 4. 文件身份与资源生命周期

### 4.1 只读打开规则

通用 GET 支持现有校验路径中的 `RECORD_FORMATE_OPUS_16K_MONO` 已保存录音，不转码、不添加音频封装，也不把 DAT/MTA 当作 RAW 内容发送。

1. 先取得公共下载占用，再从有效 DAT 校验 SN/名称。
2. 结合名称、start、格式、元数据及首帧指纹校验 MTA/RAW，固定本事务有效长度。
3. 索引恢复可能重新分配 SN，通用 GET 不机械要求 MTA SN 等于当前 DAT SN；产测仍保留本轮 SN/start 的严格规则。
4. MTA `ready=1` 仅代表指纹已持久化，不代表录音已结束；还需录音收尾、索引交接和公共准入确认。
5. 按已核实的 RAW 有效范围顺序读取；未知格式、身份不匹配、提前 EOF 和读取错误明确失败，绝不回退到“最新文件”。

已审核录音写入器直接写 RAW，BLE 读取按请求 offset 定位并原样复制有效内容；完整下载对应 RAW `[0, 固定长度)`，不含 BLE 封装。接入过程见附录 A.6。两媒介导出内容仍需以独立 RAW 比对，不能仅由相同文件名或重复下载相同 SHA-256 推导内容正确。

### 4.2 所有权与超时

文件资源独立于协议 generation。串口重连不能通过清空协议上下文丢掉仍在执行的句柄、缓冲和占用。

| 对象 | 释放规则 |
|---|---|
| 文件句柄 | worker 串行打开/读/关闭；控制任务只请求停止，不并发 fclose |
| 双缓冲 | 读操作返回且消费者不再引用后才复用 |
| 公共占用 | 文件及相关资源确认关闭后，由匹配事务释放一次 |
| 迟到结果 | 旧打开仅用于关闭，旧读结果丢弃，不进入新流 |
| USB 队列/DMA | 沿用原生传输清理，不提前覆盖或释放在途内存 |

正常流程为 IDLE → OPENING → STREAMING → CLOSING → IDLE；关闭失败或资源归属未确认时保持 QUARANTINED。正常关闭后才发送 END，终止帧发送完成前不接纳下一事务。

| 超时 | 当前预算/处理 |
|---|---|
| 底层发送无进展 | 2 秒；失败并清理传输会话 |
| 源打开 | 8 秒；晚到句柄仅关闭 |
| 单次读取/关闭 | 各 3 秒；停止生产，等待在途调用退出，必要时隔离 |
| 整个事务 | 110 秒，不因局部进展无限延长 |
| 主机 | 读取 5 秒、打开 10 秒、总时限 120 秒 |

超时不能强制打断同步文件系统调用。重新打开串口不解除未清理的占用；资源未归还时不得假装 IDLE。OFF 不等待主机确认，也不被下载锁否决，保留原生关机和复位兜底。

普通拒绝或完整 ERROR 且资源已释放后可重新 GET；半帧/发送超时则废弃临时文件、重开串口并确认 CAPS 就绪。当前失败后重新完整下载，不承诺暂停或断线续传。

## 5. 跨业务冲突与静态库补丁

### 5.1 冲突策略

**连接可共存，冲突资源串行，以实际取得资源为准；后来请求失败，不抢占、不排队。**

| 场景 | 规则 |
|---|---|
| BLE 文件下载/列表、录音开始或恢复 | 与 CDC 文件事务双向互斥 |
| 播放/恢复播放、删除、格式化、索引操作 | 通过公共准入协调，不在活动下载中修改或抢占存储 |
| DUT/产测文件、包装、可选 MSC | 沿用共享资源保护，不中途切换所有权 |
| OTA、恢复默认设置 | 真正执行前检查；冲突不启动升级、不写默认配置或安排重启 |
| 第二个 CDC LIST/GET | 不覆盖现有事务；LIST 结束与 GET 之间重新准入 |
| BLE/HID 连接及电量/版本查询 | 不因下载全局禁用；首次连接/重连的全部时序仍待验证 |
| 取消、停止、清理、物理 OFF | 保持可达，不能用全局 BUSY 阻止释放或关机 |

`rdx_record_format_download_acquire()` 与 `rdx_record_format_io_enter()/leave()` 协调下载占用和在途调用。CDC 取得占用后复查外部业务，发现迟到冲突立即归还；异步列表和 OTA 真正执行时再次准入，避免“入口检查通过、执行时已冲突”。

BLE 沿用既有失败/停止/状态回复，不是所有命令都返回字面 BUSY。应用不可将拒绝当作真实空列表或自动无限重试。取消受理、终止帧入队和资源释放不是同一时刻，切换业务不要靠固定延时猜测。

### 5.2 为什么需要修改 RDX 补丁库

部分 BLE 协议和 UXFILE 入口位于预编译库，只改 CDC 源码无法完整保护反向冲突。因此补丁让原忙分支识别 CDC 占用，并保护协议在途窗口及异步列表准入；不新增 BLE 原始分片解析器，不修改 BLE 文件线上命令。

- 原始 `librdxApp.a` 保持不变；提交可重现补丁脚本及必需依赖 `librdxApp_patched.a`。
- `patch_librdxApp_protocol.ps1` 配合既有 UXFILE 补丁更新 `rdx_protocol.c.o`、`rdx_uxfile.c.o`，生成过程校验原库身份。
- 归档版本补丁库 SHA-256：`02DFC0E94C302CE481E50E82FB165220B5932CA3006B0C74873C156F39440D43`；后续改库需同步审计及测试，不将此值作为永不变化的协议约定。
- 这是存储安全改动，不是内存 BENCH 门控引入的依赖，也不是可随意排除的构建产物。

冲突日志使用 `[STORAGE_BUSY] owner=CDC_FILE request=...`。原库部分日志仍写 `Format in progress`，须结合上下文判断，不据此认定发生格式化。

## 6. 配置、工具与验证

### 6.1 配置与日志

配置位于 `SDK/apps/earphone/include/t2620_project_config.h`。

| 宏 | 当前配置 | 作用 |
|---|---|---|
| `TCFG_T2620_CDC_FILE_ENABLE` | 1 | 通用文件服务；旧 MVP 宏不再兼容 |
| `TCFG_T2620_CDC_FILE_BENCH_ENABLE` | 1 | 本轮统一回归临时开启；产品配置应恢复 0，开启要求 FILE=1 |
| `TCFG_T2620_CDC_TX_STATS_ENABLE` | 0 | 可选发送统计 |
| `TCFG_T2620_CDC_TX_TIMING_ENABLE` | 0 | 可选续交抽样，要求 STATS=1 |
| `TCFG_T2620_FACTORY_USB_CDC_LOG_LEVEL` | 1 | 命令、生命周期及传输摘要，禁止二进制负载日志 |

关闭 BENCH 不改变真实文件双缓冲、高速发送和 CANCEL。空闲时禁用的 bench 返回错误码 1；忙时仍遵守不插入文本规则。FILE=0 保留原产测路径。

`queued` 只代表终止帧入队，不代表主机收完；IRQ 抽样时间不代表总线包间隔或硬件中断响应延迟。关闭统计仍必须保留背压、低水位重武装和全部生命周期保护。

### 6.2 操作入口

运行 `CDC-test.bat`，进入菜单 3：

- 类型 1（默认）：真实录音下载；自动获取列表，只选择一次文件。
- 类型 2：内存测试；每轮 10 MB、4 KB 块，需开启 BENCH 并重新构建，用后恢复关闭。
- 两类均只提供 1「快速测试：1 轮」和 2「稳定性测试：10 轮」；q 返回上一级。
- 真实稳定性测试完整重复下载同一文件十次、分别保存并比较 SHA-256；不是断点续传。
- 真实下载保留两种文件：`.raw` 为设备原始 Opus 帧、用于长度/CRC/SHA-256 对照；同名 `.raw.opus` 为 Ogg Opus 试听文件，用于人工核对录音效果。全部下载轮次成功后，关闭串口再逐份封装，不重编码、不修改 RAW，也不把封装耗时计入下载速度。封装沿用已验证产测的单声道 40 字节/20 ms 帧参数，无需安装 ffmpeg；播放需支持 Ogg Opus 的播放器。取消或下载失败不触发试听导出，封装失败保留 RAW 并返回错误；报告单独记录试听路径、封装耗时或错误，下载完整性与人工听感分别验收。
- 结束汇总通过/失败/未开始轮数及完整校验通过轮次的平均、最低、最高速度。不足 10 MB 只验证完整性并展示速度，不作为性能失败；报告仍保留严格的 `passes_600KBps` 判定。
- 取消和 deferred 对照仅保留命令行诊断入口，不再占用日常菜单；普通产测和包装流程不变。

真实文件使用 inline 接收；deferred 仅供内存诊断。主机严格验证帧 CRC、ID、连续 offset、END 长度和文件 CRC，完成并关闭文件后才发布结果。错误保留诊断，不自动放宽检查。

## 7. 性能结论与历史经验

### 7.1 速率口径与波特率

600 KB/s 指 600,000 个文件有效字节/秒。内存源、真实文件端到端和固件发送统计不是同一口径，不能将瞬时峰值、入队字节或 BLE 固件侧耗时直接用于倍速结论。

**保持串口参数 115200 即可，调高不会提高当前 CDC 文件速度。** `cdc.c` 的 SET_LINE_CODING 仅保存/打印参数，数据走“串口 API → CDC 驱动 → USB Bulk 端点 → 固件”，不经过按该波特率发送的实体 UART，也不按 UART 起始/停止位传输。默认 `dwDTERate=460800` 同样不是链路上限。若将来做 CDC 转实体 UART 或主动按波特率限速，需重新评估。

真实文件还包含读盘、文件系统和缓冲交接开销，读盘与发送重叠；不能把累计 read_ms 直接加到 USB 耗时，也不能由真实速度认定 SD NAND 极限。内存约 720 KB/s 是历史实现能力，不是 CDC 理论上限。

### A.1 起点：先隔离 USB 与存储因素

BLE 对照 `COM3_2026-10-08_15-43-01.log`：1,403,120 字节，固件统计 15,127 ms，约 92.76 KB/s；普通业务块 24,480 字节，读缓存 49,152 字节。这不是 BLE 空口包长，也不包含主机最终落盘，不能与 CDC 端到端计时直接宣称正式倍速。

原 CDC 产测文件路径受本轮录音归属、40 KB 上限、80 字节十六进制分块及逐请求交互约束。通用业务没有简单放宽这些保护，而是独立构建二进制流，保留产测语义。

原驱动每次推进最多提交 64 字节、忙时依赖任务/定时推进，小队列和低频补货不能支撑 600 KB/s。预算要求每秒至少约 9375 个 64 字节有效包，尚不含协议开销。因此先验证内存源，再接真实文件，不将 SD 读盘混入 USB 瓶颈判断。

RAW 审核结论：录音按帧直接写文件，无该路径附加音频头；BLE 按 offset 读 RAW 并原样复制负载。mono 帧长 40 字节，底层能识别 stereo 80 字节不代表 CDC 已开放该格式。GET 合法名称为现有 3～6 位十六进制名加 `.raw`；LIST JSON 不受 RAW 的 40 字节对齐限制。

worker 配置栈参数 2048；当时下载打开路径报告静态栈帧 1052 字节，仍需实机关注峰值栈和重启，不能由构建成功推定充分余量。正常关机沿用有界收尾与 reset 回退，不强制释放尚在 I/O 中的资源。
