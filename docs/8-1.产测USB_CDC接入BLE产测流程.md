## 1. 复评结论

保留已实现的 CDC 字节层，扩展现有 DUT 服务，按真实 APP 流程补齐功能。旧方案主要有四处缺口：遗漏喇叭/按键测试；没有录音取回协议；把包装完成误写为自动关机；把 CDC 连接资格与 DUT 状态绑定，导致退出后无法取文件、查询结果。

本次流程是：设备连接及信息查询 → 进入 DUT → LED → 喇叭 → 按键布局/测试阶段 → 普通录音及保存 → 退出 DUT → 下载录音 → 断开重连 → 再进入 DUT → 整包结束 → 红灯常亮 → 后续断连及关机。日志证明这些请求和部分执行结果，不包含 APP 全部判定，不能直接视为五键、音质和所有产测项均通过。

新的目标流程允许工站先连接 CDC、读取信息，再进入 DUT 做测试；正常退出 DUT 后保留 CDC，继续取录音文件和查询结果。插线只建立通信，不自动启动测试。用户已确认允许工厂 APP 通过 CDC 命令进入 DUT，无需先按实体键；见第 2.3 节。

**解除 DUT 门控解决了连接生命周期问题，并未自动补出音频传输能力。** 原文本 v1 只有控制和查询；实时流回放与文件下载的完整设计已拆至 [8-5.CDC录音测试与文件下载测试实施方案.md](8-5.CDC录音测试与文件下载测试实施方案.md)。控制接入可以先验收；纯 USB 音频测试必须分别完成实时流和保存文件的校验、回放与判定，不能用 BLE 下载代替 CDC 验收。

SPP MIC 频响不作为此次已验证的主流程。日志只见 SPP 初始化，没有 MIC 命令或频响结果；普通录音不等于 SPP MIC。确实使用该功能时再纳入资源互斥及板测，不将“三通道全部通过”作为 LED/喇叭/按键接入的统一前置关口。

### 2.3 新准入模型：连接独立于 DUT

以下为目标边界；本轮先实现通信生命周期部分，业务接入进度见第 10 节：

| 状态 | CDC 通信 | 业务准入 |
|---|---|---|
| ON、系统/USB 就绪，未进入 DUT | 允许枚举、连接、查询 | 不因插线启动产测；新测试动作仍需 DUT |
| DUT 活动中 | 保持同一会话 | 灯、喇叭、按键、录音等统一仲裁 |
| 正常退出 DUT | 保持 CDC，generation 不因退出而变化 | 查询及满足存储条件的文件读取；禁止新的 DUT 测试 |
| SD 未就绪/格式化失败 | USB 本身正常时保留通信 | 查询错误；文件/录音/格式化分别判断，不能因有串口就绕过存储保护 |
| 整包成功待 OFF | 保持 CDC 可查结果 | 禁止新测试、重复包装及恢复被重置的数据 |
| 拔线、总线复位、USB 类释放 | 会话失效，新连接使用新 generation | 旧请求/响应不重放，已接纳动作按自身规则收尾 |
| DIP OFF/关机 | 关闭 CDC，服从正常关机及独立 3 秒保护 | 不等待工站；OFF 冷服务是否 MSC 取决于 PC_STORAGE 配置及 USB 条件 |

保留现有 USB 类切换所有权，不因解除 DUT 门控同时实现 CDC+MSC 复合设备。ON 正常模式可能持续存在 CDC，应验证低功耗/充电、蓝牙和 Windows 驱动表现；产品是否启用 CDC 仍由编译配置决定。

**进入 DUT 策略已确认：** 允许工厂 APP 用 CDC `DUT ft_dut 1` 显式进入，无需实体键先行授权，实体键入口保留；插线仅建立通信，不自动进入 DUT 或启动测试。进入请求仍检查初始化、关机、录音/存储/OTA 占用及故障状态；已经进入时幂等成功，不翻转模式。包装后的“禁用按键进入”标记仍只约束按键，不可未经定义扩展为禁用所有工站入口；包装完成的本次锁定仍优先于进入请求。

`task_pc.c` 应使用传输就绪条件，DUT 层只管理测试准入；从传输门控移除实体键、DUT 和 SD 健康的强依赖，保留 USB 角色、端点资源、模式切换和关机检查。退出 DUT 不再触发 `rdx_dut_factory_usb_revoke()` 意义上的端口销毁；业务令牌和测试占用仍须安全清理。

该模型替代旧版“OFF 等待 DUT 退出再关 CDC”和“只在厂测失败时开放受限重连”的特殊设计。ON 可查询并不代表所有故障都可恢复；底层存储要求重启时仍报告并转维修。8-0 已同步新通信边界；实现时仍需修改固件及相关契约测试，不能继续保留旧门控。

## 3. 文本协议 v1

本节保留 CDC 文本封装草案，不另建一套 BLE 测试业务实现；模式准入以本文第 2.3 节最新决定为准。8-0 已同步新通信边界，其字节传输和队列规则继续复用；旧门控固件的验收记录仅作历史。

### 3.1 帧与请求顺序

- ASCII，CRLF（`\r\n`）结尾；请求正文 ≤128 字节，响应正文 ≤256 字节。
- 命令关键字与 DUT 名称不区分大小写，参数严格匹配；输出大小写固定。
- DUT 请求使用单个 ASCII 空格分隔，不接受额外字段、前后空白、符号整数或 `atoi()` 式前缀解析。
- `;` 与 `=` 仅用于响应字段；字段值不得包含 `;`、`=`、CR、LF 或其他控制字符。
- 空行、非 ASCII、非法控制字符、裸 LF、孤立 CR 和非法语法返回 `ERR CMD`；超长行返回 `ERR ARG`。非法帧整体拒绝，具体丢弃与恢复规则如下，不能从错误位置之后重新尝试匹配命令。
- 客户端采用一问一答，不流水发送。设备仍须按到达顺序处理同包多行，并在每条 DUT 的准入结果确定后再处理下一条，不能二次异步入队导致后继检查旧状态。
- 每个有效请求最多一条响应；断线或传输故障允许响应不可达，不能据此推断命令未执行。

分帧器仅在完整 CRLF 到达后校验并提交正常帧。CR 暂存为结束符候选，不计入正文；其后不是 LF 即判为孤立 CR。正文只接受 `0x20–0x7E`；出现其他字节、裸 LF、孤立 CR，或正文出现第 129 字节时，锁定该帧的首个错误并进入丢弃状态。丢弃状态不保存正文、不解析任何命令，一直消费到下一完整 CRLF（可跨 USB 包）；裸 LF 本身不作为恢复边界。若同一字节同时触发非法字符和超长，优先 ERR CMD；进入丢弃后不改变错误码。

错误响应在消费到完整 CRLF 后仅发送一次，然后开始接收下一帧；空行及完整但语法非法的帧也只响应一次。丢弃期间没有 CRLF 时保持有界内存且不产生重复错误响应，会话失效则清除该状态。客户端遇到无响应按超时恢复会话，不自动补发原动作。错误响应仍受[8-0.厂测USB通信协议设计](8-0.厂测USB通信协议设计.md) 第 5.2 节队列与背压规则约束。

| 输入字节流（转义表示实际字节） | 结果 |
|---|---|
| `\x80DUT ft_format 1\r\nPING\r\n` | 一条 ERR CMD，再一条 OK PONG；格式化不执行 |
| `PING\nDUT ft_format 1\r\nPING\r\n` | 裸 LF 后持续丢弃到首个 CRLF；仅 ERR CMD、OK PONG |
| `PING\rDUT ft_format 1\r\n` | 孤立 CR 使整帧非法；仅 ERR CMD，格式化不执行 |
| 129 个 `A` 后接 `DUT ft_format 1\r\nPING\r\n` | 仅 ERR ARG、OK PONG；丢弃期间不解析 DUT |

### 3.2 命令与响应

```text
PING\r\n
-> OK PONG\r\n

GET_INFO\r\n
-> OK PROTO=1;NAME=<名称>;AUTH=<24字符>;ADDR=<12位HEX>;FW=<产品版本>\r\n

GET_STATUS\r\n
-> OK DUT=<0|1>;ACTIVE=<动作>;LAST_ID=<编号>;LAST_CMD=<命令>;LAST_STATE=<状态>;LAST_ERR=<原因>\r\n

DUT <name> <value>\r\n
-> OK ID=<编号>;STATE=<DONE|RUNNING>\r\n
-> ERR <code>\r\n
```

GET_STATUS 在有效 CDC 会话中可用，不改变业务；进入 DUT 前、正常退出 DUT 后及存储业务故障时仍允许查询。CDC 不再绑定 DUT，具体准入见第 2.3 节。`ACTIVE` 为 `NONE/OLED/MOTOR/KEY/SPEAKER/REC/REC_CALL/MIC/WIFI/FORMAT/FINALPACK`；`LAST_CMD` 为第 4.1 节的规范动作名称或 `NONE`（包含仅 BLE 支持的动作）；`LAST_STATE` 为 `NONE/RUNNING/DONE/FAILED`；`LAST_ERR` 为 `NONE/STATE/BUSY/IO/UNSUPPORTED`。无历史时 ID 为 0，其余历史字段为 NONE。MIC 若后续纳入，是外部资源占用，不分配 DUT ID；本次日志未验证此通道。

成功接纳的 DUT 请求分配本次启动内单调递增的非零 u32 ID，重连保留、复位清零；耗尽时拒绝新动作。它用于状态关联，不是跨重启幂等令牌。`DONE` 表示软件动作或设置完成，不代表马达、LED、录音等物理测试通过。

USB、BLE 与物理按键共用同一 ID 序列和 LAST 记录：每条经公共接口成功接纳的动作（包括幂等设置）都更新记录，拒绝及只读查询不更新。非 USB 入口须先按第 4.1 节归一化，不能因 CDC 未开放同名命令而绕过记录；异步完成只能更新仍匹配自身 ID 的记录。所有入口在 app_core 串行仲裁，RUNNING 期间均禁止接纳新的修改动作；一般终态后其他入口可以提交新动作并覆盖 LAST；包装成功待 OFF 和未解除的故障/资源隔离除外。v1 不提供 USB 独占控制权，也不保留可按 ID 检索的历史。ID 耗尽返回 ERR STATE，不回绕复用；系统必要的资源清理与关机保护不依赖分配新 ID。

工站仅在收到接受响应、持续保持同一有效会话，且 GET_STATUS 的 LAST_ID 与已收到的 ID 相同时，将该状态认定为自身请求的结果。ID 不同表示记录已被覆盖，不能用 LAST_CMD 相同推断成功。接受响应丢失、会话失效、串口关闭重开或工站进程重启后，未确认结果一律标记为“结果未知”；重连 GET_STATUS 仅用于判断设备当前状态及安排恢复，不自动将其归属到旧请求。v1 不提供启动标识，不能凭重连后的同 ID、同命令或 ID 为 0 证明启动连续性或原动作未执行。此前已经确认的终态记录可保留，但不得据此推断掉电后的物理状态。

长动作返回 RUNNING，客户端轮询 GET_STATUS 至 DONE/FAILED。RUNNING 期间只允许只读查询，新的 DUT 请求返回 ERR BUSY，不能覆盖该记录。持续亮灯、马达循环和已启动录音通过 ACTIVE 表示，其启动设置完成后请求可为 DONE，因此随后仍可提交停止/退出命令。终态保留到下一条 DUT 请求成功接纳。v1 不发送自发 EVT；按键结果使用第 4.2 节的累计状态查询。该约束仅针对 CDC，BLE 保留 ft_key_event 和既有录音上报。

### 3.3 错误码

| 错误码 | 含义 |
|---|---|
| CMD | 未知命令或语法非法 |
| ARG | 参数不在允许集合、请求超长 |
| BUSY | 当前动作/业务占用，或能够回复时的容量不足；请求未执行 |
| STATE | 未进入 DUT、存储/USB 切换状态不允许、身份未就绪 |
| DATA | 身份字段非法或超出协议范围 |
| UNSUPPORTED | 当前产品未编译对应测试功能 |
| IO | 操作提交、持久化或即时执行失败 |

异步完成失败通过 LAST_STATE/LAST_ERR 返回，不补发第二条请求响应。接受响应丢失时不得自动重发格式化、整包结束或关机；按第 3.2 节标记结果未知，并在传输恢复后查询当前状态。复位后历史不可恢复时同样报告结果未知，重新进行人工或工站流程判定；轮询超时不表示动作已取消，不解除设备的 RUNNING 保护。

### 3.4 GET_INFO 字段

| 字段 | 来源与约束 | 异常处理 |
|---|---|---|
| PROTO | 固定 `1` | 协议不兼容时客户端拒绝继续 |
| NAME | `rdx_ble_server_get_local_name()`，1–24 字节安全可打印 ASCII | VM 无名可使用现有默认名；非法字符/超长 ERR DATA，不静默截断 |
| AUTH | `rdx_vm_get_auth_info()->AuthKey`，恰好 24 字符，`[0-9A-Za-z]` | 初始化完成且全零返回 24 个字符 `0`，测试站判未烧录；部分无效 ERR DATA |
| ADDR | `le_controller_get_mac()`，12 大写 HEX，顺序 `[5][4][3][2][1][0]` | 控制器未初始化 ERR STATE；无效值 ERR DATA |
| FW | 当前产品分支的 `FIRMWARE_VERSION`，1–32 字节安全可打印 ASCII | 与产品上报版本保持同源，非法/超长 ERR DATA |

初始化未完成与“初始化完成但未烧录”必须区分。不得对定长 AuthKey 无界 `strlen/%s`；字段输出前检查长度和字符。FW 不使用 `sdk_version_info_get()`：该函数返回 SDK 链接段版本串，无产品版本或 32 字节保证。当前 GET_INFO 最大正文为 123 字节，含 CRLF 为 125 字节。

ADDR 与 `rdx_app_earphone_get_dev_base_info()` 的 `ble_mac_str` 保持同序；VM 烧录地址初始化会调用 `le_controller_set_mac()`。测试站将运行时地址与烧录记录比较，不一致判失败；设备仅返回一个地址并不能自行证明烧录一致。

USB 协议 v1 无额外鉴权；本轮决定允许 ON 正常模式连接和查询，并允许显式命令进入 DUT，不再以实体键资格作为访问前提。当前内部调试继续保留 `rdx_vm.c` 已有身份及 AUTH 日志，不将删除调试日志作为阶段 3 开发前置条件。正式工站仅在内存中校验 AUTH，不打印或持久化；正式交付前确认固件调试配置并关闭含 AUTH 的输出，检查 GET_INFO 收发日志。内部调试包与正式交付包分别记录日志配置。

### 3.5 app_core 消费、响应预留与会话失效

阶段 2 的 `factory_cdc_send()` 只提供完整复制入队或拒绝，没有应答预留接口。阶段 3 在协议层持有一个固定的 258 字节待发送响应槽；它是动作执行前的容量保证，不将“查询 TX 是否空闲”当成预留。协议消费者是正式 CDC 响应的唯一生产者，TEST 必须为 0；正式协议构建禁止内容日志等级 2，避免 AUTH 经底层包预览泄露。

1. USB RX 回调只把带 generation 的整个包复制到固定容量邮箱，成功接管后返回 0。邮箱满时不复制、不产生任何业务副作用并返回拒收，由传输层重投同一包；禁止部分接管后拒收。邮箱容量、包长上限与 RAM 占用在实现中固定并记录。
2. app_core 按包顺序消费，每轮限定字节/命令预算。完整帧先校验会话、语法和模式；执行任何 DUT 动作前独占响应槽。槽已占用时保留当前包及偏移，暂停后续命令，通过邮箱满向 USB 传播背压，不继续执行同包下一行。
3. 公共接口完成准入、资源预留及 ID 分配后，立即生成完整接受响应或拒绝响应。`factory_cdc_send()` 返回 FULL 时保留原响应，后续有界调度重试；返回 OK 才释放协议槽并继续下一条。错误帧响应使用同一槽和顺序，不允许错误流抢占已接受动作的应答。
4. 协议槽、RX 邮箱、半帧及通知均携带 generation。消费及提交动作前重查；会话失效时清理旧待处理数据，不向新会话补发。动作接纳是分界：此前失效不执行，此后失效不撤销已接受动作，动作依靠自身 ID 安全收尾。跨任务检查与接纳的同步必须明确该分界，不把一次过早的 generation 快照当成永久授权。
5. 使用非阻塞的合并通知及周期补偿推进消费与发送；通知入队失败不能遗失邮箱内容或永久停住。协议层发送等待采用有界截止时间，超时停止消费并请求传输层会话失效；若当前公开接口不足，补充异步失效请求，由 usb_stack 释放资源。不得从 app_core 同步等待 USB，也不得从 USB 回调等待 app_core。

正常退出 DUT 和整包结束成功不关闭 CDC。独立关机路径先形成响应，给非阻塞发送留下有界机会，再停止 CDC；达到配置上限继续安全清理，不以主机收包作为前提。DIP OFF 走平台关机保护，不等待工站确认。

## 4. 业务映射与全流程缺项（待实施）

### 4.1 动作集合

CDC 文本使用严格参数；BLE 保留既有空参数和别名兼容，不能将 CDC 语法强加给原 APP。

| CDC 请求 | BLE 对应 | 公共动作语义 |
|---|---|---|
| `DUT ft_dut 1/0` | ft_dut 1/0 | 1 显式进入 DUT，无需实体键；0 安全退出但保留 CDC。均按目标状态幂等执行 |
| `DUT ft_oled 1/0` | ft_led_cycle / ft_oled | LED；保留 BLE 响应名称 ft_led_cycle |
| `DUT ft_speaker 1/0` | ft_speaker 1/0 | 实际 PLAYING 后确认启动，停止回收后释放资源 |
| `DUT ft_key_layout 1` | ft_key_layout 空值或 1 | 开启按键捕获、分配 ID、持有 KEY 资源，不当只读查询 |
| `DUT ft_key 0` | ft_key 0 | 停止捕获并隔离旧事件；结果保留供查询 |
| 录音控制草案，见 8-5 | ft_rec_chat / ft_rec | 实时流与本地保存、开始/停止及结果关联由 8-5 定义；当前 CDC 未开放 |
| `DUT ft_format 1` | ft_format | 等待格式化和存储恢复结果；与录音、下载、MSC 等互斥 |
| `DUT ft_finalpack_end 0` | ft_finalpack_end 空参数 | 格式化→重置/解绑→禁用按键回读→红灯常亮，等待 OFF |
| `DUT ft_poweroff 1` | ft_poweroff | 独立关机；与包装完成区分，有限发送机会后正常关机 |
| `DUT ft_key_dut_enable 1` | ft_key_dut_enable | 显式恢复按键使能并回读；0 返回 ARG，不绕过包装完成锁定 |
| `DUT ft_motor 1/0`、`DUT ft_wifi 1/0` | ft_vibrate/ft_motor、ft_wifi | 非本次主流程；未编译支持返回 UNSUPPORTED |
| 首期 CDC 暂不开放 | ft_rec_call、ft_key_dut_disabled | BLE 仍保留通话录音/独立禁用，纳入公共准入及结果记录 |

LAST_CMD 采用表内规范名；仅 BLE 支持的动作保留自身名称。持续测试启动可 DONE，但 ACTIVE 保持占用；启动/停止过渡为 RUNNING。包装成功 LAST=DONE、ACTIVE=FINALPACK，保持锁定至 OFF，不能因 DONE 开放下一项。

CDC 工站显式停止按键再录音；BLE 适配保留现有“KEY→下一项旧测试”自动清理，因为日志没有 ft_key 0。只能释放 KEY，不能跳过 SPEAKER/REC 的停止屏障。按键测试期间保留现有物理按键/HOGP 截获与迟到事件隔离。

### 4.2 按键结果：CDC 轮询，BLE 保留事件

原文本 v1 没有按键结果通道。建议新增只读 `GET_KEY_STATUS`，保持 CDC 一问一答，无需引入异步 EVT：

```text
DUT ft_key_layout 1
-> OK ID=12;STATE=DONE
GET_KEY_STATUS
-> OK TEST_ID=12;LAYOUT=A,B&C,D&E;SEEN=00011;ACTIVE=1
DUT ft_key 0
-> OK ID=13;STATE=DONE
```

示例省略 CRLF；SEEN 按 A→E 顺序，1 为本轮观察到去抖按下，示例是 D/E。布局复用源码表，不在 CDC 复制另一份硬件映射。

- TEST_ID 关联开始动作，与 LAST_ID 分离；停止会更新 LAST，但不毁掉本轮结果。无历史时 TEST_ID=0、LAYOUT=NONE、SEEN=00000、ACTIVE=0。
- 新接纳的布局动作清空累计位；旧事件带实例/来源令牌，不能写进新一轮。事件投递失败须使本次结果不可判为通过，不能静默丢失。
- 停止/退出 DUT 后可查本轮结果；CDC 会话失效后，旧工站仍按“结果未知”处理，不凭相同 TEST_ID 认领重连结果。
- BLE 继续发送 `ft_key_layout` 布局和 `ft_key_event` A..E 至原 token；CDC 测试不能把事件发给其他 BLE owner。
- 全 1 只证明五键被观察到；释放、电气指标或严格次序若是工站要求，另增计数/事件能力，不从位图推断。

### 4.3 补充信息与录音专项入口

GET_INFO 之外，日志还有 battery、mem 及硬件/协议版本需求。拟增加 `GET_TEST_INFO`，字段需与 APP 界面冻结：电量/充电、存储就绪、容量/剩余空间和必要版本信息；单位、无效值及工站阈值必须明确，不能把厂商内存数字未经确认当字节。该命令尚未定稿/实现。

录音授权、UTC 校时、实时音频流、保存结果查询、文件选择与分块下载、完整性校验及两次回放，已迁至 [8-5.CDC录音测试与文件下载测试实施方案.md](8-5.CDC录音测试与文件下载测试实施方案.md)。原“CDC 默认仅本地保存”的设想由该专题的“CDC 实时流＋本地保存”目标替代。

本文件只保留公共 DUT 仲裁和流程衔接：五键显式停止后进入录音；停止保存和资源清理完成后退出 DUT，保持 CDC 进入文件阶段。录音及下载均通过后，才具备进入独立包装工位的音频前提；不能以文本控制通过代替音频验收。

## 5. 整包结束与退出兼容

当前源码及新日志一致：**格式化成功 → 参数重置/解绑 → 最后写入并回读按键禁用 → 红灯常亮，等待 DIP OFF**。旧版“先重置再格式化”“回调不检查 result”“成功即自动断开关机”作废。

一次整包只有一个动作 ID。接纳前检查录音启动/停止/保存、文件传输、喇叭回收、MIC、OTA、MSC 和存储占用；不能只检查 `current_func` 或 `rp->run`。建议状态为格式化中、参数提交中、完成待 OFF、失败，查询可以看见阶段/错误。

- 成功：LAST_STATE=DONE、ACTIVE=FINALPACK，保留红灯、CDC 查询和完成锁定；禁止新测试及重复包装，DIP OFF 不等待查询确认。
- BLE：日志中整包启动约 151 ms 后 ft_dut 0，现有 `rdx_dut_finalpack_mode_ack()` 对 0/1 只回显，不退 DUT、不清 pending、不改红灯。保留该兼容；不把回显记为新的退出完成 ID。
- CDC：包装 RUNNING/成功锁定时 ft_dut 0/1 返回 BUSY；查询不覆盖 LAST。包装成功不自动关闭 CDC 或关机。
- 失败：停止后续成功步骤，不亮成功灯、不自动重试；已完成格式化/重置不可回滚。禁用提交不确定时显式使能并回读或转维修，不能凭标记推断工站通过。
- 回调：当前格式化回调通过 app_core 投递提交，投递失败走失败分支。公共接口接入后使用完成槽和重通知，统一在 app_core 修改 ID/LAST，不丢完成、不跨任务随意写状态。

已有 BLE 整包/独立禁用不因本次文档评估被撤销。CDC 正式开放破坏性动作前，验证失败注入、按键恢复及实际 JL Studio/ISD 维修步骤，记录 VM/身份保留范围。普通重刷不等于已验证恢复；掉电和首响应丢失仍按结果未知处理。

## 6. 实施接口与故障边界

### 6.1 扩展已有服务，保持来源隔离

复用 `dut_service()`、录音 ticket 和喇叭工作任务，抽取传输无关请求/结果层。不要让 CDC 直接调用 `rdx_dut_ble_cmd_handle()`：旧命令仍有 strstr/atoi 和提前回显，队列需要 BLE token；按键/喇叭又有较严格完成条件，不能将所有路径一概视为同步完成。

请求至少带来源 BLE/CDC/KEY、来源会话令牌、规范动作、目标值以及接纳后动作 ID。BLE token、USB generation、动作 ID 分别管理通信和业务；所有修改入口经同一 app_core 仲裁。响应回原来源，异步完成关联原 ID。保留 16 项有界队列、周期补偿、录音保存屏障和音频回收。

CDC 断线撤销未接纳请求，停止按键捕获和持续喇叭；录音触发停止保存并等待清理；不可取消的格式化/整包安全收尾，不向新会话补发。BLE 失效仅撤销其所属动作，不能取消独立 CDC 测试。正常退出 DUT 不使 CDC generation 失效，但必须清理测试资源和旧测试事件。

长动作超时进入 FAILED 后，未确认终止的资源仍保持隔离。迟到回调不把失败改成功、不继续整包后续提交；系统清理和关机不受普通 RUNNING 禁令阻塞。

### 6.2 故障可查询与真正恢复

CDC 不依赖 SD 健康后，格式化/保存失败可以继续查询，但不代表存储可用。保持故障状态和资源隔离，拒绝新的冲突业务；只有实际修复/复位及准入检查通过才清除。当前 `dut_record_failed` 有重启要求，协议应诚实返回，不靠退出再进入清零。

不再另设“必须仍在 DUT 才能恢复 CDC”的特殊授权。通信故障、总线复位和关机仍可导致结果不可达，工站按结果未知处理；不得把 CDC 可见当作动作已执行/未执行的证据。查询接口在正常模式开放后，身份读取与正式工站日志按第 3.4 节的交付要求执行。

### 6.3 SPP MIC 按需纳入

沿实际接收、音频开关和断连路径确认配置；`rdx_spp_recieve_callback()` 设备信息查询与 SDK 在线 MIC 调试并非一条已验证链路，不能只开启宏就宣布可用。

启用时 MIC 从启动预留到关闭确认均占资源，ACTIVE=MIC，不分配 DUT ID/覆盖 LAST；与喇叭、两种录音、格式化/包装双向互斥。SPP 断线和退出触发清理，关闭未确认不释放，频响结果由工站判定。

## 10. 阶段 3 首批实现：通信生命周期与文本基础（2026-09-29）

### 本批开放范围

- CDC=1 时，ON、业务初始化已开始且 USB 角色/资源允许即可枚举；不要求按键授权、进入 DUT 或 SD 健康。普通 DUT 退出不撤销 CDC，关机专用撤销仍锁存。MSC 持有 USB 类时不抢占，OFF/关机仍禁止 CDC。

### 调度、容量与恢复

USB RX 只复制完整包到 4×64 字节邮箱，每项连同 generation/长度/偏移占 72 字节，邮箱共 288 字节。app_core 使用 10 ms 周期服务，单轮最多消费 256 字节/提交 4 条响应；无需每包投递消息，避免消息队列满导致永久停滞。半帧为 129 字节，独立响应槽为 258 字节；TX 满时保留响应和输入偏移，并经邮箱传播背压。

分帧遵循第 3.1 节：CRLF 才恢复，非法字节/裸 LF/孤立 CR 整帧丢弃，首错误锁定，129 字节溢出返回 ARG。响应等待超过 2 秒通过 `factory_cdc_abort(generation)` 原子撤销匹配会话；该接口不等待、不释放端点，USB 任务沿用原 300 ms 重新枚举路径。旧请求/半帧/响应不进入新会话，旧 abort 不影响新会话。正常退出 DUT 不改变 generation。

当前没有修改动作，因此还没有“generation 校验与动作接纳”的跨任务提交边界；下一批必须实现，不能把当前只读分发直接作为动作事务入口。
