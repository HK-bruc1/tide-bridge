# T2620 充电、BLE 业务与 PC U 盘互斥分析及拨码分流实施方案

> 更新日期：2026-09-08
> 适用工程：T2620 / AC701N（BR28），RDX + HOGP 双 Peripheral ACL，SD0 整盘 MSC 导出
> 状态：第一阶段基础功能暂时验收通过，保留 8.2.7 的遗留问题，已提交 `a3d0a20`。按用户后续授权进入第二阶段 A：拨码 ON 正常开机时，USB 插拔仅改变充电状态，保持 BLE、录音及正常业务，不启动 U 盘。第二阶段 A 的实现及验证记录见 8.3.1；完整双向切换尚未交付，第二阶段尚未实机验收。

> 本文以拨码分流方案作为当前实施基线，替代此前“PC 模式保留 BLE 非存储业务”的共存目标。保留原文件名，避免已有引用失效。

## 1. 结论：为什么不能三者共存

**在本工程同一张 SD0 整盘导出为 U 盘的架构下，“充电 + 完整 BLE 业务（包括录音）+ PC U 盘”不能同时成立。PC U 盘与 BLE 的 SD 访问业务只能二选一。**

核心冲突是 SD 使用权，不是充电与 BLE 或 USB 在原理上互斥：

1. BLE 录音必定写入 SD；文件列表、读取、删除、传输、SD 文件播放等业务也依赖 SD。
2. PC 模式将 SD0 通过 USB MSC 导出，电脑直接管理该盘的文件系统和缓存。
3. 固件同时访问同一文件系统，会与电脑的目录、分配表及数据缓存产生不一致，可能造成读写错误、录音文件损坏或文件系统损坏。
4. 当前工程没有两端文件系统一致性协调机制。底层读写轮流执行、简单加锁或仅允许固件读取，都不足以保证安全；当前整盘导出方案必须禁止设备侧文件访问。

BLE 广播、连接和 HOGP 本身不必访问 SD，理论上可与 U 盘并行。但**BLE 保持连接不等于 BLE 录音可用**。仅保留连接或键盘，不能满足本产品所要求的完整 BLE 业务，因此不作为本轮目标。

充电可以分别与 BLE 业务或 U 盘运行配合；它不能解除 SD 独占限制。实际能否在相应负载下给电池净充电，仍需板级供电和电流实测。

`TCFG_CHARGE_POWERON_ENABLE` 只提供开机充电策略能力，不能解决 SD 争用；开启蓝牙后台同样不能让 BLE 录音与整盘 U 盘安全共用 SD。

## 2. 折中方案：用拨码选择业务，充电独立维持

**拨码关机（OFF）插入电脑 USB：充电 + PC 模式 U 盘，关闭 BLE 业务。**

**拨码开机（ON）插入 USB：充电 + BLE 业务，允许录音及其他正常 SD 业务，不启动 U 盘。**

这里的“关机”表示用户拨码关闭业务；插电脑后芯片仍需运行 USB、存储及充电管理程序，并非芯片完全断电或一直处于软关机。

| 拨码与接入条件 | 目标行为 | SD 使用权 |
|---|---|---|
| OFF，插电脑 USB | 充电 + U 盘；BLE/RDX 业务关闭 | 电脑独占 |
| ON，插电脑 USB | 充电 + BLE 业务，包括录音；不出盘 | 固件独占 |
| OFF，插纯充电器 | 仅充电，不启动 U 盘或 BLE 业务 | 不开放业务访问 |
| ON，插纯充电器 | 充电 + BLE 业务，包括录音 | 固件独占 |
| ON，无 USB | 正常 BLE 业务 | 固件独占 |
| OFF，无 USB | 正常关机 | 不开放业务访问 |

仅检测到 VBUS 不代表连接电脑。必须完成 OTG 角色识别，纯充电器不得误入 PC 模式。角色未确认时先维持安全的充电状态，不提前导出 SD。

ON 插电时，已有录音应继续，新录音也应能正常开始；不得因充电事件误停录音。OFF 的 U 盘模式不开放 BLE 业务，也不要求保持 HOGP 连接。

## 4. 本工程是否具备实现能力

**源码评估结论：PC 模式 U 盘已经实现，本次复用现有 MSC、SD 接管与恢复流程，不重新开发 U 盘功能。新增工作是先实现 OFF 的“充电 + U 盘、关闭 BLE 业务”，验收通过后再实现 ON 的“充电 + BLE 业务及录音、不启动 U 盘”。现有固件尚不满足这套完整分流策略。**

### 4.1 可直接复用的能力

- `app_main.c` 的 `app_task_init()` 在业务模式选择前执行共享 VDD 早期初始化和 `dev_manager_init()`。SD 基础准备不依赖先启动整套 BLE。
- `pc.c` 已有独立的 USB MSC 启停流程，以及 `dev_manager_takeover("sd0")` / `dev_manager_restore("sd0")` 存储交接。
- `pc_task_stop()` 先停止 USB，再恢复 SD；恢复失败进入禁止设备访问的状态。这些安全约束必须保留。
- `rdx_peripheral_power.c` 已提供 USB 对共享供电的持有保护，应继续统一管理 PA4。
- RDX 已有开机充电状态、满充检测及自动关机策略分支，可复用并按新场景调整。

### 4.2 必须修改的现有行为

| 位置 | 修改前基线行为 | 新方案要求 |
|---|---|---|
| `app_main.c` | 带线启动优先进入 `IDLE_MODE_CHARGE` | 按 DIP 与 OTG 分流到 PC、BT 或充电待机 |
| `charge.c` 的 `app_charge_allow_usb_pc_poweron()` | OFF 仅充电，ON 保持开机供 PC 使用 | 分开计算业务运行许可与 USB 服务运行许可 |
| 公共 OTG 设备事件入口 | USB 上线可直接请求 PC | ON 禁止出盘，OFF 确认电脑后才允许请求 PC |
| `pc_mode_try_enter()` | 明确拒绝 DIP OFF | 按新策略检查 OFF、OTG 和安全交接条件；ON 拒绝进入 |
| `rdx_dip_switch.c` | ON 且 USB 在线请求 PC；OFF 请求关机 | 按当前 USB 状态切换业务，不能无条件关机或出盘 |
| `rdx_dip_switch_init()` | 在 RDX 全量初始化中调用，发现 OFF 就请求关机 | 基础拨码监听应独立可用，OFF 的 PC 模式也能响应 ON |
| `rdx_app_charge_prepare()` | 插电清理会停止录音、OTA、Wi-Fi | ON 插电只处理充电，业务收尾仅在实际模式切换等需要时执行 |
| PC 失败、拔出及“下一模式”路径 | 存在通用模式回退 | OFF 不能误入 BLE；ON 不能被旧事件重新拉入 PC |

独立 PC 启动仍需逐项确认 SD 注册、充电指示、拨码监听、公共消息及失败回退的初始化完整性。不能仅依据“有 `dev_manager_init()`”就宣称整条冷启动已经验证通过。

## 5. 充电复用与硬件边界

### 5.1 TCFG_CHARGE_POWERON_ENABLE 的作用

当前生成配置中 `TCFG_CHARGE_ENABLE = 1`、`TCFG_CHARGE_POWERON_ENABLE = 0`。JL 的运行时 `set_charge_poweron_en()` 不会改变 RDX 的编译条件。

RDX 宏为 1 的分支已有插入时启动充电状态、关闭 BLE 自动关机，拔出时停止充电状态、恢复自动关机策略的逻辑。ON 的 BLE + 充电可复用此能力。

但 OFF 的 PC 模式也需要芯片继续运行，不能再把 DIP OFF 简单等同于运行时充电许可为 0 或立即软关机。应根据“DIP、VBUS、OTG、当前服务及清理状态”统一计算运行策略。OFF 模式没有初始化 BLE 时，充电路径不得依赖或操作未初始化的 BLE 模块。

宏不能代替启动分流、USB 启停、录音收尾、SD 交接和拔线关机。满充也不能错误结束正在运行的 U 盘或 ON 的录音业务。

已有 JL 工具配置项优先通过 JL Studio 生成，不手改 `sdk_config.h/c`；新增 T2620 产品策略覆盖放在 `t2620_project_config.h`，不重复建设充电机制。

### 5.2 必须核实的充电问题

- 本工程原生 `charge_start()` 被注释，实际充电依赖板级外置电路。不能仅由 USB 在线或充电灯判断电池正在净充电。
- 当前 `BJ_BOARD_VERSION_03` 的满充检测脚为 PB5，但 `charge_check_is_full()` 仍调用 `usb_iomode(1)`。应核实并清理不适用的 USB IO 操作，避免周期检测影响 MSC；当前尚无实机证据证明具体掉线后果。
- 满充检测周期为 5000 ms，应覆盖多个周期测试。
- 检查充电定时器、LED 和共享 VDD 生命周期，不能绕过共享电源管理器直接关闭 PA4。
- 分别测量“充电 + U 盘读写”和“充电 + BLE 录音”的 USB 输入、整机负载及电池净电流。源文件名 `sk4558.c` 不能单独证明实际板上芯片型号或供电能力。

## 6. 带线启动和拨码切换规则

### 6.1 冷启动

```text
基础硬件、共享供电、设备管理及拨码监听就绪
  -> 读取 DIP、VBUS，异步确认 OTG
  -> OFF + 电脑：准备 SD -> 接管 -> 启动 PC U 盘，维持充电
  -> OFF + 纯充电器：充电待机
  -> OFF + 无 USB：关机
  -> ON：沿原生 BT / multi_protocol 路径初始化 RDX，开放 BLE 业务
           USB 在线时同时维护充电，不请求 PC
```

OFF 的 PC 冷启动不通过 `rdx_app_all_init()` 顺带初始化基础设施。该函数还会创建录音任务、初始化协议、处理录音异常恢复等，不适合作为 PC 基础初始化入口。

### 6.2 ON → OFF，电脑仍连接

1. 关闭新 BLE/本地存储业务准入，阻止后续录音和文件请求。
2. 按正常业务接口停止录音、保存并关闭文件，结束传输、扫描等已有工作。状态变量变为 STOP 不等于文件已写完。
3. 确认协议队列及文件任务没有后续 SD 副作用，再完成业务退出。
4. 保持共享供电，卸载设备文件系统并接管 SD0，随后启动 MSC。
5. 任一步失败或超时均不启动 U 盘，维持安全状态及充电，并记录失败原因。

当前 `rdx_pc_storage_is_busy()` 只是忙状态快照，不能代替准入关闭与任务完成证据；其初始化标志为假时返回空闲，也不能证明此前创建的任务已退出。`rdx_app_all_exit()` 主要退出 BLE 服务，不是完整的录音、协议任务销毁屏障。

RDX 预编译库内的工作仍需核实收尾接口和完成条件。新方案不需要在 MSC 期间筛选、放行部分 RDX 命令，但模式切换时仍必须证明旧工作已结束。已有事务需要的确认、取消和收尾不能被准入关闭误拦截。

### 6.3 OFF → ON，电脑仍连接

1. 停止 MSC 并确认 USB 不再访问 SD0。
2. 恢复设备文件系统，确认成功后才开放存储业务。
3. 经正常 BT/RDX 生命周期进入 BLE 业务；不得在 PC 回调中重复执行全量初始化。
4. USB 保持供电，继续充电，不重新枚举为 U 盘。

电脑侧尚未提交的写缓存不能由固件保证保存；电脑应先安全弹出 U 盘再拨到 ON。固件仍必须执行停止与恢复检查，不能用电脑安全弹出替代设备侧清理。USB 停止或 SD 恢复失败时，不允许启动录音。

### 6.4 拔线、快速拨动及异常

| 场景 | 处理要求 |
|---|---|
| OFF 的 PC 模式拔 USB | 停止 USB、完成必要存储清理，然后关机；不回退到 BLE |
| ON 拔 USB | 更新充电状态，BLE 与录音继续，不因拔线重启或关机 |
| ON → OFF，只有充电器 | 完成业务收尾后进入充电待机，不启动 MSC |
| 切换过程中反复拨动或插拔 | 重新核实实时条件，取消旧请求；按已发生操作清理后进入最新合法目标 |
| SD 恢复失败或所有权不明 | 保持设备侧访问禁止，不假报成功 |
| 低电保护或电源故障 | 按实际电源条件执行保护，不能为维持 U 盘跳过必要清理 |

状态转换由 `app_core` 串行推进，等待采用消息/定时通知，不阻塞等待依赖同一任务的回调。事务标识独立于 BLE runtime token，旧回调不得重新启动 USB 或错误开放 SD。

## 7. RDX 框架符合性与 JL 修改边界

新方案保持“RDX 管业务策略和收尾，JL 管模式及 USB，设备管理器管 SD 交接”。必要的 JL 原生修改可以接受，集中在明确的调度入口。

| 层级 | 职责 |
|---|---|
| RDX 应用层 | 录音/文件业务准入、停止及完成确认，正常 BLE 生命周期 |
| 拨码产品策略 | 发布当前拨码与服务目标，基础监听不依赖 BLE 已初始化 |
| RDX 充电层 | 充电状态、指示和定时器；适配无 BLE 初始化的 PC/充电模式 |
| JL `app_main.c`、充电及公共设备事件 | 冷启动、OTG 分流、模式请求及拔线处理 |
| JL `pc.c` | PC 进入条件、MSC 启停、真实交接结果、失败回退 |
| 设备管理及共享 VDD | 存储所有权、恢复失败保护、USB 持有期间供电 |

保留 RDX 双 wrapper、单 GATT、现有 owner/token 和 HOGP 路由，不新增 BLE profile 或复制会话状态机。模式切换引发真实断链时遵守现有生命周期，不用伪造 `ble_conn = 0` 或借用重连 barrier 状态来代表 SD 归属。

本轮不启用 BLE 后台作为交付前提，不建设 PC 模式 HOGP 放行或 MSC 期间 RDX 非存储命令白名单。USB 模式与 BLE 业务模式按拨码互斥运行。

## 8. 分阶段实施

### 8.1 复评结论与已有基线

此前把“两种稳定模式”一起放进第一阶段，范围过大，也没有突出 PC U 盘已经实现的事实。本轮调整为两个功能阶段，每阶段分别完成软件检查、构建和板测，通过后再进入下一阶段，不把验证统一拖到最后。

| 能力 | 当前判断 | 本轮处理 |
|---|---|---|
| PC 模式 U 盘、MSC 启停及 SD 交接 | 已实现 | 保留并回归，不重建 |
| OFF 插电脑运行 U 盘并充电，BLE 关闭 | 软件候选已落地，待完整验收 | 第一阶段 |
| ON 插电充电并保持 BLE 录音，不出盘 | 新策略待实现 | 第二阶段 |
| 纯充电器不启动 U 盘 | 两阶段共同的硬性条件 | 第一阶段建立识别和保护，第二阶段回归 |
| 带线双向拨码切换 | 完整产品必须覆盖 | 第一阶段保证清理和互斥，第二阶段完成两种目标间的切换验收 |

### 8.2 第一阶段：充电 + 已有 U 盘，关闭 BLE 业务

**交付目标：DIP OFF 插电脑，运行现有 PC U 盘并充电，BLE/RDX 业务关闭；OFF 插纯充电器仅充电。**

实施范围：

1. 记录现有 U 盘枚举、读写及 SD 交接基线，复用 `pc.c` 和设备管理器已有能力。
2. 补齐 OFF 带线冷启动、OTG 电脑/充电器识别、PC 进入许可及独立拨码监听。角色未确认或为纯充电器时不得启动 MSC。
3. 使充电状态、检测和指示在未初始化 BLE 全量业务时可用；检查 PB5 的 USB IO 遗留调用、共享 VDD、定时器及满充行为。该阶段即验证实际净充电电流。
4. 修改 ON 自动请求 PC 的现有入口，禁止 ON 出盘。第一阶段尚不承诺 ON 插电可持续录音，此能力留给第二阶段，不能把中间版本当成完整产品交付。
5. 保证进入 PC 前旧业务完成收尾；不能因 BLE 已退出就认定 SD 空闲。OFF 冷启动与从已有业务转入 PC 分别核查。
6. 覆盖 OFF 拔线关机、PC 退出、USB 停止/SD 恢复失败及拨码变化。ON 请求发生时，必须先安全退出 PC；充电 + BLE 的完整目标行为在第二阶段验收。

第一阶段通过条件：

- OFF 插电脑：U 盘枚举与文件读写校验通过，BLE 业务关闭，电池净充电和满充检测通过实测。
- OFF 插纯充电器：仅充电；ON 插纯充电器及角色未确认期间也不得误启动 MSC。
- U 盘连续读写跨越多个满充检测周期，无周期掉线；拔线、拨码及失败路径不产生两端 SD 并发访问。
- 完成对应产品契约更新、统一 host 检查和固件构建，保存阶段固件版本及板测日志。

| 切换场景 | 目标行为及安全顺序 |
|---|---|
| ON → OFF，电脑在线 | 关闭新业务准入，停止录音/播放和文件传输，等待录音文件、标记及索引保存和后台工作排空，完成 BLE 退出，再允许 SD 交给 MSC；切换过程中不允许两端同时访问 SD |
| OFF PC → ON | 停止 MSC 并确认 USB 不再访问 SD，恢复设备侧挂载及文件视图，再启动 BLE 并开放录音；USB STOP 或 SD 恢复失败时不开放业务 |
| 纯充电器在线，ON ↔ OFF | ON 提供充电 + BLE，OFF 在业务安全收尾后进入仅充电；无已确认电脑角色时始终不启动 MSC |
| 切换中再次拨码或拔线 | 去抖后按最新稳定输入决定目标；已开始的必要收尾继续完成，旧队列事件不得重新开放过期目标；无 USB 且 OFF 时安全关机 |
| OTA、格式化或其他不可立即结束操作中拨码 | 逐项明确允许安全取消还是等待完成；不能强杀任务、切断存储电源或超时强制导出；等待/失败状态应有可辨识反馈 |

1. **录音收尾结果：** 与本次录音关联，覆盖原始音频尾部写入、关闭、标记与 DAT 保存及必要刷写；明确短文件丢弃规则。真实失败保留错误与可恢复数据，不能由 READY 超时器变成成功。
2. **文件工作收尾请求/回执：** RDX 先关闭业务准入，再提交带交接序号的请求；库内部停止会继续产生工作的定时器/扫描生产者，完成此前队列及删除子队列中的工作，关闭持久化句柄，检查刷写结果后回执。回执之后不得再发生设备侧 SD 访问，直到显式恢复；排空失败或超时不交出 SD。
3. **PC 归还后的恢复结果：** USB STOP、SD 挂载成功后使旧缓存失效，按 PC 实际文件变化刷新索引并确认完成；保存/扫描/视图恢复失败不开放录音。该接口解决已登记的 PC 删除后旧索引依赖，不能只 remount。
4. **协调层职责：** 输入去抖、最新目标、业务准入、交接序号及等待/失败灯效归 RDX；USB STOP 和 SD 所有权继续复用 JL 现有入口。BLE owner/token 仍只承担协议会话职责。全程不重启与保存后受控重启的选择，待上述契约成立及重建能力核查后确定。

本轮结论是已定位必须先补齐的实现条件，不是宣布产品目标不可实现，也不是阶段 2B 可交付测试。源码或新库到位后先验证短写、关闭/刷写失败、异步删除与扫描排空，再接双向拨码路径；原阶段 2A 固件行为保持不变。

### 8.3.7 阶段 2B 实施：库补丁与带线双向切换候选（2026-09-09）

用户随后明确授权沿用 `librdxApp_patched.a` 的补丁方式，故不再等待库源码。本节替代 8.3.6 中“等待源码/新库”的后续安排。**本阶段已形成热切换代码候选；软件验证与实机验收分开记录，不能将编译通过视为硬件验收。** 本轮不执行 Git 提交。

实现采用“无需拔插 USB，完成收尾后允许受控重启”。ON → OFF 用受控重启重新建立冷态服务；OFF PC → ON 复用现有 PC 退出/BT 启动路径。没有删除 `s_business_mode_entered` 冷态导出保护，没有在运行过业务的同一次启动中直接把 SD 交给 PC，也没有把 BLE owner/token 改成存储所有权。

| 场景 | 当前实现 |
|---|---|
| ON 插电脑/纯充电器 | 延续阶段 2A：充电并保持 BLE/HOGP/录音，不启动 MSC |
| 带线 ON → OFF | RDX 关闭新业务准入、停止本地播放及 WiFi 请求；向录音任务投递带序号的关闭请求，同时断开真实 BLE ACL；录音任务关闭 MIC/DAC 流并处理暂停录音尚未保存的上下文。待录音回执和既有 BLE FIFO/工作线程清理完成，再请求 UXFILE 排空及刷写 |
| 文件收尾完成 | UXFILE 请求使库定时器停止产生新工作，工作任务处理先前队列和删除子队列、关闭读句柄、保存 dirty 缓存并刷写文件系统；成功后冻结其普通消息处理，最后发布相同序号的完成回执。RDX 收到成功后才调用 `rdx_cpu_reset()`；冷启动重新读取拨码及 USB 角色，OFF 接电脑出盘，OFF 接纯充电器只充电 |
| OFF PC → ON | 原生 PC 路径先确认 USB STOP、再恢复 SD 挂载。RDX 标记需要刷新文件视图；UXFILE 创建方完成初始化后向工作队列投递刷新消息，处理完正常索引同步后才解除准入。等待期间不广播、不接受 BLE 写入或新录音/播放；完成后刷新本地播放列表、恢复广播和当前灯效 |
| 纯充电器 OFF → ON | 复用冷态 idle → BT；不启动 MSC。若此前从 PC 退出留下待刷新标志，则同样先刷新再开放业务 |
| OTA、格式化或 DUT 中拨 OFF | 等待已有操作结束/退出，保留其通道和灯效；此时拨回 ON 可取消等待。进入真正收尾后不再恢复旧业务，按最新稳定拨码/供电完成收尾并重启，录音不会自动续录 |
| 快速拨码、收尾中拔线 | 保留两次一致采样去抖。已经开始的收尾继续执行；成功后重启读取实际输入，不沿用旧目标；无 USB 且 OFF 走冷启动关机路径 |
| 保存失败、入队失败、排空超过 30 秒 | 红灯闪烁，保持业务关闭；不因超时强行出盘或自动重启。需要重新上电/硬件复位排查，拨码不能强制放行。30 秒是保护上限，不是承诺切换用时；等待 OTA/格式化/DUT 的时间不计入该排空期限 |

灯效复用现有引擎和配置表：实际收尾/ON 索引恢复期间黄灯闪烁，失败红灯闪烁；状态高于普通充电及业务提示，避免异步停止通知覆盖等待/失败状态。OFF 仅充电时即使留有待刷新标志，仍显示充电灯，不伪装成正在恢复。此前正常 ON 充电的录音、OTA 优先策略保留。

| OFF 的 U 盘安全弹出后拨 ON | USB 停止、SD 恢复成功后才开放 BLE 录音 |
| PC 读写中拨 ON | 不发生两端并发访问；验证异常卸载及恢复保护，不承诺保存电脑未提交缓存 |
| OFF 的 PC 模式拔线 | 清理后关机，不自动进入 BLE |
| 接管边界并发到达 BLE/按键请求 | 新工作被阻止，旧工作收尾后才交接 |
| 快速拨码及 USB 插拔 | 无旧事件重启错误模式，无任务/定时器重复创建 |
| USB 停止或 SD 恢复失败 | 不开放设备侧 SD，不启动录音，不伪报恢复成功 |
| 持续 U 盘读写并跨越多个满充检测周期 | 文件校验一致，无周期 USB 掉线 |
| BLE 双 ACL、复合 owner、真实重连及配键回归 | ON 模式遵守原有传输、生命周期及安全契约 |
| 两种模式下的充电实测 | 分别确认负载下电池净充电电流及满充行为 |
