# T2620 充电与 USB 存储模块边界

## 当前产品策略（2026-09-24）

本轮整改以 `10-1.量产产线问题积累.md` 第 5.8 节为准：历史录音检查只影响文件服务，不阻止 BLE/HOGP、电量查询或 OFF。旧收尾屏障不再控制关机。

客户取消关机插电脑导出 U 盘的需求。默认关闭 USB PC 存储，保留关机充电、开机充电与 BLE/录音共存。本文覆盖 `7.T2620_U盘与BLE及充电共存可行性评估与实施方案.md` 中旧的默认出盘策略；原文保留历史设计与板测记录。

| 输入 | 目标行为 |
|---|---|
| OFF 插电脑或充电器 | 充电待机，不枚举 U 盘、不启动 BLE 业务 |
| ON 插拔 USB | 更新充电状态，保持 BLE、录音及本地存储业务 |
| 带线 ON → OFF | 尽力通知录音停止，进入原生关机并受控重启到充电待机；保存失败不能否决 OFF |
| 带线 OFF → ON | 启动正常业务，不导出 U 盘 |
| OFF 拔线 | 经应用关机流程退出 |

## 配置职责

配置入口统一为 `SDK/apps/earphone/include/t2620_project_config.h`。

| 配置 | 默认 | 职责 |
|---|---:|---|
| `TCFG_T2620_PC_STORAGE_ENABLE` | 0 | 可选的 SD0 USB MSC 导出；关闭时强制 PC 模式关闭，避免工具重新生成配置后意外恢复出盘 |
| `TCFG_T2620_CHARGE_COEXIST_ENABLE` | 1 | 充电不打断开机业务，带线初始化充电状态，管理满充、自动关机和灯效策略 |
| `TCFG_T2620_STORAGE_PRESERVE_ON_BOOT` | 1 | 启动不自动格式化，独立于 USB 导出 |
| `TCFG_SD_ALWAY_ONLINE_ENABLE` | SD0 启用时为 1 | 板载焊接介质属性，独立于 USB 导出 |

JL 工具继续管理 SD0、MSC 硬件配置及原有充电宏，不直接修改 `sdk_config.h/c`。PC 关闭后，SDK 根据 `TCFG_PC_ENABLE=0` 关闭 USB Slave 及其各 Class；BLE HOGP 不属于 USB HID，不受此开关影响。

当前产品支持的配置是“充电共存开启，USB 导出关闭或开启”。充电共存设为 0 将恢复旧充电策略，不是本次验收的产品组合。存储安全不提供绕过开关。

## 模块职责与调用方向

| 模块 | 负责 | 不负责 |
|---|---|---|
| `rdx_dip_switch.c/h` | PB1 初始化、消抖、OFF 锁存、独立超时复位保护、冷启动模式选择 | 文件保存成功判定 |
| `rdx_storage_lifecycle.c/h` | 文件服务准入、PC 归还后的索引恢复准入 | 关机否决、BLE/HOGP 准入、GPIO 配置 |
| `mode/pc/pc.c` | MSC 启停、SD 独占接管、停止 USB 后归还 SD | 开机充电策略 |
| `rdx_charge.c` 与平台 `battery/charge.c` | 充电检测、CPU 服务许可、开机业务共存及充电事件 | 是否允许导出 SD |
| `t2620_project_config.h` | 产品配置和依赖约束 | 运行时状态机 |

拨码先响应 OFF，再处理存储生命周期；独立用户计时器在主任务未推进时提供复位保护。文件整理运行于 UXFILE，完成索引与缓存交接后开放文件服务。PC 成功停止 USB 并恢复 SD 后，仍通过归还通知恢复文件服务。

可选 MSC 仍需遵守 SD 独占所有权；此保护不得用于否决 OFF。底层保留的 USB quiesce 接口不再构成关机保存屏障。

## 重启边界

关机一旦接受，不原地恢复正在销毁的蓝牙运行时。正常原生退出保留平台反初始化与硬件 RTC 保存；最终 ON 或有 USB 时受控重启，重新采样 DIP/VBUS。默认 OFF+USB 进入充电待机，OFF+电池进入软关机，ON 启动全新业务运行时。

录音停止是尽力通知，失败不能锁死整机。独立保护按首次接受 OFF 累计约 3 秒，重复请求不刷新期限；超时触发复位，冷启动 OFF 不进入业务。该保护不等同物理断电，长时间关中断等覆盖范围需板测。

若未来需要彻底消除受控重启，应单独实现并验证 RDX worker 的退出/重建协议；本次不扩大为预编译库生命周期重写。

## 历史验证与维护（以下为旧方案记录）

日常软件检查仍使用 `tests/host/run_host_tests.ps1`，不引入额外编译器依赖。产品契约覆盖默认不出盘、充电与 PC 解耦、固定 SD、存储保护、收尾模块常驻以及可选 PC 的原有所有权约束。

历史验证曾使用 `test_rdx_usb_switch.py` 从生命周期模块提取实现进行状态机执行检查。测试框架精简后已移除该 Python/LLVM 专项脚本，当前统一入口与覆盖范围见 [主机测试说明](../tests/host/README.md)。下方执行测试结果为当时的验证记录。

固件链接使用 Windows wrapper 的 `cpu/br28/tools/sdk.elf` 目标。`all` 后处理会调用下载器，本轮软件验证不运行下载后处理，不烧录设备。

板测至少覆盖：OFF 插电脑不出盘；OFF 纯充电器充电及拔线；ON 带线冷启动；录音中反复插拔 USB；带线录音拨 OFF 后文件完整；OFF → ON；满充不误关业务；关机途中拔线。软件通过不等于净充电电流、满充截止或板级供电已验证。
