# T2620 BLE 连接后低功耗设计

> 更新时间：2026-09-09
> 文档状态：设计阶段，尚未实施或完成连接态低功耗板测
> 适用工程：T2620 / AC701N（BR28）RDX + HOGP，最多两条 Peripheral ACL
> 已实现基础：[6-0 BLE 未连接外设低功耗方案](6-0.T2620外设低功耗与共享VDD电源管理设计.md)

## 1. 目标与范围

BLE 未连接慢广播时，共享 VDD 安全断电及业务恢复的核心闭环已经实现，整机实测约 1.5 mA。该结果及尚未完成的量产前回归保留在 6-0，不作为连接态功耗数据或验收结论。

本阶段保留 BLE 连接，从两个方向降低空闲功耗：

1. 根据每条 ACL 的实际业务协商连接参数，减少无线连接事件带来的开销。
2. 共享外设连续无业务两分钟后，复用现有安全停用流程关闭 PA4；需要 SD NAND/RGB 的业务到达后先恢复，再执行。

两项策略独立判定：BLE 参数调整不依赖 PA4 已关闭，PA4 关断也不依赖主机接受低功耗参数。PE5 继续独立跟随 DAC 生命周期。自动关机及 RDX 会话所有权策略不在本阶段调整范围内，外设休眠不释放 RDX/HID owner。

## 2. 当前实现与扩展缺口

当前 `rdx_peripheral_power.c` 将任一 BLE 连接计入 `BLE_LINK` 忙状态，空闲判定还会复检实际连接数；建链会恢复整个共享域，连接期间保持 PA4 高。现有空闲触发绑定慢广播及其 generation/wake epoch。

因此，不能仅删除 `BLE_LINK` 位或复用广播的两分钟定时器。连接态必须具有独立于广播状态的外设空闲期限，并补齐连接期间的业务恢复门禁。

`rdx_ble_server.c` 已包含以下参数请求档位：

| 档位 | 原始参数（min/max/latency/timeout） | 间隔 | latency | 监督超时 |
|---|---|---|---:|---:|
| 传输快档，索引 0 | `{6, 10, 4, 600}` | 7.5–12.5 ms | 4 | 6 s |
| 传输后低功耗档，索引 8 | `{60, 80, 19, 2000}` | 75–100 ms | 19 | 20 s |

间隔单位为 1.25 ms，监督超时单位为 10 ms。现有请求路径通过 RDX token 解析目标链路，不能据此认为仅 HOGP 链路已有完整的空闲参数策略。表内数据是请求值，实际参数以成功的连接完成/参数更新事件为准。

## 3. BLE 连接参数策略

按实际 ACL 聚合业务需求。同一 ACL 上 RDX 与 HOGP 共存时，参数必须同时满足两者；两条独立 ACL 分别调整，不以单一 owner 的状态代表所有连接。

| 链路业务 | 设计方向 |
|---|---|
| 文件传输、实时数据 | 短间隔优先，保障吞吐与连续性；现有快档作为测量起点 |
| 仅 HOGP、等待按键 | 尝试较短间隔配合适当 latency，验证空闲电流和首键响应 |
| RDX 空闲 | 请求低功耗参数；现有低功耗档作为比较基线 |
| 已连接但尚无 owner | 使用兼容服务发现及后续认领的默认参数，不能因无 owner 漏管链路 |
| 同一 ACL 的 RDX + HOGP | 综合传输需求和键盘响应约束，不能直接套用纯 RDX 空闲档 |

latency 允许外设空闲时跳过部分连接事件，不表示按键必然等待整个跳过周期。JL 控制器实际唤醒行为、主机接受情况及首键延迟均需板测。参数应满足 BLE 约束，包括 `监督超时 > 2 × (1 + latency) × 最大连接间隔`；满足协议约束仍不等于满足产品体验。

参数请求需防止业务切换抖动和无界重试，并绑定当前链路的有效身份/生命周期，防止断链后的旧请求作用于复用槽位。主机拒绝时继续使用实际参数，不阻塞正常业务；记录请求、成功/拒绝和实际生效值。具体参数、切换延迟及有限重试规则在实测后确定，不直接沿用外设两分钟期限。

单条 ACL 连接时，另一个空闲槽位仍可能广播；测量需记录其快慢广播状态。两条 ACL 都连接时，没有广播超时也必须能够进入外设休眠。

监督超时主要决定失联判定时长，增大它本身不能作为省电收益；现有 20 秒档还需验证异常失联后 owner 释放及重连等待体验。外设主动按键与主机下发首条命令的等待行为不同，二者都要测量。每条 ACL 应统一协调现有传输快档与传输后低功耗请求，避免旧低功耗请求覆盖新业务需求。

## 4. 连接态共享 VDD 空闲策略

### 4.1 连续空闲两分钟

本阶段以 120 秒作为连接态联调值，单独配置，不复用 `RDX_LED_BLE_ADV_TIMEOUT_MS`。6-0 的量产 300 秒属于未连接快广播窗口；连接态量产空闲时长待确认。

建议计时规则：

- 建链初始化完成且没有共享外设业务时，开始计时；首轮保留现有建链恢复行为，随后允许连接内超时关电。
- 需要 SD/RGB 的业务开始前先取消旧空闲请求并确保恢复完成；业务活动、暂停持有文件及收尾期间不计为空闲。
- 所有外设业务结束、文件关闭及 worker 空闲后，重新开始完整的 120 秒计时。
- BLE 保活、确认不访问共享域的状态查询、纯 HOGP 报告不重置外设空闲期限，也不要求 PA4 上电。
- 任一 ACL 的外设业务都阻止整个共享域断电；第二条连接建立或断开时重新聚合状态，使旧期限失效并按当前状态重新评估。
- 最后一条 ACL 断开后回到 6-0 的未连接策略，不让旧连接态超时误触发关断。

### 4.2 忙状态与灯效

计时补充约束：仅在“忙 → 空闲”或有效拓扑周期初始化时启动期限，重复空闲通知不能重新计时。复检发现业务仍忙时取消空闲资格，确认结束后再计完整的 120 秒；无结束通知的预编译业务可在活动期低频复检。建链初始化完成须确认共享域恢复、已启动的扫描/初始化任务结束且无待执行外设命令，不以固定延时或获得 owner 替代。断开一条但仍有连接时重新聚合并计时，不因断链本身强制上电。

连接态不再把“存在物理 ACL”本身作为共享 VDD 的长期忙条件，但实际外设占用仍需聚合录音、播放、文件传输/同步/扫描、格式化恢复、USB MSC 和必要 RGB 场景。未知或无法证明已结束的外设业务继续阻止关断。

普通连接指示灯应在空闲期限到达时退出，随后复检其他必要灯效；不能让普通连接灯自己永久阻止空闲计时或关电。充电、低电、DUT、OTA 等是否必须亮灯需逐项明确，必要场景仍保持供电。仅 HOGP 按键若伴随 RGB 提示，需按实际灯效需求决定是否唤醒，不能一概视为纯内存业务。

### 4.3 复用安全关断与恢复

普通指示灯策略必须区分计时和关断资格：普通连接/第二连接窗口提示灯可以在计时期间显示，期限到达后经过灯效仲裁退出；实际场景仍非 OFF 时禁止断电。剩余槽位的快慢广播事件不重置连接态期限，也不自动重亮已超时退出的普通提示灯；显式用户操作需要显示时作为新的 RGB 业务处理。

当前快照将充电非 OUT 状态、DUT、OTA 直接计为忙，即使灯灭也阻止关电。本阶段保留这些保守门禁，不能因拆分普通提示灯而一并删除。

继续由现有共享 VDD 管理器统一控制 PA4，复用 `ON_READY → STOPPING → OFF → STARTING → ON_READY`、SD0 所有权、转换互斥及失败保持供电机制。

超时只提交空闲请求到 `app_core`。停用仍必须停止 RGB 定时器及 SPI/DMA、确认业务文件收尾、刷盘卸载 SD、设置接口安全态，最终复检后才能拉低 PA4。停用期间的新业务通过 wake epoch 取消旧决策，恢复成功后才允许访问外设。

实现时审查所有慢广播、连接数、generation 和业务结束复检条件，使未连接与连接态的策略入口复用同一停用执行器；稳定 OFF 后不保留无意义的周期轮询。

## 5. 连接期间的业务唤醒门禁

这是本阶段开放关电的前置条件。6-0 依靠建链恢复保障后续 ATT 访问；连接内断电后，必须在每次需要共享外设的业务入口保障恢复。

| 入口 | 要求 |
|---|---|
| RDX 文件列表、扫描、读取、上传、删除、重命名等 | 进入可能访问 SD 的处理路径前恢复；覆盖预编译库入口 |
| 录音、播放及相关索引操作 | 恢复成功后再启动；完成文件和 worker 收尾才释放占用 |
| RGB 场景 | 确认需要显示后经过统一恢复入口，再访问 SPI |
| USB MSC | 保留先恢复为设备侧可用状态、再交接 Host 所有权的流程 |
| 纯 HOGP 报告、纯内存查询 | 确认无共享外设依赖后允许 PA4 保持关闭 |

不能仅以“有没有 ATT 数据包”判断业务，也不能无差别地让每个包都上电。需逐项审查命令的真实外设依赖，包括内部扫描、异步 worker、定时器和库内延后访问。无法确认依赖的路径在完成审查前保持供电。

业务开始必须先发布受同步保护的占用/待执行事实并使旧超时失效，再执行恢复，成功后才访问外设；占用持续到最后一次异步访问和收尾结束。只调用 `ensure_on()` 再稍后设置忙状态会留下重新关电窗口，wake epoch 也不能代替持续占用。沿用固定业务事实聚合即可，不必引入通用租约框架；短命令及库内异步操作必须有明确的完成边界。

命令分流和恢复之前保留现有长度、权限、加密、owner/token 校验，非法或非 owner 请求不应通过恢复门禁获得存储访问权。若异步排队，需复制回调缓冲、限制队列容量，并在真正执行前重验链路 token；断链后的旧命令不得在新连接上执行。ATT Write Command 没有 ATT 错误响应，不能统一假设“返回 busy 后主机会重试”，必须按现有协议确定可用的失败响应或排队方式。

同步恢复能否继续使用，要测量连接期间的最坏耗时及对双链路/HOGP 的影响。如果需要改为工作任务恢复，必须同时定义 STARTING 期间的命令排队或可重试响应、顺序和失败处理，不能在恢复未完成时放行。恢复失败沿用故障状态并向业务返回失败，不将其视为可访问，也不因动态恢复失败自动格式化。

## 6. 实施与验收顺序

1. **连接态基线**：固定电压、仪器、采样窗口和调试接口状态，记录一条/两条 ACL、实际连接参数、广播状态、PA4/PE5、业务及平均/峰值电流。
2. **外设闭环**：保持 BLE 参数策略不变，补齐业务门禁和独立空闲计时；依次验证判定、安全卸载和真实断电，复用现有三级验证模式。
3. **参数优化**：在外设状态一致的条件下比较连接参数，分别测量仅 HOGP、仅 RDX、同 ACL 复合业务及双 ACL。
4. **联合回归**：组合两项优化，确认功耗收益、键盘响应、吞吐、文件完整性和连接稳定性。

必须覆盖以下场景：

- 单/双 ACL 连续空闲 120 秒后 PA4 关闭，连接和 owner 保持有效；双 ACL 无广播时同样成立。
- OFF 后首个 HOGP 按下及释放不丢失；纯报告不唤醒共享域。
- OFF 后首条文件命令、录音、播放、RGB 和 USB 先恢复再访问，业务结束重新计时并再次关电。
- 文件收尾、扫描、暂停持有文件、USB Host 占用和必要灯效期间不误关电。
- 超时边界新命令、STOPPING 期间新业务、第二 ACL 建链、断链及槽位复用不会被旧事件误关电。
- 重复空闲通知、普通连接灯和第二连接窗口快慢广播不会无限推迟期限；新业务发布到忙状态可见之间无关电窗口。
- 首条主机下行命令等待时间、无响应写命令处理及非法/non-owner 请求均符合协议；异步命令不使用失效缓冲或旧连接身份。
- 参数拒绝或更新失败仍能正常工作；传输期间吞吐、HOGP 首键及释放延迟满足后续确定的门限。
- 挂载/卸载失败、消息投递失败及恢复失败不造成掉电访问、自动格式化或所有权失真。
- 回归 6-0 未连接慢广播、建链唤醒、离线业务及再次断电，保持其既有行为；6-0 未完成的 U1–U5 继续独立跟踪。

连接态目标电流、键盘延迟门限、最低吞吐、恢复耗时上限、循环次数及量产空闲时长均需结合基线确定。当前不将任何连接态收益或测试项标记为已通过。
