# T2620 BLE 连接待机低功耗设计

> 更新时间：2026-10-17
> 本文记录连接态方案、已取得的收益和踩坑经验，不保留实施流水、逐条日志与详细回归清单。未连接基础设施见 [6-0](6-0.T2620外设低功耗与共享VDD电源管理设计.md)，功放原则见 [6-1](6-1.通用功放低功耗设计.md)。

## 1. 已取得的收益

**保持 BLE 连接，先关掉不需要的外设负载，再优化连接参数与剩余软件活动。**

| 阶段 | 已采用的措施 | 用户实测连接待机电流 |
|---|---|---|
| 优化前 | 功放随 DAC 模拟保持开启，PA4 因存在连接不能关闭 | 约 16 mA |
| 阶段 1：PE5 | 功放跟随 DAC 实际输出，不再随模拟资源常开 | 约 7 mA |
| 阶段 2：PA4 | 连接空闲 120 秒后关闭 SD/RGB 共享 VDD，真实业务按需恢复 | PA4 开启约 7 mA，关闭约 6 mA |

**阶段 1 已通过，阶段 2 核心板测通过，可独立收尾。** 已确认连接保持、空闲关电、列表/录音唤醒及业务收尾后再次关电；RGB 定时器超时问题修复后未再出现。上述电流来自用户仪器反馈，属于单 RDX 连接场景，不外推为 HID/双 ACL 或量产长稳全部通过。

## 2. 采用的方案

### 2.1 保持连接与既有安全能力

- 目标是正常开机、电池供电、USB/VBUS 拔出且无业务/收尾；充满不等于拔线。
- 不断开 ACL，不释放 RDX/HID owner，不改变订阅、加密或绑定，不靠关闭第二连接入口省电。
- 按键、录音、播放和文件访问正常唤醒；关机、低电保护、USB 所有权与 OTA 安全不因省电放宽。
- 不新增常驻连接态轮询。空闲窗口与灯效在 `app_core` 按事件调度；存储入口仍可在调用任务同步恢复共享域。

### 2.2 PE5 跟随实际输出

**PE5 = DAC 模拟就绪且数字输出运行。** 输出停止后关闭功放，不等待 DAC 模拟关闭，不绕过 JL 框架强关模拟资源。此策略与 BLE 状态和 PA4 无关，未连接时同样适用。

### 2.3 PA4 复用共享域管理器

连接态和未连接态分别判断关电资格，共用安全停用/恢复执行器。不能简单删除“有连接则忙”的判断，更不能用第二入口慢广播冒充整机未连接。

| 环节 | 策略 |
|---|---|
| 开始计时 | 至少一条 ACL；无 USB/充电/OTG 占用，无录音、播放、文件、RGB、DUT、OTA 等业务及持久存储占用 |
| 空闲期限 | 条件全部就绪后计满 120 秒，不从建链瞬间计时；业务/拓扑变化或恢复后重新评估完整窗口 |
| 不延长窗口的活动 | 纯版本/电量查询、协议空检查、重复状态通知；列表/容量/文件读取属于真实存储业务 |
| 安全关断 | 确认无排队请求、脏缓存、读句柄、删除/保存及在途 IO，完成 SD 卸载和 RGB/SPI 停用后关闭 PA4 |
| 按需恢复 | 真实访问先登记占用再同步恢复；可用后才放行访问，纯 HOGP 报告不需要 PA4 |
| 竞争与失败 | 新业务、USB 或拓扑变化撤销旧关断；停用失败保留供电，恢复失败拒绝访问，不自动格式化 |
| 调度 | 仅空闲期限保留单次超时；忙时等待业务结束事件，不用 1 秒轮询等待空闲 |

共享域恢复与灯效调度分开：恢复 RGB 硬件默认 OFF，不无条件创建灯效定时器；OFF/永久常亮停表，短提示等截止时间，动态效果才短周期续约。

## 3. 踩过的坑

### 3.1 空闲资格不能只看表面状态

| 坑 | 原因与处理原则 |
|---|---|
| 连接后静置很久仍高耗电 | PE5 随未关闭的模拟资源常开，PA4 又被连接永久挡住；分别按实际输出和连接空闲资格管理 |
| 每 5 秒又重新计时 | 缓存空检查被算成业务；空检查与真实脏缓存保存分开，前者不唤醒 PA4、不延长窗口 |
| 查版本/电量也重置空闲 | 协议解析被当成存储 IO；短暂解析占用与真实存储业务分开 |
| 第二入口切慢导致重复等待 | 重复停用被算成新活动；状态通知幂等，连接窗口独立于广播速度 |
| 恢复后不再进入空闲 | 状态通知在恢复途中被提前消费；恢复完成后重新通知评估 |
| 文件请求已排队却仍可能断电 | 只看当前执行任务，漏掉队列和持久句柄；从准入到收尾完整登记占用，投递失败也成对释放 |
| 插 USB 或充满仍进入关电 | 只看“正在充电”；VBUS、充电状态和 USB OTG 一并判断 |

### 3.2 RGB 恢复成功，定时器却绑错了任务

PA4 OFF 后查询文件列表，协议任务同步恢复 SD/RGB。旧 RGB 初始化无条件创建 20 ms 普通系统定时器，定时器随创建者绑定到不处理系统定时消息的 `protocol_recv_task`，随后持续出现 `timer_no_response`。

**这不是大量业务任务超时，也不是 SD 恢复卡死，而是一个灯效定时器的任务归属错误。**

处理与经验：

- 硬件初始化不等于启动周期业务；初始化为 OFF、不建表，灯效回调明确指定 `app_core`，按需安排单次超时。
- 不把整个同步存储恢复搬到主任务后持锁等待，也不把 SPI 放到中断，更不为此新增专用轮询任务。
- 去掉 tick 后补齐绑定等状态通知，用真实时间判断期限；旧回调、迟到 START/STOP 不能覆盖新场景。
- 队列/定时器失败保留待办，复用已有优先级 0 恢复桥接；无法继续灯效时安全灭灯并释放占用，不新增常驻兜底。
- 定位时用对应固件 ELF 找回调，再追创建任务；测试必须经过断电后的真实业务恢复，不能只测开机初始化。

修复后列表和录音唤醒正常，超时告警消失，PA4 开/关约 7/6 mA 的收益保持。

### 3.3 参考分支不能整包照搬

参考分支 `低功耗优化` 证明了独立连接空闲窗口和按实际输出控制功放的方向，但当前分支已先建立未连接低功耗基础设施，应复用而非重复建设。

- 不带回参考分支忙时 1 秒复检，使用现有业务完成事件。
- 闭源库补丁以当前脚本合并并重新生成，不直接复制旧二进制；内部消息标记必须避开已有消息号。
- 强关 DAC 模拟曾导致 MIC 无法拾音，只关 PE5、不绕过 JL 音频资源管理。

## 4. 尚未实施的后续优化

| 方向 | 当前边界与取舍 |
|---|---|
| 阶段 3：按 ACL 协调连接参数 | 现有下载结束后回落仍保留，但不等于完整待机策略；后续补从未下载的 RDX 空闲，并区分纯 RDX、HID 和同链路复合业务，每条 ACL 统一协调，以实际协商结果为准 |
| 阶段 4：业务按待办调度 | HID ready 时仍有 10 ms HOGP 服务，缓存仍有 5 秒检查；后续停表必须保留首键、松键、背压重试与文件保存，不直接删除 |
| CDC 与 JL 原生定时器 | CDC 无有效 DTR 会话已停表，有效会话仍有 10 ms 服务；原生 USB 检测、按键、电池、ADC、时钟未改，盘点见 [6-0](6-0.T2620外设低功耗与共享VDD电源管理设计.md) |
| 阶段 5：双 ACL 休眠门禁 | 一条 ACL 加第二入口广播、或两条 ACL 时仍阻止系统休眠，用于规避 controller 断言；未获得 JL 支持确认前不删门禁、不屏蔽断言、不关闭第二入口换收益 |

后续参数优化遵守 [BLE 下载策略](10-3.BLE下载速度优化专项.md)，不牺牲连续下载与 HID 响应；休眠门禁依据见 [双 ACL 低功耗断言复盘](3-5.BLE双ACL低功耗断言问题复盘与量产最佳实践.md)。当前约 6 mA 不等于系统已经能够充分休眠，也不承诺直接达到未连接的 1.5–3 mA。
