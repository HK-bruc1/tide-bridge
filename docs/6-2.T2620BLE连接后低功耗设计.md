# T2620 BLE 连接待机低功耗设计

> 更新时间：2026-10-16
> 代码基线：`76cf95e1`（`功耗2`）。阶段 1（PE5 跟随实际输出）已实现、待板测；阶段 2 及以后尚未实施。
> 适用工程：T2620 / AC701N（BR28）RDX + HOGP，最多两条 Peripheral ACL。
> 未连接策略与共用基础设施见 [6-0](6-0.T2620外设低功耗与共享VDD电源管理设计.md)，功放原则见 [6-1](6-1.通用功放低功耗设计.md)。本文只维护连接态增量策略、参考经验和验收要求。

## 1. 结论

**保持 ACL 不断开，空闲时关掉不需要的负载（PE5、PA4），再按链路调整连接参数、停掉业务定时器；系统休眠门禁作为独立专项。**

按收益和风险排序：

| 顺序 | 措施 | 预期 | 风险 | 依据 |
|---|---|---|---|---|
| 1 | PE5 跟随 DAC 实际输出 | 大 | 低 | 当前连接后 DAC 模拟不关，功放随之常开 |
| 2 | 连接空闲 120 秒后关 PA4 | 大 | 高 | 参考分支 PA4 + PE5 合计约 10 mA |
| 3 | 按 ACL 调连接参数 | 待测 | 中 | 门禁阻止休眠时收益可能有限 |
| 4 | HOGP 等业务定时器按待办调度 | 小 | 中 | 系统不休眠时只省 CPU 负载 |
| 5 | 双 ACL 休眠门禁 | 大 | 高 | 依赖 JL 修复或确认支持边界 |

不承诺复现未连接的 1.5–3 mA。门禁不解除时，连接态底电流主要由“系统不休眠”决定。

## 2. 目标与边界

- 测量场景：电池供电、USB/VBUS 拔出、正常电量、一条或两条 ACL 在线、无业务也无收尾。USB 在线、充电或充满时不进入连接低功耗。
- 不断开 ACL，不释放 RDX/HID owner，不清除 CCC、加密或绑定，不触发 `rdxclose`；**量产不靠关闭第二连接入口换取功耗**。
- 按键、录音、播放、文件命令在空闲后照常工作，只允许增加可接受的首次恢复延迟。
- 关机、低电保护、DIP 关机、USB/SD 所有权、OTA 安全策略不因省电放宽；关机不等待空闲期限。
- 所有策略由事件驱动、在 `app_core` 串行执行；只为真实期限或重试安排单次超时，**不新增常驻 10 ms / 100 ms / 1 秒的连接态检查器**。

## 3. 现状基线（2026-10-16）

日志：`RDXapp连接静置2分钟了，还没有触发低功耗.log`。单 RDX 连接、静置 2 分钟以上、日志开启，电流约 **16 mA**。

| 项目 | 现象 | 结论 |
|---|---|---|
| 系统休眠 | 连接前 `S<>w[]` 245 次；连接后出现 `system_sleep_block=1 connected=1 second_acl_window=1`，之后再无 `S<>` | 双 ACL 门禁在“一条连接 + 第二入口广播”时阻止休眠 |
| DAC/PE5 | 连接前有 `dac analog close`；连接提示音后只有 `Audio DAC Stop`，没有模拟关闭 | SDK 只在蓝牙已低功耗时关 DAC 模拟，PE5 跟随模拟生命周期，推断一直为高 |
| PA4 | `links_changed links=1 busy=0x41` | 任一 ACL 都阻止关电，SD/RGB 一直供电 |
| 连接参数 | 最终 30 ms / latency 0 / 5 s，固件未发起更新 | 省电档只在 RDX 传输结束后请求，从未下载的连接永远不回落 |
| 日志 | `{}` 约 34 次/秒，另有大量 `{V}`、`q0` | 疑似 controller 逐事件打印，来源未核实；量产需关日志复测 |

## 4. 参考分支 `低功耗优化` 的经验

该分支与当前分支同源于 `976cceb1`，已在**未清理定时器之前**完成连接态 PA4/PE5 优化：`c99cc157`（P1 观察）、`b67ce005`（P2 只卸载）、`bf833eec`（P3 断电 + PE5）。实测单 RDX、日志开启，**约 17 mA → 7 mA**；PA4 与 PE5 各自贡献未分开测。剩余约 7 mA 同样归因于双 ACL 门禁，其日志连接后也是 `system_sleep_block=1`。

**可借鉴：**

- 连接态独立 120 秒空闲窗口，与未连接共用同一停用/恢复执行器，按“仅观察 → 只卸载 → 实际断电”三级上板。
- PE5 改为 `模拟就绪 && 正在输出`：用 `media.a` 的弱函数 `_audio_dac_status_hook` 获取 DAC START/STOP，同时保留 `audio_dac_power_state` 的模拟就绪门禁。
- 外部电源判定同时看 VBUS、充电状态和 USB OTG，任一非空闲即不进入。

**不能照搬：**

- 它业务忙时用 1 秒周期复检，违背当前“无待办不留定时器”的原则，应改为业务结束事件触发。
- 它修改了 `librdxApp_patched.a` 和补丁脚本，当前分支也改过；只能合并脚本后重新生成库，不能直接取二进制。
- 新增的 `rdx_power_query.c`、`rdx_adv_policy.c` 业务计数接口、消息标记位调整需逐项核对后移植。

**踩坑记录（移植时必须覆盖）：**

| 现象 | 原因 | 处理 |
|---|---|---|
| 空闲期限每 5 秒后移 | RDX 库缓存刷新定时器空检查也发布“业务活动” | 只在真正保存脏缓存时计业务 |
| 查版本/电量也刷新计时 | 协议解析被当成 IO 业务 | 解析占用与 IO 占用分开 |
| 恢复后不再重新计时 | 恢复期间的观察消息被提前消费 | 恢复成功后补发一次状态通知 |
| 内部消息被误判为业务 | pending 标记位 bit30 与已有消息号冲突 | 改用 bit29，C 与补丁库同步 |
| GETLIST 排队期间可能被断电 | 库内直接投递消息，未登记占用 | 改走带占用的投递接口，失败回 ACK=1 |
| 插 USB 或充满后仍计时 | 只判断“正在充电” | VBUS、充电状态、USB OTG 任一非空闲即忙 |
| 失败补偿改写状态 | 补偿在调用者上下文执行 | 窗口与定时器只在 `app_core` 修改 |
| 强关 DAC 模拟省约 10 mA，但 MIC 无法拾音 | BR28 DAC 模拟全关会连带 ADC 共享资源 | 回退；只控 PE5，不绕过 SDK 准入 |

## 5. 策略

### 5.1 PE5：跟随 DAC 实际输出

- `PE5 = analog_ready && output_running`：DAC START 拉高，STOP 立即拉低；模拟未就绪、INIT 或未知状态一律拉低。
- 不强关 DAC 模拟，不绕过 SDK 的低功耗准入，保证 MIC 拾音和提示音不受影响。
- 仍由 `rdx_peripheral_power_amp_set()` 唯一写脚，与 BLE 状态、PA4 无关。边沿日志在中断内记录、`app_core` 打印。
- 不依赖连接态计时，未连接同样受益；6-1 第 6、7 节已同步。
- 状态：已实现（`rdx_peripheral_power.c` 覆盖 `_audio_dac_status_hook`，`TCFG_T2620_AMP_TRACE_ENABLE` 默认 0），主机测试 `test_amp_output.py` 对照 `media.a` 校验回调 ABI；连接待机电流、MIC、提示音待板测。

### 5.2 PA4：连接空闲后关共享 VDD

**资格判定与执行器分离。** 零 ACL 沿用 6-0 慢广播资格；有 ACL 时使用连接态资格，两者共用 `ON_READY → STOPPING → OFF → STARTING`、`QUIESCED_ON`、`FAULT_ON` 执行器。所有停用复检都使用当前生效的资格，不能前面允许有连接、最后又要求零连接；也不能只删 `BLE_LINK` 忙位或伪造慢广播通知。

连接态资格：

- 建链初始化、提示音、恢复完成且无占用后，开始完整 120 秒计时；配置独立于广播的 `ADV_IDLE_MS`。
- 录音、播放、文件扫描/传输/索引、格式化、异步 worker、排队业务、CDC 和收尾都算占用；结束后重新计满。
- 保活、内存查询、纯 HOGP 报告不重置计时，也不要求 PA4 上电。
- 普通连接提示灯不永久阻止计时；充电、低电、DUT、OTA、USB MSC 等门禁不变。
- 拓扑变化使旧期限失效；最后一条断开后回到 6-0。

访问顺序：**校验请求与身份 → 同步登记占用并取消待执行的关断 → 确认恢复成功 → 执行业务 → 最后一次异步访问和收尾完成后释放占用。** 覆盖 RDX 文件命令（含预编译库内延后访问）、录音/播放存储、RGB SPI/DMA、USB MSC 交接。非法或非 owner 请求不能先唤醒存储再判权限；恢复失败拒绝访问、不自动格式化。

### 5.3 按 ACL 切换连接参数

现有参数表：传输快档索引 0 `{6, 6, 4, 600}`（7.5 ms），省电档索引 8 `{60, 80, 19, 2000}`（75–100 ms / latency 19 / 20 秒）。快档约 2 秒重试、最多 3 次；传输结束约 5 秒后请求省电档。依据见 [10-3](10-3.BLE下载速度优化专项.md) 第 29、30 节，连续下载不得回退。

| 链路业务 | 参数原则 |
|---|---|
| 建链、发现、配对、尚无 owner | 兼容默认参数，完成后进入待机评估 |
| RDX 传输 | 快档意图，按实际参数和背压运行 |
| 仅 RDX 空闲（含从未下载） | 以省电档为候选，**补齐当前缺口** |
| 仅 HOGP，或 RDX + HOGP 同链路 | 兼顾按键响应的待机档，不套用纯 RDX 省电档 |
| 两条独立 ACL | 各自决策，互不提速 |

HID 候选（实测起点，不冻结）：H1 15 ms / lat 4 / 4 秒；H2 30 ms / lat 4 / 5 秒（首选）；H3 45–60 ms / lat 2 / 6 秒。监督超时满足 `timeout > 2 × (1 + latency) × 最大 interval` 并留余量。

协商约束：每条 ACL 只有一个参数协调者；纯链路决策校验槽位与代次，业务意图校验 token；意图、请求中、实际参数三态分离，只有连接更新完成事件才更新实际值；迟到更新按最新需求重评；有限重试，预算耗尽后按实际参数服务。

### 5.4 业务定时器

| 模块 | 状态 |
|---|---|
| DUT、DIP/USB、CDC | 已事件化，直接复用 |
| HOGP | HID ready 时仍保留 10 ms 服务；改为有输入、待发报告、重试或清理才调度 |
| 文件缓存 | 干净无待办即停表，沿用 6-0 后续事项 |
| JL 原生 USB、按键、ADC、电池、时钟 | 不改，只实测 |

HOGP 停表前必须覆盖首键、连按、长按、松键零报告、ATT 背压、订阅/加密/挂起变化；“没有新按键”不等于“上一份报告已完成”。系统不休眠时，这一项只降低 CPU 负载，排在 PE5/PA4 之后。

### 5.5 双 ACL 休眠门禁

| 拓扑 | 门禁 |
|---|---|
| 零 ACL；或一条 ACL 且第二入口关闭 | 允许休眠 |
| 一条 ACL 且第二入口广播；或两条 ACL | 阻止休眠 |

门禁用于规避预编译 controller 的双 ACL 低功耗断言（`bb_le_power.c:352`），见 [3-5 复盘](3-5.BLE双ACL低功耗断言问题复盘与量产最佳实践.md)。本设计不删门禁、不屏蔽断言、不自动关闭第二入口。可选方向（均需 JL 确认和断言专项回归）：

1. 验证“一条 ACL + 广播 + 休眠”是否稳定，若稳定仅在双 ACL 时阻止休眠；
2. 产品层面评估首连后第二入口的开放窗口，需产品确认，不作为默认方案。

## 6. 诊断开关（非量产）

`TCFG_RDX_BLE_CONN_LP_DIAG` 是临时测量补丁，当前代码中不保留；需要阶段 0 数据时临时加入 `rdx_ble_server.c`，**不得提交**：

- `bit0`：连接 15 秒后按物理链路请求索引 8 省电档（含仅 HID 链路）。
- `bit1`：已有连接时不开第二入口广播，使门禁放行。会关闭第二连接入口，量产禁止。

每组配置记录实际参数（`[RDX_BLE_PARAM] update`）、`system_sleep_block`、`S<>` 是否恢复、PE5/PA4 和至少 1 分钟平均电流，并各做一次关日志对照。

## 7. 分阶段实施与验收

| 阶段 | 变更 | 放行条件 |
|---|---|---|
| 0 基线 | 诊断开关测门禁和参数各自占比 | 数据可复现，开关恢复为 0 |
| 1 PE5 | 跟随 DAC 实际输出 | 提示音、播放、录音 MIC 正常；连接空闲 PE5=0 |
| 2 PA4 | 连接态资格 + 访问入口，依次验证仅观察、只卸载、断电 | 不断连；首个文件/录音/灯效可恢复；文件完整 |
| 3 参数 | 统一按链路协调，测 HID 候选 | 不断连，首键与连续下载不回退，无请求竞争 |
| 4 停表 | HOGP 按待办调度 | 输入/释放/收尾不丢 |
| 5 门禁 | 独立专项 | JL 确认 + 双 ACL 长稳 |

每阶段独立可回退，不用后续收益代替本阶段验收。

| 指标 | 场景 | 基线 | 目标 |
|---|---|---|---|
| 平均电流 | 单 ACL 仅 RDX 空闲，第二入口开放 | 16 mA | 阶段 1–2 后 ≤ 7 mA（参考分支） |
| 平均电流 | 单 ACL 仅 HOGP / 双 ACL 空闲 | 待测 | 待定 |
| 首键延迟 | 空闲 ≥ 2 分钟后按键 | 待测 | 待定 |
| 首条下行响应 / 下载吞吐 | 空闲后首条命令 / 连续下载 | 待测 | 不低于现有基线 |
| 外设恢复耗时 | PA4 OFF 后首次文件访问 | 待测 | 待定 |

回归矩阵：

- **拓扑**：仅 RDX、仅 HOGP、同链路复合、两条独立 ACL、未认领、`rdxclose` 后保留 HID；零/单/双 ACL 转换。
- **业务**：空闲后首键、连按、长按；首条命令、文件首包、连续下载；录音、播放、提示音、灯效。
- **并发与失败**：期限边界上的新业务、STOPPING/STARTING 期间请求、卸载/挂载失败、消息或定时器投递失败、断链后的旧命令。
- **电源**：休眠时插拔 USB、拨码 OFF、低电关机；PA4/PE5 实测电压和上电波形。
- **回归**：6-0 未连接慢广播、DUT、DIP 关机保护、全部断开后的休眠恢复、双 ACL 长稳与 controller 断言。

## 8. 维护入口

源码均位于 `SDK/apps/common/third_party_profile/rdx_protocol/`：

- `rdx_peripheral_power.c/h`：PA4 执行器、PE5 控制、连接态资格。
- `rdx_adv_policy.c`、`rdx_storage_lifecycle.c/h`：业务占用、存储准入、未连接策略。
- `rdx_ble_server.c`、`rdx_ble_session.c/h`：拓扑、实际参数、传输调度、token、休眠门禁、诊断开关。
- `rdx_hogp_input.c`、`rdx_hogp_key_action.c`：HID 输入与报告调度。

实施后同步更新本文状态、6-0 边界和 6-1 第 7 节。主机测试和构建只验证软件约束，功耗与首次业务恢复必须实机验收。
