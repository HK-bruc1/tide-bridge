# 10-6. 录音提示音设备端方案

> 更新：2026-10-23。设备端已实现并通过主机测试；APP 对接与实板验收待完成。
> APP 对接协议见 [10-7. 录音提示音APP对接说明](10-7.录音提示音APP对接说明.md)。

## 1. 目标

关闭录音的开始/结束提示音，省掉开始时等待提示音播完的时间，让录音更快开始。为此新增一个设备级开关「录音提示音」，由 APP 查询和设置。

## 2. 功能约定

| 项目 | 约定 |
| --- | --- |
| 开启（默认） | 与原行为一致，播放开始、结束提示音 |
| 关闭 | 不播放开始、结束提示音，开始时不等待 |
| 适用范围 | APP 录音、F18 会议、F19 灵感；在线/离线、CHAT/CALL 均适用，与物理键无关 |
| 不影响 | 工厂/DUT 音频、系统提示音（连接、电量、开关机等）、存储不足等异常告警 |
| 不改变 | 录音选路、推流/存储策略、暂停/恢复规则、灯效和低功耗策略 |
| 保存 | 设备本地持久保存；断连、释放 RDX、换 APP、重启后保持 |
| 恢复出厂 | 整机恢复出厂后恢复为开启；单独重置配键不影响 |

这是一个设备级设置，不区分 APP、连接对象或录音类型；设备是唯一的配置来源。

## 3. 设备行为

### 3.1 开机

开机读取保存的设置。设置不存在、损坏或读取失败时按开启运行，不主动补写默认值。

### 3.2 查询与设置

- **查询**：随时可用，录音期间也可以查。返回当前生效值，不访问存储。
- **设置**：只在录音业务完全空闲时执行。正在录音、等待 APP 开始、提示音播放中、停止收尾中，或处于工厂测试、OTA、格式化、关机、恢复出厂等状态时，直接拒绝并回复「忙」，不排队等待之后自动执行。
- **保存确认**：先写入存储并回读校验，一致后才生效并回复成功。保存失败时保持原值并回复失败；之后再设置同一个值也会重新写入。
- **会话绑定**：请求只在收到它的 RDX 连接上执行和回复。连接已断开或被替换时不执行，也不会把旧应答发给新连接。

### 3.3 录音接入

每次录音开始时锁定当时的设置，整次录音（包括暂停/恢复和结束）都按这一份执行，录音中途不会改变。

- **开启**：保持原逻辑，开始提示音完整播放后才开始录音，结束时播放结束提示音。
- **关闭**：不创建提示音播放，直接进入原有的录音启动流程；结束时也不播放。只跳过声音，原有的录音资格检查、松开取消、状态上报、灯效和停止收尾全部照常执行。
- 原本取消后不播放结束提示音的场景，关闭后同样不播放。

关闭后不会因为提示音而打开功放；本功能不直接控制 DAC、ADC 或功放，硬件是否开启仍由实际音频业务决定。

### 3.4 恢复出厂

整机恢复出厂时一并把本设置写回开启并校验。写入失败则恢复出厂整体失败、不重启，不对外报告恢复成功。

## 4. 时延收益（单样本估算）

日志 `COM3_2026-10-23_18-04-46.log` 中一次在线灵感样本：

- 开始提示音从开始播放到结束约 **441 ms**。
- 长按受理到首个有效音频处理点约 1.12 s，关闭提示音后估计约 0.68 s。

这是单样本推算，不是实测值。关闭结束提示音不会缩短录音启动时间。各录音入口的实际收益需要分别板测。

## 5. 验证

主机测试已覆盖：协议解析、默认值与恢复出厂、保存失败、忙保护、连接隔离、默认 MTU 分包，以及各录音入口在开关两种状态下的开始/结束行为、工厂/DUT 隔离。2026-10-23 统一入口 22 项中 19 项通过；3 项失败是与本功能无关的过时资源断言，跳过这些断言后，三个套件余下的检查全部通过。

实板验收清单：

- 默认开启；设置后断连、重启保持；整机恢复出厂恢复开启，单独重置配键不变。
- 关闭后，APP/F18/F19 在在线和离线下都没有开始/结束提示音；开启时与原行为一致。
- 录音中设置被拒绝；查询正常。
- 早松开、迟到开始、快速连按、录音中断连都能正常收尾，下一次录音不受影响。
- 工厂/DUT、系统提示音、存储不足告警不受影响。
- 开关两种状态各做多轮时延与首字音质对比。
