# T2620 未连接慢广播低功耗与共享 VDD 设计

> 更新时间：2026-10-19
> 当前结论：**独立 LRC 正常业务版未连接慢广播实测 0.6–1.6 mA 跳动，用户确认可以并锁定本阶段收益。** 证据为 `COM3_2026-10-19_20-11-56.log` 与用户仪表反馈；日志同时记录低功耗后建链、APP 录音/停止保存、断连后再次进入慢广播并关闭 PA4。这是显示波动区间，不是积分平均值或全部业务、量产可靠性验收。
> 当前实施：`TCFG_T2620_LOWPOWER_LRC_ENABLE=1` 保持默认开启，保留正常按键、USB/CDC、动态调频、安全保护及原 **500 ms 可连接慢广播**；启动时配置原生睡眠时钟，不随快慢广播切钟。**后续优化暂不执行，只保留为方向，不再制作 A/B 双包或引入其他降耗改动。** 组合门禁另存实验分支，其 0.6–1.3 mA 历史结果不混作业务版结果。
> 阅读顺序：第 1 节看已锁定收益与暂缓方向，第 2–3 节看现行基础设施，第 4 节看踩坑，第 5 节看实现、板测证据及边界，第 6 节保留实验机制及证据。连接态独立结论见 [6-2](6-2.T2620BLE连接后低功耗设计.md)。

## 1. 当前结论与收益优先级

**本页始终优化零物理 ACL、保留原 500 ms 可连接慢广播时的功耗。** 不停广播、不延长广播间隔、不降低 RF 功率，不把第二入口关窗、断开已有连接或关机的电流计入本场景。

### 1.1 已取得的结果

| 阶段 | 实现与验证状态 | 用户电流观察 | 本轮决策 |
|---|---|---|---|
| 现行业务基础设施 | CDC/HOGP 无会话停表、PA0 所有权清理、PA4 安全关电及 PE5 按输出控制；已测场景保留 | 快广播 4–5 mA；慢广播 1.5–3 mA，历史录音正常 | 不撤回、不重复记功 |
| 后续事件化 | DUT、DIP/USB 产品服务事件化；DUT 与拨码开关机已获用户确认 | 未拆出单项电流收益 | 作为现行方案保留 |
| BT_OSC 组合探底 | 普通按键停扫、USB 检测暂停、锁 24 MHz、PA4/PE5 已关闭 | 日志版约 1.5–2 mA；静默版约 1.3–1.8 mA | 收益有限；不能认定已到硬件下限 |
| LRC 组合探底 | 保持上述组合，增加原生 LRC 睡眠时钟；仅实验分支 | 0.6–1.3 mA 跳动，用户确认探底目标达成 | 历史方向证据，不作为正常业务基线或精确单项节省量 |
| **LRC 独立正常业务版** | 本分支只启用原生 LRC，保留正常业务；两次零 ACL 慢广播/PA4 OFF，中间完成建链及 APP 录音停止保存 | **0.6–1.6 mA 跳动，用户确认本阶段收益锁定** | **保留默认开启；后续优化暂不执行**，证据与剩余验证边界见第 5 节 |

电流来自用户仪表观察，不由串口日志推算。没有固定窗口积分结果，不用区间中点计算“平均低于 1 mA”，也不从区间端点相减生成精确节省量/百分比。保留用户对业务版收益的确认，不再标为“功耗待板测”；同时不将阶段锁定扩大为量产平均功耗或所有功能验收。

### 1.2 收口决策：保留 P1，其余仅作优化方向

| 顺序 | 因素 | 收益证据与取舍 | 实施状态 |
|---|---|---|---|
| 已有底座 | PA4/PE5、业务停表、接收阻塞与缓存按需保存 | 必须继续保留；混合历史收益不再拆算或累加 | 已实现，回归边界见第 2–3 节 |
| **P1** | **原生 LRC 睡眠时钟** | 正常业务版实测 0.6–1.6 mA，用户确认锁定 | **已实现并锁定本阶段功耗收益，默认保持开启**；不等于量产验收 |
| **P2** | 调试输出减负 | BT_OSC 静默版只见小幅变化；正常业务日志版 LRC 已满足本阶段要求 | **暂不执行**；若重启优化，再比较同配置 trace/quiet，不直接关闭整个 UART |
| **P3** | USB 原生检测按需化 | 250 ms 检测可能带来残余唤醒，但组合未给出独立收益，恢复链路风险高 | **暂不执行**；保留原生检测，未来必须先证明独立可靠的 VBUS 恢复链路 |
| **P4** | CPU 调频尾部与普通键扫描 | 探针生效前原生 CPU 已回到 24 MHz；优先级 0 键扫描不能按标称 10 ms 认定高收益 | **暂不执行**；保留动态调频和普通键扫描，未来先看活动占空比证据 |
| 按证据重排 | MIC/PA0、共享域反灌、板级底流 | 尚无证据指向具体负载；若剩余电流主要为脉冲间底流，应优先于继续删软件定时器 | **仅保留排查方向**，本阶段不新增供电/寄存器改动 |

**P1 已达到用户本阶段要求，按用户决定停止继续优化；P2–P4 不自动进入实施，也不是已经量出的收益排行榜。** 若未来明确重启优化，再以 0.6–1.6 mA 业务版观察为参照，补齐固定条件和平均值，每次只验证一项。现有测试边界继续保留，但不是开启新优化的授权。

## 2. 已实现的正常业务方案

**无 BLE 连接、无 USB 接入且无业务时，停止无意义的软件高频轮询；连续空闲 120 秒后进入慢广播，安全关闭 SD NAND/RGB 共享供电。功放独立按实际音频输出开关。**

### 2.1 适用范围

- 两条 Peripheral ACL 的实际连接总数为零。RDX 逻辑退出但 HID 或物理链路仍在，不属于未连接。
- 正常开机、电池供电、USB/VBUS 物理拔出。充满或停止充电不等于拔线。
- 无录音、播放、文件、DUT、OTA 等业务，也无排队请求、资源占用或收尾。
- 关机与低电保护独立执行，不等待低功耗空闲期限。

### 2.2 空闲与唤醒

| 状态 | 策略 |
|---|---|
| 开机或最后一条链路断开，且无业务 | 快广播，开始完整 120 秒空闲窗口 |
| 有效用户操作或新业务 | 恢复/保持快广播；访问 SD/RGB 前先恢复共享域 |
| 业务进行中、待启动、暂停占用或正在收尾 | 保留所需供电，不消耗空闲窗口 |
| 全部业务及文件、缓存、索引收尾完成 | 重新开始完整 120 秒空闲窗口 |
| 连续空闲满 120 秒 | 切慢广播；共享外设安全停用后关闭 PA4 |
| 新业务、建链或 USB 接入 | 撤销旧关断请求，按新状态处理 |

灯效刷新、后台空检查和重复结束通知不算用户活动。广播速度与外设供电分别判断，必要灯效可保留 PA4，但不应永久保持快广播。

**无用业务定时器应立即停止，不必等待 120 秒。** 120 秒是空闲窗口，不是广播包间隔，也不是允许软件空转的时间。

连接态自动慢参数已因交互退化停止采用，见 [6-2](6-2.T2620BLE连接后低功耗设计.md)。这不影响未连接快/慢广播。正常业务固件的历史慢广播基线为 **1.5–3 mA**；独立 LRC 后本阶段已锁定 **0.6–1.6 mA 跳动**。第 6 节的 0.6–1.3 mA 仍只属于历史实验版，不替换本轮业务版读数。

### 2.3 外设供电与安全边界

原理图 `T2620-MMI-V00_20260608.pdf` 确认三个独立控制域：

| 引脚 | 供电对象 | 管理原则 |
|---|---|---|
| PA0 / `MIC_BIAS_CE` | MIC | 由 JL 原生 ADC/MIC_LDO 生命周期管理；业务申请/释放采集通路，不直接写脚 |
| PA4 / `VDD_EN` | SD NAND + RGB | 共用一条电源轨，统一停用与恢复，不能由两个业务各自断电 |
| PE5 | 外置功放 | 模拟就绪且 DAC 实际输出时开启；无输出时关闭，与 BLE/PA4 解耦 |

共享 VDD 的安全规则：

- 未连接时必须满足零 ACL、有效慢广播、无共享资源占用；连接时使用 [6-2](6-2.T2620BLE连接后低功耗设计.md) 的独立资格，共用同一执行器。
- 先完成文件/缓存/索引收尾及 SD 卸载，再停止 RGB、SPI 并设置安全 IO，最后断电。
- 新业务先登记占用，再恢复共享域；恢复成功前不得访问 SD/RGB。关断中出现新请求，应取消旧关断。
- 无法确认空闲或停用失败时保留供电；恢复失败拒绝访问，不自动格式化，不以省电牺牲数据。
- USB 存储接管、必要灯效与离线音频照常工作，不因 BLE 未连接而强行关电。

功放的通用原则见 [6-1](6-1.通用功放低功耗设计.md)。

## 3. 慢广播定时器现状与取舍

以下针对零 ACL、无 USB、正常电量、无业务且 PA4 已关闭的稳定慢广播场景。按职责区分项目业务与 JL 框架，不按文件目录区分；结论来自源码及链接实现，不是板端活动定时器快照。

### 3.1 项目业务定时器

| 模块 | 现行策略与剩余项 |
|---|---|
| CDC 协议 | 无有效 DTR 会话停表；有效会话仍保留 10 ms 服务。USB 插入或仅充电不等于 CDC 会话有效 |
| HOGP 输入 | HID 未就绪时停表；已连接、已订阅、已加密且未挂起时仍有 10 ms 服务，在线按需化留待后续 |
| DUT | 已取消待命 1 秒和模式内通用 10 ms 服务；八击、BLE/CDC 指令及完成事件触发，仅真实期限/重试保留单次超时 |
| DIP/USB 产品服务 | 已取消常驻 100 ms 系统轮询；PB1 边沿、USB/VBUS 和业务事件触发，实际重试/收尾使用单次超时 |
| DIP 保护与恢复桥接 | 保留两个常驻 100 ms、优先级 0 的用户定时器：独立关机保护，以及失败待办恢复；不是一次性定时器，但不要求按周期主动唤醒 |
| RGB | OFF/无期限常亮不建表；短提示按截止时间，动态效果才按 20 ms 续约；恢复硬件不会自动启动周期服务 |
| 广播/共享 VDD | 120 秒切慢超时完成后退出；未连接的忙/待关断阶段保留必要的 1 秒复检，稳定关电后不常驻 |
| 文件缓存 | RDX 第三方库业务，非 JL 原生：原为启动 10 秒后每 5 秒自续约检查；现改为按需调度，干净停表，变脏后固定 5 秒保存，临时忙时才重试。保留同步保存和 IO 失败脏位；单 RDX 板测仍约 4/2 mA，新增功耗收益未量化，作为基础设施保留，写入持久化待验收 |
| RDX 接收任务 | 已改为信号量无限等待，只有成功出队才刷新业务算力，空通知后重新阻塞；发送/文件任务维持空闲阻塞。原生调频检测回调固定在 `app_core`，不依赖协议任务分发定时消息；上一阶段单 RDX 主路径已测，断连慢广播收益保持，其他功能回归待完成，见 6-2 |
| CDC 传输、录音、播放及保护灯效 | 仅业务或保护条件有效时存在；目标无业务场景应无残留 |

DIP 开机依靠 PB1/P33 唤醒，不依赖系统轮询；边沿后有限消抖，接受 OFF 后按原生流程退出，保留不依赖 `app_core` 的约 3 秒复位保护。两个优先级 0 检查不等于原 100 ms 产品系统轮询仍在运行。

DUT 八击由原生按键事件识别，不需要待命定时器。连接、USB 在线或已经进入 DUT，也不是保留空转周期的理由；不能把未连接时的轮询转移到其他状态。

### 3.2 JL 原生框架定时器

| 模块 | 现状与取舍 |
|---|---|
| USB 热插拔检测 | 默认 250 ms 系统检测，转换期可能为 50 ms；无 USB 时仍可能唤醒，暂保留，不与 CDC 协议混淆 |
| 电池/低电检测 | 约 10 秒启动一轮短时高频采样；保留安全保护，不是泄漏的永久 10 ms 服务 |
| IO 按键 / ADC | 标称 10 ms / 5 ms、优先级 0；保留首次按键、手势和采样能力，不据标称频率推算主动唤醒次数 |
| 时钟校准、RTC/P11 维护 | 保留平台时间基准；优先级 0 检查与临时校准按实际初始化路径存在 |
| 调频、VBUS 消抖、SD 检测 | 按启动、边沿或异常阶段运行，不全部计入稳定待机常驻项 |

**先处理阻碍降频/睡眠的机制，再按实测边际收益处理残余唤醒。** 接收事件化和缓存按需保存继续保留；缓存的写入、下载、删除及重启持久化仍需验收，见 [6-2 第 4.6 节](6-2.T2620BLE连接后低功耗设计.md)。连接态第二入口窗口的约 4/2 mA 不属于零连接结果，也不是缓存增量或 PA4 开/关的单独贡献。

第二入口期限独立于 PA4 空闲期限，不改变零连接快慢广播；关闭确认失败时仍保留原睡眠保护。USB 原生检测若改为 VBUS 驱动，必须先有独立可靠的恢复事件，不能删掉检测后又依赖它产生插入事件。普通按键、电池、时钟保护不作为直接删减对象；P1 只改睡眠时钟配置，不改本节定时器。

## 4. 功耗排查经验

### 4.1 关了外设，不等于系统充分休眠

分开看外设负载、软件唤醒和芯片休眠条件。灯灭不代表 SPI/SD/LDO 已停用；日志显示 PA4 已关，也不能代替电气测量。`sys_timer/sys_timeout` 到期仍会唤醒，单次超时不断自续约也属于轮询；优先级 0 用户定时器则允许休眠时跳过节拍，不能混算。

### 4.2 无会话高频定时器会吃掉慢广播收益

曾在 PA4 已关闭的情况下出现慢广播电流回退。根因之一是 CDC/HOGP 无会话也常驻 10 ms 服务：回调发现无业务直接返回，仍然付出了唤醒成本。处理是按有效会话启停，并保留输入、收尾与失败恢复事件，而不是单纯延长周期。

### 4.3 旧 VDD 名称掩盖 PA0 所有权冲突

旧 `VDD_POWER_PORT_IO` 错指 PA0，开机、DUT 和旧存储路径会绕过 JL 框架改写 MIC 供电。已清理这些历史写脚，存储供电统一交给 PA4 管理器。**不能只把旧宏改成 PA4**，否则旧上下电逻辑仍会绕过 SD/RGB 安全停用。这是长期隐患，不能单独归因为本次功耗回退。

### 4.4 停表不能丢掉原来隐含的恢复能力

移除轮询时同步补齐状态通知、首次输入、松键、异步收尾和失败待办恢复。超时不等于资源已释放；消息投递失败也不能丢弃待办。复用既有优先级 0 桥接，仅实际待办才投递任务，不再添加常驻系统兜底。

### 4.5 外设重新初始化会改变定时器所属任务

PA4 OFF 后，文件查询在协议任务恢复 RGB，普通系统定时器随创建者绑定到了不分发定时消息的任务，造成持续 `timer_no_response`。修复将硬件初始化与业务调度分开，RGB 初始化为 OFF、不建表，灯效明确交给 `app_core` 按需执行。告警应先用对应 ELF 定位回调并追创建任务，不能把告警条数当成失败业务任务数，也不能只测试开机初始化。连接态复盘见 [6-2](6-2.T2620BLE连接后低功耗设计.md)。

### 4.6 CPU 低频不等于睡眠时钟已优化

首轮组合已经 PA4 OFF、USB 停检、CPU 24 MHz，仍有 1.5–2 mA。遗漏项是工具配置的 `TCFG_LOWPOWER_OSC_TYPE=OSC_TYPE_BT_OSC`：CPU 运行频率与睡眠时钟是两条配置链。LRC 组合降到 0.6–1.3 mA 后，不能再把 1.5–2 mA 当成“只有广播时的物理下限”。采用原生 LRC 配置，不直接关闭晶振、不修改 `btosc_disable`，保留 SDK 选择/回退和校准。

独立业务版随后在保留 USB 检测、按键和动态调频时取得 0.6–1.6 mA，说明本阶段无需搬入其余探底限制即可满足用户要求；不据此声称这些模块完全不耗电，或已经精确量出 LRC 的独立节省量。

### 4.7 睡眠次数与软件广播状态都不是完整电气证据

BT_OSC 与 LRC 组合的睡眠进出计数均约 4 次/秒，而电流明显不同。计数不说明驻留时间、睡眠深度、底流或 RF 次数。`slow_adv=1` 是软件/原生接口状态，不是空口抓包；扫描 App 的旧条目也不是持续广播证据。电流验收须同时核对活广播和测量条件。

### 4.8 实验成功不等于整包正式化

探针从开机禁用普通按键，准入后停止 USB 检测、锁频并拒绝新的共享域业务。这些正是“不担心业务影响”的实验条件，不是正常产品策略。迁出 LRC 时必须退出探针，恢复完整业务路径；不能为了保住实验数字而丢掉首次按键、USB 插入、建链后提频或文件恢复。

## 5. 独立 LRC 收口与验收边界

### 5.0 已实现方案的验收边界

- CDC/HOGP 按会话停表与 PA0 清理后的快广播 4–5 mA、慢广播 1.5–3 mA 和录音正常，是历史组合初测；未拆出三项单独贡献，不替代 MIC 供电或 DUT 录音/喇叭切换专项。
- DUT 事件调度与 DIP/USB 产品服务拆分已实现，用户分别确认 DUT 相关业务及拨码开关机正常；未明确覆盖的 USB 枚举、DTR 开关、拔线收尾、USB/BLE 共存及功耗不据此全部验收。

- 历史单连接探针约 2.5/1.5 mA 的备份 `实验性组合探针打底`（`2893e900`）不整包恢复。连接态后续实现及剩余验收见 6-2；本页新增 LRC 也不自动升级为所有 USB/HID 组合、异常或量产长稳通过。

### 5.1 P1：独立 LRC 正常业务方案，收益已锁定

只把已显示大收益的原生睡眠时钟配置迁出组合，**不同时优化 USB、普通键扫描、UART 或 CPU 调频**。

- 配置入口仍为 `SDK/apps/earphone/include/t2620_project_config.h`，新增 `TCFG_T2620_LOWPOWER_LRC_ENABLE`，**本阶段锁定默认 `1`**。仅覆盖 `TCFG_LOWPOWER_OSC_TYPE=OSC_TYPE_LRC`，经 `power_config.c` 的 `power_param.osc_type` 交给 SDK。设为 `0` 并重新构建则跟随工具配置，目前为 BT_OSC。
- 本分支不包含组合探针实现，也不定义三个 `TCFG_T2620_IDLE_PROBE_*` 实验开关；若旧构建参数将任一实验开关设为非零，则编译拒绝，防止混用。LRC 开关非法值或启用 LRC 时未开启原生低功耗同样报错。
- 保留普通按键、USB/CDC 与充电、动态调频、文件/录音/播放、PA4/PE5、BLE 参数及安全保护。保留现有日志，只在原生 `power_init()` 后增加一条启动快照，不新增周期任务。
- **这是全生命周期的启动配置，不是慢广播切 LRC、快广播切回 BT_OSC。** LRC 是睡眠计时源，不代替 CPU 工作时钟和蓝牙射频所需时钟。不调用强制切钟 API；SDK 仍可按实际需要选择/回退。因而连接态、快广播和业务恢复必须回归，不能因本页只研究未连接而跳过。
- 本轮状态为“正常业务版未连接慢广播收益已获用户确认并锁定”，不是仍待测的探底候选，也不代表量产默认已完成所有验收。保留配置回退能力：若后续发现明确回归，将开关改为 `0` 后构建、刷机，无需撤回已验收基础设施。

启动快照示例：

```text
[T2620_LP] sleep_clock product_lrc=1 cfg=0 default=0 selected=0 (0=LRC 1=BT_OSC)
```

快照仅表示启动时配置和选择，不表示后续慢广播始终使用该时钟；`selected=1` 时保留现象排查，不强制切钟或宣称 LRC 持续生效。业务版不应出现 `[IDLE_PROBE] applied`，也不要求 `usb_stopped=1` 或 CPU 永久 24 MHz。

## 6. 零连接慢广播组合探底（实验，非正式策略）

**本节为实验分支的历史机制与证据，保留踩坑经验，不代表当前业务分支含有这些代码。** 用户已将组合门禁另起分支保存；以下实验开关、`test_idle_probe.py`、日志与旧固件归档均属于该实验上下文。当前单项实现与烧录入口以第 5 节为准。

### 6.1 目标与不变量

用户要求先测“保留慢广播时能到多低”，允许牺牲业务，再根据组合收益决定是否拆分正式优化。**零 ACL + 慢广播持续可发现，是本实验不可移除的条件。** 不是无射频实验，也不是关机电流测试。

- 保持现有 `RDX_BLE_ADV_INTERVAL_LOW=800`，即 500 ms；不延长间隔、不改变 `ADV_IND`、广播信道、广播内容、Scan Response 或 wrapper 拓扑。
- 不调用探针专用停广播接口，不覆盖任何 `is_idle` 返回值，不取消 controller 断言。既有广播协调器继续独立管理快/慢广播和广播故障。
- 仅零连接、电池供电、USB/VBUS 拔出、无业务/收尾且 PA4 已由现有管理器安全关闭、PE5 已关闭时准入。不能以快广播、关广播或外设仍供电的读数冒充目标状态。
- 未连接基础电流历史为 1.5–3 mA；本轮组合用户观察见 6.5，不能认定为物理下限，不引用连接态 1.5 mA 作为本场景结果。

### 6.2 组合措施与保留项

| 因素 | 实验措施 | 边界 |
|---|---|---|
| BLE 慢广播 | **完整保留原 500 ms 可连接广播** | 手机必须仍能扫描到；扫描请求/响应会影响读数，测试扫描条件必须一致 |
| SD/RGB、功放 | 等待既有安全流程关闭 PA4、PE5；实验生效后拒绝新的共享域/存储业务准入 | 不跳过缓存落盘、SD 卸载，不直接改 PA0、PA4 或 DAC 模拟寄存器 |
| 普通按键 | 实验镜像从启动起不注册普通按键扫描定时器 | KEY1–KEY5、按键产测等不可用；PB1 DIP 的独立 P33 关机链路保留 |
| USB | 准入后调用原生 OTG 挂起并删除检测定时器 | 测量时不插 USB，不承诺 CDC、热插拔或业务恢复；探针退出恢复自己暂停的检测 |
| CPU | 准入后锁 24 MHz，停止原生调频观察器的当前定时器，屏蔽实验锁定期的刷新提频 | 仅实验使用；锁失败或实际频率不符则退出，不把未生效状态标为成功 |
| 睡眠时钟 A/B | 独立 `LRC=1` 从开机起将原生 `TCFG_LOWPOWER_OSC_TYPE` 设为 `OSC_TYPE_LRC`；`LRC=0` 保留工具配置 BT_OSC | 不等同于 CPU 降频；保留 SDK 校准、时钟选择/回退和 controller 保护，不直接关闭晶振或改 `btosc_disable`；广播可靠性仍须板测 |
| 睡眠日志 | 实验镜像中 `<`/`>` 改为内存计数；仅输出生效、10 秒后、再 30 秒后三次快照 | 保留日志版仍可能有底层 `Sw[]` 等，不声称已关闭全部打印 |
| UART | 独立 `UART_OFF=1` 构建关闭 SDK 调试 UART | 先用日志版确认状态；静默版无探针日志，不能把串口静默当作成功证据 |
| HOGP/CDC/DUT/文件缓存/协议任务 | 复用现有无会话停表、缓存干净停表与接收任务阻塞 | 不再引入无意义轮询；不关闭有脏数据的保存、不销毁未知库任务 |
| 安全与平台维护 | 保留低电检测/关机、DIP 独立保护、看门狗、GPADC、电源/RTC/时钟校准及原生睡眠门禁 | 因此是“现有慢广播与安全底座下的组合探底”，不是保证关闭芯片所有模块后的绝对物理下限 |

ADC 服务还承担电池检测，不能为了去掉一个标称 5 ms 节拍同时撤掉低电保护。此实验同样不以修改电源电压、取消晶振维护、强制软关机或绕过原生门禁来获取更小数字。若快照仍有 `native blocker=...`，先结合电流与原生实现继续定位，不直接强制该门禁放行。

| LRC 对照，带快照 | 1 | 0 | 1 |
| LRC 对照，关闭调试 UART | 1 | 1 | 1 |

没有停广播档。`UART_OFF=1` 或 `LRC=1` 但 `ENABLE=0`、非法开关取值均编译报错。全部实验构建都从开机禁用普通按键；即使实验准入失败，也不能拿该镜像验证正常按键业务。LRC 是启动期电源配置，不随 150 秒探针准入或失败回滚切换；恢复 BT_OSC 需刷回相应镜像，不能把准入失败等同于恢复全部正常配置。

1. BLE 初始化后建立一次 150 秒超时，让正常 120 秒空闲窗口和外设关断先完成。
2. 条件不足时每 5 秒复查，最多 12 次准入检查（约启动后 150–205 秒），之后退出，不常驻等待、不随断连无限重试。重新实验须重启。
3. 准入前和施加组合前均复查慢广播有效及安全条件；生效后保持广播，挂起 USB 并锁低频，打印 `applied`。
4. 10 秒后 `sample1`，再 30 秒后 `sample2; no more probe timers`。此后组合保持，但**探针自身不再有定时器**；不是整机所有原生定时器都消失。
5. 定时器分配失败、准入失效或锁频失败均打印 `aborted`，停止采样并恢复自己修改的时钟/USB；旧超时回调通过序号隔离。BLE 退出同样取消探针。没有强行取得测量资格的兜底路径。

测量期间不得连接手机、按键、插 USB 或启动业务。最后一次快照后不再持续监控条件，任何外部活动都使后续读数失去本实验含义；本镜像不承诺业务唤醒恢复。重启退出本次状态，但仍会再次自动进入实验；恢复完整功能必须使用 `ENABLE=0` 的正常固件。

### 6.4 板测方法与结果判定

1. 固定硬件、电池电压/供电方式、仪表档位、手机扫描条件和其他固件配置。USB 物理拔出；串口采集仅接必要信号和共地，排除串口模块供电/反灌。
2. 先刷带快照实验版，确认 `applied`、`sample1`、`sample2` 均为 `links=0 slow_adv=1 pa4=0 pe5=0 hz=24000000 usb_stopped=1`。任一条件不符、出现 `aborted`、断言或复位，本次无有效探底结果。
3. 对比 `sample1` 到 `sample2` 的 `sleep`/`delta`。计数增长只证明经过睡眠回调，不代表睡眠占比、深度或 RF 电流。`native blocker` 仅是快照时刻的门禁观察。
4. 用手机短时确认设备仍可发现，然后按固定扫描条件测量；不要把扫描 App 缓存的旧条目当作持续广播证据。记录三次快照之后至少 60 秒的平均电流及波动，避免只摘一个谷值。
5. 再刷 `UART_OFF=1` 的静默版，保持其他条件完全一致，开机静置至少 5 分钟后测同样窗口，并再次确认仍能扫描到。静默版的实际进入条件和锁频仍需结合带日志版、匹配 ELF 与仪表验证，串口无输出本身不构成验收。
6. 与正式默认的同样 500 ms 慢广播状态对比。先判断组合是否有显著收益；需要正式实施时逐项恢复/拆分做 A/B，不能把组合差值直接记到 USB、按键、时钟或 UART 中某一项。

实验分支的软件验证入口为 `tests/host/run_host_tests.ps1`，其中 `test_idle_probe.py` 执行真实有限采样状态机和平台适配，检查慢广播必须有效、原参数/广播控制不被实验改写、失败恢复、旧回调和配置门禁，并检查两种时钟配置的快照查询。主机模拟不证明 RF 持续广播、USB 挂起电气效果、系统真实睡眠时长或电流；已有板测边界及新增待测项见 6.5。

### 6.5 已有板测证据与归因边界

**A. 首轮 BT_OSC：组合收益有限，证据继续保留。**

此前核对的 `PA4关闭后依旧是1.5-2ma.log` 与用户反馈：带日志组合约 **1.5–2 mA**，静默组合约 **1.3–1.8 mA 波动**。原始文件当前工作目录不再保留，以下为已核对历史摘录，不冒充本轮重新读取原始日志。它说明首轮措施没有解决主要余量，而不是只剩 RF 或已到芯片下限。

- 第二次启动后 `00:02:14.847` 确认 PA4 OFF；`00:02:30.619`、`00:02:40.623`、`00:03:10.626` 三次快照均为 `links=0 slow_adv=1 pa4=0 pe5=0 hz=24000000 usb_stopped=1`，没有探针失败日志。
- 后两个观察窗口睡眠进出增量分别为 40/40、125/125，对应约 4 次/秒。不能据此推导驻留时间、睡眠底流，也不能把它直接等同于广播次数或某个泄漏定时器。
- 每 10 秒仍有电量消息。源码电池流程为每 10 秒启动一次 6 次、10 ms 间隔的采样，属于保留的原生低电保护，不是“所有非广播活动都已关掉”。静默版的小幅变化也不支持把主要余量直接归因于日志。
- 日志前段还有一次 `P33_VDDIO_LVD_RST`，发生于首次启动后。后续稳定段不能解释这个复位原因；复测需保持供电及仪表档位稳定，记录是否复现，不能用降低 VDDIO 或关闭低压保护掩盖它。

**B. LRC 日志版：本轮已有明显收益，实验目标获用户确认。**

依据为 `COM3_2026-10-19_19-19-24.log` 和用户反馈“进入低功耗后 0.6 跳 1.3 mA，达成小于 1 mA 要求”。以下按设备运行时间整理，不按夹杂旧值的主机接收时间排序：

| 设备时间 | 日志事实 | 说明 |
|---|---|---|
| `00:00:20.889` → `00:00:26.341` | 建立一条 ACL，发生 RDX 读写/RTC 设置，然后断连 `reason=0x13` | 并非从开机到结束始终零连接；只说明早期快广播能建链，不能替代低功耗后的业务恢复测试 |
| `00:00:26.350` | FIFO 清理完成，runtime READY，`system_sleep_block=0 connected=0` | 后续目标测量段已无 ACL |
| `00:00:46.359` 起 | 原生调频已到 `curr_clk=24000000`，后续观察一致 | 低频不是等到探针强锁才第一次获得；不能把全部收益记给锁频 |
| `00:02:26.372` → `00:02:26.384` | 切慢广播，SD 停用、RGB/SPI 静默，`pa4=0 state=OFF` | 是断连后的完整 120 秒窗口；并非从开机固定 120 秒强行断电 |
| `00:02:30.650` | `applied`，sleep=1995/1995 | 组合准入成功 |
| `00:02:40.655` | `sample1`，sleep=2035/2035，delta=40/40 | 10 秒观察窗 |
| `00:03:10.660` | `sample2; no more probe timers`，sleep=2153/2153，delta=118/118 | 再 30 秒观察窗；之后不再有探针定时器 |

三次快照均满足：

```text
links=0 slow_adv=1 pa4=0 pe5=0 hz=24000000 usb_stopped=1
[IDLE_PROBE] sleep_clock lrc_test=1 cfg=0 default=0 selected=0 (0=LRC 1=BT_OSC)
```

- 本段未见 `aborted`、复位、断言或 `timer_no_response`；日志仍有 `Sw[]` 和每约 10 秒的电池消息，**收益并不依赖关闭全部日志或安全维护**。
- 睡眠回调仍约 4 次/秒，与 BT_OSC 组合接近；这支持优先调查睡眠时钟，而不支持“多关了大量唤醒定时器”的归因。不能凭次数计算 LRC 的实际睡眠驻留。
- 启动段仍有提示音资源失败和 `btadc clock set error, no this option !!!`；不能写成整份日志无错误，也没有证据将这些直接归因于 LRC。若业务复测受影响，需与同源 A 对照排查。
- 最后一条带设备时间的电池日志为 `00:03:20.416`，未提供固定窗口积分数据或长稳记录；用户观察区间与实验目标确认如实保留，**平均值低于 1 mA、RF 时序、LRC 静默版及量产可靠性尚未验收**。
- `slow_adv=1` 确认软件/原生接口状态，源码保持原 500 ms 广播；本日志没有空口抓包，不能额外宣称已经测得空口周期、无漏播或全部广播信道正常。

**C. 原生配置链与独立业务版衔接。**

工具配置 `sdk_config.h` 的睡眠时钟为 `OSC_TYPE_BT_OSC`，经 `power_config.c` 的 `power_param.osc_type` 进入 SDK。首轮探针只锁 CPU 运行频率，没有改变睡眠时钟。LRC 对照在项目 overlay 覆盖为 `OSC_TYPE_LRC`，不编辑工具生成文件，不调用运行时强制切钟接口，不停校准，不调整 RF 功率、广播内容或间隔。RTC 原有独立配置已为 LRC，本次不另改 RTC 配置。

`cfg` 是编译配置，`default`/`selected` 是原生 API 的配置/选择读数，不是晶振电气状态或整段睡眠占比。三次均为 0 是本轮快照事实，不代表没有任何原生回退。后续出现 `selected=1` 时须保留证据，不强制改成 0。

实验阶段同源组合包曾归档于 `cache/idle-probe-images/lrc-comparison/`，其中 `btosc-quiet/` 与 `lrc-quiet/` 的配置仅 LRC 探针开关不同，`lrc-trace/` 对应本节日志验证用途；这些是历史归档位置，不保证当前工作区仍保留。旧包不代表当前业务分支。**第 5 节独立业务 LRC 已去掉停键、停 USB 和锁频限制，取得 0.6–1.6 mA 实测并获用户确认锁定。** 其余优化按用户决定暂不执行，不补做 A/B，不累加不同实验条件的差值；本节机制与踩坑经验仅作保留。
