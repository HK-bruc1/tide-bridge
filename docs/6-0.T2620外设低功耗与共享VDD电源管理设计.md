# T2620 未连接时的低功耗策略

> 更新时间：2026-10-16
> 适用工程：T2620 / AC701N（BR28）RDX + HOGP 固件。
> 本文只维护产品策略、安全边界和排查经验，不保留实施过程。连接态低功耗另见 [6-2 设计](6-2.T2620BLE连接后低功耗设计.md)。

## 1. 未连接时的低功耗策略

**无 BLE 连接、无 USB 接入且无业务时，停止无意义的软件高频轮询；连续空闲 120 秒后进入慢广播，安全关闭 SD NAND/RGB 共享供电。功放独立按音频需求开关。**

### 1.1 适用边界

- “未连接”指两个 Peripheral ACL 的实际连接总数为零，不以 RDX 会话、RDX owner 或 HID 是否就绪判断。仅断开 RDX 逻辑会话、仍保留 HID 或物理链路，不属于未连接。
- 目标待机场景是正常开机、电池供电、物理 USB/VBUS 未接入、无录音/播放/文件等业务及收尾。“电池充满”或“当前未充电”不等于 USB 已拔出。
- 离线录音、播放和按键操作仍须正常使用；省电不能以丢失首次按键、手势、文件保存或唤醒能力为代价。
- 本文不扩展连接态外设断电策略：任一 ACL 存在时，仍保持共享 VDD 开启；第二连接窗口进入慢广播不代表整机未连接。
- 用户关机、低电保护和专用模式由各自策略管理，不受 120 秒等待限制；不得为低功耗复检延迟已接受的关机。

### 1.2 广播与空闲窗口

| 场景 | 策略 |
|---|---|
| 正常开机，或最后一条 BLE 链路断开，且无业务 | 快广播，开始完整 120 秒空闲窗口 |
| 接受有效用户操作 | 恢复或保持快广播，重新计算空闲窗口；访问外设前先恢复供电和可用状态 |
| 录音、播放、文件等业务进行中 | 保持快广播及所需供电，不消耗空闲窗口 |
| 业务待启动、暂停但仍持有资源，或正在收尾 | 仍视为有业务，不允许提前关电 |
| 所有业务结束，文件、索引及后台处理均已收尾 | 重新开始完整 120 秒快广播窗口 |
| 连续空闲满 120 秒 | 切换慢广播；无外设占用且安全停用成功后，关闭共享 VDD |
| 慢广播期间出现操作、新业务、BLE 建链或 USB 接入 | 取消旧关断请求，按新状态恢复；不得继续按旧超时关电 |

例如：离线录音 10 分钟，全程保持快广播；停止并保存完成后，再空闲 2 分钟才进入慢广播。

补充规则：

- 快广播不要求广播灯一直亮，也不禁止芯片在广播事件之间休眠；业务灯效优先。
- 灯效刷新、后台状态查询和重复结束通知不算新的用户活动，不得不断延长空闲窗口。
- 广播速度和外设供电分别判断。充电/低电等必要灯效可以要求保持共享 VDD，但不因此永久保持快广播。
- 模式禁止广播时，不因操作强行开启广播。自动关机策略独立管理，测量时应确认其实际配置，避免设备在待机采样前已关机。

### 1.3 软件唤醒策略

**周期服务只在对应业务有效时运行；无业务时以事件唤醒为主，不能靠高频空转等待业务出现。**

| 模块或场景 | 策略 |
|---|---|
| CDC：无 USB、未枚举或串口未打开 | 不保留协议层 10 ms 周期服务；仅插入充电器不足以启动 CDC 业务 |
| CDC：有效 DTR 串口会话 | 保留在线 10 ms 服务及收发事件处理；会话关闭、复位或拔线后停止周期服务 |
| HOGP：无 BLE 连接、仅 RDX 连接或 HID 未就绪 | 不保留 HOGP 输入模块的 10 ms 周期服务；按键和状态变化通过事件处理 |
| HOGP：HID 已连接、已订阅、已加密且未挂起 | 保留在线 10 ms 服务，保障按键报告、长按释放和发送重试 |
| DUT：未进入且无待办或收尾 | 不应保留 1 秒待命服务；不靠定时器等待八击、CDC 或 APP 指令 |
| DUT：收到有效请求，或已有测试/收尾 | 事件处理状态变化，仅为明确期限或重试安排单次超时；DUT 模式内空闲、等按键及喇叭稳定播放也不保留通用周期服务 |
| 离线物理按键及录音手势 | 保留必要的按键检测，由有效事件触发业务；稳定无按键时不反复唤醒业务处理 |
| 会话退出后仍有文件/录音收尾，或通知丢失 | 继续保证必要收尾和恢复，但不因此恢复无会话的常驻高频轮询 |

软件停表条件在快广播和慢广播期间都适用，**无需等待 120 秒**；120 秒约束的是广播切慢和共享 VDD 关断，不是无用定时器的退出。

当前 DIP/USB 的 100 ms 产品服务仍保留，并复用作异常恢复检查，CDC/HOGP 不另增离线常驻唤醒源。其后续拆分取舍见第 3 节；独立关机保护仍须保留。因此本策略不等于“完全没有定时器”，也不等于芯片可以无限期休眠。

对目标待机场景，CDC 指令需要 USB，APP 指令需要 BLE 连接，均不构成预先保留 DUT 周期服务的理由。八击可以在无 BLE、无 USB 时发生，但由原生按键检测产生消息，不依赖 DUT 的 1 秒服务识别；一旦接受八击进入 DUT，已属于用户主动发起的测试业务，不再是无业务待机。

## 2. 外设供电与安全边界

### PA0：MIC 供电使能，由 JL 音频框架管理

按 `T2620-MMI-V00_20260608.pdf` 第 1–2 页，PA0 接 `MIC_BIAS_CE`，控制 U6（SK6011D4-28）的 CE，输出 `MIC_BIAS` 给两颗 MIC 供电；不是 SD/RGB 的共享 VDD。PA4 接 `VDD_EN`，控制 U7（SK6018D4-33）的 CE，输出 `VDD_3.3V` 给 SD NAND/RGB。

当前 ADC0/ADC3 的供电选择均为 `AUDIO_MIC_LDO_PWR`（16 / PA0），继续由 JL 原生 ADC/MIC 生命周期管理。业务只申请和释放采集通路，不在开机、DUT、存储休眠或关机路径直接操作 PA0；无采集使用者时应关闭 MIC 供电，有离线录音时不能因 BLE 未连接而强关。PA0、PA4、PE5 是三个独立控制域。

### PA4：SD NAND/RGB 共享 VDD

PA4 高电平开启共享 LDO，SD NAND 和 RGB 同时供电；PA4 低电平同时切断两者。两者不能由软件独立断电，必须统一管理，业务模块不得各自直接开关 PA4。

关断必须同时满足：**零 ACL、有效慢广播、无共享外设占用、无新唤醒请求、外设已安全停用。**

- 先完成文件保存、缓存/索引收尾及 SD 卸载，再停止 RGB 定时器、SPI 和总线活动；相关 IO 进入安全态后才能关电，避免文件损坏和反向灌电。
- 关断过程中出现新业务、建链或 USB 接入，应取消旧关断；恢复供电并确认外设可用前，禁止访问 SD/RGB。
- 无法确认空闲、卸载失败或恢复异常时，不贸然切电；保持必要供电并报告错误。保持供电不代表存储已经可用，恢复失败不得自动格式化。
- USB 存储接管（功能启用时）和必要灯效属于独立资源需求，不能被未连接空闲流程误关电。

### PE5：独立功放使能

PE5 高电平使能功放。功放跟随 DAC 模拟输出生命周期：输出准备好后开启，关闭输出前关断，开机默认关闭。没有音频输出时应保持低电平。

PE5 不跟随 BLE 快慢广播、连接状态或 PA4 开关；不能因为 BLE 未连接就强制切断离线播放或提示音。通用原则见 [6-1 功放低功耗设计](6-1.通用功放低功耗设计.md)。

## 3. 慢广播定时器盘点与优化取舍

**先优化项目业务自增定时器，暂不改 JL 原生框架定时器。DUT 按待办调度已实施；DIP/USB 服务拆分和缓存检查按需化仍待实施。**

原始盘点基线为 2026-10-16 三项修复后的代码（`0c81977e`）及链接产物，DUT 条目已随本轮整改更新；场景限定为零 ACL、USB 物理拔出、正常电量、非 DUT、无业务及收尾、稳定慢广播且 PA4 已成功关闭。结论来自源码及链接实现核对，**不是板端活动定时器实测清单**；业务、配置和异常状态变化时需重新确认。

### 3.1 先区分归属和唤醒语义

按职责归属分类，不按文件是否位于 `SDK/`、也不按是否调用 JL 定时器 API 分类。RDX 库、产品 DIP 服务、项目工厂 CDC 均属于业务侧；USB OTG 检测、原生按键、ADC、电池和时钟维护属于 JL 框架。

依据 `SDK/interface/system/timer.h`：

| 定时器类型 | 对低功耗的影响 | 判断方式 |
|---|---|---|
| `sys_timer` / `sys_timeout` | 允许休眠，但到期唤醒；自续约的单次超时也会形成周期唤醒 | 重点清理无业务的常驻服务，不能只让回调空返回 |
| `usr_timer(..., 1)` | 注册期间阻止进入低功耗 | 检查是否仅在必要业务或短暂采样窗口内存在 |
| `usr_timer(..., 0)` | 休眠时可忽略节拍，实际周期会拉长 | 不能按标称周期推算强制唤醒次数；`sys_s_hi_timer_add` 属于此类 |

多个回调可能在同一次唤醒中执行，不能把回调频率直接相加为独立唤醒频率，更不能据此估算节省多少 mA。

### 3.2 项目业务自增定时器

| 模块 / 回调 | 目标待机场景的现状 | 取舍 |
|---|---|---|
| DIP/USB 产品服务 `rdx_dip_switch_deferred_handle` | 常驻 `sys_timer`，100 ms；处理 DIP、USB、模式/存储协调，并调用 CDC/HOGP 的轻量兜底检查 | 优先拆分职责；稳定空闲不必每 100 ms 检查全部业务，但不能直接停表或统一拉长周期 |
| DUT 服务 `dut_service` | 已取消初始化时的 1000 ms 服务及 DUT 模式内的通用 10 ms 周期；事件触发处理，实际待办才有单次超时 | 同时适用于未连接、BLE 已连接、USB 在线及 DUT 内空闲，不把轮询转移到其他连接状态 |
| 文件缓存检查 `rdx_uxfile_flush_cache_timer_cb` | RDX 库初始化后首次 10000 ms，随后每 5000 ms 自续约；缓存干净也续约，恢复/争用时可短暂改为 500 ms | 后续改为有脏数据才调度；收益与数据安全风险分开评估，不直接删除保存逻辑 |
| DIP 独立关机保护 `rdx_dip_switch_guard` | 常驻 100 ms、`usr_timer` 优先级 0；ON 空闲允许休眠，OFF/中断消抖及关机阶段配合低功耗锁保证推进 | 保留，不与 100 ms 产品服务一起删除或降频；维护独立于 `app_core` 的约 3 秒复位保护 |
| CDC 协议 / HOGP 输入服务 | 已按有效 DTR 会话 / HID 就绪状态管理 10 ms `sys_timer`；目标场景应停表 | 保持现有策略；100 ms 兜底检查不等于两个 10 ms 服务仍在运行 |
| 工厂 CDC 传输 `factory_cdc_kick` | 传输启动后使用优先级 1 的短周期轮询（常态 10 ms，快速阶段 2 ms）；无 USB 时正常准入不启动，停止传输时删除 | 目标场景确认无残留即可；有 USB 时的传输优化另评估，不与协议定时器或原生 OTG 检测混淆 |
| RGB 刷新 / 广播策略 / 共享 VDD 复检 | RGB 20 ms 在共享域停用时删除；快转慢 120 秒超时在稳定慢广播结束；1 秒业务/关电复检只用于忙或待关断阶段 | 稳定慢广播且关电成功后均不应常驻；若持续运行，先查未结束的业务或关断失败，而非扩大周期 |
| 录音、播放、传输、低电灯效等 | 按业务或保护条件存在；硬件 RTC 路径不启动旧的 3 分钟软件 RTC 保存定时器 | 不计入正常空闲常驻项，必须覆盖业务退出后的撤销与收尾 |

其中，文件缓存检查位于 `librdxApp`，仅搜索 C 文件中的定时器注册会漏掉。现有慢广播关电路径没有停止这条续约链；**回调存在不代表每次都访问 SD**，但不能把“缓存干净”或“PA4 已关”当成它已停表的证据。

核对入口：`rdx_protocol/rdx_dip_switch.c`、`rdx_dut.c`、`rdx_factory_cdc.c`、`rdx_hogp_input.c`、`rdx_adv_policy.c`、`rdx_peripheral_power.c`；缓存另核对 `patch_librdxApp_storage.ps1`、`patch_librdxApp_recovery.ps1`、`rdx_record_format.c` 及链接后的 `rdx_app_tasks_init` / `rdx_uxfile_flush_cache_timer_cb_impl`。这些 RDX 文件位于 `SDK/apps/common/third_party_profile/rdx_protocol/`；CDC 传输位于 `SDK/apps/common/device/usb/device/usb_factory_cdc.c`。

### 3.3 JL 原生框架定时器

| 模块 / 回调 | 目标场景及条件 | 本阶段取舍 |
|---|---|---|
| USB 热插拔检测 `usb_hotplug_detect` | USB 任务初始化后注册 `sys_timer`，默认 250 ms，检测转换阶段可能为 50 ms；未见产品按 VBUS 缺失停表 | 暂保留；它是无 USB 时仍有唤醒的独立来源，不是 CDC 协议轮询。业务优化后再评估 VBUS 事件驱动的启停 |
| 电池检测 `vbat_check_slow` / `vbat_check` | 电池供电时每 10000 ms 唤醒，启动 10 ms、优先级 1 的采样；正常电量约采 6 次后删除，低电流程不同 | 保留电量和低电安全保护；这是周期性短暂禁止休眠窗口，不是永久泄漏的 10 ms 定时器 |
| IO 按键扫描 `key_driver_scan` | 标称 10 ms，优先级 0；按键活动期间另有低功耗约束 | 保留离线首次按键、多击/长按和录音手势，不以标称频率直接认定为 100 次/秒强制唤醒 |
| ADC 扫描 `adc_scan` | 标称 5 ms，优先级 0，支持电池/温度等采样 | 暂不动；不等同于持续开启音频 MIC ADC 或 PA0 |
| LRC/RCH 时钟校准、RTC/P11 时间维护 | 已链接路径中，LRC/RCH 初期 10 ms，稳定后约 1000 ms；P11 时间维护约 2000 ms，均为优先级 0，实际存在取决于初始化路径 | 保留时钟/时间基准；RTC 校准中的临时定时器不重复算作永久常驻项 |
| 动态调频、LDO5V 消抖、SD 检测等 | 调频 10 秒检查在有限轮次后退出，资源变化可重启；LDO5V 的 2 ms 优先级 1 采样在稳定后退出；当前 SD 常在线配置在成功挂载后撤销检测 | 按启动、边沿或异常状态核对，不笼统计入稳定慢广播常驻项；低电提醒、自动关机也按各自触发条件核对 |

核对入口：`SDK/apps/common/device/usb/usb_task.c`、`usb_common_def.h`，`SDK/apps/earphone/battery/battery_level.c`，`SDK/apps/common/device/key/`、`clock_manager/clock_manager.c`、`dev_manager/dev_manager.c` 及 `SDK/cpu/br28/charge/charge.c`；USB 热插拔、ADC 和时钟库内部实现另以链接产物核对。BLE 广播无线调度仍是必要唤醒源，不在应用定时器表内，也不能为消除定时器而停止可连接广播。

### 3.4 推荐顺序与不可牺牲的能力

按**改动风险和验证成本**安排顺序，不把频率最高直接等同于最先改，也不承诺各项电流收益：

1. **先取消 DUT 的常驻周期服务，所有连接状态统一整改。** 开机只初始化模块；无 BLE、已有 BLE、USB 在线和已进入 DUT 都不构成持续轮询的理由。有效八击、BLE/CDC 指令和异步结果触发处理，没有待办就停表，包括 DUT 模式内等命令、按键测试等输入、喇叭稳定播放等场景。模块可用性与定时器存在分离；仅为明确的截止时间或失败重试设置单次超时，不再保留 1 秒/10 ms 的通用服务周期。
2. **再拆 DIP/USB 的 100 ms 产品服务。** 这是目前最频繁的业务侧常驻系统定时器，优先级高于缓存检查。DIP 边沿、USB/VBUS、会话与存储状态变化负责触发处理；仅在消抖、模式切换、重试或收尾窗口保持必要频率，稳定态只留有明确恢复时限的低频兜底。先补齐安全上下文的唤醒入口，并将依赖回调次数的消抖/重试改为明确时间约束，不能直接把 100 ms 改成 1 秒。P33 中断仍不操作任务队列、文件系统或协议栈；独立关机保护不变。
3. **最后评估缓存检查按需化。** 首次产生脏数据时安排有期限的保存，后续写入不能无限推迟；干净且无待办后停表。所有写入入口、保存失败重试、恢复后重启和并发关断都须闭环。关 PA4 前确认缓存/索引已保存、无在途 IO 且 SD 已安全卸载，断电期间不访问 SD；无法证明时保持供电。涉及库内状态且频率仅为 5 秒，在这些保证不完整时宁可暂留原检查。
4. **业务优化完成并实测后，再决定是否动原生 USB 检测。** VBUS 事件启停需要覆盖开机已插线、纯充电器、枚举失败、反复插拔及通知丢失；不能先删 OTG 检测，再期待由它产生的 USB 事件来恢复它。原生电池保护、按键、ADC、时钟维护不作为本轮削减目标。

DIP 服务目前还承担 CDC/HOGP 通知失败后的恢复，拆分时必须迁移这项职责，不能为省电丢失首次按键、松键释放、DTR 状态同步或收尾。低频兜底只处理异常恢复，不得成为正常业务唯一入口；具体周期以这些能力的响应时限验收，不在未验证前统一拉长。

DUT 当前调度约束（软件验证与板测边界见第 5 节）：

| 具体待办 | 调度方式 |
|---|---|
| 命令、按键、BLE/CDC 会话撤销 | 事件合并后在 `app_core` 处理；不依赖周期轮询发现 |
| 喇叭启动/结束、录音首帧/保存完成、格式化完成 | 生产者发布状态并通知；等待期间只保留必要的超时截止点，稳定播放和按键等待不运行 DUT 周期服务 |
| 包装提示音循环 | 播放期间等待完成事件，仅在两次提示音之间设置一次 1 秒间隔；不是每秒检查全部 DUT 状态 |
| 命令执行超时 | 使用绝对截止时间，其他事件不得不断延后；超时不等于资源释放，迟到音频完成仍须回收资源，格式化/包装超时后的结果不再提交成功 |
| 录音停止请求投递失败 | 只为该未投递请求按 100 ms 重试，最长 60 秒；超过期限保持隔离并报告失败，不永久高频空转；投递成功后等待完成通知，不继续检查保存状态 |
| 消息队列满或定时器分配失败 | 保留待办/截止时间，复用已有产品服务仅恢复投递失败或到期未调度的工作；不把 DUT 正常周期搬进产品服务，也不新增常驻兜底定时器 |

验收必须同时覆盖无连接、BLE 已连接、USB/DTR 在线、DUT 内空闲四类状态，以及通知失败、录音保存、喇叭收尾、旧超时回调和毫秒计数回绕。不能只证明未连接时停表，就宣布本项整改完成。

**阶段目标是“无业务就不保留业务高频服务”，不是“定时器数量归零”。** 即使完成业务优化，原生 USB 的 250 ms 检测和电池采样仍可能限制连续休眠时间；需要同条件测量，不将减少回调数直接等同于同比例降低电流。

## 4. 功耗排查经验

### 4.1 外设断电不等于系统已充分休眠

待机功耗需要分别看三层：**外设是否仍带电、软件是否频繁唤醒、BLE/芯片是否有足够休眠时间。**

历史阶段测量中，功放常开时约 15 mA，PE5 按需关闭后约 3–5 mA，SD/RGB 停用但仍供电时约 2–3 mA，共享 VDD 断电后曾达到约 1.5 mA。经验是先关闭不必要的负载，再停止软件活动，最后检查剩余唤醒和静态电流。

这些是不同阶段的表显值，不是同一采样条件下的精确器件功耗分解。“灯灭”不等于 SPI、SD 或 LDO 已停用；日志中的 `pa4=0` 也不能代替 PA4、LDO 输出及 PE5 的电压实测。

### 4.2 2026-10-16：功耗回退暴露常驻高频定时器问题

- 历史对照为快广播 3–7 mA、慢广播 1.5–2.6 mA；回退版本反馈为快广播 5–6 mA、慢广播 4–5 mA。
- 两份日志均在约 120 秒记录 SD/RGB 停用及 `pa4=0 state=OFF owner=IDLE_BLOCKED`，不能仅凭电流升高就认定 PA4 没关。
- 排查发现新增 CDC 协议和 HOGP 输入模块各自无条件保留 10 ms 周期定时器，即使没有对应会话也持续唤醒。普通系统定时器虽然允许休眠，到期仍会唤醒；**在回调中发现无业务就返回，并不能消除唤醒成本。**
- 处理原则是将定时器绑定到有效 CDC 会话或 HID 就绪状态，离线输入改用事件处理，并保留必要的收尾和异常恢复来源。
- 本次同时完成 CDC 会话按需定时、HOGP 就绪按需定时和 PA0 遗留控制清理后，用户实测反馈为快广播 **4–5 mA**、慢广播 **1.5–3 mA**，录音业务暂未发现问题。

排查证据来源：`952fbf5c快广播3-7ma__慢广播1.5-2.6.log`、`COM3_2026-10-16_12-35-18.log` 及对应代码对比；修改后结果来源为 2026-10-16 用户实测反馈。慢广播低功耗收益已明显恢复，但三项改动未做独立对照，不能拆分各项电流贡献，也不将本次范围等同于历史 1.5–2.6 mA 指标。

### 4.3 2026-10-16：旧 VDD 名称掩盖 PA0 所有权冲突

原理图核对发现旧 `VDD_POWER_PORT_IO` 错指 PA0：开机和进入 DUT 会直接拉高 MIC 使能，旧 EMMC 复位/上下电及退出路径也会改写它。这些操作可能使 MIC 额外耗电或干扰采集，不能凭 PA4 已关就排除它。

历史提交 `952fbf5c` 中已存在相同错误宏和开机/DUT 写脚，故它是长期隐患，不是本次新增问题；不能据此单独解释新旧慢广播电流差异，也不能把 MIC 电流与高频定时器收益混为一项。

清理原则是删除错误宏及业务层 PA0 写脚，废弃独立 EMMC 断电定时器和影子状态；库兼容入口只转交现有 PA4 管理器，不直接开关电源。**不能把旧宏简单改为 PA4**，否则旧复位/断电逻辑会绕过 SD/RGB 安全停用。MIC 原生配置和驱动不改；实际 PA0 电平、MIC 电源及节省电流仍需板测。

### 4.4 后续新增功能的约束

- 增加周期任务前，明确它在哪些业务状态下运行、何时停止，以及能否改用已有事件；不要在初始化时默认永久启动。
- 省电不能删除必要恢复能力：首次按键、断链释放、异步收尾和通知失败都要有处理入口，但恢复入口不必是独立的高频定时器。
- 诊断优先使用计数、低频汇总或 GPIO 波形，避免高频串口日志本身增加功耗。看到休眠进出标记，只证明发生过休眠，不证明休眠时间足够长。
- 先区分“无法休眠”“频繁被唤醒”和“休眠后仍有静态电流”，不要直接用延长广播间隔掩盖问题。120 秒是快转慢的空闲窗口，不是广播包的发送间隔。

## 5. 验证边界

广播策略、CDC/HOGP 按需调度及 PA0 遗留控制清理已通过统一 14 组主机测试和固件构建。2026-10-16 用户板测反馈：快广播 **4–5 mA**、慢广播 **1.5–3 mA**，录音业务暂未发现问题。该结果属于原三项修复（`0c81977e`）的初测记录；尚未附同条件波形和各电源实测，不能外推为完整板级回归通过，约 1 mA 目标也尚未验收。

DUT 本轮整改通过统一 14 组主机测试和固件构建，其中 DUT 生产状态机覆盖 32 个场景，包括无连接/有连接/USB 在线/DUT 内空闲停表、各请求入口、事件合并、队列与定时器失败恢复、固定截止时间、旧回调、计数回绕及音频收尾；提示音间隔和生产者仅在状态变化时通知也有软件检查。DIP/USB 服务拆分和缓存检查按需化未实施。

2026-10-16 用户实机回归反馈：**DUT 相关业务没有问题**。据此记录本轮 DUT 业务功能回归通过；未提供逐项故障注入记录、定时器/唤醒计数或新的电流测量，不能外推为全部异常专项或功耗验收通过。**本轮慢广播功耗收益仍待确认，上述 1.5–3 mA 不作为 DUT 调度整改后的测量结果。**

后续每项单独对照：记录相关定时器的存在状态、回调计数、实际唤醒和电流波形，并验证触发后及时处理、收尾后再次停表；DUT 需覆盖未连接、已连接和 USB 在线，不能只测慢广播。诊断采用一次性快照或低频计数汇总，不新增常驻高频日志。主机测试和构建只能验证软件约束，不能替代功耗板测。

后续专项板测保留以下四项：

1. 固定供电电压、仪器、采样窗口、广播参数和调试输出；USB 物理拔出、两路 ACL 均为零，分别记录快广播和稳定慢广播的平均电流、峰值及波形。
2. 同时测量 PA0/MIC_BIAS、PA4/共享 VDD、PE5，检查实际唤醒频率；分别确认 MIC 原生关电、共享域断电与软件停表的效果。覆盖冷启动未录音、录音停止、仅播放、进入/退出 DUT；DUT 本身不应强开 MIC。
3. 回归离线首次按键、多击/长按、录音保存、播放、业务结束后重新等待 120 秒，以及建链唤醒、HID 重连与松键释放。
4. 回归反复断电/恢复及文件完整性、USB 插拔与 DTR 开关、传输中拔线、关断中的新业务和独立关机保护。出现存储、电气或唤醒异常时，先停用物理断电定位，不以省电为由牺牲安全性。
