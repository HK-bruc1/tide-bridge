# T2620 未连接时的低功耗策略

> 更新时间：2026-10-17
> 本文记录现行方案、已取得的收益和踩坑经验，不保留实施流水与详细测试记录。连接态增量策略见 [6-2](6-2.T2620BLE连接后低功耗设计.md)。

## 1. 未连接时的低功耗策略

**无 BLE 连接、无 USB 接入且无业务时，停止无意义的软件高频轮询；连续空闲 120 秒后进入慢广播，安全关闭 SD NAND/RGB 共享供电。功放独立按实际音频输出开关。**

### 1.1 适用范围

- 两条 Peripheral ACL 的实际连接总数为零。RDX 逻辑退出但 HID 或物理链路仍在，不属于未连接。
- 正常开机、电池供电、USB/VBUS 物理拔出。充满或停止充电不等于拔线。
- 无录音、播放、文件、DUT、OTA 等业务，也无排队请求、资源占用或收尾。
- 关机与低电保护独立执行，不等待低功耗空闲期限。

### 1.2 空闲与唤醒

| 状态 | 策略 |
|---|---|
| 开机或最后一条链路断开，且无业务 | 快广播，开始完整 120 秒空闲窗口 |
| 有效用户操作或新业务 | 恢复/保持快广播；访问 SD/RGB 前先恢复共享域 |
| 业务进行中、待启动、暂停占用或正在收尾 | 保留所需供电，不消耗空闲窗口 |
| 全部业务及文件、缓存、索引收尾完成 | 重新开始完整 120 秒空闲窗口 |
| 连续空闲满 120 秒 | 切慢广播；共享外设安全停用后关闭 PA4 |
| 新业务、建链或 USB 接入 | 撤销旧关断请求，按新状态处理 |

灯效刷新、后台空检查和重复结束通知不算用户活动。广播速度与外设供电分别判断，必要灯效可保留 PA4，但不应永久保持快广播。

**无用业务定时器应立即停止，不必等待 120 秒。** 120 秒是空闲窗口，不是广播包间隔，也不是允许软件空转的时间。

## 2. 外设供电与安全边界

原理图 `T2620-MMI-V00_20260608.pdf` 确认三个独立控制域：

| 引脚 | 供电对象 | 管理原则 |
|---|---|---|
| PA0 / `MIC_BIAS_CE` | MIC | 由 JL 原生 ADC/MIC_LDO 生命周期管理；业务申请/释放采集通路，不直接写脚 |
| PA4 / `VDD_EN` | SD NAND + RGB | 共用一条电源轨，统一停用与恢复，不能由两个业务各自断电 |
| PE5 | 外置功放 | 模拟就绪且 DAC 实际输出时开启；无输出时关闭，与 BLE/PA4 解耦 |

共享 VDD 的安全规则：

- 未连接时必须满足零 ACL、有效慢广播、无共享资源占用；连接时使用 [6-2](6-2.T2620BLE连接后低功耗设计.md) 的独立资格，共用同一执行器。
- 先完成文件/缓存/索引收尾及 SD 卸载，再停止 RGB、SPI 并设置安全 IO，最后断电。
- 新业务先登记占用，再恢复共享域；恢复成功前不得访问 SD/RGB。关断中出现新请求，应取消旧关断。
- 无法确认空闲或停用失败时保留供电；恢复失败拒绝访问，不自动格式化，不以省电牺牲数据。
- USB 存储接管、必要灯效与离线音频照常工作，不因 BLE 未连接而强行关电。

功放的通用原则见 [6-1](6-1.通用功放低功耗设计.md)。

## 3. 慢广播定时器现状与取舍

以下针对零 ACL、无 USB、正常电量、无业务且 PA4 已关闭的稳定慢广播场景。按职责区分项目业务与 JL 框架，不按文件目录区分；结论来自源码及链接实现，不是板端活动定时器快照。

### 3.1 项目业务定时器

| 模块 | 现行策略与剩余项 |
|---|---|
| CDC 协议 | 无有效 DTR 会话停表；有效会话仍保留 10 ms 服务。USB 插入或仅充电不等于 CDC 会话有效 |
| HOGP 输入 | HID 未就绪时停表；已连接、已订阅、已加密且未挂起时仍有 10 ms 服务，在线按需化留待后续 |
| DUT | 已取消待命 1 秒和模式内通用 10 ms 服务；八击、BLE/CDC 指令及完成事件触发，仅真实期限/重试保留单次超时 |
| DIP/USB 产品服务 | 已取消常驻 100 ms 系统轮询；PB1 边沿、USB/VBUS 和业务事件触发，实际重试/收尾使用单次超时 |
| DIP 保护与恢复桥接 | 保留两个常驻 100 ms、优先级 0 的用户定时器：独立关机保护，以及失败待办恢复；不是一次性定时器，但不要求按周期主动唤醒 |
| RGB | OFF/无期限常亮不建表；短提示按截止时间，动态效果才按 20 ms 续约；恢复硬件不会自动启动周期服务 |
| 广播/共享 VDD | 120 秒切慢超时完成后退出；未连接的忙/待关断阶段保留必要的 1 秒复检，稳定关电后不常驻 |
| 文件缓存 | 库内仍有 5 秒自续约检查；空检查不唤醒 PA4、不延长空闲，真实脏缓存保存才登记业务。完全按需停表尚未实施 |
| CDC 传输、录音、播放及保护灯效 | 仅业务或保护条件有效时存在；目标无业务场景应无残留 |

DIP 开机依靠 PB1/P33 唤醒，不依赖系统轮询；边沿后有限消抖，接受 OFF 后按原生流程退出，保留不依赖 `app_core` 的约 3 秒复位保护。两个优先级 0 检查不等于原 100 ms 产品系统轮询仍在运行。

DUT 八击由原生按键事件识别，不需要待命定时器。连接、USB 在线或已经进入 DUT，也不是保留空转周期的理由；不能把未连接时的轮询转移到其他状态。

### 3.2 JL 原生框架定时器

| 模块 | 现状与取舍 |
|---|---|
| USB 热插拔检测 | 默认 250 ms 系统检测，转换期可能为 50 ms；无 USB 时仍可能唤醒，暂保留，不与 CDC 协议混淆 |
| 电池/低电检测 | 约 10 秒启动一轮短时高频采样；保留安全保护，不是泄漏的永久 10 ms 服务 |
| IO 按键 / ADC | 标称 10 ms / 5 ms、优先级 0；保留首次按键、手势和采样能力，不据标称频率推算主动唤醒次数 |
| 时钟校准、RTC/P11 维护 | 保留平台时间基准；优先级 0 检查与临时校准按实际初始化路径存在 |
| 调频、VBUS 消抖、SD 检测 | 按启动、边沿或异常阶段运行，不全部计入稳定待机常驻项 |

**先优化业务，再评估原生框架。** 下一步业务侧关注缓存按需保存；原生 USB 检测若改为 VBUS 驱动，必须先有独立可靠的恢复事件，不能删掉检测后又依赖它产生插入事件。按键、电池、时钟保护不作为直接删减对象。

## 4. 功耗排查经验

### 4.1 关了外设，不等于系统充分休眠

分开看外设负载、软件唤醒和芯片休眠条件。灯灭不代表 SPI/SD/LDO 已停用；日志显示 PA4 已关，也不能代替电气测量。`sys_timer/sys_timeout` 到期仍会唤醒，单次超时不断自续约也属于轮询；优先级 0 用户定时器则允许休眠时跳过节拍，不能混算。

### 4.2 无会话高频定时器会吃掉慢广播收益

曾在 PA4 已关闭的情况下出现慢广播电流回退。根因之一是 CDC/HOGP 无会话也常驻 10 ms 服务：回调发现无业务直接返回，仍然付出了唤醒成本。处理是按有效会话启停，并保留输入、收尾与失败恢复事件，而不是单纯延长周期。

### 4.3 旧 VDD 名称掩盖 PA0 所有权冲突

旧 `VDD_POWER_PORT_IO` 错指 PA0，开机、DUT 和旧存储路径会绕过 JL 框架改写 MIC 供电。已清理这些历史写脚，存储供电统一交给 PA4 管理器。**不能只把旧宏改成 PA4**，否则旧上下电逻辑仍会绕过 SD/RGB 安全停用。这是长期隐患，不能单独归因为本次功耗回退。

### 4.4 停表不能丢掉原来隐含的恢复能力

移除轮询时同步补齐状态通知、首次输入、松键、异步收尾和失败待办恢复。超时不等于资源已释放；消息投递失败也不能丢弃待办。复用既有优先级 0 桥接，仅实际待办才投递任务，不再添加常驻系统兜底。

### 4.5 外设重新初始化会改变定时器所属任务

PA4 OFF 后，文件查询在协议任务恢复 RGB，普通系统定时器随创建者绑定到了不分发定时消息的任务，造成持续 `timer_no_response`。修复将硬件初始化与业务调度分开，RGB 初始化为 OFF、不建表，灯效明确交给 `app_core` 按需执行。告警应先用对应 ELF 定位回调并追创建任务，不能把告警条数当成失败业务任务数，也不能只测试开机初始化。连接态复盘见 [6-2](6-2.T2620BLE连接后低功耗设计.md)。

## 5. 验证边界

- 已取得的未连接收益：CDC/HOGP 按会话启停与 PA0 清理后，用户实测快广播 **4–5 mA**、慢广播 **1.5–3 mA**，录音正常；三项改动未拆分单独电流贡献。
- 后续 DUT 事件调度、DIP/USB 产品服务拆分完成，用户分别确认 DUT 业务及拨码开关机正常，未单独量化两项功耗收益。
- 连接态 PA4/RGB 改进复用本页基础设施，已取得的连接态收益与结论统一见 [6-2](6-2.T2620BLE连接后低功耗设计.md)，不把历史慢广播电流写成本次复测结果。
- 这些是已测试场景的结论，不代表所有 USB/HID 组合、异常与量产长稳均已验收。
