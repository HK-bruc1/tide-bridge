# T2620 外设低功耗与共享 VDD 电源管理设计

> 更新时间：2026-09-07
> 文档状态：`DRY_RUN` 已通过；`UNMOUNT_ONLY` 正常闭环及录音业务唤醒后的同周期二次停用已通过实机验证；播放、USB MSC 与多轮循环回归完成前不开放 `POWER_CUT`
> 适用工程：T2620 / AC701N（BR28）RDX + HOGP 固件
> 联调超时：当前测试固件为 120 秒（2 分钟），量产目标为 300 秒（5 分钟）
> 管理归属：RDX/T2620 产品策略；JL SDK 仅提供 GPIO、DAC、存储和任务机制

## 1. 本轮重新评估结论

结合当前工程中的 SD0 常在线机制、PC MSC 接管流程、双 Peripheral ACL、异步 RGB SPI DMA、旧 PA0 电源路径和现有 PA4 SD 电源回调再次核对后，本方案结论为：

- **架构方案通过**：PE5 独立、PA4 统一管理共享 LDO 的边界正确；
- **`DRY_RUN` 已通过实机正常路径验证**：120 秒时双 ACL 为 0、业务位图为 0，管理器稳定输出 `would_off`；实测 3–5 mA 是完成 PE5 优化、但 PA4 仍为高时的阶段结果；
- **`UNMOUNT_ONLY` 正常路径已通过一轮实机验证**：首轮暴露的关中断区 JL BLE API 断言已修复；修复版已完成未连接停用、BLE 建链恢复、SD 录音/文件业务、断链以及再次停用，无断言或停用/恢复失败；此时 PA4 仍保持高，实测降至 2–3 mA；
- **录音业务结束复检已通过板测**：录音、播放、RGB 的明确结束点已主动通知管理器；实机已证明录音从 `QUIESCED_ON` 恢复后，在同一慢广播 generation 内停止并完成文件收尾后可再次停用；播放通知和预编译文件业务的 wake epoch 绑定 1 秒复检已通过代码、契约和完整固件构建验证；
- **`POWER_CUT` 有条件通过**：只有完成 PA4 早期初始化与唯一写入口、USB MSC 所有权交接、完整唤醒入口和板级电气确认后，才允许真正拉低 PA4；
- **首版范围不扩大**：任一 BLE ACL 已连接仍保持 PA4 高，连接态按命令休眠留到首版稳定以后评估。

确认板上除功放外的目标外设均由 PA4 控制的 LDO 供电后，最终方案可以明确简化为：

- `PE5` 独立控制功放，继续跟随 DAC 模拟输出生命周期，已经完成；
- `PA4` 独立控制共享 LDO，SD NAND 和 RGB 作为一个电源域整体开关；
- 有共享 VDD 业务时打开 PA4；完全无业务并完成安全停用后关闭 PA4；
- RGB 不再建立一套独立的长期低功耗策略，停止定时器、停止 SPI 和设置 DATA 安全态只是 PA4 关断序列的一部分；
- SD NAND 不再单独决定 PA4 电平，但断电前仍必须关闭文件、刷盘、卸载并停止总线；
- 软件只保留一个共享 VDD 管理器、一个忙状态位图和一个开关状态机，不允许 BLE、RGB、SD 或旧 RDX 代码分别直接写 PA4。

最终稳定态就是：

```text
有业务：PA4 = 1，LDO 开启，SD NAND/RGB 按业务使用
无业务：SD 已安全卸载，RGB/SPI 已停止，接口为安全态，PA4 = 0
功放：  PE5 独立跟随 DAC，不受 PA4 或 BLE 快慢广播直接控制
```

这里需要区分两件事：

1. **产品运行架构应当简单**：只有“共享 VDD 开”和“共享 VDD 关”这一条闭环；
2. **验证仍应逐步开启**：先验证判定和卸载，再打开物理断电，避免把文件系统问题、IO 反灌问题和 LDO 时序问题混在一起。

因此，本轮取消原方案中“RGB suspend 作为独立产品阶段”的设计，也不建设通用、复杂的多客户端电源租约框架。保留的停驱动、卸载、状态复检和恢复步骤，均是直接关闭 LDO 所必需的工程动作。

## 2. 硬件与软件事实

### 2.1 电源域

| 控制脚 | 有效电平 | 负载 | 管理策略 |
|---|---:|---|---|
| `PE5` | 高有效 | 外置功放 | 跟随 DAC 生命周期，独立管理 |
| `PA4` | 高有效 | SD NAND + RGB | 作为共享 VDD 整体按需开关 |

PA4 关闭后，RGB 和 SD NAND 会同时掉电，软件无法只关闭其中一个器件。因此产品策略不再把二者描述成两个可独立断电的电源使用者。

如果后续实测发现“必须保留 SD NAND、但希望单独关闭 RGB 电源”，只能修改硬件电源域，软件无法突破现有 LDO 拓扑。

### 2.2 BLE 一拖二的实际含义

本工程有两个 Peripheral ACL 槽位和两个 `app_ble` wrapper，但任一时刻只有一个活动广告者。不存在“两路 wrapper 同时进入慢广播”。

首版共享 VDD 关闭条件固定为：

- 两个 ACL 的实际连接数均为 0；
- 唯一活动广告者已经进入慢广播；
- 没有任何共享 VDD 业务占用。

第一条 ACL 建链后，另一个空闲 wrapper 会重新开启第二连接窗口并从快速广播重新计时。即使这个第二连接窗口随后超时进入慢广播，只要已有一条 ACL 连接，首版仍保持 PA4 开启。

`ADV_CHANNEL_ALL` 表示活动广告者使用 BLE 主广播信道 37/38/39，不代表三个业务广播，也与两个 ACL 槽位无关。

关断复检必须读取两个 wrapper 的实际连接聚合值。不能使用单一 `rdx_ble_server_get_conn_handle()`、当前 RDX owner 或当前 HID owner 代替总连接数，否则第二条 ACL、仅 HOGP 链路或 owner 尚未声明的物理链路可能被漏判。实现时应由 BLE 模块提供只读的双 ACL 连接数查询接口。

### 2.3 当前超时与自动关机

- 当前联调固件：`RDX_LED_BLE_ADV_TIMEOUT_MS = 120 * 1000`，用于两分钟快速验证；
- 量产目标：恢复为 300 秒（5 分钟）；
- RDX 自动关机运行值来自 VM 中的 `VM_RDX_AUTO_OFF_TIME`，不能只看 `TCFG_AUTO_SHUT_DOWN_TIME = 180` 秒的编译宏；
- 本次共享 VDD 优化不调整自动关机产品策略。

发布候选版本必须恢复 300 秒并重新跑完整流程，避免把测试值带入量产。

### 2.4 当前实现与剩余缺口

当前代码已根据实机 `DRY_RUN` 结果推进到 `UNMOUNT_ONLY`：

- `rdx_ble_server_adv_interval_change_timer_cb()` 切换慢广播、设置 LED OFF，再把空闲请求投递到 `app_core`；
- `rdx_led_hardware_deinit()` 先删除 20 ms 灯效定时器，再同步发送黑帧、关闭 SPI、释放 RGB 缓冲并把 DATA 固定为低；
- `dev_manager_takeover("sd0")` 同时阻止自动重挂载并卸载设备侧文件系统，失败时 PA4 保持高；
- takeover 后和最终状态切换前均重新读取双 ACL、业务快照和唤醒 epoch；慢广播请求携带的 epoch 会一直保留到最终决策，晚到的快广播/建链请求会取消停用并恢复；
- `STOPPING/STARTING` 通过管理器内部 OS mutex 跨任务串行化，避免 `btstack`、`app_core` 与 USB 同时触发重复 takeover/restore；SD 驱动供电回调只做幂等拉高，不递归进入该锁；
- `UNMOUNT_ONLY` 成功后进入 `QUIESCED_ON`：SD/RGB 已停用，但 PA4 明确保持高，避免用虚假的 `OFF` 表示电源仍开；
- 按键快广播、BLE 建链、录音/播放入口、RGB 非 OFF 场景和 USB MSC 接管均先执行 `dev_manager_restore("sd0")` 与 RGB 重建；
- PC MSC 已通过窄接口发布 `DEVICE/USB_HOST/RECOVERY` 所有权，避免和空闲 takeover 嵌套；
- 录音收尾、播放停止和 RGB OFF 已接入业务结束通知；录音/传输在慢广播后结束时，灯效恢复逻辑会识别慢广播并继续保持 OFF，不会错误恢复快广播灯效；如果慢广播到达时文件同步、索引扫描等预编译库内部状态仍忙，管理器会启动一个携带 wake epoch 的 1 秒单次复检，业务仍忙时续期，空闲停用、快广播、建链或 USB 接管时立即取消，因此稳定待机不存在周期复检；
- `POWER_CUT` 分支已与同一停用流程连接，但当前产品配置没有开放；只有切换该模式才会把 SD IO 设为高阻并拉低 PA4；
- SD0 被配置为常在线，文件系统和驱动不会因为 PA4 被拉低就自动忘记旧状态；
- `app_task_init()` 已在 SD 初始化前通过共享 VDD 管理器明确拉高 PA4，`sd_set_power_user(1)` 也已改为委托管理器幂等确保上电，不再直接写 PA4；
- `sd_set_power_user(0)` 继续被故意忽略，底层请求不得绕过共享 VDD 管理器关电；
- 工程已有 `dev_manager_takeover("sd0")` / `dev_manager_restore("sd0")`，可用于受控卸载和恢复；
- 旧 RDX `emmc_poweroff` 路径仍使用过期的 PA0 定义，不能把该宏直接替换成 PA4；
- PA4 已增加旧 Wi-Fi、DLOG 和当前 RDEC0 的编译冲突门禁；后续每增加板级复用仍必须同步扩展唯一所有权检查；
- 当前已接入关键唤醒入口和录音、播放、RGB 的明确结束通知；文件、充电、DUT、OTA 等预编译库或分散状态仍由慢广播期间的低频复检兜底，每次决定前仍以真实聚合快照为最终门禁。

所以“无业务”只能触发一个关断请求，不能直接等价为 GPIO 拉低。真正允许 PA4 变低的状态是“业务为空且外设已经安全停用”。

另外，PA4 管理不能只覆盖运行期慢广播：还必须覆盖开机首次挂载、从 `OFF` 唤醒、USB MSC 接管/归还、软关机和异常恢复。缺少其中任一路径都会重新出现绕过管理器的 GPIO 写入或在掉电状态访问 SD/RGB 的问题。

### 2.5 2026-09-05 DRY_RUN 实机结论

日志 `COM3_2026-09-05_17-38-16.log` 已给出完整正常路径证据：

```text
[00:02:00.976] 快速广播超时，切换到慢速广播
[00:02:00.979] RDX LED Scene: 1->0
[00:02:00.980][PWR] idle_request gen=2 links=0 busy=0x00
[00:02:00.981][PWR] would_off gen=2 mode=DRY_RUN pa4=1 state=ON_READY
```

这组日志只能证明“条件满足时管理器会申请关断”，不能证明外围已经掉电。实测灯灭后仍有 3–5 mA 波动，与日志中的 `pa4=1` 完全一致：共享 LDO、SD NAND 和 RGB 芯片仍处于上电状态。因此继续测量 DRY_RUN 电流没有价值，下一步必须验证 `UNMOUNT_ONLY` 的停用/恢复闭环；闭环通过后再开放 `POWER_CUT`，届时才验证约 1 mA 目标。

日志在约 2 分 12 秒后出现连接，该连接发生在前述未连接电流窗口之后，不改变上述结论。

### 2.6 未连接待机功耗的阶段实测与经验

开发板在未连接、RGB 灯熄灭并进入慢广播后的阶段性实测如下。下表为当时仪表显示值/波动范围，不等价于使用统一采样窗口得到的精密平均功耗：

| 实现阶段 | 关键状态 | 未连接待机实测 | 阶段结论 |
|---|---|---:|---|
| 优化前 | PE5 功放使能常开 | 约 15 mA | 功放是待机大电流的主要来源，独立使能脚不应硬编码常开 |
| PE5 生命周期优化后 | PE5 跟随 DAC 模拟输出生命周期；PA4 仍为高 | 约 3–5 mA | 功放关闭收益明显；剩余电流不能继续归因于功放 |
| `UNMOUNT_ONLY` 修复版 | SD0 进入 `IDLE_BLOCKED`，RGB/SPI 停用；PA4 仍为高 | 约 2–3 mA | 停止 SD/RGB 软件活动继续带来收益，但共享 LDO 和两个外设仍带电 |
| `POWER_CUT` 目标 | 安全停用后 PA4 拉低，共享 LDO 关闭 | 目标约 1 mA | 尚未板测，不得用 2–3 mA 的 `UNMOUNT_ONLY` 结果代替验收 |

本轮形成的工程经验是：

- 优先治理 PE5 这类独立、高收益的使能脚，使其跟随真实设备生命周期，而不是跟随 BLE 状态或永久开启；
- “RGB 视觉熄灭”不等于“外设已低功耗”，还需要停止定时器和 SPI，并阻止 SD 文件系统/总线继续活动；
- 15 mA → 3–5 mA → 2–3 mA 证明“独立功放优化→共享外设停用→共享 VDD 物理断电”的分阶段路线能够隔离问题并量化每步收益；
- 上述数据只能用来比较阶段收益，不能精确分解单个器件的功耗。进入 `POWER_CUT` 验收时应固定供电电压、仪器、采样时长、广播参数和调试接口状态，同时记录平均值与峰值。

## 3. 统一术语

| 术语 | 本文定义 |
|---|---|
| 共享 VDD | PA4 控制的 LDO 输出，同时给 SD NAND 和 RGB 供电 |
| 业务占用 | 要求共享 VDD 保持开启的产品状态，使用一个忙状态位图表示 |
| 外设空闲 | 两路 ACL 均未连接、已进入慢广播且业务占用位图为 0 |
| 安全停用 | RGB/SPI 已停止，文件已关闭并刷盘，SD 已卸载，总线和 DATA 已进入安全态 |
| 共享 VDD 关闭 | 安全停用完成后 PA4 输出低；不是仅仅“视觉灭灯” |
| 唤醒请求 | 要求取消旧关断并把共享 VDD 恢复到可用状态的事件；请求到达不代表恢复已经完成 |
| 恢复完成 | PA4 已高且稳定，接口和驱动已恢复，SD 已重新识别和挂载，可以放行业务 |
| SD0 所有权 | SD0 当前由设备侧文件系统、空闲关断流程或 USB MSC Host 中的哪一方占用；任一时刻只能有一个所有者 |
| `FAULT_ON` | PA4 在电气上保持高，但外设恢复结果未知或 SD 不可用；不等同于 `ON_READY` |

避免使用模糊说法“没有操作所以可以直接断电”。应用层暂时没有文件调用，并不能证明缓存已经提交、DMA 已经结束、文件系统已经卸载或驱动已经进入可掉电状态。

## 4. 职责边界

### 4.1 RDX/T2620 产品层

共享 VDD 策略继续放在 RDX/T2620 产品模块中，建议扩展现有：

- `rdx_peripheral_power.c`
- `rdx_peripheral_power.h`

该模块是 PA4 和 PE5 的产品所有者，但两者采用互相独立的判据：

- PE5：只看 DAC 生命周期；
- PA4：只看共享 VDD 状态机和业务占用。

### 4.2 JL SDK 与业务模块

| 模块 | 负责 | 不负责 |
|---|---|---|
| BLE/RDX 业务 | 上报慢广播、建链、断链和业务开始/结束事件 | 不直接写 PA4/PE5 |
| RGB 控制 | 提供关断前停驱动、恢复后重建场景的窄接口 | 不决定 LDO 电平 |
| 存储业务 | 在清除自己的忙状态前关闭自有文件、完成收尾并上报结果 | 不要求电源管理器强制关闭业务私有句柄，不直接关闭共享 LDO |
| PC 模式 | 在 USB 栈启动前申请共享 VDD 和 SD0 Host 所有权，在 USB 栈停止后归还 | 不直接嵌套调用一套与空闲关断无关的 takeover/restore 流程 |
| 共享 VDD 管理器 | 串行执行门禁、复检、公共缓存刷盘、SD0 所有权交接、PA4 开关和恢复 | 不猜测业务文件是否可关闭，不修改 JL 通用平台策略 |
| JL SDK | 提供 GPIO、SPI、设备 takeover/restore 和任务执行机制 | 不感知“两分钟/五分钟慢广播后关外设”的产品规则 |

空闲停用统一投递到 `app_core` 执行，直接来自 `btstack`、`app_core`、灯效与 USB 的同步恢复入口则由管理器内部 OS mutex 与停用流程串行化；PA4 物理写入统一经过管理器私有函数。开机早期初始化和 SD 驱动内部的同步“确保上电”只允许幂等拉高，不能从驱动回调触发卸载、挂载、关电或递归获取转换锁。唤醒入口采用同步恢复门禁：BLE 建链、按键业务或 USB 在继续访问 RGB/SD 前完成 restore；真正发生物理上电时使用 1 个 OS tick（当前约 10 ms）让出 CPU 等待稳定，不做关中断忙等。这样 BT stack 在恢复完成前不会继续处理可能访问存储的 ATT 业务。`dev_manager_takeover/restore` 的最坏耗时必须在 `UNMOUNT_ONLY` 实测；若同步恢复明显影响连接或按键响应，再把恢复下沉到受控工作任务并给 ATT/业务增加显式 `STARTING` 重试门禁。这里使用 JL 的任务和设备接口，不代表把产品策略写进 JL 原平台。

## 5. 简化后的软件模型

### 5.1 一个业务占用位图

不建立通用引用计数或复杂电源租约，只维护当前产品需要的固定忙状态。每一位必须有唯一事实来源，不能让多个调用者各自无条件置位、清位：

| 标志 | 唯一事实来源 | 置位与释放规则 |
|---|---|---|
| `BLE_LINK` | 两个 `app_ble` wrapper 的实际连接数 | 任一 Peripheral ACL 已连接即置位；只有实际连接数重新聚合为 0 才清除 |
| `RECORD` | 录音状态和录音工作任务 | 录音、暂停但文件未关闭、停止收尾或索引写入期间置位；文件关闭且 worker 空闲后清除 |
| `PLAYBACK` | 本地播放状态机 | 播放、暂停但仍持有文件、扫描或读取期间置位；完全停止并释放文件后清除 |
| `FILE_OP` | 文件传输、同步、扫描、删除、重命名等状态的聚合结果 | 任一子操作活动即置位；必须重新聚合确认所有子操作结束后才能清除 |
| `USB_MSC` | USB 检测和 PC 存储状态 | USB 插入并准备接管前即置位；USB 栈停止、SD0 归还且恢复成功后才能清除 |
| `FORMAT_RECOVERY` | SD 初始化、格式化和恢复状态机 | 首次初始化、格式化、修复或恢复判断期间置位；结果明确并释放存储后清除 |
| `RGB_REQUIRED` | 当前产品灯效策略 | 快广播重新显示、充电、低电、DUT、OTA 等要求显示 RGB 时置位；场景结束后清除 |

规则只有一条：**任一标志置位，PA4 必须开启；全部清零且满足慢广播条件，才允许尝试关闭。**

业务开始必须先请求共享 VDD 开启并等待恢复完成；业务结束只更新自己拥有的事实状态，由对应聚合器决定何时清除标志，再由管理器统一判断是否具备关断条件。

位图不是唯一安全依据。进入 `STOPPING` 和 PA4 拉低前都必须再次查询真实连接数、PC 存储状态、录音/播放 worker、文件传输/同步/扫描/格式化状态。位图用于快速汇总和可观测性，真实状态复检用于防止漏接事件。

跨任务事件不得直接对同一个整型位图执行无保护的读改写。首版优先把置位、清位和状态转换统一投递到 `app_core`；若某个入口必须同步置位，则使用临界区或原子操作，并保证“业务先置位，随后才访问外设”。

### 5.2 一个共享 VDD 状态机

```text
ON_READY --空闲请求----------------------------> STOPPING
   ^                                                |
   |                           安全停用且最终复检通过 |
   |                                                v
   +<--恢复成功-- STARTING <--唤醒请求------------- OFF
                     ^
                     |
STOPPING --已卸载后取消/失败------------------------+
STOPPING --未卸载前取消--------------------------> ON_READY
STARTING --受控重试耗尽--------------------------> FAULT_ON
FAULT_ON --显式重试/重新初始化--------------------> STARTING
```

状态含义：

- `ON_READY`：PA4 高，所需设备已恢复，可以放行业务；
- `STOPPING`：禁止新存储直接访问，正在等待业务收尾、停 RGB、刷公共缓存和卸载 SD；
- `OFF`：PA4 低，共享 VDD 已关闭；
- `STARTING`：PA4 已高，正在等待稳定、恢复驱动和挂载；
- `FAULT_ON`：流程失败，PA4 保持高，禁止继续尝试掉电并上报原因。

状态机不是为了增加产品逻辑，而是为了表达 SD 卸载和恢复不是瞬时 GPIO 操作。PA4 最终仍只有开和关两个硬件状态。

取消和失败必须根据停用进度处理：尚未卸载 SD 时可以直接退回 `ON_READY`；SD 已卸载后必须经过 `STARTING` 重新挂载，不能直接宣称就绪。`FAULT_ON` 只表示失败安全的电气状态，存储业务必须返回“暂不可用”，不能把 PA4 为高误判为 SD 已恢复。

`FAULT_ON` 不自动反复刷挂载。只允许按受控次数和间隔重试；重试耗尽后等待显式诊断命令、模式重入或重启，期间禁止再次进入 `STOPPING`。

### 5.3 防止旧超时事件误关电

慢广播超时与 BLE 建链可能同时发生。例如设备刚建立连接，旧的两分钟回调随后才在 `app_core` 中执行。

最小保护方式是维护一个递增的请求序号：

- 创建空闲请求时携带当前序号；
- 建链、用户操作或业务申请时递增序号；
- 执行关断前发现序号已经变化，立即取消；
- PA4 拉低前再次复检连接数、业务位图和各业务真实状态。

这是避免竞态的必要检查，不扩展为通用事件框架。

### 5.4 PA4 唯一写入口与开机顺序

“PA4 只有一个所有者”必须覆盖 SD 驱动回调和开机初始化，不能只约束慢广播流程。建议在 `rdx_peripheral_power` 内保留一个私有硬件写函数，其他模块只能提交请求：

```text
复位/启动
→ rdx_peripheral_power_vdd_early_init()
→ PA4 明确输出高，状态进入 STARTING
→ devices_init / dev_manager 初始化并首次挂载 SD0
→ 初始化 RGB 驱动
→ 确认 SD 和 RGB 可用
→ 状态进入 ON_READY
```

早期初始化函数只能建立确定的 PA4 电平和最小内部状态，不依赖 BLE、RDX 任务或文件系统已经启动。它必须早于 SD0 首次 `dev_open()` / `mount()`，避免 SD 驱动先调用 `sd_set_power_user(1)` 时管理器尚未准备。

现有 `sd_set_power_user()` 按以下方式收口：

- `sd_set_power_user(1)` 只能委托共享 VDD 管理器执行幂等的“确保硬件已上电”，不得自行写 PA4；
- 该委托不能递归触发挂载或完整 `STARTING` 流程，因为它本身可能由挂载过程内部调用；
- `sd_set_power_user(0)` 只表示 SD 驱动不再需要电源，不得直接拉低共享 LDO；是否关 PA4 仍由上层状态机决定；
- 旧 `rdx_app_emmc_poweron/poweroff`、DUT、充电和软关机中的直接电源操作统一迁移，禁止把旧 PA0 宏简单改成 PA4。

产品编译契约还要禁止 PA4 同时启用旧 `WIFI_POWER_PORT_IO`、DLOG SPI CS、RDEC 或其他板级功能。当前 `RDX_WIFI_ENABLE = 0` 和 RDEC 关闭只是现状，不能代替长期冲突检查。

运行期关闭 PA4 默认使用确定的 `PORT_OUTPUT_LOW`。只有硬件确认外部下拉可靠且高阻态不会漂移、误开启或反向灌电时，才允许使用高阻态代替低输出。

### 5.5 SD0 所有权与 `mount_blocked`

`mount_blocked` 只是阻止固件重新挂载的底层机制，不是所有权模型。共享 VDD 管理器必须同时记录 SD0 当前所有者：

| 所有者 | 含义 | PA4 规则 |
|---|---|---:|
| `DEVICE` | 设备侧 FAT 已挂载，可供录音、播放和文件业务使用 | 高 |
| `IDLE_BLOCKED` | 空闲关断流程已 takeover 并卸载，等待或已经执行 PA4 关闭 | 可高可低，由 VDD 状态决定 |
| `USB_HOST` | PC MSC 已接管裸 SD0 | 必须高 |
| `RECOVERY` | 归还、挂载或恢复结果尚未确定 | 必须高 |

首版不修改 `dev_manager` 为通用引用计数。由上层状态机保证 `dev_manager_takeover/restore` 不发生嵌套，并按所有权检查每次调用：

```text
DEVICE --空闲 takeover 成功--> IDLE_BLOCKED
IDLE_BLOCKED --普通业务唤醒并 restore 成功--> DEVICE
DEVICE --PC takeover 成功--> USB_HOST
USB_HOST --USB 栈停止且 restore 成功--> DEVICE
任一 restore 失败--> RECOVERY / FAULT_ON
```

USB 在 `OFF` 状态插入时，先置位 `USB_MSC` 并唤醒共享 VDD，再把 `IDLE_BLOCKED` 恢复为 `DEVICE`，随后才允许 PC 流程重新 takeover 为 `USB_HOST`。首版接受这一次额外的挂载/卸载，以复用已经验证的接口；禁止在 PA4 仍低或仍属于 `IDLE_BLOCKED` 时直接启动 MSC。

## 6. PA4 关闭流程

### 6.1 入口条件

只有同时满足以下条件，才进入 `STOPPING`：

1. 当前仍处于慢广播；
2. 两个 Peripheral ACL 的实际连接数均为 0；
3. 业务占用位图为 0；
4. 没有新的唤醒请求；
5. 当前请求序号仍有效；
6. VDD 状态为 `ON_READY`，SD0 所有者为 `DEVICE`；
7. 录音、播放、文件传输/同步/扫描/格式化和 PC 状态的真实复检均为空闲。

任一条件不满足，PA4 保持高，只记录一次低频拒绝原因。

快转慢回调的职责顺序固定为：记录当前活动广告者已经进入慢广播、结束“快广播需要显示 RGB”的场景、根据当前充电/低电/DUT/OTA 等高优先级灯效重新聚合 `RGB_REQUIRED`，最后投递空闲请求。若高优先级灯效仍要求显示，回调只切换广播速度，不得熄灯或关 PA4。

### 6.2 必要关断顺序

```text
复检空闲
→ 关闭外设直接访问门禁；新业务只能排队并触发取消/唤醒
→ 确认各业务已经关闭自有文件和完成 worker 收尾
→ 刷新公共索引/缓存并确认成功
→ dev_manager_takeover("sd0")，确认卸载成功
→ SD0 所有者切换为 IDLE_BLOCKED
→ 再次复检唤醒 epoch、双 ACL 和业务状态
→ RGB 停止 20 ms 定时器并同步发送最后一帧全黑
→ 关闭 SPI、释放 RGB 缓冲并把 DATA 置低
→ 确认 SD 总线不再活动
→ RGB DATA、SD CLK/CMD/DAT 进入板级安全态
→ 最终复检请求序号、连接数、真实业务状态和 SD0 所有权
→ UNMOUNT_ONLY：PA4 保持高，状态进入 QUIESCED_ON
→ POWER_CUT：PA4 确定输出低，状态进入 OFF
```

RGB 侧实际使用下面两个内部动作：

- `rdx_led_hardware_deinit()`；
- `rdx_led_hardware_resume()`。

不需要让 RGB 自己拥有 PA4，也不需要维护独立的电源投票。当前实现先删除灯效定时器，保证不再产生新的异步 update，再通过同步 `spi_dma_send()` 发黑帧作为发送完成屏障，随后 `spi_deinit()` 并把 DATA 置低。`UNMOUNT_ONLY` 板测必须确认日志之后不再出现 RGB SPI 活动；如果实测证明该 SDK 的同步发送不能等待先前 ISR DMA 收尾，则必须改用 `spi_get_pending()`/驱动完成回调补充显式超时，不能直接开放 `POWER_CUT`。

SD 侧必须把 `dev_manager_takeover("sd0")` 成功作为最低卸载门槛。现有接口会同时处理配置启用时的 `sd0_rec`，但它不会替业务强制关闭私有文件；卸载失败、仍有文件、仍有 DMA 或无法确认总线停止时，立即取消关断并保持 PA4 高。

禁止采用以下捷径：

- 在慢广播定时器回调中直接 `gpio_direction_output(PA4, 0)`；
- 把旧 `VDD_POWER_PORT_IO` 从 PA0 直接替换为 PA4；
- 让 `sd_set_power_user(0)` 绕过产品状态机直接关 LDO；
- 只发黑色帧但不停止 SPI，就认为 RGB 已经可以掉电；
- 文件暂时没有读写就跳过卸载。

### 6.3 关断失败

任一步失败时：

- PA4 保持或恢复为高；
- 尚未完成的停用流程停止；
- 若 SD 尚未卸载，重新开放业务门禁并返回 `ON_READY`；
- 若 SD 已卸载，状态转入 `STARTING`，调用 `dev_manager_restore("sd0")` 恢复挂载；
- 记录失败步骤和错误码；
- 只有恢复成功才能进入 `ON_READY` 并把所有权标为 `DEVICE`；恢复失败进入 `FAULT_ON/RECOVERY`，不能半断电继续运行。

失败安全原则是“多耗一点电，也不能带着未知存储状态关电”。

## 7. PA4 开启与业务恢复流程

### 7.1 唤醒来源

以下任一事件都要求共享 VDD 开启：

- 任一 BLE 建链；
- 用户按键触发录音、本地播放或其他文件业务；
- PA4 已关闭时，用户按键要求重新进入快速广播并恢复广播灯效；
- 文件读取、上传、同步、删除、格式化；
- USB 物理插入或准备进入 PC MSC；USB 事件必须先唤醒，再进入 `pc_storage_prepare()`；
- OTA、DUT、诊断；
- 充电、低电等产品策略要求显示 RGB。

### 7.2 恢复顺序

```text
置位业务占用并取消旧关断请求
→ PA4 = 1
→ 等待 LDO、RGB 和 SD NAND 上电稳定
→ 恢复 SD IO、控制器和 RGB DATA/SPI
→ 若 SD0 属于 IDLE_BLOCKED，则 dev_manager_restore("sd0") 并验证挂载
→ SD0 所有者恢复为 DEVICE
→ 根据当前产品状态重建 RGB 场景
→ 状态进入 ON_READY
→ 放行等待中的业务
```

只有需要 RGB、完全不访问存储的场景，也可以在硬件稳定后先恢复灯效；但首版仍把整个共享 VDD 域作为一个整体恢复，不实现“连接后保持 SD 关闭、首条命令再唤醒”的二级优化。

恢复期间，可能访问存储的 BLE 命令、按键录音和 USB MSC 入口必须等待 `ON_READY`。本批实现以同步恢复作为首版门禁，阻塞上限由 `UNMOUNT_ONLY` 实测确认；无论采用同步还是后续异步方式，都不能在 SD 尚未恢复时直接 `fopen()`。

BLE 建链本身可以先完成，但连接上的首条 RDX 文件命令必须经过业务门禁。HOGP 键盘报告不访问共享 VDD 外设时可以继续走原链路；首版仍因 `BLE_LINK` 置位而完成整个共享域恢复，避免引入连接内二级休眠。

动态恢复失败时：

- PA4 保持高；
- 按受控次数和间隔重试；
- 存储标记为暂不可用，并向业务返回明确错误；
- 不得因为一次动态恢复失败立即触发格式化。

USB MSC 必须与空闲关断使用同一个上层状态机，避免对现有单一 `mount_blocked` 状态发生嵌套 `takeover/restore`。

### 7.3 USB MSC 从 `OFF` 接管

USB 插入是必须优先处理的唤醒事件，完整顺序为：

```text
USB 插入
→ 同步置位 USB_MSC，递增请求序号
→ 若正在 STOPPING，取消关断
→ 若为 OFF/IDLE_BLOCKED，先执行共享 VDD 恢复并回到 DEVICE
→ pc_storage_prepare() 执行 takeover，DEVICE → USB_HOST
→ 启动 USB MSC 栈
```

退出顺序为：

```text
停止 USB MSC 栈并确认资源释放
→ dev_manager_restore("sd0")，USB_HOST → DEVICE
→ 确认设备侧重新挂载成功
→ 清除 USB_MSC
→ 若仍处于慢广播且其余业务为空，重新提交空闲关断请求
```

恢复失败时保持 `USB_MSC` 或恢复故障标记，PA4 保持高，禁止空闲流程把失败状态当成无业务。现有 `pc.c` 中的直接 takeover/restore 需要通过产品窄接口与该顺序衔接，但无需把 USB 通用平台改造成电源策略所有者。

### 7.4 软关机

软关机不要求处于慢广播，但必须复用同一套外围停用动作：停止新业务、请求各业务收尾、停止 RGB/SPI、关闭并刷盘、卸载 SD、设置安全 IO，最后由共享 VDD 唯一写入口把 PA4 明确拉低。PE5 仍由 DAC 关闭过程提前拉低。

用户触发的正常软关机应等待受控收尾完成，不允许旧 `VDD_POWER_PORT_IO` 或 `sd_set_power_user(0)` 绕过该路径。低电压、看门狗等不可延长的异常关机仍按系统既有兜底策略执行，但必须保证板级 power-off GPIO 配置将 PA4/PE5 置于已验证的关闭电平，并记录无法完成文件系统收尾的异常原因。

## 8. PE5 功放策略（已完成）

PE5 不并入共享 VDD 状态机。功放跟随播放输出 DAC，不跟随 BLE 快慢广播，也不跟随 SD/RGB 电源状态。

| DAC 状态 | PE5 |
|---|---:|
| `DAC_ANALOG_OPEN_PREPARE` | 低 |
| `DAC_ANALOG_OPEN_FINISH` | 高 |
| `DAC_ANALOG_CLOSE_PREPARE` | 低 |
| `DAC_ANALOG_CLOSE_FINISH`、未知状态 | 低 |

当前已经完成：

- PE5 开机和软关机默认输出低；
- `rdx_peripheral_power_amp_set()` 成为唯一运行时写入口；
- 应用层 `audio_dac_power_state()` 实现同步、幂等映射；
- PE5 与旧 RDX Wi-Fi SPI CS 冲突在编译期失败；
- Windows 构建、链接和打包通过；
- 4 项 PE5 产品契约通过；
- 实机提示音和播放功能测试正常；
- 同一未连接待机场景下，表显电流由功放常开时约 15 mA 降至约 3–5 mA，阶段收益已确认。

现有电流数据可用于确认优化方向；示波器边沿、复位窗口以及统一仪器/采样窗口下的精确电流仍应在量产测试表中补齐，但不阻塞共享 VDD 软件开发。通用原则见 [`6-1.通用功放低功耗设计.md`](6-1.通用功放低功耗设计.md)。

## 9. 产品状态矩阵

| 场景 | PA4 | SD NAND / RGB | PE5 |
|---|---:|---|---:|
| 开机初始化 | 高 | 初始化、挂载并显示开机灯效 | 低，音频需要时由 DAC 拉高 |
| 未连接快速广播 | 高 | SD 在线，RGB 显示广播灯效 | 通常低 |
| 未连接慢广播且完全空闲 | 低 | SD 已卸载，RGB/SPI 已停止 | 低 |
| `OFF` 时按键恢复快速广播 | 先高并进入 `STARTING` | 恢复完成后才显示广播灯效 | 低 |
| 已连接 1 个或 2 个 ACL | 高 | 首版整个共享电源域恢复并保持 | 仅播放时高 |
| 录音/文件操作/本地播放 | 高 | 按业务工作 | 仅 DAC 播放时高 |
| `OFF` 时 USB 插入 | 先高并恢复，再交给 MSC | SD0 最终归 `USB_HOST`，RGB 按产品策略 | 低 |
| USB MSC | 高 | SD 由 MSC 接管，禁止空闲关断 | 低 |
| 格式化/恢复/OTA/DUT | 高 | 按业务工作 | 仅音频需要时高 |
| 充电或低电灯效要求显示 | 高 | RGB 工作；首版共享域整体保持 | 低 |
| `FAULT_ON` | 高 | SD/RGB 可用性按故障结果处理，存储入口禁止误放行 | 仅 DAC 播放时高 |
| 软关机 | 低 | 停用并进入安全态 | 低 |

首版规则故意简单：**任一 BLE 连接也算业务占用，PA4 保持高。**等首版稳定后，才评估“连接状态下没有文件业务仍关闭 PA4”的按命令唤醒优化。

## 10. 简化后的实施与验证计划

- 慢广播请求通过后依次输出 `stopping`、`sd0_owner=IDLE_BLOCKED`、`rgb_quiesced` 和 `quiesced`；PA4 始终保持高；

本批次只用于确认“停用和恢复是否可靠”，不能用于验证 1 mA。烧机时预期在两路 ACL 均未连接、120 秒进入慢广播且业务快照为零时看到：

```text
[PWR] idle_request gen=<n> links=0 busy=0x00
[PWR] stopping gen=<n> mode=UNMOUNT_ONLY epoch=<e>
[PWR] sd0_owner=IDLE_BLOCKED
[PWR] rgb_quiesced data=LOW spi=OFF
[PWR] quiesced mode=UNMOUNT_ONLY pa4=1 state=QUIESCED_ON owner=IDLE_BLOCKED
```

按键恢复快速广播或建立 BLE 连接后应看到：

```text
[PWR] restored reason=FAST_ADV|BLE_LINK owner=DEVICE pa4=1 state=ON_READY
```

随后必须验证录音、播放、文件访问和重复进入慢广播均正常。若出现 `stop_failed`、`restore_failed`、文件系统异常或重启，本阶段失败，不能开放 PA4 物理断电。

业务结束复检需单独覆盖“业务跨过快转慢时刻”的场景：保持未连接录音、播放或文件操作超过 120 秒，首次空闲判断应因对应 busy 位拒绝；停止业务后无需重新建链、按键或重启广播，应在主动通知后立即、最迟在 1 秒兜底复检后继续进入 `stopping → QUIESCED_ON`：

```text
[PWR] idle_request gen=<n> links=0 busy=0x<非零>
[PWR] reject_off gen=<n> reason=RECORD|PLAYBACK|FILE_OP|RGB_REQUIRED ...
... 业务结束 ...
[PWR] stopping gen=<n> mode=UNMOUNT_ONLY epoch=<同一有效epoch>
[PWR] quiesced mode=UNMOUNT_ONLY pa4=1 state=QUIESCED_ON owner=IDLE_BLOCKED
```

进入 `QUIESCED_ON` 后不应继续周期出现 `idle_request/reject_off`；若期间发生快广播、建链或 USB 接管，旧复检只能被取消或输出 `stale_business_ignored`，不得继续停用外设。

### 10.4 同一实现的三级验证开关

为降低存储风险，同一套状态机按以下模式验证，不形成三套产品逻辑：

| 模式 | 行为 | 目的 |
|---|---|---|
| `DRY_RUN` | 完成条件判断，只打印 `would_off`，PA4 不变 | 验证连接和业务判定无误 |
| `UNMOUNT_ONLY` | 执行停 RGB、卸载和恢复，PA4 始终高 | 隔离验证文件系统生命周期 |
| `POWER_CUT` | 在相同流程最后真正拉低/拉高 PA4 | 验证 LDO、IO 和物理上下电 |

正式代码只保留一个状态机；模式开关仅用于逐级放开最后的硬件动作和快速回退。`DRY_RUN` 每个空闲请求序号只记录一次；`UNMOUNT_ONLY` 完成 takeover 后保持在 `QUIESCED_ON`，直到按键、建链、业务或 USB 唤醒时执行 restore，借此完整覆盖真实卸载时长。只有 `POWER_CUT` 才进入 PA4 实际为低的 `OFF` 稳态，禁止出现“状态为 OFF、PA4 实际仍高”的状态失真。

升级门槛固定为：

- `DRY_RUN → UNMOUNT_ONLY`：两路 ACL、业务位图、按键快广播、USB 插入和旧请求失效日志均正确；
- `UNMOUNT_ONLY → POWER_CUT`：卸载/恢复循环、USB 所有权交接、RGB DMA 停止和失败回滚全部通过，并取得板级 PA4/IO/稳定时间结论；
- 任一门槛未通过时保留在当前模式，不允许通过延时或忽略错误强行进入下一模式。

## 11. 验收方案

### 11.1 功能验收

- 两路 ACL 均未连接，当前活动广告者在 120 秒后进入慢广播；
- 当前 `UNMOUNT_ONLY`：无业务时 RGB 熄灭、SPI 停止、SD 卸载，PA4 仍为高；按键和建链均能完整恢复；
- 后续 `POWER_CUT`：复用相同流程并在最终复检后把 PA4 拉低；只有该阶段才验收约 1 mA；
- BLE 慢广播在 PA4 低期间仍能被发现和连接；
- 任一 ACL 建链立即触发 PA4 恢复；第二连接窗口变慢时不得关闭 PA4；
- PA4 低时按键恢复快速广播，必须先恢复共享 VDD，再显示广播灯效；
- PA4 低时插入 USB，必须先恢复并完成 SD0 所有权交接，再启动 MSC；拔出后设备侧重新挂载成功；
- 按键录音、本地播放、文件传输和 USB MSC 都能先恢复共享 VDD 再访问 SD；
- 录音、播放、传输、格式化、MSC、OTA/DUT 和要求显示的灯效期间 PA4 始终为高；
- 所有恢复场景都按当前状态重建灯效，不恢复过期动画；
- 冷启动首次 SD0 挂载前 PA4 已处于确定高电平，软关机结束时 PA4 为确定低电平；
- PE5 继续只跟随 DAC，不受 PA4 开关影响。

### 11.2 竞态验收

在 `STOPPING` 每一步注入 BLE 建链、按键录音、USB 插入和文件请求：

- 旧空闲请求必须失效；
- PA4 不得在新业务到达后继续拉低；
- 已卸载但尚未断电时必须转入恢复；
- 不出现重复 takeover/restore；
- `FILE_OP` 的两个子操作并发时，一个子操作结束不能提前清除聚合忙状态；
- USB 插入与空闲 takeover 同时发生时，最终所有者只能为 `USB_HOST` 或明确的 `RECOVERY`，不能保持未知状态；
- 不出现文件入口绕过 `ON_READY`；
- 失败路径始终保持 PA4 高。

### 11.3 存储可靠性

先在 `UNMOUNT_ONLY` 模式反复执行：

```text
挂载 → 写文件 → 关闭 → 卸载 → 恢复挂载 → 校验
```

再在 `POWER_CUT` 模式反复执行：

```text
挂载 → 写文件 → 关闭 → 卸载 → PA4低 → PA4高 → 恢复挂载 → 校验
```

量产前建议各完成至少 1000 次循环，并校验目录、文件长度、索引和内容。动态恢复失败不得自动格式化；PC MSC 接管期间触发慢广播关断时 PA4 必须保持高。

循环中至少穿插录音停止收尾、播放暂停/恢复、文件同步、索引扫描、USB 插拔和断链重连。每次 `dev_manager_takeover()` 前确认所有业务文件已经关闭；不能把一次 unmount 成功当作所有业务入口均已正确接入门禁的替代证据。

### 11.4 电气与功耗

至少记录以下状态：

- 快广播 + RGB 灯效；
- 慢广播 + 仅视觉灭灯、PA4 高；
- 慢广播 + PA4 低；
- PA4 低时 RGB DATA 与 SD IO 电平；
- PA4 上电到第一条 SD 命令的时间；
- DAC 关闭/开启时 PE5 电平；
- 整机软关机。

测试报告给出平均电流、峰值、采样窗口和仪器设置。

## 13. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 慢广播回调直接拉低 PA4 | FAT 损坏、驱动状态失真 | 只提交空闲请求，完成安全停用后再断 LDO |
| RGB/SD IO 在掉电后输出高 | 反向灌电、假上电 | 关断前进入硬件验证过的安全态 |
| 异步 SPI DMA 未结束就断电 | 数据脚异常、驱动竞态 | 停止新发送并等待完成，超时则取消关断 |
| 文件暂时空闲但仍挂载 | 缓存未提交、恢复访问失败 | 关闭、刷盘并受控卸载 |
| 多个文件子业务共用一位并提前清位 | 仍在访问 SD 时误判空闲 | 每位唯一事实来源，聚合所有子状态后再清除 |
| 旧两分钟事件晚到 | 建链或业务开始后仍被关电 | 请求序号和 PA4 拉低前最终复检 |
| PC 与空闲流程嵌套 takeover | `mount_blocked` 状态错误 | 单一上层状态机串行管理 |
| PA4 低时 PC 直接接管 | MSC 访问未上电 SD 或所有权失真 | USB 先置位并唤醒到 `DEVICE`，再 takeover 为 `USB_HOST` |
| PA4 低时直接恢复快广播灯效 | SPI 向掉电 RGB 发送 | 快广播入口先请求 VDD，恢复后再设置场景 |
| SD 驱动早于 RDX 初始化写 PA4 | 开机状态与管理器记录不一致 | 提供无任务依赖的早期初始化，SD 回调委托唯一写入口 |
| 动态恢复失败触发格式化 | 用户数据丢失 | 动态路径只重试和报错，不自动格式化 |
| 把 PA0 宏直接改成 PA4 | 旧路径绕过所有安全检查 | 删除旧直控并统一接入管理器 |
| 软关机继续走旧直控 | PA4 未明确关闭或未完成存储收尾 | 复用停用序列并固定 power-off GPIO 电平 |
| 120 秒测试值进入量产 | 产品发现窗口缩短 | 发布契约强制 300 秒 |
| 自动关机早于快转慢阈值 | PA4 慢广播关断路径永远不可达 | 发布前读取 VM 实际值并校验时序关系 |
| 把功放并入 PA4 判据 | BLE/存储状态切断正常声音 | PE5 始终独立跟随 DAC |

## 14. 待确认参数

架构已不再依赖复杂产品选择，但实现物理关断前仍需确认以下板级参数：

1. PA4 外部是否有可靠的默认关闭或保持电路；
2. PA4 低时 RGB DATA、SD CLK/CMD/DAT 的推荐安全态；
3. LDO、SD NAND 和 RGB 的最小上电稳定时间；
4. 当前量产 VM 中 `VM_RDX_AUTO_OFF_TIME` 的实际值及其与 300 秒快转慢阈值的关系；
5. 充电、充满、低电、DUT 和 OTA 哪些场景必须显示 RGB；
6. USB 插入但尚未进入 PC 模式时，是否立即置位 `USB_MSC`，本文建议立即置位；
7. PA4 在复位、开机 GPIO 配置和 power-off GPIO 配置阶段的真实波形；
8. `dev_manager_takeover/restore` 的最坏耗时，是否会对 `app_core` 响应造成不可接受阻塞；
9. 量产功耗目标以及 PA4 关闭前后的最低收益门限。

这些参数影响等待时间、安全 IO 和业务位图，不改变“PA4 统一直接控制共享 LDO”的总体架构。

## 15. 最终建议

本轮重新评估后，推荐方案收敛为：

```text
PE5：DAC 有输出时开，无输出时关（已完成）

PA4：共享 VDD 有业务时开
     两路 ACL 均未连接、进入慢广播且无业务时
     完成 RGB/SD 安全停用后直接关 LDO
     建链、按键快广播、USB、充电或新业务到达时
     先恢复 LDO、驱动、挂载和 SD0 所有权，再放行业务
```

RGB 停驱动和 SD 卸载都是共享 VDD 闭环的内部步骤，不单独形成另一套产品电源策略。

当前结论是“架构通过、DRY_RUN 通过、UNMOUNT_ONLY 正常业务闭环已通过一轮、物理断电有条件通过”。下一步在 `UNMOUNT_ONLY` 下补测 USB MSC、按键恢复和 3–5 轮重复卸载/挂载；全部通过后，把同一配置切换为 `POWER_CUT`，再测 PA4 电压及约 1 mA 整机电流。

工程上仍通过 `DRY_RUN → UNMOUNT_ONLY → POWER_CUT` 逐级打开同一实现。这样既保持产品架构直接、代码所有权清晰，也避免用一次未经验证的 GPIO 拉低操作承担文件系统损坏、USB 所有权失真、掉电访问和反向灌电风险。
