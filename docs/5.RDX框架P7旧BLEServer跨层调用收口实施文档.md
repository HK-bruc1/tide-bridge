# RDX 框架 P7 旧 BLE Server 跨层调用收口实施文档

> 日期：2026-07-19
> 当前代码基线：`f495bd6 修复：恢复 BUSY 录音命令并持久化 MIC 增益`
> 上游规划依据：`docs/3.RDX框架JL平台复用性优化大纲.md`、`docs/4.RDX框架重构进度与完成度评估.md`
> P7 定位：在不破坏 `librdxApp.a` ABI 的前提下，收口旧 `rdx_ble_server.c` 对 record/protocol 状态的跨层直连。

## 1. 目标与非目标

### 1.1 目标

P7 只解决旧 BLE server 的 record/protocol 跨层访问问题：

- `rdx_ble_server.c` 不再直接访问 `RecordStatus`。
- `rdx_ble_server.c` 不再直接调用 `rdx_record_get_status()`。
- `rdx_ble_server.c` 不再直接调用 `rdx_protocol_record_state_indicate()`。
- 旧 BLE server 只负责 BLE GATT、连接状态、广播、MTU、收发和必要的 BLE 时序协调。
- record/protocol 状态判断和状态同步下沉到 `rdx_record_service` 或专门 facade。
- 新增静态边界规则，防止后续回退。

### 1.2 非目标

P7 不做以下工作：

- 不修改、替换、反编译或重编译 `librdxApp.a`。
- 不改 `RecordStatus` 结构体布局。
- 不改 `RdxProtocolCallbacks`、`RdxProtocolIndicateOps` 等静态库相关回调结构体布局。
- 不删除、不改名、不改签名任何旧 ABI 外部符号。
- 不把 `rdx_ble_server.c` 一次性改造成全新 BLE service。
- 不同时启动 P8 产品配置拆分。
- 不强行清零所有 `rdx_ble_server.c` 中的历史 `extern`，只处理 P7 范围内的 record/protocol 状态直连。

## 2. ABI 硬约束

`docs/3` 已明确要求 `librdxApp.a` 二进制不变，且静态库 ABI 不破坏。P7 必须按以下门禁执行。

### 2.1 禁止改动

以下对象在 P7 中禁止做破坏性修改：

| 类型 | P7 约束 |
|---|---|
| `librdxApp.a` | 不修改二进制，不替换 archive，不调整链接位置。 |
| 旧外部函数 | 函数名、参数、返回值不改；不能删；不能改为 `static`。 |
| 旧全局变量 | 名称、类型、可见性不改。 |
| 静态库可见结构体 | 字段顺序、字段类型、结构体大小不改。 |
| 协议回调结构体 | 不增删字段，不调整字段顺序，不改函数指针签名。 |
| 旧头文件兼容边界 | 不做破坏性签名清理；需要 clean API 时新增 service/facade 头。 |

### 2.2 允许改动

P7 允许以下低风险改动：

- 旧 ABI 函数内部实现改成 thin wrapper，但旧符号必须保留。
- 新增 `rdx_record_service_*` 或 `rdx_ble_service_*` clean API。
- `rdx_ble_server.c` 调用新增 clean API，停止直接读写 `RecordStatus`。
- service 内部继续使用 `RecordStatus`，因为 record 状态归属在 record service。
- 新增静态边界脚本规则。
- 新增 host mock 或静态扫描用例。

## 3. 当前问题清单

当前 `rdx_ble_server.c` 仍有以下 P7 命中：

| 位置 | 当前行为 | 问题 |
|---|---|---|
| extern 声明区 | 声明 `rdx_protocol_record_trigger_indicate(RecordStatus*, bool)` | BLE server 暴露 `RecordStatus` 类型依赖。 |
| extern 声明区 | 声明 `rdx_record_get_status()` | BLE server 可直接取得 record 内部状态。 |
| extern 声明区 | 声明 `rdx_protocol_record_state_indicate()` | BLE server 直接触发 protocol 状态上报。 |
| `rdx_ble_server_disconnected_handle()` | 读取 `rp->orig_mode`、`rp->run`，并写 `rp->rerun` | 断连行为跨过 record service 直接操作 record 状态。 |
| `rdx_ble_server_syn_data_after_ble_write_ready()` | 读取 `rp->run/mode/orig_mode`，直接调用 `rdx_protocol_record_state_indicate()` | BLE 写就绪后同步录音状态的职责应归 record/protocol facade。 |
| `rdx_ble_server_adv_interval_change_timer_cb()` | 读取 `rp->run` 判断 LED 是否熄灭 | 广播降速时的“录音中”判断应通过 record service 查询。 |
| `rdx_ble_server_auto_shut_down_enable()` | 读取 `rp->run` 判断是否允许自动关机 | 自动关机条件不应直接读 record 内部结构。 |

注意：`rdx_record_service.c`、`rdx_device_service.c`、`rdx_storage_service.c` 内部仍可使用 `RecordStatus`。P7 的清理对象是旧 BLE server，不是全局清零 `RecordStatus`。

## 4. 目标边界

P7 后的依赖方向应为：

```text
rdx_ble_server.c
  -> rdx_ble_service.h
  -> rdx_record_service.h
  -> rdx_storage_service.h
  -> rdx_event_bus.h

rdx_record_service.c
  -> rdx_record_get_status()
  -> rdx_record_process()
  -> rdx_protocol_record_state_indicate()
  -> RdxProtocolIndicateOps

librdxApp.a
  -> old ABI symbols remain unchanged
```

边界原则：

- BLE server 可以问“录音是否正在运行”“断连时如何处理录音”“是否允许自动关机”。
- BLE server 不可以知道 `RecordStatus.run/orig_mode/mode/rerun` 的字段细节。
- protocol 状态上报由 record service 或 protocol facade 触发。
- 旧 ABI 符号保留在原位置或兼容 wrapper 中。

## 5. 建议新增 API

优先在 `rdx_record_service.h` 新增小接口，避免 BLE server 直接接触 record 内部结构。

### 5.1 record 查询接口

```c
bool rdx_record_service_is_running(void);
bool rdx_record_service_can_auto_shutdown(void);
```

语义：

- `is_running`：`RECORD_STATE_START` 或 `RECORD_STATE_RESUME` 返回 1。
- `can_auto_shutdown`：record 停止且无 record service 内部禁止条件时返回 1。

### 5.2 BLE 断连处理接口

```c
rdx_err_t rdx_record_service_handle_ble_disconnected(void);
```

职责：

- 保留当前产品条件编译行为。
- 对当前断连后切离线模式的产品，内部调用 `rdx_record_service_set_mode_offline()`。
- 对其他产品，如果原模式不是离线且录音正在运行，则按旧逻辑设置必要的 rerun 状态并调用 `rdx_record_service_stop_from_ble()`。
- 所有 `RecordStatus` 字段访问留在 `rdx_record_service.c`。

### 5.3 BLE 写就绪后状态同步接口

```c
rdx_err_t rdx_record_service_sync_state_after_ble_write_ready(void);
```

职责：

- 如果录音正在运行，触发原 `rdx_protocol_record_state_indicate()` 行为。
- 保留原日志语义，但不要在 BLE server 中打印 `rp->run/mode/orig_mode` 字段。
- 调用 `rdx_record_service_mode_active_check(false)`。
- 返回 `RDX_OK` 或具体错误码，BLE server 可只记录结果。

### 5.4 可选：protocol facade

如果不希望 `rdx_record_service.c` 继续直接调用 `rdx_protocol_record_state_indicate()`，可新增 `rdx_protocol_facade.h/c`：

```c
rdx_err_t rdx_protocol_facade_record_state_indicate_if_running(void);
```

但 P7 建议先不新增额外 facade 文件，除非当前文件职责继续膨胀。优先采用最小 service API，降低改动面。

## 6. 代码替换表

| 当前 BLE server 调用 | P7 后替换 |
|---|---|
| `RecordStatus *rp = rdx_record_get_status()` in disconnect | `rdx_record_service_handle_ble_disconnected()` |
| `rp->orig_mode != RECORD_MODE_OFFLINE` | service 内部判断 |
| `rp->run == RECORD_STATE_START || rp->run == RECORD_STATE_RESUME` | `rdx_record_service_is_running()` 或 service 内部判断 |
| `rp->rerun = true` | service 内部提供断连处理，不暴露 setter |
| `rdx_protocol_record_state_indicate()` | `rdx_record_service_sync_state_after_ble_write_ready()` |
| 广播降速判断 `rp->run` | `!rdx_record_service_is_running()` |
| 自动关机判断 `rp->run == RECORD_STATE_STOP` | `rdx_record_service_can_auto_shutdown()` |

## 7. 实施步骤

### P7.0 基线确认

1. 确认工作树干净。
2. 记录 `librdxApp.a` SHA256 和 symbol dump。
3. 记录当前 P7 命中：

```sh
rg -n "RecordStatus|rdx_record_get_status\\(|rdx_protocol_record_state_indicate\\(" SDK/apps/common/third_party_profile/rdx_protocol/rdx_ble_server.c
```

4. 跑静态边界脚本：

```powershell
pwsh -ExecutionPolicy Bypass -File tools/check_rdx_boundaries.ps1
```

### P7.1 增加 service API，不改调用点

在 `rdx_record_service.h/c` 增加：

- `rdx_record_service_is_running()`
- `rdx_record_service_can_auto_shutdown()`
- `rdx_record_service_handle_ble_disconnected()`
- `rdx_record_service_sync_state_after_ble_write_ready()`

要求：

- 新 API 不暴露 `RecordStatus`。
- 新 API 返回 `u8` 或 `rdx_err_t`，不返回内部结构体指针。
- 第一提交只新增 API 和局部测试，不替换 BLE server 调用点，方便 review。

### P7.2 替换断连路径

修改 `rdx_ble_server_disconnected_handle()`：

- 删除局部 `RecordStatus *rp`。
- 删除对 `rp->orig_mode`、`rp->run`、`rp->rerun` 的直接访问。
- 将当前 `#if APP_*` 断连录音处理块整体迁入 `rdx_record_service_handle_ble_disconnected()`。
- BLE server 中只保留：

```c
rdx_record_service_handle_ble_disconnected();
```

要求：

- 原有产品条件编译结果保持一致。
- `APP_TURING_EN` 下不设置 rerun 的行为保持一致。
- BLE 断连后的 adv、OTA、file cleanup timer 时序不变。

### P7.3 替换 BLE 写就绪后状态同步

修改 `rdx_ble_server_syn_data_after_ble_write_ready()`：

- 删除 `RecordStatus *rp`。
- 删除 `rp->run/mode/orig_mode` 日志。
- 删除直接调用 `rdx_protocol_record_state_indicate()`。
- 调用：

```c
rdx_record_service_sync_state_after_ble_write_ready();
```

要求：

- 录音正在运行时仍会上报 record state。
- 录音未运行时仍跳过上报。
- `rdx_record_service_mode_active_check(false)` 行为保留。
- `stream_tx_ready` 延迟 timer 行为不变。

### P7.4 替换广播降速 LED 判断

修改 `rdx_ble_server_adv_interval_change_timer_cb()`：

```c
if (wifi_info->onoff != TRANSFER_BY_WIFI_ON
    && !rdx_record_service_is_running()) {
    rdx_hook_led_set_scene(RDX_LED_SCENE_OFF);
}
```

要求：

- WiFi 传输中不改变灯效。
- 录音中不熄灭 LED。
- 不读取 `RecordStatus`。

### P7.5 替换自动关机判断

修改 `rdx_ble_server_auto_shut_down_enable()`：

```c
if (bt_get_total_connect_dev() == 0
    && g_rdx_ble_server_info.ble_conn == 0
    && rdx_record_service_can_auto_shutdown()) {
    sys_auto_shut_down_enable();
}
```

要求：

- 原来的“record stop 才允许自动关机”语义保持一致。
- 后续 record service 可集中叠加更多禁止自动关机条件。

### P7.6 清理 extern 和 include

在 `rdx_ble_server.c` 中移除 P7 范围内不再需要的声明：

- `extern void rdx_protocol_record_trigger_indicate(RecordStatus* d, bool factor);`
- `extern RecordStatus* rdx_record_get_status(void);`
- `extern void rdx_protocol_record_state_indicate(void);`

如果 `RecordStatus` 类型只因这些声明存在，P7 后 `rdx_ble_server.c` 不应再需要该类型。

### P7.7 增加静态边界规则

在 `tools/check_rdx_boundaries.ps1` 增加 P7 规则：

```powershell
Assert-NoHits `
  -Name "P7 rdx_ble_server.c has no direct record/protocol state access" `
  -Path "SDK/apps/common/third_party_profile/rdx_protocol/rdx_ble_server.c" `
        -Pattern 'RecordStatus|rdx_record_get_status\s*\(|rdx_record_process\s*\(|rdx_record_mode_active_check\s*\(|rdx_protocol_record_(state|trigger)_indicate\s*\(|#\s*include\s*["<]rdx_record\.h[">]'
```

如果后续发现 `RecordStatus` 仍因兼容声明必须保留，则只能用更窄规则：

```powershell
"rdx_record_get_status\s*\(|rdx_protocol_record_state_indicate\s*\("
```

并在文档和代码注释中说明为什么 `RecordStatus` 不能清零。默认目标仍是 `RecordStatus` 命中为 0。

## 8. 提交拆分建议

建议 P7 拆成 3 个提交：

1. `重构：新增 record service BLE 状态 facade`
   - 只新增 service API。
   - 不改 BLE server 行为。

2. `重构：收口旧 BLE server record 状态直连`
   - 替换断连、同步状态、LED、自动关机路径。
   - 移除 P7 范围 extern。

3. `工具：新增 P7 BLE server 边界检查`
   - 更新静态边界脚本。
   - 更新 P7 文档验收记录。

如改动很小，可以合并 2 和 3；不建议把 P7 与 P8 配置拆分合并。

## 10. 风险与回滚点

| 风险 | 表现 | 控制方式 |
|---|---|---|
| 断连时序变化 | BLE 断开后录音 stop/rerun 行为不同 | 先迁移原逻辑到 service，不改变条件编译和调用顺序。 |
| 协议状态上报丢失 | APP 不再收到 record state indicate | `sync_state_after_ble_write_ready` 内部保留原 running 判断和 indicate 调用。 |
| ABI 被误改 | 静态库链接失败或运行异常 | P7 禁止改旧符号签名和结构体布局，提交前做 ABI diff。 |
| service API 过度抽象 | P7 扩散到产品配置和 protocol 大改 | 只新增 BLE 所需最小接口，不启动 P8。 |
| host mock 不稳定掩盖回归 | 本地测试不能可靠证明 P7 | P9.1 优先修；未修前在验收记录中明确限制。 |

回滚建议：

- 若目标板断连行为异常，优先回滚 P7.2-P7.5 的 BLE server 替换提交。
- P7.1 新增 service API 可保留，除非它引入编译问题。
- 不允许通过修改 `librdxApp.a` 或旧 ABI 头来规避问题。

## 12. 当前实施状态
