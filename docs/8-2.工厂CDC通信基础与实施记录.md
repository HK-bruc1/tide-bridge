> 整理日期：2026-10-08。状态：通信基础及后续 DUT 主流程已实现；本文按实施阶段整理，不变更固件或协议。
> 适用工程：T2620 / AC701N（BR28），RDX + HOGP 双 Peripheral ACL。可选 MSC 默认关闭，启用时与 CDC 运行时择一，不新增复合枚举。

## CDC 实施主线与文档分工

CDC 产测是在已有 BLE 工厂 APP 的 DUT 业务上增加 USB 通信入口，不是另建一套产测业务。已支持的 DUT 控制请求统一使用 `*APP#custom#...#`，CDC 追加实际 CRLF 收帧；来源由通道标记，状态查询、回复及音频/文件传输不要求与 BLE 相同。

2026-10-08 最新对比证据为 `COM3_2026-10-08_15-10-13.log`：普通控制及录音启停请求已对齐，两路录音落盘均记录 error=0；本轮脚本报告尚未核对，且两路测试均有 `timer_no_response: app_core` 告警，不能据此宣称全部验收通过。详细范围见 8-3 第 14 节、8-4 第 10 节；本轮未覆盖包装。

| 实施顺序 | 交付内容 | 文档归属与状态 |
|---|---|---|
| 1：识别 CDC | 电脑识别 CDC 串口，可打开端口；此时尚无产测命令 | 本文第 8.6 节保留枚举阶段记录 |
| 2：串口收发回显 | 第三方串口调试工具发送消息，设备原样回显；验证收发链路，不执行业务 | 本文第 8.7 节保留字节收发记录，历史测试使用 TEST=1 |

## 当前基线与阅读规则

- 正式默认配置为 CDC=1、TEST=0、LOG_LEVEL=1；TEST=1 的原始字节回显与正式协议消费者不同时运行。普通串口工具可验证正式文本请求，但正式固件不再将任意输入原样回显。
- CDC 在 ON、USB 从机角色及传输资源就绪时可枚举，不依赖先进入 DUT、实体键资格或 SD 健康；插线不自动启动测试。退出 DUT 保留通信，业务操作仍受资源和存储门禁约束。
- 当前已接入基础信息、普通控制、AUDIO=1 录音/下载和独立包装。正常模式共存、故障注入等专项未因主流程通过而全部验收；范围以 8-3 第 12–13 节、8-4 第 9 节的具体证据为准。
- 本文维护 USB 枚举、generation、DMA、背压和生命周期；8-3 维护文本控制与公共 DUT 接入；8-4 维护音频/文件扩展。8-0、8-1 仍是 BLE APP 新增测试项文档。
- 第 8.6–8.7 节保留旧门控下的原始实现与板测记录，其中“未实现”“需要实体键进入 DUT”等仅描述当时版本，不是当前操作要求。旧阶段通过不自动证明后续准入调整后的全部场景通过。
- 固件日志配置不变；工站终端及 JSON 报告展示、保存完整身份信息（包括 AUTH），用于工厂核对。

## 1. 范围与现有代码边界

CDC 仅提供字节传输，不直接访问 SD；但通过 CDC 发起的录音、格式化和整包结束会访问 SD，仍须经过已有业务与存储准入检查。

当前仓库已有 CDC 类驱动、后台枚举入口、DUT 动作和拨码/MSC 切换逻辑；阶段 1A 新增厂测 CDC 开关和 `usb_factory_*` 枚举协调接口，实现在 `device/usb/device/task_pc.c`，由拨码的 app_core 定时服务发布准入，USB 任务执行类切换。阶段 2 新增 `usb_factory_cdc.c/h` 字节传输层与 USB 任务消息，实施状态见第 8.7 节；厂测命令消息、身份查询和 DUT 公共接口仍为阶段 3 要求。

| 已有代码 | 源码事实 | 对设计的约束 |
|---|---|---|
| `device/usb/device/task_pc.c` | OTG 插入时可经 standby 启动 CDC，返回 0 可抑制应用 IN 事件 | 能避免插线进入 PC，但不能独自覆盖带线拨码切换 |
| `device/usb/usb_task.c` | START 先 stop；PAUSE 后可直接启动 CDC；CDC_BACKGROUND 直接启动 CDC | 所有启动入口须统一门控，不能只改 standby |
| `device/usb/device/cdc.c` | 收发共用 mutex；write 按包循环并返回累计 offset；release 释放全局句柄 | 须核实发送计数、短写、等待时间和收发/释放并发 |
| `rdx_protocol/rdx_dip_switch.c` | 当前 OFF 进入原生关机，并有独立 3 秒保护；PC/MSC 为可选冷服务 | CDC 不增加等待 DUT/主机/USB 清理确认的关机门槛 |
| `rdx_protocol/rdx_dut.c` | 已有队列、目标状态判断、按键/喇叭及录音停止屏障；原 BLE 链路在 DUT 内有日志证据 | 扩展来源与结果接口；CDC 不能依赖 BLE token，也不能仅更名旧入口 |
| `rdx_protocol/rdx_vm.c` | 初始化已有 AuthKey 打印 | “AUTH 不记日志”需要同时整改已有日志 |

表中 `device/usb/` 与 `rdx_protocol/` 分别位于 `SDK/apps/common/` 和 `SDK/apps/common/third_party_profile/`。

阶段 1A 的 factory 分支不注册应用收发消费者，bulk OUT 配置为不触发接收中断、不读取端点数据，等待硬件缓冲耗尽后背压；实际 NAK、主机写超时及总线复位后行为须板测。停止时先屏蔽设备中断源再释放资源，并回收 CDC mutex；该阶段约束不能替代阶段 2 的在途 I/O 与会话同步。

## 2. 运行时分流与业务边界

### 2.1 稳态分流

下表以 CDC 编译开启为前提；关闭时不枚举厂测 CDC。以下为已接入的通信与业务分离规则，具体板测覆盖按验证记录判断。

| 拨码/OTG 条件 | USB 数据功能 | 业务与充电 |
|---|---|---|
| ON + 电脑，系统及 USB 传输就绪，未进入 DUT | 仅 CDC，不进入 APP_MODE_PC | 正常 BLE/HOGP/录音及充电保持；插线不自动开测 |
| ON + 电脑，已进入 DUT | 保持同一 CDC 会话 | 厂测动作统一准入；不因模式变化重枚举 |
| ON + 电脑，正常退出 DUT | 保持 CDC | 安全清理测试后恢复允许业务，可查询结果及按条件取文件 |
| ON + 电脑，SD 未就绪或业务存储失败 | USB 资源正常时仍可 CDC | 可查询故障；存储动作独立拒绝或恢复，不强行操作 SD |
| OFF + 电脑，允许冷服务，PC_STORAGE=1 且存储准入通过 | 仅 MSC，APP_MODE_PC | SD 由电脑独占；按平台策略充电，无 CDC |
| OFF + 电脑，PC_STORAGE=0 或导出条件不满足 | 无厂测 CDC，不强行启动 MSC | 按现有冷服务/关机和充电策略 |
| 充电器，仅 VBUS、无从机角色 | 无数据类 | 按现有拨码及充电策略 |
| ON + 无 USB / OFF + 无 USB | 无 | 正常业务 / 正常关机 |

CDC 开启条件概念式：

```text
CDC_ENABLE && ON && system_usb_service_ready
&& VBUS && OTG_SLAVE_CONFIRMED
&& !shutdown && !APP_MODE_PC
&& old_usb_class_released && usb_transition_safe
```

其中 `system_usb_service_ready` 指 USB 协调/任务等必要系统资源已就绪，不得暗含 DUT、实体键资格、BLE owner、用户绑定或 SD 健康检查。具体准入由 USB 执行端重查；不是主机操作系统或工站身份认证。

PC/MSC 退出和旧 USB 类释放仍是 CDC 启动前提；但 MSC 停止后 SD 重挂载失败应表现为存储业务故障，不应永久隐藏串口。若 USB 类仍被占用或释放失败，则不能启动 CDC。角色/任务暂未就绪时周期补偿重试，不能因一次判断失败永久漏枚举。

### 2.2 通信与 DUT 分离

用户已确认允许通过 CDC `*APP#custom#ft_dut#1#` 显式进入 DUT，无需先按实体键；实体键入口保留。插线只建立通信，不自动进入 DUT、不自动录音或格式化。进入/退出按目标状态幂等执行，并检查初始化、关机、OTA、资源占用及故障状态。

正常 ON 模式可连接 CDC，执行 PING、信息/状态查询；可通过 8-4 定义的文件协议在存储准入通过时读取产测录音。新灯测、喇叭、按键、录音、格式化等测试仍要求 DUT 和对应资源许可，未进入时返回状态拒绝。枚举成功不等于测试已获准。退出 DUT 完成业务清理，但不使 CDC generation 失效；同一会话可查询结果和取文件。

包装成功保持红灯和完成锁定，可通过 CDC 查询，等待 DIP OFF；不自动关机或关闭 CDC，不接受新测试和重复包装。按键禁用标记仍只约束按键入口，本次包装锁定优先于新的进入请求。详细兼容见 8-3 第 5 节。

| 通道 | 边界 |
|---|---|
| BLE | 保留原工厂 APP 命令、事件、录音和下载协议；DUT 内重连另行板测 |
| CDC | 独立通信生命周期；显式进入 DUT，复用公共动作，退出后继续查询/文件阶段 |
| SPP MIC | 按工站实际需求保留和接入；日志仅有初始化，不将频响或三通道共存当成已验证前提 |

CDC/BLE 同用业务接口，响应、按键事件及录音数据按来源隔离。通道可并存不代表音频/存储可并行占用。CDC 常驻正常模式新增的功耗、调度、充电及 BLE/HOGP 共存须回归；不新增 DUT 内 HOGP 在线承诺。

正式命令已接入，原始字节回显仅在 TEST=1 的历史测试固件使用；正式协议使用唯一消费者、TEST=0。完整 USB 产测的音频/文件能力由 [8-4.工厂CDC录音与文件下载测试实现说明.md](8-4.工厂CDC录音与文件下载测试实现说明.md) 定义并实现，包括录音授权、实时音频流、保存结果和独立文件传输。

## 3. 构建与配置

项目开关放在 `SDK/apps/earphone/include/t2620_project_config.h`，不修改工具生成的 `sdk_config.h/c`：

```c
/* 当前默认开启正式 CDC；验收范围见各阶段记录。 */
#ifndef TCFG_T2620_FACTORY_USB_CDC_ENABLE
#define TCFG_T2620_FACTORY_USB_CDC_ENABLE 1
#endif

#if TCFG_T2620_FACTORY_USB_CDC_ENABLE
#undef TCFG_USB_CDC_BACKGROUND_RUN
#define TCFG_USB_CDC_BACKGROUND_RUN 1
#endif
```

合入 `不加HFP` 后，`TCFG_T2620_PC_STORAGE_ENABLE` 保持当前产品默认值 0，CDC 不再要求开启 U 盘导出。需要复测原分支的 MSC/CDC 切换时，显式设置该宏为 1；`usb_start()` 在厂测配置下不加入 `CDC_CLASS`，仅在允许 PC 存储接管后启动 MSC。关闭导出时 PC 就绪查询固定返回 0。

以上宏片段不是完整实现：`app_config.h` 后续调音配置可能覆盖后台 CDC 宏，`usb_common_def.h` 又会派生 USB 类与 OTG 配置。必须在最终派生配置后增加编译检查：厂测开启时 CDC、USB slave、SD0 和拨码依赖全部成立，否则编译失败；可选 MSC/PC 依赖由存储导出开关独立检查。

本版本厂测 CDC 与在线调音工具配置互斥，组合启用时编译报错，避免 UART 调音覆盖后台宏或 USB 调音争读同一端点。保留原有非厂测调音行为；不得同时派发 `MSG_FROM_CDC_DATA` 与 `MSG_FROM_FACTORY_CDC` 消费同一份数据。

新增源文件列入 `SDK/Makefile`，消息编号在现有应用消息定义处分配，避免冲突。分别检查开关 0/1 的最终预处理结果和构建；默认开启不代表所有量产验收项均已通过。

## 4. USB 生命周期与热切换

### 4.1 统一协调入口

复用 `usb_factory_*` 与 `NONE / MSC / CDC / STOPPING` 状态协调。app_core 发布协调请求，usb_stack 串行拥有类启动、端点 I/O 与释放；请求入队不等于启动成功。拨码、OTG、系统/USB 就绪、模式退出、旧类释放和关机驱动协调，周期服务补偿丢通知和暂未就绪。

当前 `task_pc.c` 的 `factory_cdc_allowed()` / `usb_factory_service()` 调用 `rdx_dut_factory_usb_ready()`，后者绑定实体键、DUT 和存储。新实现须改为第 2.1 节独立通信准入；不能仅在 CDC 命令解析处跳过 DUT 判断，也不能只改 standby 而遗漏后台重启入口。

`usb_cdc_background_standby()` 在 ON 时抑制转入 PC 的应用 IN；未就绪由后续协调启动。所有 START、PAUSE、CDC_BACKGROUND 和直接后台启动按实际类状态及最新目标统一检查。OFF 仅按可选 MSC 冷服务规则，不保留 OFF 等待 DUT 的 CDC 重连例外。

类变化必须先停止/释放旧类，再注册目标；同类重复协调不得反复重枚举。USB 执行前重查实时 ON、角色、关机及资源条件，拒绝过期启动请求。DUT 进入、普通退出和 SD 故障本身不触发 CDC stop/start。

### 4.2 转移规则

| 场景 | 必须执行的顺序 |
|---|---|
| ON 插电脑 / ON 带线冷启动 | 系统及 USB 就绪、角色确认、旧类释放后启动 CDC；无需 DUT/实体键/SD 健康；不进入 PC |
| 带线按键或命令进入 DUT | 检查业务准入并设置目标状态；已有 CDC 保持，不等待新 IN、不重枚举 |
| 正常退出 DUT | 关闭新测试准入，等待必要停止/保存/资源清理，记录结果并恢复允许业务；保持 CDC 会话 |
| 格式化/保存失败 | 保持可用 CDC，查询故障；隔离未释放资源，拒绝冲突动作，不自动重试破坏性操作 |
| 整包成功 | 保留完成锁定、红灯和 CDC 查询，等待 DIP OFF；详见 8-3 |
| OFF 插电脑 | 仅 PC_STORAGE 开启且冷服务/存储准入满足时走 PC/MSC；不启动 CDC |
| 带线 OFF→ON | 停止 PC/MSC、释放旧 USB 类，按新通信条件启动 CDC；SD 恢复结果独立决定业务准入，不等待新 IN |
| ON→OFF / 系统关机 | 关闭通信新准入并通知 USB 尽力清理，继续平台正常关机及独立 3 秒保护；不等待 DUT 退出、USB 确认或主机读取 |
| 拔线/角色失效 | 失效会话、停止 CDC、清旧数据；按动作来源执行安全收尾，不自动启动另一数据类 |
| 总线复位/取消配置/DTR 关闭/发送超时 | 按传输层规则失效及清理会话；需要重枚举时，仅按当前独立通信准入恢复，不要求退出再进入 DUT |
| USB 类切换/释放失败 | 不强行启动 CDC/MSC，保留资源保护；与 SD 业务故障区分 |

取消旧版“OFF 等待 DUT 退出”和“仅曾进入 DUT 才能 ON 故障重连”的特殊状态。正常 ON 本就允许通信，因此 SD 故障无需另授枚举资格。故障信息和动作结果仍独立保留；退出 DUT 或 LAST 被覆盖不能清除未解决的资源/存储错误，具体恢复依据 8-3 第 6 节。

OUT 仍须可达 USB stop；核对所有活动模式的事件分发。连续插拔、拨码反转与延迟消息按最新目标收敛，不依赖旧请求恢复端口。取消 CDC 关机等待门槛不等于跳过平台已有录音/存储清理，USB 通知路径也不得提前释放在途 DMA 缓冲。

### 4.3 会话与资源释放

每次 CDC 启动分配递增 session generation。RX 通知、命令和 TX 队列均携带 generation；重新枚举后丢弃旧消息。消息传稳定的 USB ID 与 generation，避免把可过期资源指针当作会话身份。

新边界下，会话失效覆盖物理拔线、角色失效、USB 总线复位、取消配置、DTR 关闭、实际类释放及发送超时重建；正常 DUT 进入/退出不使会话失效。不依赖这些事件一定经过完整 stop/start。先关闭准入并使旧 generation 失效，清理旧数据，完成传输准备后才开放新会话。USB 总线复位不等于整机复位，不清除已接受动作的状态记录。

当前传输层已处理 DTR 下降沿失效/停止，但串口关闭是否产生该事件仍需目标驱动实测。关闭/重开不能自动证明新会话；无法确认时通过明确的 USB 重枚举或拔插恢复。退出再进入 DUT 在新设计中不重建 CDC，不能继续作为清理会话的方法；仅清 PC 输入缓存或发送 PING 也不能证明旧数据已清理。

USB 任务停止前关闭准入并等待在途 I/O 安全退出，之后才能 `cdc_release()`；app_core 不能在释放过程中使用句柄。需实现生命周期锁或等效串行 I/O 所有权，且定义锁顺序，禁止 app_core 同步等待 USB stop、USB 任务又等待 app_core 的死锁。

断线清除半行、超长丢弃状态、待解析数据和未发送响应。已接受的格式化等动作不因拔线强制中止；安全完成并保留本次启动内的状态，供重连查询。旧回调不得向新会话发送旧响应。

## 5. CDC 收发与背压

### 5.1 接收

`usb_cdc_wakeup()` 位于中断上下文，只投递或合并 RX 通知，不解析、不执行 DUT、不收发协议响应。厂测消息处理在任务上下文调用 `cdc_read_data()`，每次读缓冲至少覆盖当前最大包长（当前 64 字节），跨包组帧。

现有驱动会按最大包读取后裁剪到调用者长度，小缓冲可能丢尾部。通知队列满不能只打一条日志后遗失数据：采用 pending 标志与有界补偿调度，并确认端点 NAK/重通知行为；不能假定丢一次消息必有下一次中断。每轮处理包数设上限，主动让出 app_core。

### 5.2 发送

协议层只生成完整响应，进入有界 TX FIFO。初始容量为 4 条、每条最多 258 字节（256 字节正文加 CRLF），实施时计入 RAM 预算。动作执行前必须预留应答容量，不能执行完才发现无处回复。

发送保留 `offset`，按 `cdc_write_data()` 返回长度推进，只有完整行写完才移除。返回 0 表示本次无进展，可能是未就绪或底层发送失败；不能立即通过同一不可用通道发送 `ERR BUSY`。正数短写必须继续发送剩余部分，不得插入另一条响应造成串行混帧。

采用有界重试与发送超时。超时后停止该会话的后续响应并清理/重建传输，客户端按超时处理；禁止将半条响应与后续响应拼接。`ERR BUSY` 仅用于通道可回复且命令尚未执行的业务占用或容量拒绝。队列完全耗尽时通过接收背压或关闭会话处理，禁止无限分配内存。

上述短写/超时是传输契约，不要求重新采用 SDK 的阻塞发送路径。已实现的阶段 2 厂测分支由 usb_stack 使用单包 DMA 推进，固定 TX FIFO 和待消费 RX 包，不能退回 app_core 循环等待 `cdc_write_data()`。新开启范围应复用现有有界传输及 I/O/release 所有权，并重新验证正常模式负载下的进展、计数和最后 DMA 包超时。

字节传输的保证限定于正常连接且成功接纳的数据：完整、有序、不重复。队列满时明确拒绝或背压，不允许静默丢弃后继续报成功。超时、复位或拔线允许未完成数据丢失，但必须报告传输失效并清理会话；不提供跨会话自动重传或业务“恰好执行一次”的保证。协议动作是否已执行仍按第 6 节查询与结果未知规则处理。

当前厂测传输已处理 DTR 关闭，目标驱动是否可靠产生下降沿仍须实测；DTR 不是厂测身份认证。正式协议客户端在端口就绪后先 PING，但 PING 不证明旧会话已清理；异常恢复按第 4.3 节执行。波特率只是 CDC line coding 参数，不决定 USB bulk 速率。

- 纯充电器无数据类；OFF 无 CDC，MSC 仅在独立开关及导出条件满足时出现。
- 记录描述符、实验 VID/PID、序列号、Windows 驱动与 COM；旧描述符可复用，但正常 ON 枚举及模式保持必须重新实测。

**检查点 1B：切换与正常业务**

- PC_STORAGE=0/1 分别验证 OFF→ON；启用 MSC 时先释放旧类，再启动 CDC。SD 重挂载失败不等同于 USB 释放失败，业务与通信按第 2.1 节分别判断。

- 正常模式 CDC 连接/收发/主机不读时回归 BLE 双 ACL、HOGP、录音、充电及低功耗；DUT 内以原测试行为为基线，不要求 HOGP 强制在线。

### 8.3 阶段 2：打通发送、接收与任务回调

**目标与接口边界**

建立与厂测命令无关的字节传输层：PC → USB RX 通知 → 任务上下文接收回调；设备 → 有界 TX 队列 → PC。USB 包边界不是应用消息边界，回调只交付字节与长度，不假定一次回调对应一次 PC 写入。

具体函数名在实施时确定，但接口必须明确：回调运行任务、数据缓冲的有效期、发送时是否复制数据、返回值表示入队还是完成、未就绪/队列满/会话失效如何报告。建议接收数据仅在回调期间有效，消费者需保留时自行复制；发送入队成功不能表示主机已经收到。

**计划工作**

1. 中断只通知或合并 pending；任务按最大包长读取，有界处理并让出 CPU。处理通知投递失败后的补偿，避免一次丢通知导致永久不再接收。
2. 实现有界发送、短写续传和超时处理。验证底层 bulk 写的最坏耗时及返回长度计数，主机停止读取不得阻塞正常业务；若现有驱动无法保证，改造有界 I/O 或引入可安全停止的专用 I/O 任务。
3. 实现 generation、I/O 与 release 同步及旧队列清理。会话失效须覆盖物理拔线、总线复位、取消配置及超时重建；另行定义串口关闭重开后的清理策略，不依赖现有 DTR 位作为可靠断线判据。
4. 提供仅用于阶段 2 板测的原始字节回显入口，以及设备主动发送固定测试字节的入口，验证两个方向。测试入口有独立开关，阶段 3 接入协议时关闭，不能与协议消费者同时读取 CDC 数据。
5. 提供最小 PC 测试脚本，按预期长度累计接收并逐字节比较；测试数据由 PC 生成，不使用 AUTH 或真实业务数据。

**通过标准**

- PC 发送的数据进入任务回调，设备回显完整一致；设备主动发送的数据也能被 PC 正确接收。
- 正常连接且数据被成功接纳时，覆盖 1、63、64、65、128、256 字节及跨多包数据、连续发送和含 `0x00` 的二进制数据，不丢字节、不乱序、不重复。至少完成 1000 轮完整字节比较。
- 覆盖 RX 通知失败、TX 队列满、0 写、正数短写、主机停止读取及超时，无无限等待、内存持续增长或正常业务卡死。
- 故障时允许未完成数据丢失，不要求跨会话补发；必须报告失效并按第 4.3 节完成清理与恢复，新会话不收到旧数据。分别记录拔线、总线复位、取消配置、发送超时和串口关闭重开的恢复步骤，不能仅用重新打开 COM 口代替会话失效处理。
- TEST=1 的字节测试按新通信条件开放，无需实体键或 DUT；普通 DUT 退出后继续收发且 generation 保持。分别验证未进入、进入、退出 DUT 以及 SD 故障时的传输，回归正常 BLE 双 ACL/HOGP、录音及功耗。TX 满明确拒绝或背压；正式协议 TEST=0，不与测试消费者混用。

阶段 2 通过后，可描述为“USB 双向字节传输与接收回调已打通”，此时仍没有厂测命令语义。

**本轮实现**

- 新增 `device/usb/device/usb_factory_cdc.c/h`。`usb_stack` 串行拥有端点 I/O 和 stop/release，短临界区保护队列及会话；回调在该任务运行、临界区外执行，最多交付一个 64 字节包。消费者需保留数据时自行复制，未来厂测解析与 DUT 处理仍投递 app_core。
- RX 中断屏蔽当前端点通知并合并投递 `USBSTACK_FACTORY_CDC_IO`，10 ms 定时通知补偿队列满、丢通知及 TX 进展。每次只处理有界工作，不把 USB 包边界当作应用消息边界。
- 固定 4×258 字节 TX FIFO，另有一个 64 字节待消费 RX 包。发送全量复制入队或明确返回满/失效/参数错误；成功仅代表入队。短写按 offset 续传，消费者拒收时保留同一 RX 包；最后一个已提交 DMA 包及 ZLP 仍受超时保护。
- 核对当前 BR28 链接产物后，未采用会循环等待的 `usb_g_bulk_read/write`。CDC 使用与 SDK 一致的单包 DMA 提交和 `maxp+4` 交替 RX 缓冲规则，每次只消费一个包，包含 ZLP；端点固定 64 字节并有编译检查。真实 DMA/IRQ 时序仍需板测。
- 启动、总线复位、SET_CONFIGURATION（包含取消配置）、DTR 关闭、停止和超时使 generation 失效。旧通知无资源指针，旧 callback 不能向新会话发送。已打开端口的 DTR 下降沿和 2 秒发送无进展触发停止，至少间隔 300 ms 再按现有 DUT 准入重新枚举。
- 串口关闭是否可靠产生 DTR 下降沿须记录目标 Windows 驱动实测结果。关闭后没有重新枚举、或发生任何收发错误时，工站必须拔插 USB / 退出再进入 DUT，不能只清输入缓存或重开端口后假定会话已清理。
- 独立 `TCFG_T2620_FACTORY_USB_CDC_TEST_ENABLE` 默认 0，依赖 CDC 开关。测试开启后每个打开会话主动发一次 `00..FF` 共 256 字节，随后原始字节回显；TEST=0 不注册测试消费者。阶段 3 接入时必须关闭该测试开关。

#### CDC 日志收束（2026-09-15）

COM3 是固件日志观察端，COM6 是 CDC 交互端。默认 `TCFG_T2620_FACTORY_USB_CDC_LOG_LEVEL=1`，不打印收发内容，不需要脚本才能观察交互。

- 日常模式每 1000 ms 汇总一次同一会话的 `RX` 与 `TX_DONE`，`len` 为累计字节数，`count` 为非零 USB 数据包数量，不是应用命令数量。小数据同样在下一个汇总周期显示；USB 任务繁忙时可能延后。
- `TX_DONE` 只在端点不再忙后计入对应包的实际字节数；入队和提交 DMA 不算完成，ZLP 不增加字节数或包数。它证明设备侧观察到端点完成，不代表电脑应用已经读取、解析或执行。复位、关闭、超时会清除未确认字节，不能将它们算到新会话。
- 默认隐藏 `TX_QUEUED`、`TX_SUBMIT`。保留 START、RESET、CONFIG、OPEN、CLOSE、STOP、TIMEOUT；重复的 `TX_REJECT` 按会话及错误码汇总。`rc=-1` 表示会话未就绪或已失效，`-2` 表示发送队列满，`-3` 表示参数无效。
- `ms` 是该条记录首个事件的设备时间，`gen` 是会话代次；跨会话不合并。记录按首次出现位置输出，汇总日志不能用于重建逐包时序。
- 队列固定 16 条，满时丢弃日志并显示 `LOG_DROPPED`，此时统计不是完整流量。日志不背压数据通道。等级 2 保留最多 32 字节的包内容预览，仍受队列和周期限制，仅供已知测试数据诊断；涉及 AUTH 的业务不得开启内容日志。等级 0 关闭本模块诊断。
- 厂测 CDC 下关闭 `cdc.c` 控制/端点回调的直接打印，诊断统一由 USB 任务在开中断时输出；非厂测 CDC 保留 SDK 日志行为。USB 停止时由 USB 任务有界输出剩余日志；恢复出厂及拨码关机调用路径不输出、不等待日志，不依赖输出完成。

例如 COM6 发送 `hello`（5 字节、不附加换行），测试回显开启时 COM3 在汇总周期内可见以下形式；时间和会话号以实机为准：

```text
[FACTORY_CDC] ms=12000 gen=3 RX len=5 count=1 rc=0
[FACTORY_CDC] ms=12020 gen=3 TX_DONE len=5 count=1 rc=0
```

测试模式打开端口时原有的主动 256 字节测试图样仍保留，其发送量也计入 TX_DONE；与 hello 同处一个周期时发送汇总可能为 261 字节。本次只收束日志，不改变该测试行为。

统一五组主机检查通过；启用 CDC=1/TEST=1、默认 LOG_LEVEL=1 的固件构建通过（保留 SDK 既有警告）。独立测试包：`output/factory-usb-cdc-log-summary/`；构建及检查记录随包保存，配置及 SHA256 见 `manifest.json`。软件验证覆盖日志等级 0/1/2、1000 次收发汇总、周期与时间回绕、会话/错误码隔离、DMA 忙时不报完成、65 字节分包完成及失效清理。板测需确认 hello 回显、持续收发时日志量及恢复出厂/拨码关机回归；此前用户已确认关机修复有效，不等于本次日志版本已完成板测。

#### RDX 架构边界收束（2026-09-15）

本轮保持“RDX 决定产品准入、USB 任务拥有端点与释放、字节传输不执行 DUT 命令”的分层。必要的 JL 原生接入保留在 CDC 驱动、配置请求及 USB 任务分发中。

- 通用 `usb_pause()` 仅在实际状态为 CDC 时停止厂测传输；NONE/MSC 停止不再递增 CDC 会话、删除 CDC 定时器或输出 CDC STOP。CDC 启动失败仍在局部失败路径清理。恢复出厂、拨码关机继续只通知，不等待 USB 清理。
- `factory_cdc_requested` 是 app_core 的协调请求，不是可长期缓存的授权。USB 执行前继续通过 RDX 的只读准入接口重查 DUT/关机/业务守卫，并检查线缆、角色和资源条件，防止退出后的旧启动消息恢复 CDC。未将这条实时保护替换为周期快照；也未将不透明的底层状态查询包进新的关中断区。未来修改这些查询时必须保持无等待、无业务副作用。
- `usb_factory_cdc.h` 仅公开字节收发、会话及消费者接口；生命周期、驱动原语和端点参数移至 `usb_factory_cdc_internal.h`。业务消费者在启动前注册，停止/重启保留注册关系；消费者不得同步等待 USB 任务。
- 回显和 256 字节图样移至独立 `usb_factory_cdc_test.c`，仍由 TEST 开关控制。测试消费者仅在没有已注册消费者时作为默认值，不再覆盖正式消费者；自定义消费者不发送测试图样。DTR 只记录测试打开事件，图样在 USB 任务、临界区外生成并通过公共发送接口入队。测试模式既有串口交互行为保持一致。
- 本轮未实现阶段 3 的分帧、厂测命令及 app_core 消费者；这些业务不能直接放入 USB 回调。

前一日志版本的板测补充：`cache/cdc_log_summary_COM6_board.log` 与 `COM3_2026-09-15_14-02-07.log` 对照，hello 5 字节回显通过，脚本 1000 轮共 661006 字节一致；COM3 同会话 RX 合计 661011、TX_DONE 合计 661267，差额为主动图样 256 字节。未见 CDC TIMEOUT、TX_REJECT、LOG_DROPPED。该结果不解释更早首次单字节失败的根因，也不代表本轮架构调整已经板测。COM6 已释放，后续只做 hello 和少量交互，不再默认执行大批量测试。
