# 10-10. 灵感录音复用闪记协议融合方案

> 状态：固件已实现，用户已构建并完成部分实板测试；本文保留方案、踩坑和验证边界。更新日期：2026-11-04。

## 1. 方案演变

| 阶段 | 方案与问题 |
| --- | --- |
| 原方案 | F19 灵感录音复用在线会议录音的握手和 `record` 状态上报。音频可以复用，但 APP 会把灵感录音当作会议录音，会议与灵感的控制和界面容易混淆。 |
| 参考与备选 | 参考 SDK 有闪记文件、在线状态和音频分包等记录；曾考虑同时本地保存和在线推流。但片段不足以证明参考 APP 实收推流，也不能覆盖参考协议中“不推流”的文字要求。双写不是本项目最终方案。 |
| 当前方案 | 会议继续使用 `record`；APP 闪记和 F19 灵感使用独立的 `flashnote`。两者复用现有录音引擎及 `stream` 音频通道，但控制、状态和会话归属分离。 |

本方案是结合产品需求的闪记适配，不是简单照搬参考 SDK，也不是把会议状态报文改个前缀。原始协议表和参考日志未纳入当前版本库。

## 2. 当前业务方案

### 2.1 入口与路线

| 入口 | 启停方式 | 录音路线 |
| --- | --- | --- |
| APP 闪记 | APP 发送闪记开始、停止指令 | RDX 就绪时纯推流，不保存本地文件；不具备启动条件时拒绝。 |
| 按键 F19 | 配置为普通 F19 的实体键稳定按下时发起，松开时结束或取消 | 受理时 RDX 就绪则只推流、不保存；未就绪则只本地保存、不推流，文件场景为 `scene=3`。 |

RDX 就绪指有效 RDX 会话、通知 CCC 和音频发送通道均就绪；仅有蓝牙物理连接或 HID 连接不等于 RDX 就绪。

**路线在会话受理时确定，途中不切换：**

- 离线 F19 录制中连接 RDX：继续本地保存，不补开推流；向 APP 同步闪记状态、真实 SN 和文件名。之后 RDX 断开不应结束本地录音。
- 在线 F19 或 APP 闪记中途失去 RDX／CCC／推流能力：取消或结束并清理会话，不转为本地保存。
- 录音尚未完成启动时松开 F19，也要取消本次请求，不能稍后自行开录。

### 2.2 会话归属与其他业务

- APP 发起的闪记由 APP 控制；F19 发起的闪记属于该次按键周期。两类会话互斥，不能互相接管或停止。
- 按键 F19 启动、录制或收尾期间，APP 闪记 START／STOP 返回设备忙 `2`；离线 F19 重连后的状态同步只用于展示，不转移控制权。旧会议 `record` 指令也不能控制闪记。
- APP 闪记期间按 F19 不得打断 APP 会话；闪记与会议、通话、DUT 等业务仍遵守既有互斥和保护规则。
- `recsave` 只控制 APP／F18 会议，不改变闪记路线。既有 CDC LIST/GET 双向共存例外仅适用于在线按键 F19，不自动扩展到 APP 闪记。

按键细节和其他业务边界分别见 [2-8](2-8.HID键值绑定本地功能设计.md)、[10-4](10-4.CDC通用文件传输业务方案.md) 和 [10-8](10-8.会议录音落盘APP控制方案.md)。

## 3. 关键协议约定

| 报文 | 含义 |
| --- | --- |
| `*APP#flashnote#1#` / `*APP#flashnote#0#` | APP 请求开始／停止自己的闪记。 |
| `*DEV#flashnote#1#<sn>#<filename>#<opus_format>#` | 闪记运行状态。 |
| `*DEV#flashnote#0#<sn>#<filename>#<opus_format>#` | 闪记结束状态。 |
| `*DEV#flashnote#2#` | 设备忙或本次无法开始。 |
| `*DEV#flashnote#3#` | 需要落盘的闪记因空间不足无法开始。 |

APP 闪记与在线 F19 没有本地文件，状态使用 `sn=0`、空文件名，即 `*DEV#flashnote#1#0##<opus_format>#` 和 `*DEV#flashnote#0#0##<opus_format>#`。`opus_format` 表示本次实际编码格式；`0##` 不代表生成了空文件。离线 F19 同步时则使用真实文件身份。

开始状态应在录音实际启动后上报；APP 应等待设备状态，不能把发出开始指令当成录音成功。`flashnote#1` 是开始请求，不能用作无副作用的状态查询；设备在离线 F19 接入 RDX 时主动同步状态。

## 4. 踩过的坑

1. **只打开闪记能力位并不能开录。** 早期设备能收到 APP 闪记指令，但缺少完整的解析和业务处理。需要下行指令、录音业务、状态上报和音频通道共同对接。
2. **复用音频通道不等于复用会议状态。** 早期 F19 虽然能够推流，却以会议录音形式上报；现在灵感只使用闪记状态，不同时按会议状态驱动 APP。
3. **SN 和文件名不能照搬会议报文。** 旧会议无文件状态中，这两个尾部字段可能省略；闪记的格式字段在它们之后，因此在线闪记必须明确发送 `0##`，不能把字段一起省掉。
4. **在线闪记不能误落盘。** 参考 SDK 的文件流程和本产品纯推流需求不同；APP 发起与 F19 在线都不应因复用文件录音流程而创建本地文件。离线 F19 才保存真实文件。
5. **状态同步不代表允许接管。** 离线 F19 中途连接 APP 后，APP 能看到真实文件信息，但不能停止按键会话；按键也不能停止 APP 发起的会话。忙响应是有意的产品规则。
6. **断连和快速操作可能留下旧状态。** 曾出现断连后重连不稳定、后续 F19 偶发无法触发等现象。当前按会话归属清理并隔离迟到事件；偶现问题仍需结合实板复测，不能仅凭单次成功认定根因已完全消除。
7. **设备提交状态不等于 APP 已收到音频。** 在线流可能拥塞或断连；停止录音后的状态提交也不证明尾帧已全部送达。需要双端日志和 APP 实际表现确认。
8. **协议没有请求 ID。** APP 应串行启停，取消后不要继续重试旧 START；不能仅靠设备判断同一连接上迟到的指令属于哪次 APP 会话。空闲时重复 STOP 返回无文件结束状态，若错过本地文件结束状态，应通过文件列表核对。

- 2026-11-04 完整主机测试为 **23/23 套件通过**；用户已构建并测试在线纯推流、离线本地保存及录制中途连接 RDX。
- 同日用户提供的 `COM3_2026-11-04_10-50-08.log` 显示：APP 闪记期间按 F19 未中断会话；在线和离线 F19 的 APP STOP 请求进入忙处理；离线 F19 重连后同步真实 SN／文件名，松开后文件保存、索引和本地播放打开成功。该日志未纳入版本库。
- 该日志未清晰记录在线 F19 的结束状态发送，也没有覆盖在线录音中途断连；设备侧发送成功不等于 APP 确认接收。在线结束 UI、断连清理、首尾音频顺序及 APP 双端兼容仍需补测。
- 旧 APP 可能依赖原来的会议录音握手；APP 需要兼容闪记的 `0##` 无文件身份、忙响应及独立页面。APP 闪记是否需要 CDC 并发，需另行评估。
