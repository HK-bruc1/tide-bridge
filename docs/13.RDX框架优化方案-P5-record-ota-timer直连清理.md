# RDX 框架优化方案 — P5：`rdx_record.c` / `rdx_ota.c` timer 直连清理

> 依据：`docs/12.RDX框架优化方案-P3a-P4-业务层timer与DUT直连清理.md` — P3a-P4 已完成，剩余 `rdx_record.c` 与 `rdx_ota.c` 的本阶段 timer 直连。
> 定位：收口 `rdx_record.c` / `rdx_ota.c` 范围内 25 处 timer 直连（+ 1 处注释）。
> 范围：**仅** `rdx_record.c`、`rdx_ota.c` 中的 `sys_timeout_add` / `sys_timeout_del` / `sys_timer_add` / `sys_timer_del` / `sys_timer_re_run` / `sys_timeout_add_2_task` 清理。
> 前置条件：需先在 OSAL 中新增两套 API：
> 1. `rdx_os_timer_add_to_task()`：封装 `sys_timeout_add_2_task()`
> 2. `rdx_os_timer_periodic_add()` / `rdx_os_timer_periodic_del()`：封装 `sys_timer_add()` / `sys_timer_del()`，**不可复用一次性 `rdx_os_timer_add()`**

---

## 术语表

| 术语 | 含义 |
|---|---|
| **timer 直连** | 业务 `.c` 中直接调用 `sys_timeout_add()` / `sys_timeout_del()` / `sys_timer_add()` / `sys_timer_del()` / `sys_timer_re_run()` / `sys_timeout_add_2_task()`，绕过 OSAL 封装 |
| **OSAL timer API** | `rdx_jl_osal.h` 中 `rdx_os_timer_add(cb, priv, timeout_ms)`、`rdx_os_timer_del(id)`、`rdx_os_timer_re_run(id)`，P2 已补齐 |
| **OSAL periodic timer API** | 本阶段新增 `rdx_os_timer_periodic_add(cb, priv, period_ms)` / `rdx_os_timer_periodic_del(id)`，封装 JL `sys_timer_add()` / `sys_timer_del()` |
| **OSAL task-timer API** | 本阶段新增 `rdx_os_timer_add_to_task(task_name, cb, priv, timeout_ms)`，封装 JL `sys_timeout_add_2_task()` |
| **boundary check** | `tools/check_rdx_boundaries.ps1` 静态边界检查脚本 |

# Part 1 — 差距分析

## 1.1 总体概览

P3a-P4 完成后，业务层 `.c` 文件中 timer 直连剩余 **25 处有效 + 1 处注释**，集中在 `rdx_record.c` 和 `rdx_ota.c`：

| 文件 | `sys_timeout_add` | `sys_timeout_del` | `sys_timer_add` | `sys_timer_del` | `sys_timer_re_run` | `sys_timeout_add_2_task` | 有效合计 | 注释 | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| `rdx_record.c` | 10 | 5 | 1 | 1 | 1 | 0 | **18** | 0 | 含多处 `priv = 0` 调用 |
| `rdx_ota.c` | 3 | 1 | 0 | 0 | 2 | 1 | **7** | 1 | line 526 为注释代码 |
| **P5 合计** | **13** | **6** | **1** | **1** | **3** | **1** | **25** | **1** | |

P5 完成后，`rdx_record.c` / `rdx_ota.c` 范围内 timer 直连清零；业务层一次性 timeout、`sys_timer_re_run` 与 Q_CALLBACK 直连按 P0-P5 已知规则完成收口。

但 P3a-P4 的历史规则未把 `sys_timer_add()` / `sys_timer_del()` 纳入全业务层扫描，当前仓库仍有 4 个 RDX 业务文件存在周期 timer 直连补漏项。**因此 P5 完成不能等同于整个框架重构完成**，只能视为进入最终收口阶段。

> 注：此前全景表 record=16、ota=7 为 grep 粗略口径（未区分 `sys_timer_add/del`）。本文按实际调用点统计：record=18、ota=7 有效（+ 1 注释）。P5 边界检查覆盖 `sys_timer_(add|del|re_run)`，避免 record/ota 周期 timer 漏检。

# Part 2 — 改造方案

## 2.1 总体思路

1. **扩展 OSAL timer API**：
   - 新增 `rdx_os_timer_periodic_add(cb, priv, period_ms)` / `rdx_os_timer_periodic_del(id)`，封装 JL `sys_timer_add()` / `sys_timer_del()`
   - 新增 `rdx_os_timer_add_to_task(task_name, cb, priv, timeout_ms)`，封装 `sys_timeout_add_2_task()`
2. **逐文件替换 25 处有效直连调用**
3. **删除 `rdx_ota.c` line 526 的注释代码**
4. **补齐 `#include "rdx_jl_osal.h"`**（如未添加）
5. **同步更新 `tests/host/mock/rdx_jl_osal_mock.c`**，为新增 API 补 stub
6. **扩展 boundary check 规则**：新增 P5 对 `rdx_record.c` / `rdx_ota.c` 的规则

## 2.2 OSAL API 扩展

### 头文件 `port/jl/include/rdx_jl_osal.h`

在现有 timer API 后追加：

```c
/*
 * Periodic timer: callback fires repeatedly until deleted.
 * JL counterpart: sys_timer_add(priv, cb, period_ms).
 */
rdx_timer_t rdx_os_timer_periodic_add(void (*cb)(void *), void *priv, u32 period_ms);
void rdx_os_timer_periodic_del(rdx_timer_t id);

/*
 * Task-attached timer: callback runs in the specified app task context.
 * JL counterpart: sys_timeout_add_2_task(priv, cb, msec, task_name).
 */
rdx_timer_t rdx_os_timer_add_to_task(const char *task_name,
                                     void (*cb)(void *),
                                     void *priv, u32 timeout_ms);
```

### 实现 `port/jl/jl7018/rdx_jl_osal.c` 与 `port/jl/jl7018_shadow/rdx_jl_osal.c`

```c
rdx_timer_t rdx_os_timer_periodic_add(void (*cb)(void *), void *priv, u32 period_ms)
{
    return sys_timer_add(priv, cb, period_ms);
}

void rdx_os_timer_periodic_del(rdx_timer_t id)
{
    sys_timer_del(id);
}

rdx_timer_t rdx_os_timer_add_to_task(const char *task_name,
                                     void (*cb)(void *),
                                     void *priv, u32 timeout_ms)
{
    return sys_timeout_add_2_task(priv, cb, timeout_ms, task_name);
}
```

> 参数顺序：
> - JL `sys_timer_add(priv, cb, period_ms)` vs OSAL `rdx_os_timer_periodic_add(cb, priv, period_ms)`：priv 与 cb 顺序对调
> - JL `sys_timeout_add_2_task(priv, cb, msec, task_name)` vs OSAL `rdx_os_timer_add_to_task(task_name, cb, priv, timeout_ms)`：priv/cb 顺序、task_name 位置均对调
> 替换时逐处核对。

## 2.3 逐文件迁移步骤

### 步骤 1：`rdx_record.c`（18 处）

替换规则：
- `sys_timeout_del(timer)` → `rdx_os_timer_del(timer)`
- `sys_timer_re_run(timer)` → `rdx_os_timer_re_run(timer)`
- `sys_timeout_add(priv, cb, ms)` → `rdx_os_timer_add(cb, priv, ms)`
- `sys_timer_add(priv, cb, ms)`（line 320）→ `rdx_os_timer_periodic_add(cb, (void *)priv, ms)`，**不可替换为 `rdx_os_timer_add()`**
- `sys_timer_del(timer)`（line 246）→ `rdx_os_timer_periodic_del(timer)`，**不可替换为 `rdx_os_timer_del()`**

注意 `priv = 0` 的调用点需转换为 `(void *)0`，保持原语义。

### 步骤 2：`rdx_ota.c`（7 处有效 + 1 注释）

替换规则：
- `sys_timeout_add(NULL, cb, ms)` → `rdx_os_timer_add(cb, NULL, ms)`
- `sys_timeout_del(timer)` → `rdx_os_timer_del(timer)`
- `sys_timer_re_run(timer)` → `rdx_os_timer_re_run(timer)`
- `sys_timeout_add_2_task(NULL, cb, ms, "app_core")` → `rdx_os_timer_add_to_task("app_core", cb, NULL, ms)`
- 删除 line 526 的注释行

## 2.4 边界检查脚本扩展

在 `tools/check_rdx_boundaries.ps1` 中 P4 规则之后追加 P5 规则：

```powershell
# P5: rdx_record.c / rdx_ota.c must have no direct sys_timeout_* / sys_timer_* / sys_timeout_add_2_task
$p5TargetNames = @("rdx_record.c", "rdx_ota.c")
$p5TargetFiles = $allRdxFiles | Where-Object {
    $_.Name -in $p5TargetNames -and
    $_.FullName -match "[/\\]rdx_protocol[/\\]"
}

$p5SysTimeoutHits = Find-Pattern -Files $p5TargetFiles `
    -Pattern "\bsys_timeout_(add|del)\b"
Assert-NoHits "P5 files have no direct sys_timeout_add/del calls" $p5SysTimeoutHits

$p5SysTimerHits = Find-Pattern -Files $p5TargetFiles `
    -Pattern "\bsys_timer_(add|del|re_run)\b"
Assert-NoHits "P5 files have no direct sys_timer_add/del/re_run calls" $p5SysTimerHits

$p5Add2TaskHits = Find-Pattern -Files $p5TargetFiles `
    -Pattern "\bsys_timeout_add_2_task\b"
Assert-NoHits "P5 files have no direct sys_timeout_add_2_task calls" $p5Add2TaskHits
```

> 注意：现有 P0-P4 边界检查通过，不代表 P5 已完成；必须先合入上述 P5 规则，再以脚本通过作为 record/ota 清零证据。
>
> 同时，`sys_timer_add/del` 已纳入 P5 定义，但历史 P3a-P4 只覆盖 `sys_timer_re_run`，未全量覆盖周期 timer add/del。若要宣称“业务层 timer 直连清零”，还需在后续阶段新增全业务层 `sys_timer_add/del` 规则，或将附录 C 中的周期 timer 补漏项全部清理。
