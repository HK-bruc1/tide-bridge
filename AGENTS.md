# AGENTS.md

Guidance for coding agents working in this repository.

## Working rules

- Work directly in the current working directory. Do not create or switch to a Git worktree unless the user explicitly asks.
- Do not edit generated files (see [Build](#build)); edit their sources instead.
- Tool-owned configuration (`sdk_config.h/.c`, `src/*.json`) is regenerated by JL Studio. Put project overrides only in `SDK/apps/earphone/include/t2620_project_config.h`.
- Fixed platform behavior (e.g. the boot clock refurbish) is not wrapped in a config switch. Add `TCFG_*` switches only for real product or experiment choices.

## Project overview

JieLi (JL) **AC701N / BR28 TWS earphone firmware** (T2620 product) built on the JL SDK in `SDK/`.

- Project descriptor: `project.jlproj` (JL Studio); SDK type "TWS耳机", BR28 CPU
- Main application: `SDK/apps/earphone/`
- Product configuration from JL Studio: `src/`; release images: `output/`
- This branch adds the **RDX third-party BLE protocol** with a **HOGP keyboard extension**: two `app_ble` wrappers expose one composite RDX + HOGP GATT profile and carry up to two Peripheral ACLs.

## Build

**The JL SDK builds on Windows only.** The JL toolchain (`clang` / `pi32v2-lto-wrapper`) and the post-build packaging tools are Windows executables; there is no supported Linux build environment. Ignore Linux-style content (`/opt/jieli`, `ulimit`, `make -j\`nproc\``) inherited from the JL template in `SDK/Makefile` and `SDK/.vscode/tasks.json`.

Toolchain location expected by the Makefile:

```
C:/JL/pi32/bin/clang.exe
C:/JL/pi32/bin/pi32v2-lto-wrapper.exe
```

### VS Code tasks (source of truth)

`SDK/.vscode/tasks.json` defines the build and test commands. Open `SDK/` as the VS Code workspace folder; each task has a `windows` command, which is the one that applies:

| Task | Group | Windows command |
|---|---|---|
| `all` | default build (`Ctrl+Shift+B`) | `.vscode/winmk.bat all` |
| `clean` | build | `.vscode/winmk.bat clean` |
| `test: host software` | default test | `powershell -NoProfile -ExecutionPolicy Bypass -File ${workspaceFolder}/../tests/host/run_host_tests.ps1` |

The non-`windows` fallback commands in that file (`make ... -j\`nproc\``, `pwsh ...`) come from the JL template and are not used.

### Command line

Run the same wrapper from `SDK/` to match the VS Code tasks:

```powershell
cd SDK
.\.vscode\winmk.bat all
.\.vscode\winmk.bat clean
```

`winmk.bat` prepends `SDK/tools/utils` to `PATH` and runs `make <target> -j %NUMBER_OF_PROCESSORS%`. Prefer it over a bare `make`. If an incremental build fails with "No rule to make target" for a removed file, run `clean` then `all`.

Outputs (copied to `output/` by the post-build script `SDK/cpu/br28/tools/download.bat`):

- `SDK/cpu/br28/tools/sdk.elf`, `app.bin`, `jl_isd.bin` / `jl_isd.fw`, `update.ufw`
- `SDK/cpu/br28/tools/download/earphone/db_update_data.bin`

Generated by the pre-build step (do not edit): `apps/earphone/sdk_used_list.used`, `apps/earphone/movable/section.txt`, `cpu/br28/sdk.ld`, `cpu/br28/tools/download.bat`, `cpu/br28/tools/isd_config.ini`.

Flashing is done with JL Studio or `ISD_download.exe`, not from this repo's command line.

## Tests

Host-side software tests (Windows, from the repository root):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\host\run_host_tests.ps1
```

This is also the VS Code default test task `test: host software`. It runs 24 independent modules (4 source contracts + 20 behavioral suites), continues after failures, and exits nonzero if any module fails. Use `-Suite contracts` or `-Suite behavior` for a focused run. Behavioral harnesses need Python with `llvmlite`, the JL compiler, and PowerShell 5.1. Coverage and on-device limits: `tests/host/README.md`.

Source contracts:

- `test_t2620_product_contract.ps1` — T2620 configuration, USB/storage ownership, power-off cleanup
- `test_hogp_profile_contract.ps1` — HOGP bytes, layout, security boundary, peer-scoped bonded CCC
- `test_rdx_transport_contract.ps1` — two-wrapper topology, owner-scoped routing, unified advertising
- `test_rdx_lifecycle_contract.ps1` — reconnect state machine, FIFO barrier, single-command RDX release

Notable behavioral harnesses:

- `test_hogp_hold.py` — HOGP hold/scan/FIFO/session, hot-apply release, recording key sessions, no periodic timer while online idle
- `test_flashnote.py` — flashnote parser, stream-only state, session ownership, busy responses and release barriers
- `test_keymap_factory_reset.py` — keymap persistence and factory defaults
- `test_record_tone.py` — shared `rectone`/`recsave` GET/SET, VM durability, busy gates and token-bound request/ACK; APP/F18 no-file recording is covered by `test_hogp_hold.py`
- `test_ble_entry.py` — second-ACL 120 s entry window, advertising-close confirmation, fault isolation; pins the reviewed `btstack.a` / `btctrler.a` ABI (re-review on library upgrade, do not just replace hashes)
- `test_cache_flush.py`, `test_record_format.py` — on-demand cache flush and record-format patch library
- `test_lowpower_lrc.py` — LRC sleep-clock configuration, board init, probe-switch rejection, boot clock refurbish

Host tests do not replace on-device validation (HCI/RF timing, sleep, current measurement). There is no firmware unit-test framework.

## Architecture

### SDK layout

- `SDK/apps/earphone/` — application entry, modes, UI, audio scenes
- `SDK/apps/common/` — shared subsystems: drivers (key, charge, USB, LED), config, third-party BLE protocols
- `SDK/audio/` — audio framework, codecs, effects, CVP/AEC/ANC
- `SDK/cpu/br28/` — chip drivers, linker scripts, prebuilt libraries (`liba/`)
- `SDK/interface/` — SDK API headers

### Tasks

`apps/earphone/app_main.c` declares the OS tasks (`app_core`, `btctrler`, `btstack`, `jlstream`, ...). Most application code runs on `app_core`.

### BLE protocol registration

`SDK/apps/common/third_party_profile/multi_protocol_main.c` registers BLE/SPP protocols and the shared ATT buffer; `app_ble_init()` inside `btstack.a` creates one ATT database. Protocols allocate wrappers with `app_ble_hdl_alloc()`.

### RDX BLE server and HOGP

RDX lives in `SDK/apps/common/third_party_profile/rdx_protocol/` (`librdxApp.a` plus sources in the Makefile):

- `rdx_ble_server.c` — GATT server, advertising, connection state, HOGP extension
- `rdx_app.c` — RDX application logic, key remapping, startup (`rdx_app_tasks_init()`)
- `rdx_flashnote.c` — APP and F19 flashnote control, state reporting, session ownership and release
- `rdx_ble_entry.c` — fixed single-ACL second-device entry: 100 ms fast advertising for 120 s, then 500 ms slow advertising without closing
- `rdx_hogp_input.c` — KEY1–KEY5 gesture entry, keymap snapshots, HID/local queues

Rules:

- `config_le_hci_connection_num = 2`, `config_le_gatt_server_num = 1`.
- HID Service `0x1812` is appended to `rdx_profile_data[]` at handles `0x0016–0x0022`, Device Information `0x0023–0x0027`, HID Output Report `0x0028–0x002a`.
- Two wrappers share one address/profile; only one idle wrapper advertises. ADV = `Flags + local name`; Scan Response = RDX Manufacturer Data, then HID UUID `0x1812`.
- One RDX owner and one HID owner globally, on separate links or one composite `RDX_HID` link. Keyboard routing requires `Input CCC enabled && encrypted && !suspended`. Bonded CCC intent is persisted per SM peer identity and lives as long as the SM bond: factory reset and unbind clear only classic BT pairing and keep it, because the PC reconnects with the old LTK and never rewrites the Input CCC.
- `*APP#custom#rdxclose#1#` releases RDX through FIFO/worker cleanup while keeping HID and the ACL (`docs/3-4.PC_APP逻辑断开无法释放RDX会话问题复盘与处理方案.md`).
- Local recording outranks BLE `opusfile` download. When F18/F19/CALL key admission passes, `rdx_file_download_preempt()` posts a stop to `protocol_send_task`; under `file_trans_mutex` it fully cleans up the live transfer (generation-checked) and answers exactly one `*DEV#filecmd#0#`. Recording does not wait for this cleanup. Fallback: the parser's recording/OTA conflict branch refuses chunks and sends the same notice, which also covers APP-started recordings and failed posts. Later `pack>=2` requests are refused silently. Transport and file failures stay silent. `*DEV#filecmd#0#` is shared with timeout and APP cancel, so the APP resumes with `pack=1` + offset after `record`/`flashnote` reports the recording stopped. GETLIST/listreq from the cached DAT is not interrupted. See section 10 of `docs/10-1.量产产线问题积累.md`.
- Key routing: defaults are modifier `0x07` (left Ctrl+Shift+Alt) with F13/F14/F17/F18/F19; product local functions require exactly `0x07` and one F13-F24 usage. Existing saved keymaps are not migrated. F17 is local playback, F18 is meeting recording/marks, and F19 starts inspiration recording on stable Down. Recording route is chosen at gesture admission from RDX owner + CCC + stream readiness. Online F18 starts on the device and publishes `record` state without the old `devrec` handshake. Full rules and acceptance status: `docs/2-8.HID键值绑定本地功能设计.md`.
- Meeting control/state uses `record`; APP and F19 inspiration use `flashnote`, sharing the `stream` audio channel. APP flashnote is stream-only; F19 is stream-only when RDX is ready at admission and otherwise local-only (`scene=3`). A later RDX connection synchronizes an offline F19's real file identity without taking control or enabling streaming. APP and key sessions cannot stop one another. Details and test limits: `docs/10-10.灵感录音复用闪记协议融合方案.md`.
- `recsave` controls APP/F18 meeting file storage (VM 168, default ON). OFF requires ready RDX, streams without a file and cancels/stops on RDX/CCC loss; rejected starts are silent. F19/CALL/factory and the F19-only CDC coexistence exception are unchanged. See `docs/10-8.会议录音落盘APP控制方案.md` and `docs/10-9.会议录音落盘APP对接说明.md`.

### Project config overlay (`t2620_project_config.h`)

Included by `app_config.h` right after `sdk_config.h`.

- `TCFG_DIP_SWITCH_POWER_ENABLE` / `TCFG_DIP_SWITCH_POWER_IO` (PB1) — DIP power switch. PB1 must not be an IO key; keep `TCFG_ADKEY_ENABLE` and `TCFG_LP_TOUCH_KEY_ENABLE` off in JL Studio. Never add `TCFG_DIP_SWITCH_POWER*` to `sdk_config.*` or `iokey_config.c`.
- `TCFG_T2620_PC_STORAGE_ENABLE` (default 0) — optional USB MSC export; requires SD0 + USB MSC, otherwise forces PC mode off.
- `TCFG_T2620_FACTORY_USB_CDC_ENABLE` (default 1) — factory CDC protocol (`rdx_factory_cdc.c`), independent of DUT and MSC.
- `TCFG_T2620_CHARGE_COEXIST_ENABLE` (default 1) — charging coexists with BLE/recording.
- `TCFG_T2620_STORAGE_PRESERVE_ON_BOOT` — never auto-format SD at boot; SD NAND is always-online.
- `TCFG_T2620_LOWPOWER_LRC_ENABLE` (default 1) — native LRC sleep clock, configured at boot.
- `TCFG_T2620_CONN_SLAVE_LATENCY` (default 49) — standing BLE connection target `{6,12,L,600}`: fast interval, power saved by slave latency; no fast/slow switching, no local latency gate. Rationale: section 2.4 of `docs/6-2.T2620BLE连接后低功耗设计.md`.
- Single-ACL second entry is a fixed product policy, not a `TCFG_*` switch: while exactly one ACL is connected the idle wrapper advertises at 100 ms for the first 120 s, then switches to 500 ms and stays open. A real business wake in the slow phase (business message or product key press) promotes back to fast for one new 120 s window; activity inside the fast phase does not extend it. Every 2→1 restart begins a new fast phase. Composite HID+RDX still closes the entry. Section 4.2.1 of `docs/6-2.T2620BLE连接后低功耗设计.md`.
- Idle-probe (`TCFG_T2620_IDLE_PROBE_*`) and connection-probe/latency-gate switches (`TCFG_T2620_CONN_PROBE_ENABLE`, `TCFG_T2620_CONN_LATENCY_GATE_ENABLE`) are rejected at compile time on this branch.

Storage/shutdown: `rdx_storage_lifecycle.c` owns file-service admission and PC-return reconciliation; `rdx_dip_switch.c` owns debounced OFF admission and a 3 s reset guard. See section 0 of `docs/7-0.T2620_U盘与BLE及充电共存可行性评估与实施方案.md`.

### Low power (zero ACL, 500 ms slow advertising)

- Sleep clock and CPU clock are independent: LRC lowers the sleep floor; the system clock sets the per-wake spikes.
- The library sets the system clock to 120 MHz at boot outside `clock_manager`, so the native clock observer never runs unless something refurbishes it. `rdx_app_tasks_init()` calls `clock_refurbish()` once, unconditionally; the native observer then drops to 24 MHz in about 10 s when idle.
- Raise CPU frequency only via `clock_alloc` / `clock_lock`; never call `clk_set("sys", ...)` directly, or the clock may not drop back.
- USB detection, battery sampling, key scan and debug UART stay native.
- Never keep a periodic `sys_timer` while idle: it wakes the system and blocks sleep. The HOGP input service is event-driven and runs its 10 ms retry timer only while a HID report is in flight or a release is owed; this took the PC HID + PC RDX composite session from about 3 mA to below 1 mA (`docs/6-2.T2620BLE连接后低功耗设计.md` section 2.7).
- A single ACL keeps the second-entry advertising on (100 ms for 120 s, then 500 ms, with business wakes promoting back to a fresh 120 s fast phase). Neither stable phase holds the sleep gate; two ACLs, single-ACL advertising transactions and faults retain protection. Board tests on 2026-11-09 (`COM3_2026-11-09_15-59-06.log`) confirmed sleep in both phases and two successful second-ACL connections during slow-phase sleep, three total with the earlier run, with no controller assert or unexpected reset. The user reported three tests in the latest run, but only two second-ACL connections appear in that log. One `timer_no_response` coincided with the business-wake fast-advertising transition; its callback address corresponds to `input_service` in the current ELF, but that is not the sampled PC and its root cause remains open. The user measured 0.5–2.2 mA total current (2.2 mA peak, roughly 1 mA visually estimated, not an integrated average); current was not separately recorded for each advertising phase. Connecting during fast-phase sleep, bonded reconnects and long-run stability remain unvalidated. Composite HID+RDX still closes the entry.
- Measured 2026-10-27 (multimeter, user confirmed): 0.6–1.4 mA without the former 2–4 mA spikes. The idle probe and logs used to find this are frozen on branch `freeze/idle-probe-20261027`.
- Details and acceptance limits: `docs/6-0.T2620外设低功耗与共享VDD电源管理设计.md` (sections 2.4, 4.6, 5, 6.6); connected-state power: `docs/6-2.T2620BLE连接后低功耗设计.md`.

### Keys and audio

- Physical IO keys come from `src/按键配置.json` → `g_iokey_info[]`; `SDK/apps/earphone/board/iokey_config.c` builds the platform data.
- Audio flows are `.x6flow` files in `src/音频流程/`, compiled to `stream.bin`.

## Workflow

1. Edit product configuration in JL Studio (regenerates `src/*.json` and `sdk_config.h/.c`).
2. Put project overrides only in `t2620_project_config.h`.
3. Build on Windows: `cd SDK` → `.\.vscode\winmk.bat all`.
4. Run host tests from the repository root.
5. Flash `output/` (or `SDK/cpu/br28/tools/download/earphone/`) with JL Studio / `ISD_download.exe`.
